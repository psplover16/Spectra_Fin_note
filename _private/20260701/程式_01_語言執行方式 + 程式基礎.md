> }

## 🤔 先想想

- 電腦的 CPU 其實只看得懂 **0 與 1（機器碼）**。你寫的 `int x = 10;` 對 CPU 來說是天書，中間一定要有人「翻譯」。
- 翻譯可以**先全部翻好再跑**（像先把整本書翻成中文再讀），也可以**邊翻邊讀**（像口譯，念一句翻一句）。這就是 Compiler 與 Interpreter 的差別。
- 迴圈與 switch 你早就會用，但考試不考你「會不會用」，考你「**少寫一個 break 會怎樣**」「**do-while 到底跑幾次**」這種細節。

帶著這三點，我們來拆解。

## 📖 觀念拆解

### 一、程式碼為什麼需要「翻譯」？

CPU 只認得**機器碼（0/1）**。人寫的程式分兩種層次：

- **低階語言**：組合語言（Assembly），跟機器碼幾乎一對一，很接近硬體。
- **高階語言**：C、Java、Python 等，接近人的語言，好讀好寫，但 CPU 看不懂。

所以中間一定要有「翻譯工具」把它變成機器碼。不同的翻譯策略，就決定了**執行速度、除錯難易、能不能跨平台**。

### 二、三種翻譯工具（核心對照表）　【硬背】

| 工具 | 翻譯什麼 | 特點 | 例子 |
|---|---|---|---|
| Assembler（組譯器） | 組合語言到機器碼 | 一對一翻譯 | 低階組合語言 |
| Compiler（編譯器） | 高階語言一次翻成機器碼並產生執行檔 | 執行快，要先編譯 | C、C++ |
| Interpreter（直譯器） | 高階語言一行一行邊翻邊執行 | 較慢，跨平台且好除錯 | Python、JavaScript |

📌 **白話拆解：**
- **Assembler**：把組合語言那種「近乎機器碼」的東西做**一對一**翻譯，一句組語對一句機器碼。
- **Compiler**：像把整本書**一次翻譯完**，產出一個「執行檔」（例如 .exe）。之後執行時不用再翻，所以**跑得快**；但你**改一行就得重新編譯整包**。
- **Interpreter**：像現場**口譯**，程式跑到哪一行才翻那一行。**啟動快、好除錯**（錯在哪行很清楚），但因為邊跑邊翻，**整體較慢**。

一句話記：**Compiler 整包翻成執行檔；Interpreter 一行一行邊翻邊執行。**

📌 **補充（常考的完整流程）：** 嚴格說 Compiler 先產生**目的碼（object code，如 .obj／.o）**，還要 **Linker（連結器）** 把多個目的檔與函式庫連結起來才成為**執行檔**；執行時再由 **Loader（載入器）** 載入記憶體開始跑。

### 三、Java 的混合模式：bytecode + JVM

Java 不是純 Compiler，也不是純 Interpreter，而是**混合型**：

> Java 是混合型：先編譯成 **bytecode（位元組碼）**，再由 **JVM** 直譯或 **JIT** 執行，達成跨平台。

流程長這樣：

```
你的 .java  ──(javac 編譯)──►  .class（bytecode）  ──►  JVM 在各平台上執行
```

- **bytecode** 不是機器碼，而是一種「JVM 專用的中間碼」。
- 每個平台（Windows／Mac／Linux）都有自己的 **JVM**，負責把同一份 bytecode 翻成該平台的機器碼。
- 這就是 Java 的招牌口號 **Write Once, Run Anywhere（一次編譯、到處執行）** 的原理：跨平台的差異都被 JVM 吸收了。
- **JIT（Just-In-Time）**：JVM 會把常跑的 bytecode 即時編譯成機器碼並快取起來，讓熱點程式碼跑得接近編譯式語言的速度。

### 四、變數與資料型別：靜態 vs 動態　【理解】

| 比較 | 靜態型別 Static | 動態型別 Dynamic |
|---|---|---|
| 何時定型別 | 宣告時就定死 | 執行時才決定 |
| 例子 | C、C++、Java | Python、JavaScript |

- **靜態型別**：宣告時就要講清楚型別，之後不能亂換。編譯期就能抓到型別錯誤，較安全。
  ```java
  int x = 10;      // x 一輩子是 int
  x = "hello";     // ❌ 編譯就報錯，型別不合
  ```
- **動態型別**：變數型別執行時才決定，同一個變數可以先裝數字再裝字串，寫起來自由，但錯誤容易拖到執行時才爆。
  ```python
  x = 10       # 此時 x 是整數
  x = "hello"  # 合法，x 現在變字串
  ```

常見型別與常數宣告：

- 常見型別：**int、float/double、char、boolean、string**。
- **常數**（值不可改）：C/C++ 用 `const`，Java 用 `final`。
  ```java
  final double PI = 3.14159;  // Java 常數
  ```
  ```c
  const double PI = 3.14159;  // C/C++ 常數
  ```

### 五、流程控制的考試陷阱　【理解＋細心】

來源整理的四個重點，全是考點：

- **switch**：對**單一變數**的多個值做分支。
- 每個 case 後要 `break`，**否則會 fall-through（穿透）** 繼續執行下面的 case。
- **for** 用於計次；**while** 先判斷、**可能一次都不跑**；**do-while** 至少執行一次。
- **break** 跳出整個迴圈；**continue** 只跳過這一輪、繼續下一輪。

**fall-through 實例**（這就是開場第 3 題）：

```java
int day = 2;
switch (day) {
    case 1: System.out.println("一");   // 沒進來
    case 2: System.out.println("二");   // ← 從這裡開始
    case 3: System.out.println("三");   // 沒 break，繼續穿透
    default: System.out.println("其他"); // 繼續穿透
}
// 印出：二 三 其他
```

只要在每個 case 尾巴補上 `break;`，就只會印「二」。

**三種迴圈跑幾次**：

```java
// for：明確計次，跑 5 次
for (int i = 0; i < 5; i++) { /* ... */ }

// while：先判斷，條件一開始就 false → 一次都不跑
int i = 10;
while (i < 5) { /* ... */ }   // 完全不執行

// do-while：先做再判斷 → 至少跑一次
int j = 10;
do { /* ... */ } while (j < 5);  // 仍會執行一次
```

## ✅ 回到題目：解答

1. **Compiler vs Interpreter**：Compiler 把高階語言**一次全部**翻成機器碼並產生執行檔，執行快但要先編譯（代表：**C、C++**）；Interpreter **一行一行邊翻邊執行**，較慢但跨平台、好除錯（代表：**Python、JavaScript**）。
2. **Java 是先編譯**成 bytecode，再交給各平台的 **JVM**（直譯或 JIT）執行。因為跨平台差異都由 JVM 處理，所以能「一次編譯、到處執行」。
3. `day = 2` 且**每個 case 都沒有 break**，會從 `case 2` 開始 **fall-through**，印出 **「二 三 其他」**。

---

## 📌 重點整理

- **翻譯三工具**：Assembler＝組語對機器碼一對一；Compiler＝整包翻成執行檔（快，需先編譯）；Interpreter＝一行行邊翻邊跑（慢，好除錯、跨平台）。
- **Java 混合模式**：`.java →（javac）→ bytecode（.class）→ JVM/JIT 執行`，靠 JVM 達成跨平台。
- **型別系統**：靜態（宣告定死，C/C++/Java）vs 動態（執行時決定，Python/JS）。常數：C/C++ `const`、Java `final`。
- **流程控制陷阱**：switch 少 break 會 fall-through；while 可能 0 次、do-while 至少 1 次；break 跳出迴圈、continue 跳過本輪。

---

## ⚠️ 常見陷阱

- **Compiler ≠ 直接能跨平台**：C/C++ 編出來的執行檔綁定平台；真正靠「中間碼＋虛擬機」跨平台的是 **Java（bytecode + JVM）**。
- **bytecode 不是機器碼**：它是 JVM 專用的中間碼，還要 JVM 再翻一次才會變成該平台的機器碼。
- **switch 忘了 break**：最常見的 bug 與考點，會一路穿透到後面的 case。
- **while vs do-while 次數**：while 條件一開始就不成立就「**一次都不跑**」；do-while 是「**先做再判斷**」，一定至少跑一次。
- **continue 不是跳出**：continue 只跳過「這一輪剩下的程式」，迴圈還會繼續；跳出整個迴圈才是 break。

## 📝 練習題（含解答）

**Q1.** 為什麼一般說 Compiler 產生的程式「執行比較快」，Interpreter「比較慢」？
<details><summary>看解答</summary>

Compiler 事先把整包翻成機器碼（執行檔），執行時直接跑機器碼、不用再翻；Interpreter 是執行時**一行一行邊翻邊跑**，多了即時翻譯的開銷，所以整體較慢（但啟動快、好除錯）。
</details>

**Q2.** 為什麼 Java 能「一次編譯、到處執行」？請點出 bytecode 與 JVM 的角色。
<details><summary>看解答</summary>

Java 先把原始碼編譯成**與平台無關的 bytecode**；各平台各自有 **JVM**，負責把同一份 bytecode 翻成該平台的機器碼。跨平台差異由 JVM 吸收，所以同一份 bytecode 能在不同作業系統上跑。
</details>

**Q3.** C 和 Python 分別是靜態還是動態型別？各有什麼特點？
<details><summary>看解答</summary>

C 是**靜態型別**（宣告時就定死型別，編譯期抓型別錯，較安全）；Python 是**動態型別**（執行時才決定型別，寫起來自由，但型別錯可能拖到執行時才爆）。
</details>

**Q4.** 下面程式印出什麼？
```java
int n = 3;
switch (n) {
    case 3: System.out.print("A");
    case 4: System.out.print("B"); break;
    case 5: System.out.print("C");
}
```
<details><summary>看解答</summary>

印出 **AB**。`case 3` 沒有 break，穿透到 `case 4` 印 B，遇到 `case 4` 的 break 才停，所以是 AB（不會印 C）。
</details>

**Q5.** 一段迴圈條件一開始就不成立，若用 while 會執行幾次？改用 do-while 呢？
<details><summary>看解答</summary>

**while：0 次**（先判斷，條件不成立就完全不進迴圈）；**do-while：至少 1 次**（先執行一次迴圈內容，才回頭判斷條件）。
</details>
