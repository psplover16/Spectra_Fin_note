# 資安：加密、雜湊、數位簽章、憑證與 TLS

> 這篇**跨兩科**：TLS 的協定面 → 網路概論；加密／雜湊／簽章／憑證／CIA → 資訊管理（資安）。一次讀通，兩科的分都拿。
>
> 學習方式：概念屬【理解】（懂原理就記得）；對照表與關鍵字屬【硬背】。TLS 版本現況已經查證。

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 「用『**公鑰加密、私鑰解密**』達成的是**機密性**還是**數位簽章**？反過來『私鑰加密、公鑰解密』又是哪一個？」
> 2. 「**數位簽章**能同時保證哪些資安性質？它負責把內容『**保密**』嗎？」
> 3. 「**HTTPS** 走哪個 port？它同時用到對稱與非對稱加密——各用在什麼階段？」

先別急著往下看答案，試著自己回答看看。

## 🤔 先想想

這篇名詞多，但骨架很清楚。給你幾個提示：

- 資安在保護三件事（**CIA**），每一件都對應一種「工具」——把「哪件事靠哪個工具」串起來就通了。
- 對稱與非對稱**不是誰比較安全**，而是各有專長（一個快、一個能解決金鑰分配）。
- 「**加密**」和「**簽章**」都用到公私鑰，但方向剛好相反——關鍵永遠是「**誰的鑰匙、哪一把**」。
- TLS 不是憑空新東西，它其實是「**把前面所有工具湊在一起用**」的綜合題。

帶著這幾點，我們來拆解。

## 📖 觀念拆解

### 一、資訊安全三要素 CIA　【硬背】

資安到底在保護什麼？核心就三件事（合稱 **CIA**）：

- **機密性 Confidentiality**：別人看不到 → 靠**加密**。
- **完整性 Integrity**：資料沒被竄改 → 靠**雜湊／數位簽章**。
- **可用性 Availability**：需要時用得到 → **防 DoS、備援**。

常見延伸：**不可否認性 Non-repudiation**（你不能否認自己做過）→ 靠**數位簽章**。

> 記法：C＝別人看不到、I＝沒被改、A＝我要用時它還活著。下面每一節，其實都是在補「某個要素靠什麼達成」。

### 二、對稱式 vs 非對稱式加密　【硬背】★

這是整篇的地基。差別在**用幾把鑰匙**。

| | 對稱式加密 | 非對稱式加密 |
|---|---|---|
| 金鑰 | 加解密同一把（祕密金鑰） | 一對：公鑰 + 私鑰 |
| 速度 | 快 | 慢 |
| 主要難題 | 金鑰怎麼安全交給對方（金鑰分配） | 慢，不適合大量資料 |
| 代表演算法 | AES、DES、3DES | RSA、ECC、Diffie-Hellman |
| 用途 | 大量資料加密 | 交換金鑰、數位簽章 |

**最重要的觀念（背）：**

- **公鑰加密 → 私鑰解密 ＝ 保密**（只有持私鑰的人看得到）。
- **私鑰加密 → 公鑰解密 ＝ 簽章／驗身分**（證明是私鑰持有者發的）。

> 比喻：**對稱式**像一把「同一支鑰匙開關」的鎖——快，但你怎麼把這支鑰匙安全交給對方（金鑰分配難）？**非對稱式**像「一個公開的投遞口 ＋ 一把私人鑰匙」：任何人都能把信投進去（公鑰加密），但只有你能打開拿信（私鑰解密）。
>
> 為什麼「私鑰加密＝簽章」？因為**只有你**有私鑰，能用它加出的東西別人偽造不了；而大家都能用你的公鑰驗證「這確實是你發的」。

💡 **數位信封（Digital Envelope）**：要安全送大量機密資料時，就用**接收者的公鑰**加密一把**對稱金鑰**、再用那把對稱金鑰加密資料本身，兩者一起送——「非對稱包鑰匙、對稱包資料」正是常考的數位信封（如 PGP 加密郵件）。

### 三、雜湊 Hash　【理解】

- **名詞：** 把**任意長度**資料 → 轉成**固定長度**的「指紋／摘要」。
- **特性：** ① **單向**（算不回原文）② **雪崩效應**（改一點點、整個變）③ **難碰撞**（兩筆不同資料很難算出同一個值）。
- **用途：** 驗完整性、存密碼（存**雜湊**不存明碼；實務常再加**鹽 salt**——每人一段隨機值一起雜湊，讓駭客預算好的「彩虹表」查不到）。
- **代表：** **SHA-256**（常用）；**MD5、SHA-1 已不安全，別用**。

> 具體感受「雪崩效應」：把一份合約裡的「新台幣 **10,000** 元」偷改成「**100,000** 元」，只差一個 0，重算出來的雜湊值卻會**完全不同**——收方一比對就知道被動過手腳。這就是它能「驗完整性」的原因。

### 四、數位簽章 Digital Signature　【理解】★

**流程（記步驟）：**

1. 發送方把「**資料的雜湊值**」用「**自己的私鑰**」加密 → 這就是**簽章**。
2. 收方用「**發送方的公鑰**」解開簽章，再比對自己**重算**的雜湊。
3. 一致 → 同時保證：**身分（不可否認）＋ 完整性**。

⚠ **易錯：** 數位簽章**不負責把內容加密保密**，它保證的是**來源 + 沒被竄改**。若還要保密，得**另外**用接收者的公鑰加密內容。

> 為什麼要先雜湊再簽？因為非對稱加密慢，直接加密整份資料太費力；改成只對「短短一段雜湊值」簽，又快又能達到同樣的驗證效果。

### 五、憑證 Certificate 與 CA／PKI　【理解】★

- **問題：** 你拿到一把公鑰，怎麼確定它**真的是那個網站的**、不是駭客冒充的？
- **解法：** **數位憑證**＝「**公鑰 + 持有者身分資訊**」，由 **CA（憑證授權中心）** 用 **CA 的私鑰**簽章背書。
- **PKI（公鑰基礎建設）：** CA、憑證、註冊機構等**整套「信任體系」**。
- **例：** 瀏覽器內建一份**信任的 CA 清單**；網站的憑證若由可信 CA 簽 → 顯示**鎖頭、https**。

> 比喻：公鑰就像陌生人自報的「電話號碼」，你怎麼知道沒被冒充？**CA** 就像「**政府核發的身分證**」——由一個大家都信任的第三方蓋章背書，你信任 CA，就能連帶信任它簽出來的憑證。

### 六、SSL／TLS（把上面全用上）　【理解】

- **TLS（Transport Layer Security）：** 網路傳輸的加密協定，**SSL 的後繼者**（SSL 已全面淘汰）。
- **HTTPS ＝ HTTP ＋ TLS**，跑在 **port 443**。
- **位置：** 在應用層與傳輸層之間（OSI 常歸到表現層附近）。
- **版本現況（查證後）：** 實際在用的是 **TLS 1.2 與 1.3**；**TLS 1.3（2018）為最新**；SSL 全部、TLS 1.0／1.1 已淘汰（2021 年由 **RFC 8996** 正式廢止，主流瀏覽器都已封鎖；舊版漏洞如 POODLE、BEAST）。

**一次連線怎麼運作（交握 Handshake 概念）：**

1. 用**非對稱加密 + 憑證／CA**：驗證網站身分，並安全地協商出一把**對稱金鑰**。
2. 之後資料改用**對稱加密**傳送（快）。
3. 完整性靠**雜湊／MAC**。

**一句話：** 非對稱**談鑰匙** + 憑證**驗身分**，對稱**傳資料**，雜湊**驗完整**。

> 看懂了嗎——TLS 就是這份講義的「總複習題」：憑證（第五節）＋非對稱（第二節）＋對稱（第二節）＋雜湊（第三節），四樣工具各司其職拼成一次安全連線。

## ✅ 回到題目：解答

1. **公鑰加密／私鑰加密各是什麼？** → **公鑰加密 → 私鑰解密 ＝ 保密（機密性）**；反過來 **私鑰加密 → 公鑰解密 ＝ 簽章／驗身分**。
2. **數位簽章保證什麼？負責保密嗎？** → 同時保證**來源（認證／不可否認）＋ 完整性**；**不負責保密**（要保密得另外用接收者的公鑰加密內容）。
3. **HTTPS 的 port 與對稱／非對稱分工？** → 走 **port 443**。**握手階段**用**非對稱加密＋憑證**驗身分、安全協商出一把對稱金鑰；**之後傳資料**改用**對稱加密**（快），完整性靠雜湊／MAC。

## 📌 重點整理

- **CIA**：機密（加密）、完整（雜湊／簽章）、可用；＋ 不可否認（簽章）。
- **對稱**（AES／DES，快，金鑰分配難）vs **非對稱**（RSA／ECC，慢，換金鑰＋簽章）。
- **公鑰加密＝保密；私鑰加密＝簽章。**
- **雜湊**：單向、固定長度、驗完整；SHA-256 好、MD5／SHA-1 淘汰。
- **數位簽章** ＝ 用私鑰加密「雜湊值」→ 驗身分＋完整（不可否認），不保密。
- **憑證** ＝ 公鑰＋身分，CA 背書；**PKI** 是整套信任體系。
- **TLS**：HTTPS／443；非對稱換鑰匙＋對稱傳資料＋憑證驗身分；TLS **1.2／1.3** 在用，**1.3 最新**。

## ⚠️ 常見陷阱

這張「陷阱 vs 正確」對照是本篇的送分重災區，務必逐條記牢：

| 陷阱（錯誤說法） | 正確 |
|---|---|
| 對稱加密「比較不安全」 | 不是安全高低，而是對稱快、非對稱解決金鑰分配 |
| 數位簽章會把內容加密 | 錯，簽章保證來源＋完整，不負責保密 |
| 雜湊可以解回原文 | 錯，雜湊是單向的 |
| 公鑰要保密 | 錯，公鑰公開；要保密的是私鑰 |
| HTTPS 只用非對稱加密 | 錯，握手用非對稱換鑰匙、傳資料用對稱 |
| SSL 還在用 | 錯，SSL 已淘汰，現在是 TLS |

## 📝 練習題（含解答）

**Q1.** 資安三要素 CIA 分別是什麼？各靠什麼技術達成？
<details><summary>看解答</summary>

**機密性（Confidentiality）**靠加密、**完整性（Integrity）**靠雜湊／數位簽章、**可用性（Availability）**靠防 DoS 與備援。延伸的**不可否認性**靠數位簽章。
</details>

**Q2.** 要把一份大檔案安全地傳給對方，實務上為什麼常「對稱＋非對稱混用」，而不是只用非對稱？
<details><summary>看解答</summary>

因為**非對稱加密慢、不適合大量資料**。實務做法：先用**非對稱**安全地把一把**對稱金鑰**交給對方（解決金鑰分配問題），再用又快又適合大量資料的**對稱加密**傳檔案，兼顧安全與速度。這正是 TLS 的做法。
</details>

**Q3.** 數位簽章的產生用「誰的哪一把鑰匙」？驗證時又用「誰的哪一把」？它能同時保證什麼？
<details><summary>看解答</summary>

產生：用**發送方的私鑰**加密資料的雜湊值。驗證：用**發送方的公鑰**解開，再比對重算的雜湊。一致即同時保證**來源（認證／不可否認）＋ 完整性**（但**不保密**）。
</details>

**Q4.** 你在瀏覽器看到某網站有「鎖頭、https」，這代表什麼？背後是誰在背書？
<details><summary>看解答</summary>

代表該網站的**數位憑證**（內含公鑰＋身分）由**瀏覽器信任的 CA（憑證授權中心）**用 CA 私鑰簽章背書，通過驗證，且連線經 TLS 加密。整套信任機制稱為 **PKI**。
</details>

**Q5.** 現在還能用 SSL 或 TLS 1.0 嗎？目前實務上在用的是哪些版本？
<details><summary>看解答</summary>

**不能**。SSL 全部、TLS 1.0／1.1 都已淘汰（2021 年 RFC 8996 正式廢止，瀏覽器已封鎖）。目前實際在用的是 **TLS 1.2 與 1.3**，其中 **TLS 1.3（2018）為最新**。
</details>
