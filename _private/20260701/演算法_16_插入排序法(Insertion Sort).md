# 插入排序法(Insertion Sort)

> 科目：演算法｜插入排序是「簡單排序三兄弟」之一，考點在流程、穩定性與最壞 O(n²)。
>
> 學習方式：把它想成「整理撲克牌」——左手的牌已排好，抽到新牌就插進正確位置。畫一次搬移過程就懂。
>
> 難度分配：流程與「往右移再插入」屬【理解】；複雜度與適用時機屬【硬背】。

## 📖 觀念拆解

### 一、演算法概念

插入排序法(Insertion Sort)會把左邊視為已排序區，每次拿一個新元素插入到正確位置。它很像整理撲克牌：手上的牌已排好，拿到新牌後就插入適合的位置。

**白話**：插入排序每次只處理一個新元素，把比它大的元素往右移，再把新元素放到空出來的位置。因為它對「幾乎已排好」的資料特別友善（新牌常常一比就定位），所以是小資料或近乎有序時的好選擇。

### 二、核心規則（逐條看）

1. 把左側視為已排序區。
2. 取出目前要插入的 key。
3. 從 key 左邊開始，把比 key 大的元素往右移。
4. 找到正確位置後，把 key 放進去。
5. 重複直到所有元素都插入已排序區。

**新手提醒**：搬移時是「複製覆蓋」——把大的值往右蓋一格，被蓋掉的位置稍後會由更左邊的值或 key 補上，不會遺失資料。

### 三、最壞時間複雜度

| 版本 | 最壞時間複雜度 | 推導重點 |
|---|---|---|
| 遞迴版本 | O(n²) | 反向排序時，每一層都要把新元素一路往前插入。 |
| 非遞迴版本 | O(n²) | 搬移次數約為 1 + 2 + ... + (n - 1)。 |

**白話**：最壞情況是資料**完全反向**（例如由大到小），每個新元素都得一路擠到最前面，搬移次數累加成 1 + 2 + … + (n-1) ≈ n²/2，所以是 O(n²)。反過來，若資料已接近排好，每次幾乎不用搬，最好情況可達 O(n)——這是插入排序的優點。

### 四、遞迴版 Java

> 先排序前 n - 1 個元素，再把第 n 個元素插入正確位置。

```java
public static void insertionSortRecursive(int[] arr) {
    insertionSortRecursive(arr, arr.length);
}

private static void insertionSortRecursive(int[] arr, int n) {
    // 前 n 個元素中，若 n <= 1，代表不需要排序。
    if (n <= 1) {
        return;
    }

    // 先排序前 n - 1 個元素。
    insertionSortRecursive(arr, n - 1);

    // 再把第 n 個元素，也就是 arr[n - 1]，插入前面已排序區。
    int key = arr[n - 1];
    int j = n - 2;

    while (j >= 0 && arr[j] > key) {
        arr[j + 1] = arr[j];
        j--;
    }

    arr[j + 1] = key;
}
```

**逐行白話**：遞迴的思路是「先把前 n-1 個排好，我只負責把最後一個 `arr[n-1]` 插進去」。內層 while 從 `j = n-2` 往左掃，把比 key 大的往右蓋；停下時 `j+1` 就是 key 的正確位置。

### 五、非遞迴版 Java

> 用迴圈逐一取出 key，插入左側已排序區。

```java
public static void insertionSortIterative(int[] arr) {
    // i 左邊視為已排序區，arr[i] 是準備插入的值。
    for (int i = 1; i < arr.length; i++) {
        int key = arr[i];
        int j = i - 1;

        // 把比 key 大的元素往右移，空出 key 應該放的位置。
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }

        // j + 1 就是 key 的正確插入位置。
        arr[j + 1] = key;
    }
}
```

**逐行白話**：外層 `i` 從 1 開始（索引 0 那一個自成已排序區），`key = arr[i]` 是要插入的新牌。內層把左側比 key 大的往右移，`while` 條件 `arr[j] > key`（嚴格大於）正是插入排序**穩定**的關鍵——相等時不再往右移，保留原相對順序。最後把 key 放到 `j + 1`。

### 六、逐步範例：排序 `[5, 2, 4, 1]`

用非遞迴版追蹤，每輪取一個 key 插入左側已排序區：

| 輪 i | key | 搬移動作 | 該輪結束後的陣列 |
|---|---|---|---|
| 起始 | — | 索引 0 的 5 自成已排序區 | `[5, 2, 4, 1]` |
| i=1 | 2 | 5 > 2，5 右移；2 放索引 0 | `[2, 5, 4, 1]` |
| i=2 | 4 | 5 > 4，5 右移；2 < 4 停；4 放索引 1 | `[2, 4, 5, 1]` |
| i=3 | 1 | 5、4、2 依序右移；1 放索引 0 | `[1, 2, 4, 5]` |

**結果：`[1, 2, 4, 5]`**。可以看到「已排序區」從左邊 1 個逐輪長到 4 個。

---

## ✅ 回到題目：解答

1. 插入排序把**左側**視為已排序區；取出新元素 key，把左側比它大的往右移，再把 key 塞進空出的位置。
2. `[5,2,4,1]` → i=1：`[2,5,4,1]` → i=2：`[2,4,5,1]` → i=3：`[1,2,4,5]`。
3. 最壞 **O(n²)**，發生在資料**完全反向**時，每個新元素都要一路往前插到底。

## 📌 重點整理

- 概念：左側為已排序區，每次插入一個新元素到正確位置（像整理撲克牌）。
- 動作：把比 key 大的元素往右移，空出位置後放入 key。
- 複雜度：最壞 **O(n²)**（反向）、最好 O(n)（近乎有序）。
- 穩定性：**穩定排序**（`arr[j] > key` 用嚴格大於，相等不搬移）。
- 空間：**原地排序（in-place）**，只需 **O(1)** 額外空間。
- 適用：小資料或近乎已排序時特別有效率。

---

## ⚠️ 常見陷阱

- **搬移方向搞反**：是把大的往**右**移、空出縫隙給 key，不是把 key 往左硬換。
- **while 條件**：`arr[j] > key` 用**嚴格大於**才能維持穩定；若寫成 `>=`，相等元素會被往後排，變不穩定。
- **插入位置**：迴圈結束後 key 要放在 **`j + 1`**，不是 j（此時 arr[j] 已不大於 key 或 j 已到 -1）。
- **起點**：外層 i 從 **1** 開始，因為索引 0 單獨一個本來就有序。

## 📝 練習題（含解答）

**Q1.** 對 `[3, 1, 2]` 做插入排序，寫出每一輪結束後的陣列。
<details><summary>看解答</summary>

- i=1：key=1，3>1 右移，1 放索引 0 → `[1, 3, 2]`
- i=2：key=2，3>2 右移，1<2 停，2 放索引 1 → `[1, 2, 3]`

結果 `[1, 2, 3]`。
</details>

**Q2.** 插入排序是穩定還是不穩定？程式裡哪個細節決定了它？
<details><summary>看解答</summary>

**穩定**。關鍵在內層 while 用 `arr[j] > key`（嚴格大於）：當元素與 key 相等時不再往右移，因此相等元素的相對順序被保留。
</details>

**Q3.** 插入排序的最好與最壞時間複雜度分別是多少？各在什麼輸入下發生？
<details><summary>看解答</summary>

最好 **O(n)**，發生在資料已（近乎）排序時，每個新元素幾乎不用搬移；最壞 **O(n²)**，發生在資料完全反向時，每個新元素都要一路往前插。
</details>

**Q4.** 非遞迴版中，外層迴圈的 i 為什麼從 1 開始而不是 0？
<details><summary>看解答</summary>

因為索引 0 只有單一元素，本身就是有序的已排序區；從 i=1 開始，才是「拿第一個新元素插入左側已排序區」。
</details>

**Q5.** 內層 while 結束後，為什麼要把 key 放到 `arr[j + 1]` 而不是 `arr[j]`？
<details><summary>看解答</summary>

while 停止時，可能是 `arr[j] <= key`（j 這格不該被 key 佔）或 j 已變成 -1（沒有更左的位置）。無論哪種，空出來、該放 key 的位置都是它右邊一格，也就是 `j + 1`。
</details>
