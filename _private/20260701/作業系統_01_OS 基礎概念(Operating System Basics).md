## 🤔 先想想

給你三個提示，幫你抓方向：

- OS 分類的判斷主軸是「**它怎麼服務工作與使用者**」——是集中成一批？切時間片輪流？還是要在時限內完成？
- 「同時做很多事」有兩種：一種是**輪流切換到看起來同時**，一種是**真的同時**。差別在硬體。
- Offline、Spooling、Buffering、Cache 全都是為了**搭配又慢又不聽話的 I/O 裝置**，只是重疊程度與放的位置不同。

帶著這三點來拆解。

## 📖 觀念拆解

### 一、OS 五大分類

作業系統依「服務型態」可分成五類，這是選擇題最愛考的對應表：

| 類型 | 定義（一句話） | 優點 | 缺點 | 實例 |
|---|---|---|---|---|
| 批次處理 Batch | 把工作集中成一批，依序自動處理，無使用者互動 | 吞吐量高、自動化 | 不能互動、回應慢、除錯難 | 早期主機月結帳 |
| 多元程式 Multiprogramming | 記憶體同時放多個工作，某個在等 I/O 時 CPU 改做另一個 | CPU 利用率高 | 排程、記憶體管理複雜 | 早期多工主機 |
| 分時 Time-sharing | 把 CPU 時間切成小片，輪流給多個使用者，可即時互動 | 多人互動、回應快 | 切換有 overhead、需保護機制 | UNIX、Linux |
| 即時 Real-time | 必須在時限內完成回應 | 即時、可預測 | 彈性低、設計嚴格 | 硬性：飛彈/醫療；軟性：串流影音 |
| 分散式 Distributed | 多台電腦透過網路共享資源、協同運算 | 資源共享、可靠、易擴充 | 複雜、依賴網路、安全議題 | 雲端、叢集運算 |

📌 **白話比喻：**
- **批次**像自助洗衣店的「洗一整批」：丟進去就走，中途不能插手。
- **多元程式**像一個廚師顧多鍋：這鍋在燉（等 I/O），就先去炒另一鍋，讓爐火（CPU）不空著。
- **分時**像老師輪流回答一群學生，每人講幾秒就換下一位，快到大家都覺得「老師一直在陪我」。

**即時系統再細分：** 硬性即時（Hard real-time）錯過時限就算失敗，例如**醫療、飛彈**；軟性即時（Soft real-time）盡量達成即可，偶爾遲到可接受，例如**影音串流**。

### 二、Concurrency（並行） vs Parallelism（平行）

| | Concurrency 並行 | Parallelism 平行 |
|---|---|---|
| 一句話 | 交錯處理多件事，看起來同時 | 真的同時做多件事 |
| 硬體需求 | 單核 CPU 就能做，靠快速切換 | 需要多核或多 CPU |
| 重點 | 如何結構化地處理多工 | 同時執行 |

📌 **記憶鉤子：並行是「一個執行單位輪流切換多件事」；平行是「多個執行單位真的同時做」。** 並行不一定平行；平行通常是並行的一種實現。

具體例子：你一個人（單核）一邊煮飯一邊回訊息，來回切換＝**並行**；你和室友兩個人（雙核）同時各做一件事＝**平行**。

📌 **多處理器系統兩型（常考）：對稱式多處理 SMP**——每顆 CPU 地位相同、共用同一份 OS 與記憶體（現代多核電腦主流）；**非對稱式多處理 AMP**——主從式，一顆主 CPU 負責調度、其餘只做被指派的工作。

### 三、Offline / Spooling / Buffering / Cache

這四個都是為了讓 CPU 不被慢速裝置拖累，差別在「重不重疊、放在哪」：

| 技術 | 定義 | 為何用 |
|---|---|---|
| Offline 離線 | I/O 不直接接 CPU，先把資料存到中間媒介 | 讓慢速 I/O 與 CPU 分離，但兩者不重疊 |
| Spooling | 用磁碟當緩衝池，慢速裝置與 CPU 重疊作業，多個工作可排隊 | CPU 不必空等慢速裝置，例如列印佇列 |
| Buffering 緩衝 | 在記憶體開一塊區暫存資料 | 平衡生產與消費速度差，讓 I/O 與計算重疊 |
| Cache 快取 | 把常用資料放在更快、離 CPU 更近的儲存 | 利用 locality 加速重複存取 |

一句話各自的關鍵：

1. **Offline**：完全分開、不重疊，是較早期的解法。
2. **Spooling**：重疊、用整個磁碟當池子、可排隊（想想印表機的列印佇列，一份接一份）。
3. **Buffering**：用記憶體小區，平衡資料流速度（像水管與水桶之間放個暫存桶）。
4. **Cache**：為了重複存取而加速（常拿的東西放手邊）。

## ✅ 回到題目：解答

1. **分時 vs 批次？** → **批次**把工作集中成一批、依序自動跑、**不能互動**；**分時**把 CPU 切成時間片輪流服務、**可即時互動、回應快**。核心差別在「有沒有即時互動」。
2. **單核輪流跑很多程式？** → 這是 **Concurrency（並行）**，靠快速切換造成「看起來同時」；要 **Parallelism（平行）** 得有多核或多 CPU 真的同時跑。
3. **邊印邊打字？** → **Spooling**：把要印的資料丟進磁碟佇列排隊，CPU 就能繼續做別的事，不必空等印表機。

---

## 📌 重點整理

- OS 五分類：**批次、多元程式、分時、即時、分散式**；判斷主軸是「怎麼服務工作與使用者」。
- 即時分**硬性**（錯過即失敗，醫療/飛彈）與**軟性**（偶爾遲到可接受，串流）。
- **並行 ≠ 平行**：並行靠切換（單核可）、平行靠多核（真同時）。並行不一定平行，平行是並行的一種實現。
- 四小技巧記關鍵字：**Offline 不重疊、Spooling 磁碟池可排隊、Buffering 記憶體平衡速差、Cache 加速重複存取**。

---

## ⚠️ 常見陷阱

- **Spooling vs Buffering 別混**：Spooling 用**磁碟**當池子、可讓多個工作**排隊**（典型是列印）；Buffering 用**記憶體**小區、重點在**平衡生產與消費的速度差**。
- **並行不等於平行**：單核 CPU 也能「並行」，但**不可能真平行**。看到「單核卻同時處理多工」就是並行。
- **多元程式 vs 分時**：多元程式重點在「CPU 等 I/O 時去做別的」提高**利用率**；分時多了「切時間片、讓多使用者即時互動」。
- **即時系統不是「跑很快」**：重點是**在時限內完成**且可預測，慢一點但準時也算成功（硬性除外）。

## 📝 練習題（含解答）

**Q1.** OS 五大分類中，哪一種的核心特徵是「把 CPU 時間切成小片、輪流給多使用者、可即時互動」？
<details><summary>看解答</summary>

**分時系統（Time-sharing）**，例如 UNIX、Linux。它靠時間片切換讓多人同時互動、回應快。
</details>

**Q2.** 在單核心 CPU 上讓多個程式輪流執行，屬於並行還是平行？為什麼？
<details><summary>看解答</summary>

**並行（Concurrency）**。單核只能靠快速切換造成「看起來同時」；真正的**平行（Parallelism）需要多核或多 CPU** 才能真的同時執行。
</details>

**Q3.** 硬性即時（Hard real-time）與軟性即時（Soft real-time）各舉一個例子，並說明差異。
<details><summary>看解答</summary>

**硬性**：醫療、飛彈——錯過時限就算失敗。**軟性**：影音串流——盡量達成即可，偶爾遲到可接受。
</details>

**Q4.** 列印時用磁碟排隊、讓 CPU 不必空等印表機，這是哪一種技術？它跟 Buffering 最大的不同是什麼？
<details><summary>看解答</summary>

是 **Spooling**。不同在於：Spooling 用**磁碟**當池子且**可排隊多個工作**；Buffering 用**記憶體**小區，重點在**平衡生產與消費的速度差**。
</details>

**Q5.** 「多元程式（Multiprogramming）」為什麼能提高 CPU 利用率？
<details><summary>看解答</summary>

因為記憶體同時放多個工作，當某個工作在**等 I/O**（例如等磁碟、等鍵盤）時，CPU 不空等，改去執行**另一個就緒的工作**，讓 CPU 幾乎一直有事做。
</details>
