# 傳輸層

> 科目：網路概論｜傳輸層是 OSI 的**第 4 層**，負責把資料「**端到端**」正確送到對方手上。這一層的兩大主角 **TCP／UDP** 幾乎年年考，握手流程與兩者比較是必拿分。
>
> 學習方式：本篇大多屬【理解】（懂邏輯就記得）；**握手順序、header 大小**屬【硬背】。

## 🤔 先想想

如果你答不太出來，給你幾個提示建立直覺：

- 傳輸層在 **OSI 第 4 層**，它的傳輸單位（PDU）叫 **Segment（區段）**；它做的是「**端到端**」——從來源主機直送目的主機。
- 兩個主角個性相反：**TCP 像掛號信**（要簽收、掉了會補寄），**UDP 像明信片**（丟出去就算了，但快又省事）。
- 「**握手（Handshake）**」是連線前後的招呼。建立要**三次**、結束要**四次**，差別跟「雙向」有關——想想電話是不是可以兩邊同時講話。

## 📖 觀念拆解

### 一、電路交換 vs 封包交換　【理解】

在講 TCP／UDP 前，先看資料「怎麼在網路上送」的兩種思路。

- **電路交換（Circuit Switching）**：像**打市內電話**——通話前先接通一條專屬線路，全程獨佔，講完才放掉。
- **封包交換（Packet Switching）**：像**寄很多張明信片**——把資料切成一個個「封包」，每個封包各自找路走，到目的地再重新拼回來。

| | 電路交換 Circuit Switching | 封包交換 Packet Switching |
|---|---|---|
| 方式 | 先建立一條專屬實體路徑，全程獨佔（像打電話） | 資料切成封包各自獨立傳，可走不同路徑、目的地重組 |
| 優點 | 連線穩定、保證頻寬（每秒能傳多少資料）、延遲固定 | 線路共享、效率高、可繞路容錯 |
| 缺點 | 獨佔線路（沒傳也佔著）、浪費、建立慢 | 延遲不固定（可能塞車／亂序）、需重組 |
| 例子 | 傳統電話網路 PSTN | 網際網路（IP） |

📌 **白話**：「保證頻寬」＝這條線每秒能穩定傳多少資料，講好了就是你的；「繞路容錯」＝某條路壞了，封包可以改走別條路。

> 一句話：**電路交換＝獨佔專線（穩但浪費）；封包交換＝共享分封（省但延遲不定）。** 我們每天用的網際網路走的是封包交換。

### 二、TCP：三方交握 + 四方交握　【理解】＋【硬背】

**TCP（Transmission Control Protocol，傳輸控制協定）特性**：**連線導向**（先建立連線再傳）、**可靠**（確認 ACK、遺失會重傳）、**有序**（按順序到達）、有**流量控制**與**壅塞控制**。適合要求「正確」的應用（**網頁、email、檔案**）。

#### 三方交握（建立連線）— SYN → SYN-ACK → ACK

用比喻：打電話前的「喂？聽得到嗎？」「聽得到，你呢？」「我也聽得到，開始講吧」——確認雙向都通了才開始。

1. **Client → Server：SYN**（我想連線）
2. **Server → Client：SYN ＋ ACK**（好，我也要連，並確認你）
3. **Client → Server：ACK**（確認）→ **連線建立**

> 小名詞：**SYN**（Synchronize，同步／請求連線）、**ACK**（Acknowledge，確認）。

#### 四方交握（結束連線）— FIN → ACK → FIN → ACK

1. **Client → Server：FIN**（我要關了）
2. **Server → Client：ACK**（收到）
3. **Server → Client：FIN**（我這邊也關了）
4. **Client → Server：ACK**（收到）→ **連線結束**

> 小名詞：**FIN**（Finish，結束連線）。

**為什麼結束要四次、建立只要三次？** 因為 TCP 是**全雙工（Full-duplex）**——雙向可同時收發。關閉時**兩個方向要各自關閉**（你關你的、我關我的），所以比建立多一步。（建立時，第 2 步的 SYN 和 ACK 可以合併成一個封包送出，結束時兩邊的 FIN 通常分開，故多一次。）

### 三、SYN Flood 攻擊　【理解】

- **手法**：攻擊者狂送大量 **SYN**（常偽造來源 IP），但**不回最後的 ACK**，讓伺服器留下一堆**半開連線（half-open）**、佔滿連線資源 → 正常使用者連不進來（**DoS 阻斷服務攻擊**）。
- **白話**：就像有人不斷打電話給你、你一接他就不出聲掛著，佔滿你所有電話線，真正要找你的人都打不進來。
- **防範**：**SYN cookies**、限制半開連線數、防火牆過濾。

### 四、流量控制 vs 壅塞控制（超常考辨別）　【理解】

兩個都是 TCP 在「**控制送多快**」，但**保護對象不同**：

| | 流量控制 Flow Control | 壅塞控制 Congestion Control |
|---|---|---|
| 保護誰 | 接收方（別淹沒對方緩衝區） | 整個網路（別塞爆路由器） |
| 看誰的狀況 | 接收方的接收能力 | 網路的壅塞程度 |
| 機制 | 滑動視窗（接收方告知還能收多少 rwnd） | 慢啟動、壅塞避免、快速重傳／恢復（cwnd） |

💡 **表裡的機制白話：**
- **緩衝區（buffer）**＝接收端暫存資料的空間；**滑動視窗（rwnd ＝ 接收視窗）**＝接收方一直告訴發送方「我還能收多少」，發送方就不會送爆它。例：接收方喊「我還有 8KB 空間」，發送方這次就最多送 8KB。
- **壅塞控制**用 **cwnd（壅塞視窗）** 搭配**慢啟動**（一開始慢慢送、沒塞就逐步加速）、壅塞避免、快速重傳／恢復——都是「偵測到網路快塞了就降速」的調節法。

> 記憶鉤子：**流量控制保護「接收方」、壅塞控制保護「網路」。**

### 五、UDP 與 TCP vs UDP　【理解】＋【硬背】

**UDP（User Datagram Protocol，使用者資料包協定）**：**非連線**（不先建立）、**不可靠**（不確認、不重傳）、**快**、**開銷小**（額外負擔少）。適合即時、可容忍少量遺失的應用（**串流、遊戲、DNS、VoIP ＝ 網路電話**）。

> 💡 **傳輸層 PDU 的名稱**：常統稱 **Segment（區段）**，但嚴格說那是 **TCP** 的 PDU；**UDP** 的 PDU 稱 **Datagram（資料包）**——這正是 UDP 全名「使用者資料包協定」的由來。

| | TCP | UDP |
|---|---|---|
| 連線 | 連線導向（先三方交握） | 非連線 |
| 可靠性 | 可靠（確認、重傳、有序） | 不可靠 |
| 速度 | 較慢（開銷大） | 快（開銷小） |
| Header | 較大（最小 20 bytes） | 較小（8 bytes） |
| 流量／壅塞控制 | 有 | 無 |
| 傳輸對象 | 僅點對點（單播） | 單播／廣播／多播皆可 |
| 適用 | 網頁、email、檔案（要正確） | 串流、遊戲、DNS、VoIP（要即時） |

> 記憶鉤子：**TCP ＝ 可靠但慢（先握手）；UDP ＝ 快但不保證（直接送）。** 想看直播卡一格沒關係、但下載檔案錯一個位元就壞了，這就是為什麼直播用 UDP、下載用 TCP。

## ✅ 回到題目：解答

1. **TCP 三方交握順序？** → **SYN → SYN-ACK → ACK**。Client 送 SYN（我想連）、Server 回 SYN＋ACK（好，我也要連並確認你）、Client 再回 ACK（確認）→ 連線建立。
2. **TCP vs UDP 最大差別？** → **TCP 可靠但慢**（連線導向、確認重傳、有序）；**UDP 快但不保證**（非連線、不重傳）。「可靠」是 TCP、「快」是 UDP。
3. **流量控制 vs 壅塞控制保護誰？** → **流量控制保護接收方**（別淹沒對方緩衝區，用滑動視窗 rwnd）；**壅塞控制保護整個網路**（別塞爆路由器，用 cwnd 慢啟動等）。

---

## 📌 重點整理

- **交換**：電路交換獨佔專線（穩但浪費）、封包交換共享分封（省但延遲不定，網際網路用它）。
- **TCP**：連線導向、可靠、有序；**建立＝三方交握（SYN／SYN-ACK／ACK）**、**結束＝四方交握（FIN／ACK／FIN／ACK）**。結束要四次是因為全雙工、雙向各自關。
- **SYN Flood** ＝ 灌半開連線的 **DoS**；防範用 **SYN cookies**、限制半開連線數。
- **流量控制保護接收方**（rwnd 滑動視窗）、**壅塞控制保護網路**（cwnd 慢啟動）。
- **TCP 可靠慢（header 最小 20B）、UDP 快不保證（header 8B）**；TCP 走網頁/email/檔案、UDP 走串流/遊戲/DNS/VoIP。

---

## ⚠️ 常見陷阱

- **建立三次、結束四次別記反**：三方交握是「建立」、四方交握是「結束」。
- **「可靠」的是 TCP、不是 UDP**：UDP 不確認、不重傳，掉了就掉了。
- **流量控制 ≠ 壅塞控制**：前者保護「接收方」、後者保護「整個網路」，考題最愛在這裡挖洞。
- **Header 大小別張冠李戴**：TCP 最小 **20 bytes**、UDP **8 bytes**。
- **SYN Flood 的關鍵是「不回最後的 ACK」**造成半開連線，屬於 DoS，不是竊聽或竄改。
- **DNS 走 UDP 也走 TCP**：常見誤以為 DNS 只用 UDP（詳見應用層那篇）。

## 📝 練習題（含解答）

**Q1.** TCP 三方交握的三個步驟（含旗標）依序是什麼？
<details><summary>看解答</summary>

**SYN → SYN-ACK → ACK**。① Client → Server：SYN（我想連線）；② Server → Client：SYN＋ACK（好，我也要連並確認你）；③ Client → Server：ACK（確認）→ 連線建立。
</details>

**Q2.** 為什麼 TCP 結束連線需要「四次」，而建立只要「三次」？
<details><summary>看解答</summary>

因為 TCP 是**全雙工**（雙向可同時收發），關閉時兩個方向要**各自關閉**（你關你的、我關我的），所以比建立多一步（建立時第 2 步的 SYN 與 ACK 可合併）。
</details>

**Q3.** 一個線上遊戲要求「即時、可容忍少量封包遺失」，應該用 TCP 還是 UDP？為什麼？
<details><summary>看解答</summary>

用 **UDP**。UDP 非連線、不確認、不重傳、開銷小、速度快，適合即時且可容忍少量遺失的應用（串流、遊戲、DNS、VoIP）。若用 TCP，重傳與確認反而會造成延遲卡頓。
</details>

**Q4.** 「流量控制」與「壅塞控制」保護的對象分別是誰？各用什麼視窗？
<details><summary>看解答</summary>

**流量控制保護接收方**（別淹沒對方緩衝區），用**滑動視窗 rwnd**（接收視窗）；**壅塞控制保護整個網路**（別塞爆路由器），用 **cwnd**（壅塞視窗）搭配慢啟動、壅塞避免、快速重傳／恢復。
</details>

**Q5.** TCP 與 UDP 的 header 最小各是多少 bytes？
<details><summary>看解答</summary>

**TCP header 較大，最小 20 bytes；UDP header 較小，8 bytes。** 這也是 UDP「開銷小、快」的原因之一。
</details>
