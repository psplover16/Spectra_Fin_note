# 資安觀念與加密 ★

> 科目：網路概論｜★ 每年必考、今年特別重，要多花時間。這一篇是「資安」的地基：先搞懂「我們到底在保護什麼（CIA 五要素）」，再看「用什麼工具去保護（加密、雜湊、簽章、憑證）」——工具全都是為了達成那幾個要素而生的。
>
> 學習方式：大多屬【理解】（懂原理就記得，不用硬背）；只有加密演算法的名稱（AES、RSA…）屬【硬背】。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 資訊安全的「**CIA 三要素**」各指什麼？各自靠什麼技術達成？
> 2. 要把一份資料「**保密**」，該用「**誰的公鑰**」加密？要「**數位簽章**」，又該用「**誰的私鑰**」？
> 3. **數位簽章**能同時達成哪些安全性質？它能不能保證內容「**保密**」？

先別急著往下看答案，試著自己回答看看。

---

## 🤔 先想想

如果你覺得「加密、簽章、雜湊」全糊成一團，給你三個定錨點：

- **加密**是為了「別人看不到」；**簽章**是為了「證明是我發的、沒被改」——兩者**目的不同**，別混。
- **公鑰是公開的、私鑰要自己藏好**。整個非對稱加密的關鍵，就在「加密用哪把、解密／驗證用哪把」。
- **雜湊是單向的指紋**：算得出去、算不回來。它不是加密（加密可以解回原文，雜湊不行）。

帶著這三點往下拆解。

---

## 📖 觀念拆解

### 一、資安五大要素　【理解】

資安到底在保護什麼？核心三個合稱 **CIA**，再加兩個延伸：

| 要素 | 意思 | 靠什麼達成 |
|---|---|---|
| 機密性 Confidentiality | 資料只有授權者能看 | 加密、存取控制 |
| 完整性 Integrity | 資料沒被竄改、保持正確 | 雜湊、數位簽章 |
| 可用性 Availability | 授權者需要時能正常使用 | 備援、備份（威脅：DoS／DDoS ＝ 灌爆流量讓服務癱瘓，DDoS 是分散式多來源版） |
| 不可否認性 Non-repudiation | 做過的事不能事後抵賴 | 數位簽章 |
| 認證性 Authentication | 確認身分是真的 | 密碼、憑證、生物辨識 |

📌 **白話理解：**
- **機密性**＝「不給別人偷看」（例：信用卡號被加密，中途攔截也看不懂）。
- **完整性**＝「沒被偷改」（例：轉帳金額 1,000 不能被人改成 10,000 還沒被發現）。
- **可用性**＝「要用時打得開」（例：網站被 DDoS 灌爆而無法服務，就是破壞可用性）。
- **不可否認性**＝「賴不掉」（例：你數位簽了合約，事後不能說「不是我簽的」）。
- **認證性**＝「你真的是你」（例：登入時用密碼／指紋證明身分）。

記憶：**CIA（機密、完整、可用）是三大核心；再加不可否認、認證。**

📌 **多因素認證（MFA／2FA）**：結合**你知道的**（密碼）＋**你有的**（手機／OTP／卡片）＋**你是的**（指紋／臉）多類憑據，比單一密碼更安全（認證性的常見強化，常考）。

### 二、對稱 vs 非對稱加密　【理解】＋【硬背】

加密分兩大類，差別在「用幾把鑰匙」：

|  | 對稱式 Symmetric | 非對稱式 Asymmetric（公開金鑰） |
|---|---|---|
| 金鑰 | 同一把金鑰加解密 | 一對：公鑰（公開）＋私鑰（自留） |
| 速度 | 快（適合大量資料） | 慢 |
| 痛點／優勢 | 金鑰分配難、金鑰數量多 | 解決金鑰分配、能做數位簽章 |
| 例子 | DES、3DES、AES | RSA、ECC、Diffie-Hellman |

📌 **白話比喻：**
- **對稱式**＝一把「同款鑰匙」，你鎖、對方也用同一把開。快，但問題是：**這把鑰匙怎麼安全地交給對方**（金鑰分配難）？而且每對通訊都要一把，人一多鑰匙數量爆炸。
- **非對稱式**＝一對配對的鑰匙：**公鑰像公開的「投信孔」**（誰都能投進去），**私鑰像只有你有的「開箱鑰匙」**。公鑰鎖上的，只有對應私鑰能開。它解決了「鑰匙怎麼交出去」的難題，但**慢**、不適合大量資料。

**非對稱的兩種用法（重要）：**
- **要保密（機密性）**：用「**接收者的公鑰**」加密 → 只有接收者的私鑰能解。（誰都能對你投信，但只有你能開箱。）
- **要簽章（認證／不可否認）**：用「**發送者的私鑰**」簽 → 大家用發送者的公鑰驗。（只有你有私鑰，能簽出來就證明是你。）

**實務常混合**：用非對稱傳「對稱金鑰」，再用對稱加密實際資料——**兼顧安全（非對稱換鑰）與速度（對稱傳資料）**。這正是 HTTPS 的做法。

### 三、雜湊 Hash　【理解】

- **雜湊函數**：把任意長度資料 → **固定長度的摘要（digest）**。特性：
  - **單向不可逆**（算得出摘要，卻算不回原文）。
  - **固定長度**（不管原文多長，摘要長度一樣）。
  - **雪崩效應**（改一點點，整個摘要就完全不同）。
  - **抗碰撞**（很難找到兩筆不同資料算出同一個雜湊值；注意：這個「碰撞」跟網路傳輸的碰撞〔CSMA/CD〕**無關**）。
- **用途**：驗證完整性（比對雜湊值看資料有沒有被改）、密碼儲存（存摘要不存明碼）。
- **例**：MD5、SHA-1（這兩個**已不安全**，別用）、SHA-256／SHA-2、SHA-3。

💡 **具體例子**：你下載一個檔案，網站附上 SHA-256 值。你下載後自己算一次雜湊，**兩個值一樣**＝檔案沒被竄改；**只要中途被改一個位元組**，算出的雜湊就會天差地遠（雪崩效應），你立刻就發現。

### 四、數位簽章 Digital Signature　【理解】★

**目的：一次達成 完整性 ＋ 認證 ＋ 不可否認（注意：不負責保密）。**

流程（依序）：

1. 發送者把訊息做**雜湊**得到摘要。
2. 用「**發送者的私鑰**」加密摘要 → 這就是**數位簽章**。
3. 連同**原訊息**一起送出。
4. 接收者用「**發送者的公鑰**」解簽章得到**摘要 A**；自己也對收到的訊息做雜湊得到**摘要 B**。
5. **A ＝ B** → 沒被竄改（完整性）、確實是發送者發的（認證、不可否認）。

**為什麼用私鑰簽？** 因為只有發送者有私鑰，別人無法偽造 → 達成不可否認。
**若還要保密**，要**另外**用「接收者的公鑰」加密訊息（簽章本身不加密內容）。

💡 一句話串起來：**簽章＝把「訊息的指紋」用「自己的私鑰」上鎖**。別人用你的公鑰解得開，就證明這鎖是你上的；再比對指紋，就知道內容沒被改。

### 五、PKI / CA / 數位憑證　【理解】

前面說「用接收者的公鑰加密」——但你怎麼知道**這把公鑰真的是他的、不是駭客冒充的**？這就是 PKI 要解決的：

- **PKI（公開金鑰基礎建設）**：一套管理數位憑證與公私鑰的架構，用來確認「某把公鑰真的屬於某人」（防止公鑰被冒充）。
- **CA（憑證管理中心）**：受信任的**第三方**，負責簽發數位憑證（把某人的身分和其公鑰綁定、由 CA 簽章背書）。
- **數位憑證**：像「網路上的身分證」，內含**持有者資訊 ＋ 公鑰 ＋ CA 的簽章**。
- **用途**：HTTPS 的 SSL／TLS 憑證就靠 PKI。（瀏覽器內建可信 CA 清單，網站憑證由可信 CA 簽 → 顯示鎖頭。）

### 六、電子商務安全　【理解】

電子商務的安全需求，其實就是把資安要素**套到交易上**：

| 需求 | 在交易裡的意思 |
|---|---|
| 機密性 | 交易／信用卡資料不被竊 |
| 完整性 | 交易內容不被竄改 |
| 不可否認性 | 買賣雙方不能否認交易 |
| 可驗證性（認證） | 確認交易雙方身分 |
| 存取控制 | 只有授權者能存取資源 |

💡 這張表其實就是**第一節五要素的「應用版」**——把抽象的 CIA＋認證＋存取控制，換成交易情境的白話。

### 七、重點整理（背這張）

- **五要素**：機密、完整、可用（CIA）＋ 不可否認、認證。
- **對稱**：同把金鑰、快、分配難（AES）；**非對稱**：公私鑰、慢、能簽章（RSA）。
- **加密保密用「收件者公鑰」、數位簽章用「發送者私鑰」。**
- **雜湊** ＝ 固定長度摘要、單向、驗完整性。
- **數位簽章** ＝ 完整性 ＋ 認證 ＋ 不可否認（**不保密**）；用發送者私鑰簽、公鑰驗。
- **PKI**：CA 簽發數位憑證，綁定身分與公鑰；HTTPS 靠它。

---

## ✅ 回到題目：解答

1. **CIA 三要素？** → **機密性**（授權者才能看，靠加密、存取控制）、**完整性**（沒被竄改，靠雜湊／數位簽章）、**可用性**（需要時用得到，靠備援、備份）。
2. **保密用誰的公鑰？簽章用誰的私鑰？** → 保密用「**接收者的公鑰**」加密（只有接收者私鑰能解）；簽章用「**發送者的私鑰**」（大家用發送者公鑰驗）。
3. **數位簽章達成什麼？能保密嗎？** → 同時達成 **完整性＋認證＋不可否認**；**不負責保密**。要保密須另用接收者的公鑰加密。

---

## 📌 重點整理

- 資安五要素：機密、完整、可用（CIA）＋ 不可否認、認證。
- 對稱（AES／DES／3DES）快、金鑰分配難；非對稱（RSA／ECC／DH）慢、解決金鑰分配又能簽章。
- **保密 → 收件者公鑰加密；簽章 → 發送者私鑰簽**（這條最常考、最容易反）。
- 雜湊：單向、固定長度、雪崩、抗碰撞；驗完整性＋存密碼。MD5／SHA-1 淘汰，用 SHA-256／SHA-2／SHA-3。
- 數位簽章 ＝ 私鑰簽「雜湊值」→ 完整＋認證＋不可否認（不保密）。
- PKI／CA：數位憑證＝身分＋公鑰＋CA 簽章，是 HTTPS 信任的基礎。

---

## ⚠️ 常見陷阱

- **加密 vs 簽章的金鑰用反**：保密用「**收件者公鑰**」；簽章用「**發送者私鑰**」。這是本主題頭號送分／扣分題，務必背牢。
- **以為數位簽章會加密內容**：錯。簽章保證**來源＋完整（＋不可否認）**，**不負責保密**；要保密得另外加密。
- **以為雜湊可以解回原文**：錯。雜湊是**單向**的，只能拿來「比對」，無法還原。
- **還在用 MD5／SHA-1 當安全雜湊**：兩者**已不安全**，正式場合請用 SHA-256 以上。
- **把「抗碰撞」的碰撞跟乙太網路傳輸碰撞混為一談**：雜湊的碰撞是「兩筆資料算出同一摘要」，跟 CSMA/CD 的訊號碰撞**無關**。
- **以為要保密的是公鑰**：錯。**公鑰本來就公開**，要死守的是**私鑰**。

## 📝 練習題（含解答）

**Q1.** 資安「CIA 三要素」分別是哪三個？各舉一個達成手段。
<details><summary>看解答</summary>

**機密性**（Confidentiality，靠加密／存取控制）、**完整性**（Integrity，靠雜湊／數位簽章）、**可用性**（Availability，靠備援／備份）。
</details>

**Q2.** 小明要傳一份機密文件給小美，讓「只有小美看得到」，他該用哪把金鑰加密？
<details><summary>看解答</summary>

用「**小美（接收者）的公鑰**」加密。因為只有小美握有對應的**私鑰**能解開，達成機密性。
</details>

**Q3.** 數位簽章能達成哪些安全性質？可以達成「機密性（保密）」嗎？為什麼？
<details><summary>看解答</summary>

達成 **完整性＋認證＋不可否認**。**不能**達成保密——因為它只是用發送者私鑰加密「摘要」並附上原訊息，內容本身沒被加密。要保密須另用接收者公鑰加密訊息。
</details>

**Q4.** 為什麼實務上（如 HTTPS）常「非對稱＋對稱」混用，而不是全用非對稱？
<details><summary>看解答</summary>

非對稱**慢**、不適合大量資料，但能安全交換金鑰；對稱**快**但金鑰分配難。所以先用**非對稱傳對稱金鑰**（解決分配），再用**對稱加密實際資料**（兼顧速度），兩者互補。
</details>

**Q5.** 你下載檔案後，用網站提供的 SHA-256 值比對，發現算出來的值不一樣，代表什麼？這用到雜湊的哪個特性？
<details><summary>看解答</summary>

代表檔案**在傳輸中被竄改或損毀**（完整性被破壞）。用到雜湊的**雪崩效應**（改一點點、摘要就完全不同）與**用於驗證完整性**的特性。
</details>
