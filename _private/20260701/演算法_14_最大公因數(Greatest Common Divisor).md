# 最大公因數(Greatest Common Divisor)

> 科目：演算法｜GCD 是國考「歐幾里得演算法」的固定考點，常考遞迴式、終止條件與時間複雜度。
>
> 學習方式：核心只有一條式子 `gcd(a, b) = gcd(b, a % b)`，把它跑順、算過一次實例，這題就穩了。
>
> 難度分配：公式與終止條件屬【硬背】；為什麼用餘數能縮小問題屬【理解】。

- 「公因數」是能同時整除兩個數的數；GCD 就是這些公因數裡**最大**的那個。
- 大數除以小數，真正有用的不是商，而是**餘數**——餘數會讓數字越變越小。
- 一直取餘數，總有一刻**餘數變成 0**。那一刻，答案就浮出來了。

## 📖 觀念拆解

### 一、演算法概念

最大公因數(GCD)是兩個整數共同因數中最大的那個數。**歐幾里得演算法（又稱輾轉相除法）**使用 `gcd(a, b) = gcd(b, a % b)`，直到 b 變成 0。

**白話**：GCD 的核心是用餘數把問題變小。當餘數變成 0 時，剩下的數就是最大公因數。

為什麼「取餘數」可以求 GCD？因為 a 和 b 的所有公因數，也一定是 `a % b` 的因數；所以把 `(a, b)` 換成 `(b, a % b)`，公因數的集合不會變，但數字卻越來越小——問題規模持續縮小，最後一定收斂。

### 二、核心規則（逐條看）

1. 先把 a 與 b 轉成非負數，避免負號影響餘數判斷。
2. 若 b 等於 0，a 就是最大公因數。
3. 若 b 不等於 0，把問題改成 gcd(b, a % b)。
4. 重複直到 b 變成 0。

**新手提醒**：終止條件是「**b 等於 0**」，不是 a 等於 0；停下來時要回傳的是 **a**，不是 b。這兩點最容易寫反。

### 三、最壞時間複雜度

| 版本 | 最壞時間複雜度 | 推導重點 |
|---|---|---|
| 遞迴版本 | O(log min(a,b)) | 每次取餘數都會讓問題規模快速變小，最壞常出現在相鄰 Fibonacci 數。 |
| 非遞迴版本 | O(log min(a,b)) | 迴圈次數與較小數字的位數成正比。 |

**白話**：`min(a, b)` 是「兩數中比較小的那個」。因為每取一次餘數，數字就大幅縮小（大約每兩步至少減半），所以步數只跟位數（log）成正比，非常快。**最壞情況**發生在輸入是**相鄰的兩個 Fibonacci 數**（例如 gcd(13, 8)），此時每次餘數縮得最慢，步數最多。

### 四、遞迴版 Java

> 用 `gcd(a, b) = gcd(b, a % b)` 持續縮小問題。

```java
public static int gcdRecursive(int a, int b) {
    a = Math.abs(a);
    b = Math.abs(b);
    return gcdRecursivePositive(a, b);
}

private static int gcdRecursivePositive(int a, int b) {
    // b = 0 時，a 就是最大公因數。
    if (b == 0) {
        return a;
    }

    // 把問題改成 gcd(b, a % b)，數字會越來越小。
    return gcdRecursivePositive(b, a % b);
}
```

**逐行白話**：先用 `Math.abs` 把負號去掉，再進入真正的遞迴。遞迴裡只有兩件事：碰到 `b == 0` 就回傳 a（答案），否則把 `(a, b)` 換成 `(b, a % b)` 再呼叫自己。

### 五、非遞迴版 Java

> 用 while 迴圈重複取餘數，直到 b 變成 0。

```java
public static int gcdIterative(int a, int b) {
    a = Math.abs(a);
    b = Math.abs(b);

    // 不斷用餘數取代，直到 b 變成 0。
    while (b != 0) {
        int remainder = a % b;
        a = b;
        b = remainder;
    }

    return a;
}
```

**逐行白話**：迴圈每跑一次做三步——先算餘數 `remainder`，再把 b 搬給 a、把 remainder 搬給 b。當 b 變 0 時跳出迴圈，此時的 a 就是答案。這正是遞迴版的「攤平」寫法。

### 六、逐步範例：gcd(48, 18)

我們用非遞迴版的 `(a, b, a % b)` 追蹤每一步：

| 步驟 | a | b | a % b（餘數） | 下一輪 (a, b) |
|---|---|---|---|---|
| 1 | 48 | 18 | 48 % 18 = **12** | (18, 12) |
| 2 | 18 | 12 | 18 % 12 = **6** | (12, 6) |
| 3 | 12 | 6 | 12 % 6 = **0** | (6, 0) |
| 4 | 6 | 0 | — | b = 0，停止 |

**結果：gcd(48, 18) = 6**。驗算：48 = 6 × 8、18 = 6 × 3，6 確實是兩者最大的公因數。

> 小補充：若一開始 a < b（例如 gcd(18, 48)），第一步 `18 % 48 = 18`，會自動變成 `(48, 18)`，等於幫你把大小順序調正，不必特別處理。

---

## ✅ 回到題目：解答

1. **gcd(48, 18) = 6**。過程：48→18→12→6，餘數依序 12、6、0，b 變 0 時回傳 6。
2. **遞迴式**：`gcd(a, b) = gcd(b, a % b)`；**當 b 等於 0 時停止**，回傳 a。
3. **時間複雜度 O(log min(a,b))**；**最壞情況**出現在輸入為相鄰的兩個 Fibonacci 數時。

---

## 📌 重點整理

- 定義：GCD 是兩整數共同因數中最大的那個。
- 核心式：`gcd(a, b) = gcd(b, a % b)`，用餘數縮小問題。
- 終止條件：**b == 0 時回傳 a**（不是 a == 0，也不是回傳 b）。
- 進入前先 `Math.abs`，避免負數影響餘數判斷。
- 複雜度：遞迴、非遞迴皆 **O(log min(a,b))**；最壞在相鄰 Fibonacci 數。
- 延伸：**gcd(a, b) × lcm(a, b) = a × b**，故最小公倍數 **lcm = a × b ÷ gcd**（常與 GCD 一起考，先求 GCD 再回推 LCM）。

---

## ⚠️ 常見陷阱

- **終止條件寫反**：是 `b == 0` 才停、回傳 **a**；別寫成 `a == 0` 或回傳 b。
- **忘記取絕對值**：負數直接取餘數，Java 的 `%` 會保留被除數的正負號，判斷可能出錯，故先 `Math.abs`。
- **遞迴參數順序寫反**：必須是 `gcd(b, a % b)`，把 b 提到前面；寫成 `gcd(a % b, b)` 就錯了。
- **邊界 gcd(a, 0)**：依定義結果是 **a**（0 與任何數的最大公因數是那個數本身）。

**Q1.** 用歐幾里得演算法求 gcd(24, 36)，請寫出每一步。
<details><summary>看解答</summary>

- gcd(24, 36)：24 % 36 = 24 → gcd(36, 24)
- gcd(36, 24)：36 % 24 = 12 → gcd(24, 12)
- gcd(24, 12)：24 % 12 = 0 → gcd(12, 0)
- b = 0，回傳 **12**。所以 gcd(24, 36) = 12。（注意第一步自動把大小順序調正。）
</details>
