# 高等樹 ★（AVL／B-Tree／Heap／紅黑樹）

> 科目：演算法｜這一章的核心問題只有一個：**普通 BST 如果失衡，搜尋會從 O(log n) 退化成 O(n)**。為了避免退化，各種「高等樹」用不同規則維持效率。
>
> 學習方式：選擇題最愛考「特色 ↔ 複雜度」配對（哪種樹保證 O(log n)、哪種磁碟友善、哪種只管父子大小）。先理解每種樹用什麼規則平衡，再記複雜度表。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 把資料 **10、20、30 照順序插入** 一般 BST，樹會變成什麼樣子？搜尋複雜度變多少？
> 2. AVL 樹的**平衡因子（BF）** 定義是什麼？允許的值有哪些？
> 3. 一個 **Max-Heap** 用陣列（索引從 1 開始）儲存，索引 i 的節點，它的左子、右子、父節點索引各是多少？

先想想再往下看。

---

## 🤔 先想想

- BST 好用是因為「小往左、大往右」，搜尋成本是 **O(樹高)**——所以只要樹高被壓住，就快。
- 「平衡」的各種樹，就是用不同手段（旋轉、多路、顏色）**把樹高控制在 O(log n)**。
- Heap 和其他樹不一樣：它**只管父子大小**，不管左右排序，所以拿極值超快、但找任意值很慢。

---

## 📖 觀念拆解

### 一、BST 與平衡需求

1. **BST 規則**：左子樹所有值 **<** 節點 **<** 右子樹所有值。
2. 搜尋與插入都從根開始，**小往左、大往右**，成本是 **O(樹高)**。
3. **中序走訪 BST 會得到由小到大的排序結果。**
4. 若資料**照順序插入**，BST 會退化成**偏斜樹（Skewed）**，樹高變 **O(n)**，搜尋也退化成 **O(n)**。

📌 **白話：** BST 快不快，完全看樹高。理想平衡時樹高約 log n；但若你把已排序資料一個個插入，每個新值都比前一個大（或小），就會一路往同一邊長，變成一條「鏈」——這就是為什麼需要下面這些會自動平衡的樹。

### 二、AVL Tree（嚴格平衡的 BST）

AVL 是**自我平衡的二元搜尋樹**，每個節點的**平衡因子 BF = 左子樹高 − 右子樹高**，必須維持在 **−1、0、+1**。一旦某節點 BF 變成 ±2 就要旋轉修正：

| 失衡型 | 形狀 | 解法 |
|---|---|---|
| LL | 左邊太高，且偏「左子的左邊」 | **右旋**，單旋。 |
| RR | 右邊太高，且偏「右子的右邊」 | **左旋**，單旋。 |
| LR | 左邊太高，但偏「左子的右邊」 | **先左旋再右旋**，雙旋。 |
| RL | 右邊太高，但偏「右子的左邊」 | **先右旋再左旋**，雙旋。 |

AVL 的**搜尋、插入、刪除都是 O(log n)**，查詢快，但插入刪除時調整（旋轉）較頻繁。

📌 **逐步範例（LL 型右旋）：** 依序插入 **30 → 20 → 10**：

```
插入30      插入20        插入10（失衡！）      右旋後（平衡）
  30          30              30                    20
             /               /                     /  \
            20              20                    10    30
                           /
                          10
```

- 插入 30：根是 30。
- 插入 20（20 < 30 放左）：BF(30) = 左高 1 − 右高 0 = **1**，OK。
- 插入 10（10 < 30 往左、10 < 20 往左）：此時 BF(30) = 左高 2 − 右高 0 = **2**，超出 {−1,0,+1}。失衡點 30，插入落在它「**左子的左邊**」→ **LL 型 → 對 30 右旋**。
- 右旋：把 20 提上來當根，30 變成 20 的右子，10 是 20 的左子。三個節點 BF 全部歸零，平衡完成。

### 三、B-Tree 與 B+ Tree（多路、磁碟友善）

1. **B-Tree** 是**多路 m-way 平衡搜尋樹**，一個節點可放**多個鍵**與**多個子節點**。
2. **m 階 B-Tree**：每節點最多 **m 個子**、最多 **m − 1 個鍵**。
3. 除根與葉外，每節點**至少 ⌈m/2⌉ 個子**，**所有葉在同一層**。
4. 節點胖、樹矮，所以**磁碟 I/O 次數少**，常用於**資料庫與檔案系統索引**。
5. **B+ Tree** 通常把**資料存葉節點**，葉節點**用鏈結串列串起來**，適合**範圍查詢**。

📌 **白話：** 一般二元樹每個節點只有 1 鍵 2 子，資料量大時樹會很高，讀硬碟要跳很多次。B-Tree 讓每個節點裝很多鍵（例如幾百個），樹就矮，讀硬碟次數大減——這正是資料庫索引愛用它的原因。B+ Tree 再把葉子串成一條鏈，要「查某範圍」時沿著鏈掃過去就好。

### 四、Heap（堆積）

1. Heap 是**完全二元樹（Complete Binary Tree）**，且符合堆積性質。
2. **Max-Heap**：每個節點 **≥** 子節點，**根最大**；**Min-Heap**：每個節點 **≤** 子節點，**根最小**。
3. Heap **只管父子大小**，不管左右或兄弟順序，因此**搜尋任意值是 O(n)**。
4. 常用於 **Priority Queue、Heap Sort**，以及隨時拿最大或最小值。

📌 **Heap Sort 複雜度：** 建堆 O(n) 再取出 n 次、每次 O(log n)，整體 **O(n log n)**；屬**原地排序但不穩定**。

📌 **陣列索引公式：** 若陣列索引**從 1 開始**，節點 i 的**左子是 2i**、**右子是 2i+1**、**父節點是 ⌊i/2⌋**。**插入與刪除根皆為 O(log n)，取根 O(1)**。

📌 **逐步範例（用陣列驗證父子索引）：** Max-Heap 存成陣列（索引 0 不用）：

```
索引:  1   2   3   4   5
值  : 50  30  40  10  20
```

- 看索引 **i = 2**（值 30）：左子 = 2i = **索引 4**（值 10）、右子 = 2i+1 = **索引 5**（值 20）、父 = ⌊2/2⌋ = **索引 1**（值 50）。
- 驗證堆積性質：50 ≥ 30、50 ≥ 40、30 ≥ 10、30 ≥ 20——每個父都 ≥ 子，是合法 **Max-Heap**，根（索引 1）＝50 為最大值，取根即 O(1)。

### 五、Red-Black Tree（紅黑樹，較鬆的平衡）

**5 條規則：**

1. 每個節點**非紅即黑**。
2. **根是黑色**。
3. **NIL 葉節點是黑色**。
4. **紅節點的子節點都是黑色**（不能連續兩個紅）。
5. 從**任一節點到其底下所有葉的路徑，黑節點數相同**。

紅黑樹用顏色規則維持**大致平衡**，保證**最長路徑不超過最短路徑的 2 倍**，因此**搜尋、插入、刪除都是 O(log n)**。

📌 **白話：** AVL 要求很嚴格（BF 只能 −1/0/+1），平衡好但常常要旋轉；紅黑樹規則較鬆，插入刪除時調整較少，所以很多程式庫（如 Java 的 TreeMap）用它。

### 六、高等樹比較表（超常考）

| 結構 | 搜尋 | 插入 | 刪除 | 備註 |
|---|---|---|---|---|
| BST 平均 | O(log n) | O(log n) | O(log n) | 取決於樹高。 |
| BST 最壞 | O(n) | O(n) | O(n) | 偏斜時退化。 |
| AVL | O(log n) | O(log n) | O(log n) | 嚴格平衡，查詢快。 |
| Red-Black Tree | O(log n) | O(log n) | O(log n) | 較鬆平衡，插刪較快。 |
| B-Tree / B+ Tree | O(log n) | O(log n) | O(log n) | 多路、磁碟友善。 |
| Heap | O(n) | O(log n) | O(log n) | 取根 O(1)，搜尋任意值慢。 |

---

## ✅ 回到題目：解答

1. **10、20、30 照順序插入 BST？** → 每個新值都比前一個大、一路往右長，退化成**偏斜樹（一條鏈）**，樹高 O(n)，**搜尋變 O(n)**。
2. **AVL 的 BF 定義？** → **BF = 左子樹高 − 右子樹高**，允許值只有 **−1、0、+1**；超出就旋轉。
3. **Max-Heap 陣列（索引從 1）的索引 i？** → 左子 **2i**、右子 **2i+1**、父 **⌊i/2⌋**。

---

## 📌 重點整理

- **BST**：左 < 根 < 右；中序＝由小到大；照順序插入會退化成 O(n)。
- **AVL**：BF ∈ {−1,0,+1}；LL 右旋、RR 左旋、LR 先左後右、RL 先右後左；三種操作皆 O(log n)。
- **B-Tree/B+ Tree**：m 階每節點最多 m 子、m−1 鍵；矮胖、少磁碟 I/O；B+ 資料存葉且葉串成鏈，適合範圍查詢。
- **Heap**：完全二元樹；Max-Heap 根最大、Min-Heap 根最小；索引 1 起左 2i／右 2i+1／父 ⌊i/2⌋；取根 O(1)、插入刪根 O(log n)、找任意值 O(n)。
- **紅黑樹**：5 規則、最長 ≤ 2×最短、皆 O(log n)、插刪比 AVL 省。

---

## ⚠️ 常見陷阱

- **BST 平均 vs 最壞**：平均 O(log n)、最壞（偏斜）O(n)。題目沒特別說「平衡」時要小心最壞情形。
- **AVL vs 紅黑樹**：AVL **查詢更快**（更平衡）；紅黑樹**插入刪除更快**（旋轉少）。兩者搜尋都是 O(log n)。
- **Heap 不能拿來快速搜尋任意值**：它只保證父子大小，找非極值要掃全部＝O(n)；別和 BST 搞混。
- **建堆別算成 O(n log n)**：由下而上 heapify 一次建好整個堆是 **O(n)**；「逐一插入 n 次」才是 O(n log n)。
- **Heap 索引公式看起算點**：索引**從 1 開始**才是 2i / 2i+1 / ⌊i/2⌋；若從 0 開始公式會變成 2i+1 / 2i+2 / ⌊(i−1)/2⌋。
- **B-Tree 的鍵與子數**：m 階是「最多 m 個子、m−1 個鍵」，別把 m 記成鍵數。

## 📝 練習題（含解答）

**Q1.** 某節點左子樹高 3、右子樹高 1，它的平衡因子是多少？符合 AVL 嗎？
<details><summary>看解答</summary>

BF = 左高 − 右高 = 3 − 1 = **2**。超出 {−1,0,+1}，**不符合** AVL，需要旋轉修正。
</details>

**Q2.** 依序插入 30、20、10 造成 AVL 失衡，是哪一種失衡型？要怎麼旋轉？
<details><summary>看解答</summary>

失衡落在失衡點的「左子的左邊」→ **LL 型**，做**單一右旋**：把 20 提為根，10 為左子、30 為右子。
</details>

**Q3.** 為什麼資料庫索引常用 B-Tree / B+ Tree，而不是普通二元搜尋樹？
<details><summary>看解答</summary>

因為 B-Tree 一個節點可放很多鍵、**樹矮**，讀取一筆資料需要的**磁碟 I/O 次數少**；B+ Tree 更把資料放葉節點、葉節點串成鏈，**範圍查詢**也很快。
</details>

**Q4.** Max-Heap 陣列（索引從 1）為 `[_, 50, 30, 40, 10, 20]`，索引 5 的父節點是誰（值多少）？
<details><summary>看解答</summary>

父 = ⌊5/2⌋ = **索引 2**，值 **30**。（且 30 ≥ 20，符合 Max-Heap 父 ≥ 子。）
</details>

**Q5.** 紅黑樹的哪條規則直接保證「不會出現連續兩個紅節點」？
<details><summary>看解答</summary>

第 4 條：**紅節點的子節點都必須是黑色**，因此紅色不可相鄰。
</details>
