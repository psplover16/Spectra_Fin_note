# 函式 + 參數傳遞 ★

> 科目：程式（專業 B）｜參數傳遞是**超高頻考點**，也是最多人搞混的地方。這張把「傳值／傳址／傳參考／傳名」一次講清楚。
>
> 學習方式：四種傳遞方式的**對照表**屬【硬背】；但只要抓住一個核心問題就能推理——**「在函式裡改參數，外面那個原本的變數會不會跟著變？」** 屬【理解】。範例以 C 與 Java 為主。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 下面的 C `swap` 用「傳值」，交換得成功嗎？
> ```c
> void swap(int a, int b) { int t = a; a = b; b = t; }
> // 呼叫 swap(x, y); 之後 x、y 有換過來嗎？
> ```
> 2. 常聽人說「Java 是 call by reference」，這句話對嗎？
> 3. 傳值、傳址、傳參考，哪些「改參數會影響外面的原變數」？

先自己想想，再往下對答案。

---

## 🤔 先想想

- 想像你把一份文件交給同事處理。給的是**影本**（他怎麼塗改都不影響你手上的正本）？還是給**正本的位置／鑰匙**（他一改就是改到正本）？這就是傳值 vs 傳址的差別。
- 「參數」和「引數」是兩個東西：一個是函式**定義時**的空位，一個是**呼叫時**真正塞進去的值。
- Java 有個經典陷阱：它「看起來」像傳參考，其實是「把參考的值複製一份傳進去」。

---

## 📖 觀念拆解

### 一、函式、參數、引數

函式是一段**有名字、可重複呼叫**的程式碼，接收參數、做事，也可以回傳結果。

- **參數 parameter**：函式**定義時**的變數（空位）。
- **引數 argument**：**呼叫時**實際傳入的值。

📌 **別名對照：** 參數又稱**形式參數（形參）**、引數又稱**實際參數（實參）**——考題兩套名詞都會出現，看到別愣住。

```java
// add 的 a、b 是「參數 parameter」
int add(int a, int b) { return a + b; }

int r = add(3, 5);  // 3、5 是「引數 argument」
```

### 二、四種參數傳遞方式（核心表）　【硬背】

| 方式 | 傳進去的是 | 改參數會影響外面嗎 |
|---|---|---|
| 傳值 Call by Value | 值的複製品 | 不影響 |
| 傳址 Call by Address | 變數記憶體位址 | 影響 |
| 傳參考 Call by Reference | 變數別名 | 影響 |
| 傳名 Call by Name | 整個表達式，用到才求值 | 影響且每次重算 |

📌 **白話拆解：**
- **傳值**：複製一份值進去，函式裡改的是影本，正本不動。
- **傳址**：把「變數的記憶體位址」傳進去，函式順著位址就能改到正本。
- **傳參考**：參數直接是原變數的「別名」，改別名等於改本尊。
- **傳名**：把「整個表達式」傳進去，用到才求值，且每次用都重算（較少見）。

一句話記：**swap 要成功需用傳址或傳參考；傳值只換到影本。**

### 三、swap 範例：傳值失敗、傳址成功（C）

```c
// 傳值：換的是影本，失敗
void swap(int a, int b) {
    int t = a; a = b; b = t;
}   // 呼叫 swap(x, y) 後，x、y 沒變

// 傳址：傳位址，改到正本，成功
void swap(int *a, int *b) {
    int t = *a; *a = *b; *b = t;
}   // 呼叫 swap(&x, &y) 後，x、y 真的互換
```

為什麼傳值失敗？因為函式拿到的是 x、y 的**影本** a、b，互換的是影本；函式一結束，影本就丟掉了，正本沒動。傳址則把 x、y 的**位址**交給函式，函式用 `*a`、`*b` 順著位址改，改的就是正本。

📌 **C++ 的傳參考寫法：** C++ 可用 `&` 宣告參考直接當「別名」——`void swap(int &a, int &b){ int t=a; a=b; b=t; }`，呼叫時寫 `swap(x, y)`（不必 `&x`），效果等同傳址但更簡潔（C 沒有這種語法，只能用指標）。

### 四、Java 的常見誤解：Java 全部都是「傳值」

Java 全部都是「傳值」：**基本型別傳值的複製，物件傳的是參考的值。**

- 透過參考改物件**內容**會影響外面。
- 把參數**重新指向新物件**不影響外面。
- 嚴格說 **Java 沒有 call by reference**。

```java
static void change(int[] arr) {
    arr[0] = 99;              // 改「內容」→ 影響外面
    arr = new int[]{7, 8};    // 重新指向新物件 → 不影響外面
}

int[] a = {1, 2, 3};
change(a);
// a[0] 變成 99；但 a 仍指向原陣列，不是 {7, 8}
```

關鍵：Java 傳進去的是「**參考的複製**」。一開始兩個參考指同一個物件，所以改內容看得到；但把參數重新指派，只是換了「函式內那份參考」的指向，外面那份不受影響。

### 五、static 關鍵字

- **C 函式內 `static` 區域變數**：生命週期持續整個程式，值會**保留到下次呼叫**。
- **Java/C++ 類別裡的 `static` 成員**：屬於**類別本身**，所有物件**共用同一份**。
- **`static` 方法**：不用建立物件就能呼叫，**不能用 this**，也**不能直接存取非 static 成員**。

```c
// C：static 區域變數，值會累積保留
void counter() {
    static int n = 0;   // 只初始化一次
    n++;
    printf("%d\n", n);  // 每次呼叫印 1, 2, 3...
}
```

```java
// Java：static 成員屬於類別，所有物件共用
class Counter {
    static int count = 0;       // 類別變數，共用一份
    Counter() { count++; }
    static void show() {         // static 方法，免建物件就能叫
        System.out.println(count);
    }
}
Counter.show();  // 直接用類別名呼叫
```

---

## ✅ 回到題目：解答

1. 傳值的 C swap **交換失敗**——函式換的是 a、b 的**影本**，x、y 的正本沒動。要成功得改用**傳址**（傳 `&x, &y`，函式內用 `*a`、`*b` 操作）。
2. 「Java 是 call by reference」**不正確**。Java 一律是**傳值**；物件是把「參考的值」複製一份傳進去，所以嚴格說 Java 沒有 call by reference。
3. **傳址、傳參考、傳名**都會影響外面（傳名還每次重算）；只有**傳值不影響**。

---

## 📌 重點整理

- 參數 parameter＝定義時的空位；引數 argument＝呼叫時塞的值。
- 四方式：傳值（影本，不影響）、傳址（位址，影響）、傳參考（別名，影響）、傳名（整個表達式，用到才算、每次重算，影響）。
- swap 要成功 → 用傳址或傳參考；傳值只換到影本。
- **Java 全部傳值**：物件改內容會影響外面，重新指向新物件不影響；沒有真正的 call by reference。
- static：C 區域變數保留值；類別 static 成員共用一份；static 方法免建物件、不能用 this。

---

## ⚠️ 常見陷阱

- **「Java 是傳參考」是錯的**：正確說法是「傳的是參考的**值**」，本質仍是傳值。
- **改內容 vs 重新指派**：Java 裡 `arr[0]=99`（改內容）會影響外面；`arr = new ...`（重新指派）不會。這兩個常被混為一談。
- **傳值也能 swap？** 不行。傳值換的是影本，函式一結束影本就丟了。
- **static 方法用 this**：static 方法不屬於任何物件，沒有 this，也不能直接碰非 static 成員。
- **參數／引數名詞別反**：定義時是參數，呼叫時傳的是引數。

## 📝 練習題（含解答）

**Q1.** 「參數 parameter」和「引數 argument」差在哪？
<details><summary>看解答</summary>

參數是函式**定義時**宣告的變數（空位）；引數是**呼叫時**實際傳入的值。例如 `int add(int a, int b)` 的 a、b 是參數，`add(3, 5)` 的 3、5 是引數。
</details>

**Q2.** C 要寫出能真正交換兩數的 swap，應該用哪種傳遞方式？為什麼傳值不行？
<details><summary>看解答</summary>

要用**傳址**（`void swap(int *a, int *b)`，呼叫 `swap(&x, &y)`）。傳值只把 x、y 的**影本**傳進去，函式內互換的是影本，函式結束影本就消失，正本沒變。
</details>

**Q3.** 下面 Java 執行後 a[0] 是多少？a 會不會變成 {7, 8}？
```java
static void f(int[] arr){ arr[0] = 99; arr = new int[]{7, 8}; }
int[] a = {1, 2, 3}; f(a);
```
<details><summary>看解答</summary>

a[0] 變成 **99**；a **不會**變成 {7, 8}。傳進去的是參考的複製：改內容（`arr[0]=99`）動到同一個物件所以外面看得到；重新指派（`arr=new...`）只換了函式內那份參考，外面的 a 不受影響。
</details>

**Q4.** C 函式內的 `static int n = 0;` 有什麼特別？
<details><summary>看解答</summary>

它是 static 區域變數，**只初始化一次**，且**生命週期持續整個程式**，值會保留到下次呼叫。所以拿來當呼叫次數計數器，每次呼叫會累加。
</details>

**Q5.** static 方法為什麼不能用 this、也不能直接存取非 static 成員？
<details><summary>看解答</summary>

因為 static 方法屬於**類別本身**、不綁定任何物件，呼叫時根本沒有「哪個物件（this）」可指；而非 static 成員屬於個別物件，static 方法沒有物件當對象，自然不能直接存取。
</details>
