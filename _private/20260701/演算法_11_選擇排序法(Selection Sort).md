# 選擇排序法(Selection Sort)

> 科目：演算法｜選擇排序的口訣是「**每輪挑一個最小值，放到最前面**」。它和氣泡排序常被拿來對比：一樣是 O(n²)，但選擇排序**交換次數很少**（每輪最多換一次），而且**不受輸入順序影響**。
>
> 學習方式：**「找最小值 → 交換到定位」的流程**屬【理解】；**三種情況都 O(n²)、不穩定排序、交換次數最多 n-1 次**屬【硬背】。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 「選擇排序法的**最好、平均、最壞**時間複雜度分別是多少？」
> 2. 「選擇排序是**穩定**還是不穩定排序？」
> 3. 「同樣是 O(n²)，選擇排序和氣泡排序最大的差別在哪？（提示：**交換次數**）」

## 🤔 先想想

給你三個提示，幫你建立直覺：

- 想像整理撲克牌：每次從**還沒排的那疊**裡「挑出最小的一張」，放到已排好那疊的最後面。
- 選擇排序**不管資料原本多接近有序**，每一輪都得把剩下的全部掃一遍才知道誰最小。

## 📖 觀念拆解

### 一、演算法概念

選擇排序像是每次從剩下的資料中挑出最小的，依序放到左邊已排序區。

> 白話：把陣列切成左右兩塊——左邊是「已排好」區、右邊是「還沒排」區。每一輪都從右邊那塊找出最小值，跟右邊那塊的第一格交換，於是已排好區就往右長一格。重複到全部排完。

### 二、核心規則

1. 把 i 視為目前要放正確值的位置。
2. 從 i 到最後找出最小值的位置 minIndex。
3. 若 minIndex 不等於 i，就交換兩者。
4. i 往右移，重複處理剩下的未排序區。

> 新手重點：第 3 點「若 minIndex 不等於 i 才交換」是小優化——最小值本來就在正確位置時就不用白換。整個過程**最多只會交換 n-1 次**，這是選擇排序省交換的關鍵。

### 三、帶數字的逐步範例（陣列 [4, 2, 5, 1, 3]）

以非遞迴版為例，`n = 5`。每一輪先掃描未排序區找出 `minIndex`，再與位置 `i` 交換。

**第 1 輪（i = 0）：** 從 j=1..4 找最小值
- 起始 minIndex=0（值 4）；j=1 值 2 < 4 → minIndex=1；j=2 值 5 不更小；j=3 值 1 < 2 → minIndex=3；j=4 值 3 不更小。
- 最小值在 index 3，minIndex(3) ≠ i(0) → 交換 arr[0] 與 arr[3]。
- 結果：`[1, 2, 5, 4, 3]`（最小值 1 定位）

**第 2 輪（i = 1）：** 從 j=2..4 找最小值
- 起始 minIndex=1（值 2）；j=2 值 5、j=3 值 4、j=4 值 3 都不小於 2。
- minIndex(1) = i(1) → **不交換**。
- 結果：`[1, 2, 5, 4, 3]`（2 定位）

**第 3 輪（i = 2）：** 從 j=3..4 找最小值
- 起始 minIndex=2（值 5）；j=3 值 4 < 5 → minIndex=3；j=4 值 3 < 4 → minIndex=4。
- minIndex(4) ≠ i(2) → 交換 arr[2] 與 arr[4]。
- 結果：`[1, 2, 3, 4, 5]`（3 定位）

**第 4 輪（i = 3）：** 從 j=4 找最小值
- 起始 minIndex=3（值 4）；j=4 值 5 不更小。minIndex(3) = i(3) → 不交換。
- 結果：`[1, 2, 3, 4, 5]`，排序完成。

> 觀察：全程只發生了 **2 次交換**（第 1、3 輪），但**比較次數固定**為 4+3+2+1 = 10 次，跟輸入是否接近有序完全無關。

### 四、最壞時間複雜度

| 版本 | 最壞時間複雜度 | 推導重點 |
|---|---|---|
| 遞迴版本 | O(n²) | 每層遞迴都要掃描剩餘區間找最小值。 |
| 非遞迴版本 | O(n²) | 比較次數約為 (n - 1) + (n - 2) + ... + 1。 |

> 白話：不論資料長怎樣，第 1 輪要掃 n-1 個、第 2 輪掃 n-2 個……加起來 n(n-1)/2，取最高次項就是 **O(n²)**。因為「找最小值」一定要看完剩下全部，所以**最好情況也是 O(n²)**——這點和氣泡／插入不同。

### 五、遞迴版 Java 程式

每次遞迴固定一個 start 位置，再處理 start + 1 之後的部分。

```java
private static void swap(int[] arr, int i, int j) {
    int temp = arr[i];
    arr[i] = arr[j];
    arr[j] = temp;
}

public static void selectionSortRecursive(int[] arr) {
    selectionSortRecursive(arr, 0);
}

private static void selectionSortRecursive(int[] arr, int start) {
    // start 到最後只剩 0 或 1 個元素時，不需要排序。
    if (start >= arr.length - 1) {
        return;
    }

    int minIndex = start;

    // 找出 start 到最後的最小值位置。
    for (int j = start + 1; j < arr.length; j++) {
        if (arr[j] < arr[minIndex]) {
            minIndex = j;
        }
    }

    // 把最小值放到 start。
    if (minIndex != start) {
        swap(arr, start, minIndex);
    }

    // start 位置已經排好，接著排序 start + 1 之後的部分。
    selectionSortRecursive(arr, start + 1);
}
```

> 新手解釋：遞迴版把「排序 start 之後」拆成「先把 start 定位，再排序 start+1 之後」。`start` 每次 +1，直到 `start >= arr.length - 1`（剩 0 或 1 個）停止。找最小值的邏輯和非遞迴版一模一樣。

### 六、非遞迴版 Java 程式

用雙層迴圈逐輪找出未排序區的最小值。

```java
private static void swap(int[] arr, int i, int j) {
    int temp = arr[i];
    arr[i] = arr[j];
    arr[j] = temp;
}

public static void selectionSortIterative(int[] arr) {
    int n = arr.length;

    // i 代表目前要放正確值的位置。
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i;

        // 從 i + 1 到最後，找出最小值的位置。
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIndex]) {
                minIndex = j;
            }
        }

        // 把最小值交換到 i 的位置。
        if (minIndex != i) {
            swap(arr, i, minIndex);
        }
    }
}
```

> 新手解釋：外層 `i` 是「要放正確值的位置」，內層 `j` 從 `i + 1` 掃到底找最小值。內層**只記位置（minIndex）不急著換**，掃完一輪才交換一次——這就是選擇排序交換次數少的原因。

## ✅ 回到題目：解答

1. **最好／平均／最壞複雜度？** → 三者**皆為 O(n²)**。因為每一輪都必須掃完剩餘元素才能確定最小值，無法提前結束。
2. **穩定嗎？** → **不穩定（unstable）**。長距離交換可能把相等元素的相對順序打亂（見常見陷阱的例子）。
3. **和氣泡排序最大差別？** → **交換次數**。選擇排序每輪最多交換 1 次（全程最多 n-1 次）；氣泡排序最壞每輪多次交換。選擇排序比較次數固定、寫入次數少。

---

## 📌 重點整理

- 核心動作：**每輪從未排序區找最小值，交換到最前面**。
- 複雜度：最好／平均／最壞**全都 O(n²)**，不受輸入順序影響。
- **額外空間 O(1)**（原地排序），**不穩定排序**。
- **交換次數最多 n-1 次**——資料搬移成本低，適合「交換成本很高」的情境。
- `if (minIndex != i)` 是避免無謂交換的小優化。

---

## ⚠️ 常見陷阱

- **最好情況不是 O(n)**：就算輸入已排序，選擇排序仍要每輪掃完找最小值，最好情況**仍是 O(n²)**，別和氣泡／插入的 O(n) 搞混。
- **不穩定要記住**：例如 `[ (5)a, (5)b, 1 ]`，第 1 輪把最小值 1 換到最前，會讓 `5a` 跳到 `5b` 後面，相等元素順序被打亂 → 不穩定。
- **「找最小」還是「找最大」**：本教材版本是找**最小值**放左邊（升冪）；有些教材找最大值放右邊，方向別記反。
- **內層只更新 minIndex**：內層迴圈裡不要每次比較就交換（那會變成類似氣泡），選擇排序是**掃完一輪才換一次**。

## 📝 練習題（含解答）

**Q1.** 對 `[3, 1, 2]` 用選擇排序跑第 1 輪，`minIndex` 是多少？交換後結果為何？
<details><summary>看解答</summary>

i=0，起始 minIndex=0（值 3）；j=1 值 1<3 → minIndex=1；j=2 值 2 不小於 1。最終 **minIndex=1**，交換 arr[0] 與 arr[1] → **[1, 3, 2]**。
</details>

**Q2.** 選擇排序的最好情況時間複雜度是多少？為什麼不像氣泡排序能到 O(n)？
<details><summary>看解答</summary>

**O(n²)**。因為它沒有「提前結束」機制——每一輪都必須把未排序區全部掃過才能確定最小值，即使資料已排序也一樣。
</details>

**Q3.** 為什麼說選擇排序「交換次數少」？全程最多交換幾次？
<details><summary>看解答</summary>

因為內層只記錄 `minIndex`，一輪結束才交換一次。外層跑 n-1 輪，所以**最多交換 n-1 次**，遠少於氣泡排序最壞的交換量。
</details>

**Q4.** 選擇排序是穩定排序嗎？舉例說明。
<details><summary>看解答</summary>

**不穩定**。例如 `[5a, 5b, 1]`（兩個 5 標記先後）：第 1 輪最小值 1 在 index 2，會與 index 0 交換 → `[1, 5b, 5a]`，原本在前的 `5a` 跑到 `5b` 後面，相對順序被破壞。
</details>

**Q5.** 遞迴版的終止條件 `start >= arr.length - 1` 代表什麼？
<details><summary>看解答</summary>

代表未排序區只剩 **0 或 1 個元素**。只剩 1 個時它必然已在正確位置，不需要再排序，因此直接 `return`。
</details>
