# Deadlock（死結）(Deadlock)

> 科目：計算機概論 · 作業系統｜死結是「一群 process 互相等對方的資源，結果全部卡死」。本章要記牢**四個必要條件**、**三種處理策略**，並會跑一次**銀行家演算法**判斷安全與否——這是計算題的重點。
>
> 學習方式：四條件、三策略屬【硬背】＋【理解】；銀行家演算法的 Need = Max − Allocation 與安全序列找法屬【動手練】。

## 🤔 先想想

- 四條件必須**同時成立**才可能死結；反過來說，**只要破掉任一個就不會死結**——這正是「預防」的思路。
- 三策略的差別在**出手時機**：事前不讓它發生、事中每次配置前先算、事後允許發生再收拾。
- 銀行家演算法的核心一句話：「**借出去之後，還能不能讓大家都順利跑完？** 能才借。」

## 📖 觀念拆解

### 一、死結與四個必要條件

**死結（Deadlock）** 是一組 process 互相等待對方手上的資源，結果全部卡住，誰也動不了。四個必要條件**必須同時成立**才可能死結；**打破任一個就不會死結**。

| 條件 | 意思 |
|---|---|
| 互斥 Mutual Exclusion | 資源一次只能給一個 process 用，不能共享 |
| 持有並等待 Hold and Wait | 手上握著資源，同時又在等別的資源 |
| 不可搶奪 No Preemption | 資源不能被強搶，只能持有者自己放掉 |
| 循環等待 Circular Wait | 形成等待環：P1 等 P2，P2 等 P3，最後繞回 P1 |

📌 **生活比喻（單線橋）：** 橋一次只准一台車（互斥），你上了橋又不肯倒退（持有並等待、不可搶奪），對向也上來，兩車頭對頭（循環等待）——四條件到齊，卡死。

Java 也能輕易寫出死結：兩個執行緒各拿一把鎖、再互相要對方那把：

```java
Object A = new Object(), B = new Object();
// 執行緒 1：先鎖 A 再要 B
synchronized (A) { synchronized (B) { /* ... */ } }
// 執行緒 2：先鎖 B 再要 A  ← 順序相反就可能形成循環等待
synchronized (B) { synchronized (A) { /* ... */ } }
```

只要規定「所有人都**依相同順序**（例如先 A 後 B）取鎖」，就破了**循環等待**，死結消失。

### 二、三種處理策略與安全狀態

| 策略 | 時機 | 做法 | 代表 / 缺點 |
|---|---|---|---|
| 預防 Prevention | 事前 | 直接破壞四條件之一，讓死結不可能發生 | 限制多、利用率低 |
| 避免 Avoidance | 事中 | 每次配置前判斷配下去是否安全 | 代表是銀行家演算法；需事先知道最大需求 |
| 偵測與復原 Detection & Recovery | 事後 | 允許死結發生，定期找環，發現後再復原 | 殺 process、搶資源、rollback |

**如何破四條件（Prevention 的具體做法）：**

1. **破互斥**：資源盡量設計成可共享。
2. **破持有並等待**：一次拿齊全部，或拿新資源前先放掉舊的。
3. **破不可搶奪**：拿不到就連手上的一起放掉。
4. **破循環等待**：資源編號，規定只能依**遞增順序**申請。

📌 **安全狀態（屬「避免 Avoidance」，不是破四條件）**：存在一個**安全序列**，能讓所有 process 依序拿到資源、跑完並釋放。**安全一定不死結；不安全是「可能」死結**（不等於一定死結）。

### 三、銀行家演算法（Banker's Algorithm）

銀行家演算法屬於**避免（Avoidance）**策略。每次有人要資源，先檢查借出去後**是否仍能讓所有人順利完成**；能才配，確保系統停在安全狀態。

四張表的意義：

1. **Allocation**：目前已配給每個 process 的資源。
2. **Max**：每個 process 最多會用到的資源。
3. **Need = Max − Allocation**：還差多少才能完成。
4. **Available**：系統目前剩多少可配。
5. **安全演算法**：令 Work = Available；反覆找 **Need ≤ Work** 的 process，假設它跑完並**釋放 Allocation**（Work += Allocation）；若全部能 Finish 就安全。

以下是經典題（三種資源 A、B、C）：

| 行程 | Allocation (A B C) | Max (A B C) | Need (A B C) |
|---|---|---|---|
| P0 | 0 1 0 | 7 5 3 | 7 4 3 |
| P1 | 2 0 0 | 3 2 2 | 1 2 2 |
| P2 | 3 0 2 | 9 0 2 | 6 0 0 |
| P3 | 2 1 1 | 2 2 2 | 0 1 1 |
| P4 | 0 0 2 | 4 3 3 | 4 3 1 |

總資源 A=10、B=5、C=7，已配出 (7,2,5)，所以 **Available = (3,3,2)**。

跑安全演算法（Work 從 Available 開始）：

| 順序 | 挑誰 | Need ≤ Work? | 跑完後 Work = Work + Allocation |
|---|---|---|---|
| 1 | P1 | (1,2,2) ≤ (3,3,2) | (5,3,2) |
| 2 | P3 | (0,1,1) ≤ (5,3,2) | (7,4,3) |
| 3 | P0 | (7,4,3) ≤ (7,4,3) | (7,5,3) |
| 4 | P2 | (6,0,0) ≤ (7,5,3) | (10,5,5) |
| 5 | P4 | (4,3,1) ≤ (10,5,5) | (10,5,7) |

📌 **結論：全部跑完，系統安全。** 安全序列 **P1 → P3 → P0 → P2 → P4**；安全序列可能不只一個，找到任一個合法序列即可。

### 四、請求資源判斷（Resource-Request）

當某個 process 提出資源請求 Request 時，依序檢查：

1. **Request ≤ Need[i]？** 否則是錯誤（要的比宣告最大需求還多）。
2. **Request ≤ Available？** 否則資源不夠，必須**等待**。
3. **假裝配置**：Available −= Request、Allocation[i] += Request、Need[i] −= Request。
4. **重跑安全演算法**：安全才**真的配**；不安全就**撤銷並等待**。

---

## ✅ 回到題目：解答

1. **四條件？** → **互斥、持有並等待、不可搶奪、循環等待**，必須**同時成立**。**打破任一個就不會死結**（不必四個都破）。
2. **三策略時機？** → **Prevention 事前**（破條件）、**Avoidance 事中**（每次配置前判斷，如銀行家）、**Detection & Recovery 事後**（允許發生、再找環復原）。
3. **Need 與安全判斷？** → **Need = Max − Allocation**。令 Work = Available，反覆找 Need ≤ Work 的 process，讓它跑完釋放資源（Work += Allocation）；若全部可 Finish 就**安全**。本題安全序列 P1→P3→P0→P2→P4。

---

## 📌 重點整理

- 四條件（同時成立才死結）：**互斥、持有並等待、不可搶奪、循環等待**；破一個即可避免。
- 三策略：**Prevention（事前破條件）、Avoidance（事中判斷，銀行家）、Detection & Recovery（事後找環復原）**；此外多數通用 OS（UNIX／Windows）其實**選擇忽略**（鴕鳥演算法），因死結罕見、預防成本高。
- **Need = Max − Allocation**；**Available = 總資源 − 已配出**。
- 安全演算法：Work=Available → 找 Need ≤ Work → 跑完 Work += Allocation → 全部 Finish 即安全。
- **安全→一定不死結；不安全→可能（非必然）死結**。

---

## ⚠️ 常見陷阱

- **「不安全」不等於「一定死結」**：不安全只代表**可能**死結；安全才保證不死結。
- **資源配置圖（RAG）有環未必死結**：畫「process→資源」（申請）與「資源→process」（配置）箭頭找環——**單一實例**時「有環 ⟺ 死結」；**多實例**時「有環」只是**必要非充分**，可能有環卻不死結。
- **四條件要「同時」成立**：只要缺一個就不會死結；預防就是刻意打破其中一條。
- **Need 別算反**：**Need = Max − Allocation**（還差多少），不是 Max 或 Allocation 本身。
- **銀行家是「避免」不是「預防」**：它在**事中**每次配置前判斷，不是事前限制條件。
- **請求要先過兩關**：Request 必須同時 **≤ Need** 且 **≤ Available**，再試配並重跑安全檢查。

## 📝 練習題（含解答）

**Q1.** 死結的四個必要條件是哪四個？要避免死結，最少要打破幾個？
<details><summary>看解答</summary>

**互斥、持有並等待、不可搶奪、循環等待**。四者須同時成立才死結，所以**打破任一個（1 個）**即可避免。
</details>

**Q2.** 「資源編號，規定只能依遞增順序申請」是為了打破哪一個條件？
<details><summary>看解答</summary>

打破**循環等待（Circular Wait）**。強制依編號遞增申請，就無法形成等待環。
</details>

**Q3.** 銀行家演算法中，某 process 的 Max=(3,2,2)、Allocation=(2,0,0)，它的 Need 是多少？
<details><summary>看解答</summary>

Need = Max − Allocation = (3−2, 2−0, 2−0) = **(1,2,2)**。
</details>

**Q4.** 本章題目 Available = (3,3,2)，為什麼一開始不能先挑 P0？該先挑誰？
<details><summary>看解答</summary>

P0 的 Need = (7,4,3)，不滿足 Need ≤ (3,3,2)，資源不夠。可先挑 **P1**（Need (1,2,2) ≤ (3,3,2)）。安全序列之一為 **P1→P3→P0→P2→P4**。
</details>

**Q5.** 一個 process 提出資源請求 Request，銀行家演算法要先檢查哪兩個條件才試著配置？
<details><summary>看解答</summary>

先檢查 **Request ≤ Need[i]**（否則出錯）與 **Request ≤ Available**（否則須等待）。都通過才假裝配置並**重跑安全演算法**，安全才真的配。
</details>
