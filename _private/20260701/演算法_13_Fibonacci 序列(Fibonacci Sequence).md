# Fibonacci 序列(Fibonacci Sequence)

> 科目：演算法｜費氏數列是理解「**遞迴**」與「**遞迴的代價**」的經典教材。它的定義天生就是遞迴的（每一項等於前兩項相加），但直接照定義寫遞迴會**大量重複計算**，複雜度爆炸成 O(2ⁿ)；改用迴圈只要 O(n)。
>
> 學習方式：**定義與遞迴拆解**屬【理解】；**遞迴 O(2ⁿ)、非遞迴 O(n)**這組對比屬【硬背】，也是考題最愛的「遞迴 vs 非遞迴效率差異」。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 「費氏數列 F(0) 到 F(7) 依序是多少？」
> 2. 「**遞迴版**費氏數列的時間複雜度為什麼是 **O(2ⁿ)** 而不是 O(n)？」
> 3. 「同樣算 F(n)，遞迴版和**非遞迴（迴圈）版**的複雜度差在哪？」

先別急著往下看答案，試著自己回答看看。

## 🤔 先想想

給你三個提示，幫你建立直覺：

- 費氏數列的定義是**前兩項相加**：0, 1, 1, 2, 3, 5, 8, 13…
- 遞迴版把 F(n) 拆成 F(n-1) 和 F(n-2)，但這兩棵子樹裡會**重複算到同樣的小項**（例如 F(2) 被算很多次）。
- 非遞迴版只用兩個變數「往前滾」，算過的不重算，所以是線性 O(n)。

帶著這三點，我們來拆解。

## 📖 觀念拆解

### 一、演算法概念與定義

Fibonacci 的重點是每一項都由前兩項相加而來，因此很適合用來理解遞迴拆解與迴圈累加的差異。

**定義（務必記牢）：**

- F(0) = 0
- F(1) = 1
- F(n) = F(n - 1) + F(n - 2)（當 n > 1）

> 白話：數列從 0、1 開始，之後每一項都是「前面兩項加起來」。0、1、1、2、3、5、8、13、21…就是這樣長出來的。

### 二、核心規則

1. F(0) 回傳 0，F(1) 回傳 1。
2. 當 n 大於 1 時，使用 F(n - 1) + F(n - 2)。
3. 遞迴版本會把問題拆成兩個更小問題。
4. 非遞迴版本從 F(2) 開始一路算到 F(n)。

> 新手重點：第 1 點的 F(0)、F(1) 是**遞迴的終止條件（base case）**，沒有它遞迴會停不下來。第 3、4 點正是遞迴與迴圈兩種思路的分水嶺。

### 三、帶數字的逐步範例（F(0) 到 F(7)）

| n | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| F(n) | 0 | 1 | 1 | 2 | 3 | 5 | 8 | 13 |

計算過程：F(2)=F(1)+F(0)=1+0=**1**；F(3)=F(2)+F(1)=1+1=**2**；F(4)=F(3)+F(2)=2+1=**3**；F(5)=F(4)+F(3)=3+2=**5**；F(6)=F(5)+F(4)=5+3=**8**；F(7)=F(6)+F(5)=8+5=**13**。

**為什麼遞迴會重複計算？看 F(5) 的遞迴樹：**

```
                F(5)
              /      \
          F(4)        F(3)
         /    \       /    \
      F(3)   F(2)   F(2)   F(1)
      /  \   /  \   /  \
   F(2) F(1)F(1)F(0)F(1)F(0)
   /  \
 F(1) F(0)
```

數一數：算一個 F(5)，其中 **F(3) 被算了 2 次、F(2) 被算了 3 次、F(1)/F(0) 更是被算了很多次**。n 越大，這種重複呈**指數成長**——同一個小項一算再算，這就是 O(2ⁿ) 的來源。

相對地，非遞迴版從 F(2) 一路往上滾（1→2→3→5→8→13），每一項**只算一次**，所以是 O(n)。

### 四、最壞時間複雜度

| 版本 | 最壞時間複雜度 | 推導重點 |
|---|---|---|
| 遞迴版本 | O(2ⁿ) | 每次呼叫會再呼叫 n - 1 與 n - 2，產生大量重複計算。 |
| 非遞迴版本 | O(n) | 從 2 算到 n，每次只更新前兩項。 |

> 白話：遞迴版每呼叫一次就再岔出兩次呼叫，呼叫總數約以 2 的次方膨脹（更精確地說接近黃金比例的 n 次方，但考試通常記 **O(2ⁿ)**）。非遞迴版一個迴圈跑到 n，是 **O(n)**——這是典型的「換個寫法就從指數變線性」的例子。

### 五、遞迴版 Java 程式

依照 F(n)=F(n-1)+F(n-2) 直接拆成兩個子問題。

```java
public static long fibonacciRecursive(int n) {
    if (n < 0) {
        throw new IllegalArgumentException("n must be >= 0");
    }

    // n = 0 回傳 0；n = 1 回傳 1。
    if (n <= 1) {
        return n;
    }

    // 把問題拆成前兩項相加。
    return fibonacciRecursive(n - 1) + fibonacciRecursive(n - 2);
}
```

> 新手解釋：`n <= 1` 是終止條件（F(0)=0、F(1)=1，剛好 `return n`）。其餘直接照定義呼叫自己兩次相加——寫起來最直覺，但就是這「兩次呼叫」造成指數級重複計算。

### 六、非遞迴版 Java 程式

用 prev 與 curr 保存前兩項，從 F(2) 一路算到 F(n)。

```java
public static long fibonacciIterative(int n) {
    if (n < 0) {
        throw new IllegalArgumentException("n must be >= 0");
    }
    if (n <= 1) {
        return n;
    }

    long prev = 0; // F(0)
    long curr = 1; // F(1)

    // 從 F(2) 算到 F(n)。
    for (int i = 2; i <= n; i++) {
        long next = prev + curr;
        prev = curr;
        curr = next;
    }

    return curr;
}
```

> 新手解釋：只用 `prev`、`curr` 兩個變數保存「前兩項」，每跑一次迴圈把窗口往前滑一格（`next = prev + curr`，再更新 `prev`、`curr`）。算過的不重算，所以是 O(n)，且只用固定額外空間 O(1)。

## ✅ 回到題目：解答

1. **F(0) 到 F(7)？** → **0, 1, 1, 2, 3, 5, 8, 13**。
2. **遞迴版為何 O(2ⁿ)？** → 因為每次呼叫會再岔出 F(n-1) 與 F(n-2) 兩次呼叫，且**大量重複計算**同一些小項（如 F(2)、F(3) 被重複算多次），呼叫數呈指數成長。
3. **遞迴 vs 非遞迴差在哪？** → 遞迴 **O(2ⁿ)**（重複計算）；非遞迴用兩個變數往前滾，每項只算一次，**O(n)**。

## 📌 重點整理

- 定義：**F(0)=0、F(1)=1、F(n)=F(n-1)+F(n-2)**。
- 數列：0, 1, 1, 2, 3, 5, 8, 13, 21…
- 遞迴版**直覺但慢**：O(2ⁿ)，元凶是**重複計算**；且遞迴堆疊最深達 n 層，**額外空間 O(n)**。
- 非遞迴版**用兩個變數往前滾**：時間 O(n)、額外空間 O(1)。
- 若要保留遞迴寫法又要快，可用 **memoization（記憶化）** 把已算結果存起來，降到 O(n)。

---

## ⚠️ 常見陷阱

- **別以為遞迴就是 O(n)**：純遞迴費氏是 **O(2ⁿ)**；只有加了記憶化或改迴圈才會是 O(n)。這是最常見的陷阱選項。
- **終止條件不可少**：漏掉 `n <= 1` 的 base case，遞迴會無限往下呼叫、堆疊溢位。
- **數值溢位**：F(n) 增長很快，`int` 很快就爆掉；程式用 `long` 也只是延後，n 很大時仍會溢位。
- **索引起算**：本教材 F(0)=0、F(1)=1；有些定義從 F(1)=1、F(2)=1 起算，看題目給的定義為準。

**Q1.** 寫出 F(0) 到 F(6) 的值。
<details><summary>看解答</summary>

**0, 1, 1, 2, 3, 5, 8**。（F(2)=1、F(3)=2、F(4)=3、F(5)=5、F(6)=8）
</details>

**Q2.** 純遞迴版費氏數列的時間複雜度是多少？為什麼？
<details><summary>看解答</summary>

**O(2ⁿ)**。因為每次呼叫 F(n) 會再呼叫 F(n-1) 與 F(n-2)，同一些子問題（如 F(2)、F(3)）被**重複計算**很多次，呼叫總數呈指數成長。
</details>

**Q3.** 非遞迴版只用 `prev` 和 `curr` 兩個變數，它的時間與額外空間複雜度各是多少？
<details><summary>看解答</summary>

時間 **O(n)**（迴圈從 2 跑到 n），額外空間 **O(1)**（只用固定幾個變數）。
</details>

**Q4.** 用 F(4) 的遞迴展開，說明 F(2) 被計算了幾次。
<details><summary>看解答</summary>

F(4)=F(3)+F(2)；F(3)=F(2)+F(1)。所以 F(2) 出現在 F(4) 直接一次、F(3) 展開又一次，共 **2 次**。這正是重複計算的縮影（n 越大重複越多）。
</details>

**Q5.** 若想保留遞迴寫法又把複雜度降到 O(n)，可以用什麼技巧？
<details><summary>看解答</summary>

用 **memoization（記憶化）**：把已經算過的 F(k) 存進陣列或 HashMap，下次要用時直接查表，不再重算，時間即可降到 **O(n)**。
</details>
