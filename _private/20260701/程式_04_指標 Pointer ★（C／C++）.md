# 指標 Pointer ★（C／C++）

> 科目：程式（專業 B）｜指標是很多人最頭痛的 C/C++ 考點，但其實**核心只有一句**：指標存的是「**位址**」，不是值本身。抓住這句，後面全部好推。
>
> 學習方式：屬【理解】——用「房號紙條」的比喻建立直覺，`&` 與 `*` 兩個符號一定要分清楚。因為指標是 C/C++ 專屬，本篇程式以 **C** 為主，並補上 **Java** 對照（Java 沒有明確指標，用參考概念）。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. `int x = 10; int *p = &x;`，請問 p 裡面裝的是 10 還是 x 的位址？`*p` 又是多少？
> 2. `&` 和 `*` 各是做什麼的？
> 3. 陣列 `int arr[3];`，`arr`、`&arr[0]`、`*(arr + 1)` 分別代表什麼？

先想想再往下對答案。

---

## 🤔 先想想

- 把記憶體想成**一排有門牌號碼的房間**。一般變數是「**房間裡放的東西**」；指標是「**一張寫著某個房號的紙條**」。紙條本身不是那個東西，但照著紙條就能找到房間、拿到東西。
- 兩個符號別搞反：`&`（取址）是「**告訴我這東西住哪**」；`*`（解參考）是「**順著這個地址，把裡面的東西拿出來**」。
- Java/Python 為什麼沒有指標？因為指標太容易出錯（指到不該指的地方就崩潰），所以它們用**參考 + 自動回收（GC）** 把危險的部分藏起來。

---

## 📖 觀念拆解

### 一、指標是什麼？（房號紙條比喻）

記憶體像一排有編號的房間；一般變數是房間裡的值，指標是寫著某房間號碼的紙條。

例如 x 住在 `0x100`，值是 10；p 住在 `0x200`，裡面放 `0x100`，所以 **p 指向 x**。

```
房號 0x100 ┌──────┐   ← 變數 x，裡面放 10
           │  10  │
           └──────┘
房號 0x200 ┌──────┐   ← 指標 p，裡面放「0x100」這個地址
           │0x100 │──→ 指向 x
           └──────┘
```

### 二、兩個關鍵符號：& 與 *　【務必分清】

| 符號 | 名稱 | 意思 |
|---|---|---|
| `&` | 取址 address-of | `&x` 取得 x 的位址 |
| `*`（宣告時） | 指標型別 | `int *p` 表示 p 是指向 int 的指標 |
| `*`（使用時） | 解參考 dereference | `*p` 順著 p 的位址拿該房間裡的值 |

📌 口訣：**`&` 拿地址、`*` 順著地址拿值。**

```c
int x = 10;
int *p = &x;          // p 存 x 的位址（&x）
printf("%d\n", *p);   // 解參考：順著 p 拿到 10
*p = 20;              // 透過 p 改 x
printf("%d\n", x);    // x 變成 20
```

注意 `*` 在**宣告**（`int *p`，代表「p 是指標」）和**使用**（`*p`，代表「拿值」）意思不同，別混。

### 三、指標與陣列

- 陣列名稱本身就是第一個元素的位址，也就是 `arr == &arr[0]`。
- `int *p = arr;` 代表 p 指向 `arr[0]`。
- `*(p + 1)` 等於 `arr[1]`；`p + 1` **不是加 1 byte**，而是**跳一個元素大小**（指標運算）。

```c
int arr[3] = {10, 20, 30};
int *p = arr;              // p 指向 arr[0]
printf("%d\n", *p);        // 10  → arr[0]
printf("%d\n", *(p + 1));  // 20  → arr[1]（跳一個 int，不是跳 1 byte）
```

### 四、用途與陷阱

| 用途 | 陷阱 |
|---|---|
| 傳址讓函式改到外面的變數 | NULL 指標解參考會崩潰 |
| 動態記憶體配置 malloc/free、new/delete | 迷途指標 dangling 指向無效記憶體 |
| 高效處理大資料與串接資料結構 | 記憶體洩漏 leak 是配置後忘了釋放 |

📌 **白話：**
- **傳址改外面變數**：就是前一張 swap 用到的招（傳 `&x` 進函式）。
- **動態配置**：程式跑的時候才跟系統要記憶體（C 用 `malloc/free`，C++ 用 `new/delete`）。
- **NULL 解參考**：對一個「沒指向任何東西」的指標做 `*p`，程式當場崩潰。
- **dangling（迷途）指標**：指向的記憶體已被釋放/失效，卻還拿來用。
- **memory leak（記憶體洩漏）**：`malloc` 了卻忘了 `free`，記憶體一直被佔著沒還。

### 五、C/C++ vs Java/Python

| 比較 | C/C++ | Java/Python |
|---|---|---|
| 指標 | 有，可直接操作位址 | 沒有明確指標，用參考概念 |
| 記憶體管理 | 手動 malloc/free、new/delete | 自動 GC |
| 取捨 | 強大底層但易出錯 | 較安全但較不底層 |

Java 的物件變數其實也是「指向物件的參考」，行為上像一個**受保護的指標**——你不能拿它去做加減位址、也不能手動釋放，記憶體交給 GC。所以 Java 不會有 dangling pointer 或忘記 free 的問題，但也碰不到底層位址。

## ✅ 回到題目：解答

1. `int *p = &x;`：p 裡面裝的是 **x 的位址**（例如 0x100），不是 10；`*p`（解參考）才是 **10**。
2. **`&` 是取址**（拿某變數的位址）；**`*` 是解參考**（順著位址把值拿出來；`*` 在宣告時則表示這是指標型別）。
3. `arr`＝第一個元素的位址（`== &arr[0]`）；`&arr[0]`＝arr[0] 的位址（同上）；`*(arr + 1)`＝`arr[1]`（跳一個元素再取值）。

---

## 📌 重點整理

- 一句話：**指標存的是「位址」，不是值本身**。
- **`&` 拿地址、`*` 順著地址拿值**；`*` 在宣告時代表「這是指標」。
- 陣列名＝第一個元素位址（`arr == &arr[0]`）；`*(p + 1) == arr[1]`，指標 +1 跳一個「元素大小」。
- 用途：傳址改外面變數、動態配置、串接資料結構。
- 陷阱：NULL 解參考崩潰、dangling 迷途指標、memory leak。
- Java/Python 沒有明確指標（用參考）＋自動 GC：較安全、較不底層。

---

## ⚠️ 常見陷阱

- **把「位址」當「值」**：`p` 是位址，`*p` 才是值。搞混就全錯。
- **`*` 的兩種意思**：宣告 `int *p`（p 是指標）vs 使用 `*p`（拿值），是不同用途。
- **指標 +1 不是 +1 byte**：`p + 1` 會跳「一個元素大小」（int 通常跳 4 bytes）。
- **指標本身大小固定**：不論指向什麼型別，`int*`、`char*`、`double*` 的 `sizeof` 都一樣（由系統位址長度決定，如 64 位元系統為 8 bytes）——別和「指向的型別大小」搞混。
- **NULL 指標解參考**：對沒指向有效記憶體的指標做 `*p`，直接崩潰（常見當機原因）。
- **malloc 要配 free**：忘了 free ＝ memory leak；free 完還用 ＝ dangling pointer。
- **別以為 Java 有指標**：Java 用參考，不能操作位址、不用手動釋放。

## 📝 練習題（含解答）

**Q1.** 指標變數裡到底存什麼？
<details><summary>看解答</summary>

存的是**位址（記憶體門牌號）**，不是值本身。要拿值要用 `*`（解參考）順著位址去取。
</details>

**Q2.** `int x = 5; int *p = &x; *p = 8;` 執行後 x 是多少？
<details><summary>看解答</summary>

x 變成 **8**。p 存 x 的位址，`*p = 8` 就是順著位址把 x 那格改成 8。
</details>

**Q3.** 陣列 `int a[4];` 中，`a`、`*(a + 2)` 各代表什麼？
<details><summary>看解答</summary>

`a` 是第一個元素的位址（等於 `&a[0]`）；`*(a + 2)` 等於 `a[2]`（往後跳兩個元素再取值）。
</details>

**Q4.** 什麼是 dangling pointer？什麼是 memory leak？
<details><summary>看解答</summary>

dangling（迷途）指標＝指向的記憶體**已被釋放/失效**卻還拿來用；memory leak（記憶體洩漏）＝動態配置（malloc/new）後**忘了釋放**（free/delete），記憶體一直被佔著。
</details>

**Q5.** 為什麼 Java/Python 不給程式設計師「明確的指標」？
<details><summary>看解答</summary>

因為指標強大但**容易出錯**（NULL 解參考、dangling、leak）。Java/Python 改用**參考概念 + 自動 GC**，犧牲一點底層控制，換取**較安全**、較不易出錯。
</details>
