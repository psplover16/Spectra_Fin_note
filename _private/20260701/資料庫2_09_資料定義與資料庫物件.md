>
> 學習方式：建表的三件事（欄位、型別、約束）與 VIEW／INDEX 的用途屬【理解】；六種約束名稱、CHAR vs VARCHAR、主鍵 vs UNIQUE、叢集 vs 非叢集屬【硬背】。

## 📖 觀念拆解

### 一、先搞懂：資料表與「建表」是什麼

一張**資料表（Table）** 就像一張 Excel 表格：每一**列（row）** 是一筆資料、每一**欄（column）** 是一個欄位。例如 `student` 表，每列代表一個學生，欄位有「學號、姓名、成績…」。

**建立資料表（CREATE TABLE）** 就是在資料庫裡開一張新表，並把三件事講清楚：**有哪些欄、每欄放什麼型別的資料、套用哪些規則（約束）**。

💡 **名詞定位**：這些「建立／修改／刪除結構」的指令屬於 **DDL（資料定義語言）**，和「對資料增刪改查」的 DML 是不同層次：**DDL 蓋房子（定義結構）、DML 搬家具（操作資料）**。

### 二、CREATE TABLE 與資料型別

基本語法：`CREATE TABLE 表名 ( 欄名 型別 [約束1 約束2 ...], … );`

每個欄位都要指定**資料型別**，告訴資料庫這欄放什麼種類的資料：

| 類別 | 型別 | 說明 |
|---|---|---|
| 整數 | `INT` | 整數，如年齡、數量 |
| 精確小數 | `DECIMAL(p,s)` | **p**＝總位數、**s**＝小數位數。`DECIMAL(5,2)`＝3 位整數＋2 位小數（最大 999.99） |
| 定長文字 | `CHAR(n)` | 固定佔 n 格，不足補空白 |
| 變長文字 | `VARCHAR(n)` | 最多 n 個字元，存多長就佔多長 |
| 日期／時間 | `DATE` / `DATETIME` | 日期 / 日期＋時間 |

最小的建表範例：

```sql
CREATE TABLE student (
  id    CHAR(8),
  name  VARCHAR(20)
);
```

💡 **CHAR vs VARCHAR：固定長度 vs 可變長度**
兩者差在「佔空間的方式」。**`CHAR(n)`** 是**固定長度**，一律佔 n 格，不足的用空白補滿——`CHAR(10)` 存「abc」會存成「abc」＋7 個空白、佔滿 10。**`VARCHAR(n)`** 是**可變長度**，存多長就佔多長（再加 1~2 bytes 記錄長度），n 只是上限——`VARCHAR(10)` 存「abc」大約佔 3＋1 = 4 bytes。

💡 **為什麼不能一律用 VARCHAR**：VARCHAR 看似省空間又有彈性，但有代價，所以**長度幾乎固定**的欄位仍常用 CHAR：

- **長度紀錄的額外開銷**：每個 VARCHAR 值要多存 1~2 bytes 記自己多長。若資料本來就幾乎固定長度（性別 `M/F`、國別碼 `TW/US`、郵遞區號），用 VARCHAR 反而多花這 1~2 bytes，比 CHAR 還浪費。
- **固定長度讀取較快**：CHAR 每列長度固定，資料庫一眼就知道每筆從哪到哪，定位、讀取都快；VARCHAR 長度不一，計算位置較麻煩。
- **更新較穩定**：CHAR 更新成等長的值不必搬動；VARCHAR 改成更長的值可能塞不回原位，造成**列遷移（row migration）／碎片化**，拖慢效能。

原則：**長度固定**（身分證、學號、代碼）用 `CHAR`；**長度不定**（姓名、地址、Email）用 `VARCHAR`。

### 三、六種約束（Constraints）

**約束**是資料庫幫你「把關」的規則，確保存進去的資料不會亂。國考常考下面六種：

| 約束 | 作用 | 範例寫法 |
|---|---|---|
| **PRIMARY KEY** 主鍵 | 每列的唯一身分，**不可重複、不可空** | `id CHAR(8) PRIMARY KEY` |
| **FOREIGN KEY** 外來鍵 | 指向**另一張表的主鍵**，確保關聯有效 | `FOREIGN KEY (sid) REFERENCES student(id)` |
| **NOT NULL** 非空 | 此欄一定要有值，不能留白 | `name VARCHAR(20) NOT NULL` |
| **UNIQUE** 唯一 | 此欄不可重複（但**可**留空） | `email VARCHAR(50) UNIQUE` |
| **CHECK** 檢查 | 值必須滿足自訂條件 | `CHECK (score BETWEEN 0 AND 100)` |
| **DEFAULT** 預設 | 沒給值時自動填入預設值 | `status VARCHAR(10) DEFAULT '在學'` |

💡 **外來鍵到底在做什麼**：它強制「**子表的值必須在父表存在**」。例如 `enrollment` 表的 `student_id` 必須是 `student` 表裡真的有的學號——這樣就不會出現「幫一個不存在的學生選課」。父表那筆被刪除時的處理方式：`ON DELETE CASCADE`（子表一起刪）、`SET NULL`（子表設為空）、`RESTRICT`（禁止刪除）。

💡 **約束可以多個嗎？** 可以。一個欄位可同時套多個約束，例如 `name VARCHAR(20) NOT NULL UNIQUE`。

💡 **主鍵 vs UNIQUE（必考差異）**：兩者都保證「不重複」，差別在——**主鍵**還要「不可空」且「一張表只能一個」；**UNIQUE** 則「可以空」且「一張表可以有多個」。

💡 **複合主鍵（組合鍵）**：主鍵可由**多個欄位合起來**當唯一身分，寫成表級約束 `PRIMARY KEY (student_id, course_id)`；常見於多對多的關聯表（如選課表以「學號＋課號」為主鍵）。此時仍是**一個**主鍵，只是它涵蓋多欄。

### 四、完整建表範例（申論標準寫法）

把約束組合起來，這就是申論題「請寫出建立資料表的 SQL」的標準答案形式：

```sql
CREATE TABLE student (
  id      CHAR(8)       PRIMARY KEY,                       -- 主鍵
  name    VARCHAR(20)   NOT NULL,                          -- 不可空
  email   VARCHAR(50)   UNIQUE,                            -- 不可重複
  score   DECIMAL(5,2)  CHECK (score BETWEEN 0 AND 100),   -- 限 0~100
  status  VARCHAR(10)   DEFAULT '在學'                      -- 預設「在學」
);

CREATE TABLE enrollment (
  id          INT        PRIMARY KEY,
  student_id  CHAR(8)    NOT NULL,
  course      VARCHAR(30),
  FOREIGN KEY (student_id) REFERENCES student(id)
    ON DELETE CASCADE                                  -- 學生被刪，其選課一併刪
);
```

💡 **怎麼讀這段**：每一行＝「**欄名　型別　約束**」。`enrollment` 最後一行的外來鍵，把 `student_id`「綁」到 `student` 表的 `id`；有了它，資料庫就不准你新增一筆對不到任何學生的選課。

**所有型別與約束總整理**（一次示範六型別＋六約束）：

```sql
CREATE TABLE student_profile (
  profile_id  INT           PRIMARY KEY,                              -- 整數＋主鍵
  student_id  CHAR(8)      NOT NULL UNIQUE,                      -- 一欄多約束
  name        VARCHAR(20)  NOT NULL,                             -- 變長文字＋非空
  gender      CHAR(1)      DEFAULT 'F' CHECK (gender IN ('M', 'F')),
  score       DECIMAL(5,2) DEFAULT 0 CHECK (score BETWEEN 0 AND 100),
  birth_date  DATE          NOT NULL,
  created_at  DATETIME      DEFAULT '2026-01-01 09:00:00',
  FOREIGN KEY (student_id) REFERENCES student(id)
);
```

這段一次包含六種型別：`INT`、`DECIMAL`、`CHAR`、`VARCHAR`、`DATE`、`DATETIME`；也包含六種約束：`PRIMARY KEY`、`FOREIGN KEY`、`NOT NULL`、`UNIQUE`、`CHECK`、`DEFAULT`。

💡 **建好之後要改結構？用 `ALTER TABLE`**：新增欄位 `ALTER TABLE student ADD phone VARCHAR(20);`、刪欄位 `DROP COLUMN`、改型別（MySQL 用 `MODIFY`、SQL Server 用 `ALTER COLUMN`）。它與 `CREATE`／`DROP` 同屬 DDL。

### 五、VIEW 檢視表

**VIEW（檢視表）** 是一張「**虛擬的表**」：它本身**不存資料**，存的是**一段 SELECT 查詢**。每次你查這個 VIEW，資料庫就**即時跑那段查詢**把結果給你看。

```
student 表（實體，存所有資料）
        │  VIEW 存的是一段查詢：WHERE score>=60
        ▼
passed_student（VIEW，查時才即時產生，虛擬不存資料）
```

建立與使用：

```sql
CREATE VIEW passed_student AS
SELECT name, score FROM student
WHERE score >= 60;
```

之後就能像查一般表一樣使用：`SELECT * FROM passed_student;`

**為什麼要用 VIEW**

- **簡化**：把複雜的多表 JOIN 包成一個名字，之後直接查這個 VIEW。
- **安全**：只開放部分欄位給某些使用者（例如隱藏薪資欄）。
- **邏輯獨立**：底層表改了，VIEW 仍可維持原本的查詢介面。

💡 **可更新性（考點）**：簡單的 VIEW 可以透過它去改底層資料；但含 **JOIN、GROUP BY、彙總函式、DISTINCT** 的 VIEW **通常不可更新**（因為改了無法對應回唯一一筆原始資料）。

### 六、INDEX 索引

**INDEX（索引）** 是替某欄位額外建立的「**查找結構**」，讓資料庫能**快速定位**，不必把整張表一列一列掃過。

💡 **用書本理解**：索引就像書本後面的「**索引頁**」。要找「正規化」這個詞，你不會從第一頁翻到最後，而是查書末索引 → 直接翻到那一頁。資料庫索引同理：先查索引、再直接取資料。

建立語法（內部通常用 **B-tree／B+tree** 結構）：

```sql
CREATE INDEX idx_student_name ON student(name);
```

**兩種索引（考點）**

- **叢集索引（Clustered）**：決定資料的「**實體排列順序**」，一張表**只能有一個**（像書的內容本身就按章節順序排）。
- **非叢集索引（Non-clustered）**：另外建一份「欄位值 → 位置」的對照，一張表**可有多個**（像書末另附的索引頁）。

**優缺點（為什麼不是每欄都建）**

- **優點**：查詢（WHERE、JOIN、ORDER BY）大幅變快。
- **缺點**：占額外儲存空間；且每次**新增／修改／刪除**資料，索引也要跟著更新 → **寫入變慢**。
- 所以只在「**經常用來查詢**」的欄位建索引，而非全部。

## ✅ 回到題目：解答

1. **含六種約束的建表 SQL** → 見「四、完整建表範例」的 `student` 與 `enrollment`：`id ... PRIMARY KEY`、`FOREIGN KEY (student_id) REFERENCES student(id)`、`name ... NOT NULL`、`email ... UNIQUE`、`score ... CHECK (score BETWEEN 0 AND 100)`、`status ... DEFAULT '在學'`。
2. **主鍵 vs UNIQUE** → 都保證不重複；但**主鍵**還要「不可空」且「一表只能一個」，**UNIQUE**「可空」且「一表可多個」。
3. **VIEW／INDEX 是什麼？為何不每欄建索引？** → VIEW 是不存資料的虛擬表（存一段 SELECT，用於簡化／安全／邏輯獨立）；INDEX 是加速查詢的查找結構（讀快但**寫慢**、占空間），所以只在常查詢的欄位建。

## 📌 重點整理

- 建表要講清楚三件事：**欄位、型別、約束**。
- 六種約束：PRIMARY KEY（唯一＋非空）、FOREIGN KEY（參照他表主鍵）、NOT NULL、UNIQUE、CHECK、DEFAULT。
- **CHAR** 固定長度（不足補空白、讀快）；**VARCHAR** 可變長度（省空間、有彈性）。
- **VIEW** 是不存資料的虛擬表（簡化／安全／邏輯獨立）；含 JOIN／GROUP BY／彙總 通常不可更新。
- **INDEX** 加速查詢、拖慢寫入；叢集（實體排序、一個）vs 非叢集（對照、多個），常用 B-tree／B+tree。

---

## ⚠️ 常見陷阱

- **主鍵 vs UNIQUE**：主鍵＝唯一＋不可空＋一表一個；UNIQUE＝唯一＋可空＋可多個。
- **外來鍵**確保參照完整性；刪父表列可設 `ON DELETE CASCADE`／`SET NULL`／`RESTRICT`，別漏。
- **VIEW 不存資料**（是虛擬表）；含 JOIN／GROUP BY／彙總函式／DISTINCT 通常**不可更新**。
- **INDEX 不是越多越好**：加快讀取、但**拖慢寫入**且占空間，只在常查詢的欄位建。
- 別把 CHAR、VARCHAR 用反：長度固定用 CHAR，長度不定用 VARCHAR。

## 📝 練習題（含解答）

**Q1.** 要求一個欄位「不可重複、但允許留空」，該用哪個約束？若改成「不可重複且不可留空、且一張表只有一個」呢？
<details><summary>看解答</summary>

前者用 **UNIQUE**（唯一但可空、可多個）；後者用 **PRIMARY KEY**（唯一＋不可空＋一表只有一個）。
</details>

**Q2.** 寫一段 SQL，建立 `products` 表：`id` 為整數主鍵，`price` 為精確到小數 2 位、最大 999999.99 的金額，且不可為負（≥ 0）。
<details><summary>看解答</summary>

```sql
CREATE TABLE products (
  id    INT           PRIMARY KEY,
  price DECIMAL(8, 2) CHECK (price >= 0)   -- 6 位整數＋2 位小數，最大 999999.99
);
```
金額要精確，用 `DECIMAL(p,s)`，不要用 FLOAT。
</details>

**Q3.** 為什麼「性別」「郵遞區號」這類欄位常用 `CHAR` 而非 `VARCHAR`？
<details><summary>看解答</summary>

因為它們**長度幾乎固定**。VARCHAR 每個值要多存 1~2 bytes 記長度，對固定長度資料反而更浪費；且 CHAR 長度固定、定位讀取快、更新不易造成列遷移。原則：長度固定用 CHAR、不定用 VARCHAR。
</details>

**Q4.** 建立一個只顯示「及格（score ≥ 60）學生的姓名與分數」的檢視表，並說明它可不可以拿來更新底層資料。
<details><summary>看解答</summary>

```sql
CREATE VIEW passed_student AS
SELECT name, score FROM student
WHERE score >= 60;
```
這是**單表、無 JOIN／GROUP BY／彙總**的簡單 VIEW，一般**可以**透過它更新底層；但若 VIEW 含 JOIN／GROUP BY／彙總函式／DISTINCT 就**通常不可更新**。
</details>

**Q5.** 索引能讓查詢變快，為什麼不把每個欄位都建索引？叢集索引為什麼一張表只能一個？
<details><summary>看解答</summary>

因為索引**占儲存空間**，且每次新增／修改／刪除資料都要一起維護索引 → **寫入變慢**，所以只在常查詢的欄位建。**叢集索引**決定資料的**實體排列順序**，一份資料只能有一種實體順序，故一張表只能有一個叢集索引；非叢集索引是額外的對照表，可以有多個。
</details>
