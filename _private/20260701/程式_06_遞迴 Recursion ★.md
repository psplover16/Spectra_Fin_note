# 遞迴 Recursion ★

> 科目：程式（專業 B）｜遞迴是**常考星號題**。核心一句：**函式呼叫自己**，把大問題拆成「同形式的小問題」。
>
> 學習方式：屬【理解】——先接受「函式可以呼叫自己」，再抓住**兩個必要元素**（終止條件＋遞迴呼叫）。factorial、Fibonacci、O(2ⁿ)、call stack 都是考點。範例以 Java 為主。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 一個遞迴函式**一定要有**哪兩個東西？少了其中一個會怎樣？
> 2. 用遞迴算 `factorial(4)`（4 的階乘）等於多少？它怎麼一步步展開？
> 3. 直接用遞迴算 Fibonacci，時間複雜度是多少？為什麼那麼慢？

先想想再往下。

---

## 🤔 先想想

- 遞迴像**俄羅斯娃娃**：打開一個，裡面還有一個一模一樣但更小的，一直打開，直到最小那個**打不開**（那就是終止條件）。
- 每個遞迴函式都在做兩件事：**「這是不是最小情況？」**（是→直接回答）和**「不是的話，把問題縮小一點、再叫自己一次」**。
- 遞迴很優雅，但每叫自己一次都會**佔一格記憶體**（call stack）。忘了設終止條件，就會一直疊、疊到爆（stack overflow）。

---

## 📖 觀念拆解

### 一、遞迴是什麼？

遞迴是一個**函式呼叫自己**，將大問題拆成**同樣形式的小問題**，直到小到可以直接回答。

比喻：**俄羅斯娃娃**一層層打開，直到最小那個不能再打開。

### 二、兩個必要元素　【務必都有】

| 元素 | 意思 |
|---|---|
| 終止條件 Base Case | 小到不用再遞迴，可直接回答；**少了會 stack overflow** |
| 遞迴呼叫 Recursive Case | 把問題縮小一點，呼叫自己處理更小子問題 |

兩者缺一不可——只有遞迴呼叫沒終止條件＝無限遞迴；只有終止條件沒遞迴呼叫＝根本沒在遞迴。

### 三、階乘 Factorial

`n! = n × (n−1) × ... × 1`；遞迴定義是 **`0! = 1`（終止條件），`n! = n × (n−1)!`（遞迴呼叫）**。

`factorial(4)` 會一路展開到 `factorial(0) = 1`，再往回乘成 **24**。

```java
int factorial(int n) {
    if (n == 0) return 1;          // 終止條件 base case：0! = 1
    return n * factorial(n - 1);   // 遞迴呼叫：n! = n × (n-1)!
}
```

展開追蹤（factorial(4)）：

```
factorial(4) = 4 × factorial(3)
             = 4 × (3 × factorial(2))
             = 4 × (3 × (2 × factorial(1)))
             = 4 × (3 × (2 × (1 × factorial(0))))
             = 4 × (3 × (2 × (1 × 1)))   ← 碰到終止條件 0! = 1，開始往回乘
             = 4 × 3 × 2 × 1 = 24
```

### 四、Fibonacci（費氏數列）

`F(0) = 0，F(1) = 1，F(n) = F(n−1) + F(n−2)`。

直接遞迴 Fibonacci 會**重複計算**，時間複雜度是 **O(2ⁿ)**，實務常改用**迴圈**或 **memoization（記憶化）**。

```java
int fib(int n) {
    if (n == 0) return 0;              // 終止條件
    if (n == 1) return 1;              // 終止條件
    return fib(n - 1) + fib(n - 2);   // 遞迴呼叫
}
```

為什麼是 O(2ⁿ)？因為 `fib(5)` 要算 `fib(4)+fib(3)`，`fib(4)` 又算 `fib(3)+fib(2)`……同一個 `fib(3)` 被算好幾次，重複量爆炸成長。改善方式是用迴圈由小往大算，或用陣列記住算過的值（memoization），可降到 **O(n)**：

```java
// 迴圈版：O(n)
int fibLoop(int n) {
    if (n < 2) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) { int t = a + b; a = b; b = t; }
    return b;
}
```

📌 **另一經典遞迴題——河內塔（Tower of Hanoi）：** 把 n 個盤子從 A 借 B 移到 C，需 **2ⁿ − 1** 次移動，時間複雜度也是 **O(2ⁿ)**，是遞迴的招牌考題。

### 五、遞迴 vs 迴圈與 call stack

| 比較 | 遞迴 | 迴圈 |
|---|---|---|
| 寫法 | 函式呼叫自己 | for/while |
| 可讀性 | 樹、分治等問題較簡潔 | 一般運算直接 |
| 記憶體 | 每次呼叫佔 call stack | 較省記憶體 |
| 速度 | 有函式呼叫開銷 | 通常較快 |

每次遞迴呼叫都把目前狀態**壓入 call stack**；到終止條件後再一層層 `return`。（call stack 是 **LIFO**：後進先出，最後壓進去的最先 return。）

📌 **尾遞迴（tail recursion）：** 若遞迴呼叫是函式的**最後一個動作**（回傳前不需再運算），部分編譯器可優化成迴圈、**不再一直堆疊**（省 call stack）；注意 `return n * factorial(n-1)` **不是**尾遞迴（回來還要再乘 n）。

---

## ✅ 回到題目：解答

1. 一定要有**終止條件（base case）** 與**遞迴呼叫（recursive case）**。少了終止條件會**無限遞迴**，一直壓 call stack 直到 **stack overflow**。
2. `factorial(4) = 4 × 3 × 2 × 1 = 24`。它展開到 `factorial(0) = 1` 後，再一層層往回乘回 24。
3. 直接遞迴 Fibonacci 是 **O(2ⁿ)**，因為 `F(n) = F(n−1) + F(n−2)` 會**重複計算**同一個子問題（例如 fib(3) 被算很多次）；改用迴圈或 memoization 可降到 O(n)。

---

## 📌 重點整理

- 遞迴＝函式呼叫自己，把大問題拆成同形式小問題（俄羅斯娃娃）。
- **兩要素缺一不可**：終止條件（base case）＋遞迴呼叫（recursive case）；少終止條件 → stack overflow。
- 階乘：`0! = 1`，`n! = n × (n−1)!`；`factorial(4) = 24`。
- Fibonacci：`F(0)=0, F(1)=1, F(n)=F(n−1)+F(n−2)`；**直接遞迴 O(2ⁿ)**，改迴圈/memoization 到 O(n)。
- 遞迴 vs 迴圈：遞迴簡潔但佔 call stack、有呼叫開銷；迴圈省記憶體、通常較快。
- call stack 是 **LIFO**：每次呼叫壓入，碰到終止條件後一層層 return。

---

## ⚠️ 常見陷阱

- **忘了終止條件**：直接無限遞迴 → stack overflow（考試最愛問）。
- **終止條件寫錯位置/條件**：例如只寫 `n == 1` 又沒處理 0，可能少算或爆掉。
- **以為遞迴一定比較快**：通常**較慢**（有函式呼叫開銷）且更耗記憶體（call stack）。
- **直接遞迴 Fibonacci 很慢**：O(2ⁿ) 因重複計算；要記得「改迴圈或 memoization」這個標準答案。
- **call stack 方向**：是 LIFO，最後壓入的最先 return（一層層倒著回來）。

<details><summary>看解答</summary>

`0! = 1`（終止條件），`n! = n × (n−1)!`（遞迴）。factorial(4) = 4 × 3 × 2 × 1 = **24**（展開到 factorial(0)=1 再往回乘）。
</details>

**Q3.** 直接遞迴版 Fibonacci 的時間複雜度是多少？為什麼？怎麼改善？
<details><summary>看解答</summary>

**O(2ⁿ)**。因為 `F(n) = F(n−1) + F(n−2)` 會**重複計算**同一子問題。改善：用**迴圈**由小往大算，或用 **memoization** 記住算過的值，降到 O(n)。
</details>

**Q4.** 為什麼遞迴通常比迴圈耗記憶體、也可能較慢？
<details><summary>看解答</summary>

因為**每次遞迴呼叫都會把當前狀態壓入 call stack**（佔記憶體），且函式呼叫本身有開銷；迴圈用 for/while 不需一直堆疊，較省記憶體、通常較快。
</details>

**Q5.** call stack 的運作順序是先進先出還是後進先出？
<details><summary>看解答</summary>

**後進先出（LIFO）**。每次呼叫把狀態壓入堆疊，碰到終止條件後，最後壓入的最先 return，一層層往回。
</details>
