# I/O 中斷方式 與 硬體保護(I/O and Interrupts)

> 科目：計算機概論 · 作業系統｜這章解決兩個問題：**慢速裝置好了，CPU 怎麼知道、資料由誰搬**（三種 I/O 方式），以及**多工系統怎麼防止程式亂搞**（三種硬體保護）。兩組各三項，是選擇題的高頻對應題。
>
> 學習方式：三種 I/O 的「效率高低與 CPU 插手程度」屬【理解】；中斷分類與三種保護的對應機制屬【硬背】，用一句口訣就能扣住。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 「搬**大量資料**（如整塊磁碟）時，最省 CPU 的 I/O 方式是 **Polling、Interrupt 還是 DMA**？」
> 2. 「**除以零** 觸發的中斷，屬於外部還是內部？是 Trap 還是 Fault？」
> 3. 「要防止使用者程式**無窮迴圈霸佔 CPU**，靠的是哪一種硬體保護？」

先想想再往下看。

---

## 🤔 先想想

- I/O 三方式的差別，抓兩個問題就好：「**CPU 怎麼知道裝置好了**」「**誰負責搬資料**」。
- 中斷分類先問「**是別人打斷我，還是我自己惹的？**」——外部/內部就分出來了。
- 三種保護各對一個硬體機制：**指令、位址、時間**各管一項。

---

## 📖 觀念拆解

### 一、I/O 中斷方式：Polling / Interrupt / DMA

核心問題是：慢速裝置準備資料很慢，**CPU 要如何知道裝置好了，以及資料由誰搬**。三種做法效率一個比一個好。

| | Polling 輪詢 | Interrupt 中斷 | DMA |
|---|---|---|---|
| CPU 怎麼知道裝置好了 | 自己一直問 | 裝置發中斷 | DMA 搬完才中斷 |
| 誰搬資料 | CPU 親自 | CPU 親自 | DMA 控制器 |
| 中斷次數 | 無，但一直忙碌等待 | 每筆一次 | 整塊只一次 |
| CPU 浪費 | 最多 | 中等 | 最少 |
| 適合 | 少量、簡單 | 中量、互動 | 大量資料，例如磁碟/網路 |

📌 **白話比喻（等外送）：**
1. **Polling**：你每 10 秒開門看外送到了沒——門口沒人也一直跑（忙碌等待），最浪費時間。裝置就緒後還得 **CPU 親自搬**資料。
2. **Interrupt**：你先做別的事，外送員**按門鈴（發中斷）**你才去開門。CPU 收到中斷後，先查**中斷向量表（Interrupt Vector Table）** 找到對應的 **ISR（中斷服務程式）** 位址再執行，處理完再回原工作；但每一筆仍是 CPU 親自搬。
3. **DMA**：你請**管家（DMA 控制器）**去簽收並把貨**整批**搬進屋，全部搞定才跟你說一聲（只中斷一次）。CPU 只需先設定「來源、目的、大小」。

📌 **Cycle Stealing（週期竊取）：** DMA 搬資料時要用記憶體匯流排，會向 CPU「借」幾個匯流排週期；此時 CPU 暫時不能存取記憶體，但仍可執行不碰記憶體的運算，故整體仍比 CPU 親自搬省很多。

一句話記：**效率 Polling < Interrupt < DMA；CPU 插手程度也是 Polling 最多、DMA 最少。**

### 二、中斷類型

判斷主軸：**外部中斷是別人打斷，跟程式執行「非同步」；內部中斷是自己造成，跟目前指令「同步」。**

| 類型 | 來源 | 同步? | 例子 |
|---|---|---|---|
| 外部－可遮罩 | 外部裝置 | 非同步 | 鍵盤、I/O 完成、計時器 |
| 外部－NMI | 外部嚴重事件 | 非同步 | 電源失效、硬體故障、記憶體錯誤 |
| 內部－Trap | 程式故意觸發 | 同步 | 系統呼叫、除錯中斷點 |
| 內部－Fault | 指令出錯 | 同步 | 除以零、page fault、非法指令 |

- **可遮罩 vs NMI**：一般外部中斷可以被暫時「遮罩（先不理）」；**NMI（Nonmaskable Interrupt）** 緊急到不准忽略，像電源失效。
- **Trap vs Fault**：Trap 是程式**故意**觸發（例如呼叫 OS 服務、下中斷點）；Fault 是指令**出錯**（除以零、存取不在記憶體的頁 page fault）。

### 三、硬體保護

多工／多人系統要防止一個程式搞壞 OS 或別人的資料。共同精神是：**危險動作只准 OS 在核心模式執行，硬體負責把關，出事就 trap 給 OS。**

📌 **底層靠雙模式（Dual-mode）把關：** 硬體用一個 **mode bit** 標示目前是**使用者模式**還是**核心模式**；**特權指令**（下 I／O、設定 Timer、改 Base／Limit 等）只能在**核心模式**執行，使用者程式擅自執行就 trap 給 OS。system call 會把模式切到核心、由 OS 代勞後再切回。

| 保護 | 防止什麼 | 硬體機制 |
|---|---|---|
| I/O Protection | 程式亂下 I/O 指令，搞亂裝置或偷資料 | I/O 指令設成特權指令；使用者程式透過 system call 請 OS 代勞 |
| Memory Protection | 程式讀寫到別人或 OS 的記憶體 | Base + Limit 界定合法範圍，每次存取都檢查位址 |
| CPU Protection | 程式無窮迴圈、霸佔 CPU 不放 | Timer 時間到就中斷，OS 收回 CPU 重新排程 |

📌 **一句話記法：I/O 靠特權指令，Memory 靠 Base/Limit，CPU 靠 Timer。**

具體例子（Memory Protection）：若 Base = 1000、Limit = 500，合法範圍是位址 **1000 ～ 1499**。程式想存取 1600 時，硬體一比對「超出 Base+Limit」就 trap 給 OS，擋下越界。

---

## ✅ 回到題目：解答

1. **搬大量資料最省 CPU？** → **DMA**。CPU 只設定來源/目的/大小，交給 DMA 控制器整塊搬，完成才**中斷一次**，CPU 浪費最少。
2. **除以零的中斷？** → **內部中斷－Fault**（指令執行出錯而產生，與目前指令同步）。
3. **防止無窮迴圈霸佔 CPU？** → **CPU Protection，用 Timer**：時間到就中斷，OS 收回 CPU 重新排程。

---

## 📌 重點整理

- I/O 三方式效率：**Polling < Interrupt < DMA**；CPU 插手：**Polling 最多、DMA 最少**。
- 誰搬資料：Polling／Interrupt 都是 **CPU 親自**；DMA 是 **DMA 控制器**，整塊只中斷一次。
- 中斷分類：**外部（可遮罩、NMI）非同步、別人打斷**；**內部（Trap、Fault）同步、自己造成**。
- 三種保護一句話：**I/O→特權指令、Memory→Base/Limit、CPU→Timer**。

---

## ⚠️ 常見陷阱

- **DMA 也會中斷**：別以為「DMA 就沒中斷」。它是**整塊搬完只中斷一次**，不是完全不中斷。
- **Trap vs Fault 別反**：**Trap 是故意的**（system call、中斷點）；**Fault 是出錯**（除以零、page fault、非法指令）。
- **同步/非同步搞反**：**內部**中斷跟目前指令**同步**（自己造成）；**外部**中斷**非同步**（隨時被打斷）。
- **保護對應機制別張冠李戴**：CPU 保護是 **Timer**（不是 Base/Limit）；記憶體保護才是 **Base/Limit**。
- **NMI 不可被遮罩**：可遮罩中斷可以「先不理」，NMI（電源失效等）不行。

## 📝 練習題（含解答）

**Q1.** Polling、Interrupt、DMA 依「CPU 浪費由多到少」排序。
<details><summary>看解答</summary>

**Polling（最多）＞ Interrupt（中等）＞ DMA（最少）**。效率則相反：DMA 最好。
</details>

**Q2.** DMA 搬完一整塊資料會中斷幾次？資料是誰搬的？
<details><summary>看解答</summary>

**只中斷一次**（搬完才通知 CPU）；資料由 **DMA 控制器**搬，不是 CPU。CPU 只負責設定來源、目的與大小。
</details>

**Q3.** 下列各屬哪種中斷（外部/內部、可遮罩/NMI/Trap/Fault）？(a) 鍵盤輸入 (b) 電源失效 (c) 系統呼叫 (d) page fault
<details><summary>看解答</summary>

(a) 外部－可遮罩；(b) 外部－NMI；(c) 內部－Trap（故意觸發）；(d) 內部－Fault（指令存取出錯）。
</details>

**Q4.** 某程式的 Base = 2000、Limit = 300，它想存取位址 2400，硬體會怎麼處理？
<details><summary>看解答</summary>

合法範圍是 2000 ～ 2299（Base 到 Base+Limit−1）。**2400 超出範圍**，硬體會 **trap 給 OS**，阻止越界存取。這是 Memory Protection。
</details>

**Q5.** 為什麼 I/O 指令要設成「特權指令」？使用者程式想做 I/O 該怎麼辦？
<details><summary>看解答</summary>

避免使用者程式亂下 I/O 指令搞亂裝置或偷別人資料。使用者程式要做 I/O 時，透過 **system call 請 OS 代勞**，由 OS 在核心模式執行。
</details>
