# SQL 三大指令分類（DDL／DML／DCL＋TCL）

> 科目：資料庫｜SQL 章節的**開場地圖**，也是選擇題與名詞辨析的高頻考點。學會把每個指令「歸到正確的類別」，之後看到任何 SQL 關鍵字，你只要問一句「它動到什麼？」就能歸位。
>
> 學習方式：四大類的**分工邏輯**屬【理解】；哪個指令屬哪一類、以及 `TRUNCATE`／`SELECT` 的歸類爭議屬【硬背】（但有「動到什麼」這個邏輯撐著，很好記）。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 「`TRUNCATE` 指令屬於 **DDL 還是 DML**？它可以 `ROLLBACK` 嗎？」
> 2. 「`GRANT`、`REVOKE` 屬於哪一類 SQL 指令？」
> 3. 「`DELETE`、`TRUNCATE`、`DROP` 三者有什麼差別？」

先別急著往下看答案，試著自己回答看看。

---

## 🤔 先想想

如果一時答不出來，給你一把萬用鑰匙——**看這個指令「動到什麼」**：

- 動到**結構**（表、欄位、索引這些「骨架」）→ 屬 **DDL**。
- 動到**資料**（表裡的一列一列內容）→ 屬 **DML**。
- 動到**權限**（誰能存取）→ 屬 **DCL**；動到**交易**（一組操作的成敗）→ 屬 **TCL**。

帶著「動到什麼」這個問句，我們來拆解。

## 📖 觀念拆解

### 一、SQL 概說與四大分類

**SQL（Structured Query Language，結構化查詢語言）** 是操作關聯式資料庫的**標準語言**。依功能可分為四大類，記憶口訣就是看它「動到什麼」：

```
                    SQL
   ┌──────────┬──────────┬──────────┬──────────┐
  DDL        DML        DCL        TCL
資料定義    資料操作    資料控制    交易控制
 CREATE     INSERT      GRANT      COMMIT
 ALTER      UPDATE      REVOKE     ROLLBACK
 DROP       DELETE                 SAVEPOINT
 TRUNCATE   SELECT
```

| 類別 | 全名 | 功能 | 代表指令 |
|---|---|---|---|
| **DDL** | Data Definition Language 資料定義語言 | 定義／修改資料庫**結構** | CREATE、ALTER、DROP、TRUNCATE |
| **DML** | Data Manipulation Language 資料操作語言 | 對表中的**資料**進行存取 | INSERT、UPDATE、DELETE、SELECT |
| **DCL** | Data Control Language 資料控制語言 | 控制使用者**權限** | GRANT、REVOKE |
| **TCL** | Transaction Control Language 交易控制語言 | 管理**交易** | COMMIT、ROLLBACK、SAVEPOINT |

> 📌 題目常問的「**三大類**」指 **DDL／DML／DCL**；TCL 為交易控制，部分教材另外獨立列出。

🗺️ **章節地圖**：這四類會逐篇展開——分類（本篇）→ 建表與物件（DDL）→ 增刪改查 CRUD（DML）→ 查詢 JOIN／彙總（DML）→ 交易 ACID（TCL）→ NoSQL。先用本篇掌握全貌，再依序深入。

### 二、DDL 資料定義語言（動「結構」）

作用對象：資料庫的**結構（綱要）**。

- `CREATE`：建立物件（表、檢視表、索引等）。
- `ALTER`：修改物件結構（如新增欄位）。
- `DROP`：刪除整個物件（含結構與資料）。
- `TRUNCATE`：清空表中所有資料，但**保留表結構**。

特性：DDL 指令通常會**自動提交（auto-commit）**，執行後即生效。

💡 **新手重點：TRUNCATE 是 DDL（常考陷阱）＋ rollback 細節**
`TRUNCATE` 整批釋放資料頁、速度快、**不可加 WHERE**。關於能不能反悔（rollback）：**考試上一律答「不能 rollback」**（因為它被視為 DDL、會自動提交）；但實務上 **SQL Server、PostgreSQL 在交易中「可」rollback**，Oracle、MySQL 則「不可」。→ 記一句話：「**考試答不能、實務看系統**」。

### 三、DML 資料操作語言（動「資料」）

作用對象：資料表中的**資料（列）**。

- `INSERT`：新增資料列。
- `UPDATE`：修改資料列。
- `DELETE`：刪除資料列（**可加 WHERE、可 rollback**）。
- `SELECT`：查詢資料。

💡 **新手重點：SELECT 的歸類**
多數教材把 `SELECT` 歸於 DML；部分教材獨立為 **DQL（Data Query Language，資料查詢語言）**。兩種說法都要會，作答時可註明「SELECT 屬 DML（部分稱 DQL）」最保險。

### 四、DCL 資料控制 與 TCL 交易控制

**DCL（Data Control Language）—— 控制存取權限**

- `GRANT`：授予權限。
- `REVOKE`：收回權限。

**TCL（Transaction Control Language）—— 管理交易**

- `COMMIT`：確認交易、永久寫入。
- `ROLLBACK`：回復交易至先前狀態。
- `SAVEPOINT`：設定交易內的存檔點，可部分回復。

### 五、DELETE vs TRUNCATE vs DROP（超高頻比較）

| 項目 | DELETE | TRUNCATE | DROP |
|---|---|---|---|
| **類別** | DML | DDL | DDL |
| **作用** | 刪除符合條件的列 | 清空所有列 | 刪除整個表 |
| **WHERE** | 可 | 不可 | 不可 |
| **速度** | 慢（逐列） | 快（釋放資料頁） | 快 |
| **Rollback** | 可 | 考試：不可（實務看系統） | 不可 |
| **觸發器** | 會觸發 | 不觸發 | 不觸發 |
| **自增值重置** | 否 | 是 | — |
| **表結構** | 保留 | 保留 | 移除 |

💡 **本質差異（一句話比喻）**：`DELETE` 逐列刪、**留軌跡**（可回復、會觸發 trigger）；`TRUNCATE` 像「整桶倒掉」、**直接釋放空間**（快但不留逐列軌跡）；`DROP` 連**桶子（表結構）一起丟**。

## ✅ 回到題目：解答

1. **`TRUNCATE` 屬 DDL 還是 DML？可以 `ROLLBACK` 嗎？** → 屬 **DDL**（最常考的陷阱，不是 DML）；因視為 DDL、自動提交，**考試答「不能 rollback」**（實務上 SQL Server／PostgreSQL 可，Oracle／MySQL 不可）。
2. **`GRANT`、`REVOKE` 屬哪一類？** → **DCL（資料控制語言）**，負責授予／收回權限。
3. **`DELETE`／`TRUNCATE`／`DROP` 差別？** → `DELETE` 是 DML、可加 WHERE、可 rollback、保留表結構；`TRUNCATE` 是 DDL、清空全表、不可加 WHERE、考試答不可 rollback、保留表結構；`DROP` 是 DDL、連**表結構一起移除**。

---

## 📌 重點整理

- SQL 四大類（看「動到什麼」）：**DDL 動結構、DML 動資料、DCL 動權限、TCL 控交易**。
- **DDL**：CREATE、ALTER、DROP、TRUNCATE（通常 auto-commit）。
- **DML**：INSERT、UPDATE、DELETE、SELECT（**改動需 `COMMIT` 才永久，未提交前可 `ROLLBACK`**）。
- **DCL**：GRANT、REVOKE。**TCL**：COMMIT、ROLLBACK、SAVEPOINT。
- 「**三大類**」慣指 DDL／DML／DCL，TCL 部分教材另列。
- `DELETE`／`TRUNCATE`／`DROP` 的差異是必背比較表。

---

## ⚠️ 常見陷阱

- **`TRUNCATE` 屬 DDL（不是 DML）**——最常考的陷阱。
- `DELETE` 是 DML、可加 WHERE、可 rollback；`TRUNCATE` 是 DDL、清空全表、**考試答不可 rollback**。
- **`DROP`** 連表結構一起刪除；`TRUNCATE`、`DELETE` 都保留表結構。
- **`GRANT`／`REVOKE` 屬 DCL**；**`COMMIT`／`ROLLBACK` 屬 TCL**，別把兩者混在一起。
- **`SELECT`** 多歸 DML，部分教材稱 DQL；作答註明兩種說法。

## 📝 練習題（含解答）

**Q1.** 下列指令各屬哪一類？`ALTER`、`UPDATE`、`REVOKE`、`SAVEPOINT`。
<details><summary>看解答</summary>

`ALTER`＝**DDL**（改結構）、`UPDATE`＝**DML**（改資料）、`REVOKE`＝**DCL**（收回權限）、`SAVEPOINT`＝**TCL**（交易存檔點）。判斷訣竅：看它「動到什麼」。
</details>

**Q2.** 想清空一張表的所有資料、但保留表結構，且要求速度最快，用哪個指令？它屬哪一類、能加 WHERE 嗎？
<details><summary>看解答</summary>

用 `TRUNCATE`。屬 **DDL**、速度快（整批釋放資料頁）、**不可加 WHERE**（不能只清部分列）。若要「條件式刪除」才用 `DELETE`。
</details>

**Q3.** `DELETE` 與 `DROP` 都能「刪東西」，最關鍵的差別是什麼？
<details><summary>看解答</summary>

`DELETE` 刪的是**資料列**（保留表結構、屬 DML、可加 WHERE、可 rollback）；`DROP` 刪的是**整個表**（連表結構一起移除、屬 DDL、不可 rollback）。一個丟內容、一個連桶子一起丟。
</details>

**Q4.** 為什麼「三大類」通常指 DDL／DML／DCL，而不含 TCL？作答 SELECT 的歸類要注意什麼？
<details><summary>看解答</summary>

因為 TCL（交易控制）在部分教材被獨立看待，傳統「三大類」指 DDL／DML／DCL。`SELECT` 多數歸 **DML**，部分教材獨立為 **DQL**，作答時兩種都提最保險。
</details>

**Q5.** `DELETE` 會觸發 trigger、`TRUNCATE` 不會；為什麼？
<details><summary>看解答</summary>

`DELETE` 是**逐列**刪除、留下逐列軌跡，故會逐列觸發 trigger、可回復；`TRUNCATE` 是**整批釋放資料頁**、不逐列處理，因此**不觸發 trigger**、速度快、還會重置自增值。
</details>
