# 基礎概念

> 科目：網路概論。本篇是網路科的「暖身包」——把最常拿來出選擇題的**基本分類與對比**一次講清楚。
>
> 學習方式：本篇大多屬【理解】，因為都是**有邏輯的兩兩對比**，只要抓住每組「差在哪」就記得住，不用死背（只有 HTTP／HTTPS 的 port 80／443 屬【硬背】）。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 「**LAN、MAN、WAN** 三者是依什麼來區分？由小到大的正確順序是？」
> 2. 「**HTTP** 與 **HTTPS** 分別使用哪個 **port**？兩者最大的差別是什麼？」
> 3. 「**Cookie** 與 **Session** 最大的差別，在於資料存放在哪一端？」

先別急著往下看答案，試著自己回答看看。

---

## 🤔 先想想

這篇沒有難算的東西，重點是**把「對比」看懂**。給你幾個提示，建立直覺：

- 網路的分類方式有很多種（依範圍、依架構、依連接形狀…），這篇幾乎都是「兩兩比一比」——抓住**每組差在哪**就會了。
- 很多概念可以用**生活比喻**理解：社區／城市／國家的範圍、公司分工 vs 街坊互助、發言權令牌…
- HTTP 本身「**記不住你**」（無狀態），那它怎麼知道你已經登入了？想想**瀏覽器**和**伺服器**各自扮演什麼角色，就會懂 Cookie 與 Session 為什麼存在。

帶著這幾點，我們來拆解。

## 📖 觀念拆解

### 一、LAN vs MAN vs WAN（依範圍大小分）　【理解】

這三個是**依「涵蓋地理範圍」大小**來分的網路。用「社區 → 城市 → 跨國」的畫面記最快。

| | LAN 區域網路 | MAN 都會網路 | WAN 廣域網路 |
|---|---|---|---|
| 範圍 | 小（一棟樓、校園、辦公室） | 中（一個城市） | 大（跨城市、跨國） |
| 速度 | 最快、延遲低 | 中 | 相對慢、延遲高 |
| 擁有／管理 | 自己擁有 | 城市／機構 | 多租用電信業者線路 |
| 例子 | 家裡/公司網路 | 城市有線電視網 | 網際網路、企業跨國連線 |

📌 **看懂表裡的白話：**
- 「**延遲**」＝資料一來一回要等多久（越低越即時）。範圍越大，訊號要跑越遠、經過的設備越多，延遲通常越高。
- 為什麼 WAN 要「**租線**」？因為跨城市、跨國的線路你自己拉不起，只能向電信業者（ISP）租。

**記憶：** 範圍 **LAN < MAN < WAN**；範圍越大、速度通常越慢、越要租線。（更小的還有 **PAN 個人區域網路**，如藍牙／穿戴裝置，約數公尺：完整排序 **PAN < LAN < MAN < WAN**。）

> 具體感受一下：你家 Wi-Fi 傳檔案給隔壁房的電腦（LAN）幾乎瞬間；但連到國外網站（WAN）就會明顯感覺「慢半拍」——這就是範圍差異造成的延遲。

### 二、Client-Server vs P2P　【理解】

這是**依「架構」分**：服務是「集中在專門的伺服器」還是「大家互相提供」。

| | 主從式 Client-Server | 點對點 P2P |
|---|---|---|
| 架構 | 有專門伺服器提供服務，用戶端請求 | 每個節點既是 client 又是 server，彼此直接分享 |
| 優點 | 集中管理、安全、易維護 | 無單點故障、成本低、越多人資源越多 |
| 缺點 | 伺服器單點故障、成本高、負載大 | 難管理、安全性差、資源品質不一 |
| 例子 | 網站、郵件伺服器 | BitTorrent、區塊鏈 |

📌 **兩個新手詞：**
- **單點故障（Single Point of Failure）**＝關鍵的那一台一壞，整個服務就停（主從式的伺服器就是這種風險；P2P 沒有，因為大家都一樣，倒幾台其他人照樣運作）。
- **節點（node）**＝網路上的一個裝置／連接點（一台電腦、一支手機都算一個節點）。

> 比喻：**主從式**像「圖書館」——書都在館裡（伺服器），大家去借（請求），館一關就沒書借；**P2P** 像「街坊互相借書」——每個人手上都有書也都能借出，沒有單一的「館」會倒。

### 三、網路拓樸 Topology（Bus / Ring / Star / Mesh）　【理解】

**拓樸（Topology）**＝網路裡的裝置「**怎麼連、排成什麼形狀**」（佈線／連接方式）。下面四種是最常見的形狀。

| 拓樸 | 運作方式 | 優點 | 缺點 |
|---|---|---|---|
| Bus 匯流排 | 全部接在一條主幹線上 | 簡單、省纜線、便宜 | 主幹斷則全網癱；會碰撞；難除錯 |
| Ring 環狀 | 串成一個環，資料沿環傳（常用 token） | 無碰撞、效能穩定 | 一處斷可能整環中斷；加裝置要斷環 |
| Star 星狀 | 全部連到中央節點（hub／switch） | 好管理、單機故障不影響別人、易擴充除錯 | 中央節點單點故障；耗纜線 |
| Mesh 網狀 | 裝置間多重互連（全連接時兩兩直連） | 可靠性最高、多路徑容錯、無單點故障 | 纜線／成本最高、複雜 |

💡 **token（環狀拓樸用）**：一個沿著環一直傳的「**發言權令牌**」，只有拿到 token 的裝置才能送資料 → 所以環狀不會互撞（像會議上「拿到麥克風才能講話」）。

**重點：** Star 是現代最常見（家裡／公司都是接到一台 switch）；Mesh 最可靠但最貴；Bus 的主幹一斷就全倒。

> 算一下成本直覺：若有 4 台裝置要**兩兩直連（全網狀）**，需要的線是 4×3÷2 ＝ **6 條**；星狀只要每台各拉 1 條到中央，共 **4 條**。裝置越多，Mesh 的線數會爆炸成長，這就是它「最可靠但最貴」的原因。

### 四、HTTP vs HTTPS　【理解】＋【硬背】

兩者都是「瀏覽網頁」用的協定，差別在**有沒有加密**。

| | HTTP | HTTPS |
|---|---|---|
| 全名 | HyperText Transfer Protocol | HTTP Secure |
| 加密 | 明文（沒加密，易被竊聽） | 加密（HTTP ＋ SSL/TLS） |
| 安全性 | 低 | 高（加密 ＋ 身分驗證） |
| Port | 80 | 443 |

📌 **白話：**「**明文**」＝資料照原樣送，中途有人攔就直接看得懂（像寄明信片）；**加密**後就算被攔也是一堆亂碼（像寄上鎖的保險箱）。**SSL/TLS** 是負責加密的協定（下一份 03 會細講）。

**一句話：** HTTPS ＝ HTTP ＋ SSL/TLS 加密。（port **80／443** 屬【硬背】，先記這兩個最常用的。）

### 五、Stateless（無狀態）　【理解】

- **定義：** 伺服器**不記得**前一次請求，每個請求都獨立、互不相干。**HTTP 本身就是 stateless。**
- **優點：** 簡單、伺服器不用存狀態、容易擴展（任何一台伺服器都能處理任何請求）、可靠。
- **缺點：** 記不住使用者（每次都像第一次見面），所以要靠 **Cookie／Session** 這類額外機制來記住登入、購物車等狀態。

> 比喻：無狀態的伺服器像個「**失憶的櫃台**」——你每次去都得重新自我介紹。為了不要每頁都重登入，就需要下面的 Cookie／Session 幫忙「貼個名牌」。

### 六、Session vs Cookie　【理解】

兩者都是用來「**幫 stateless 的 HTTP 記住狀態**」，差別在**資料存在哪邊**：

| | Cookie | Session |
|---|---|---|
| 資料存在 | 客戶端（瀏覽器） | 伺服器端 |
| 怎麼運作 | 伺服器發給瀏覽器，之後每次請求自動帶上 | 伺服器給一個 session ID（常透過 cookie 傳），真正資料在伺服器 |
| 安全性 | 較低（在客戶端，可被竄改／竊取） | 較高（資料不在客戶端） |
| 成本 | 不佔伺服器資源 | 佔伺服器資源（伺服器要存） |

**記憶鉤子：** Cookie 存「**客戶端**」、Session 存「**伺服器端**」；常見做法是「用 **Cookie 帶 session ID**」（名牌上只寫一個號碼，真正的資料在櫃台的檔案櫃裡）。

## ✅ 回到題目：解答

1. **LAN／MAN／WAN 依什麼分？順序？** → 依**涵蓋的地理範圍**分；由小到大：**LAN < MAN < WAN**。範圍越大通常速度越慢、越需要向電信業者租線路。
2. **HTTP／HTTPS 的 port 與差別？** → HTTP 走 **port 80**、HTTPS 走 **port 443**。最大差別：**HTTPS ＝ HTTP ＋ SSL/TLS 加密**（HTTP 明文易被竊聽；HTTPS 有加密＋身分驗證）。
3. **Cookie 與 Session 差在哪端？** → **Cookie 存在客戶端（瀏覽器）**、**Session 存在伺服器端**；常見做法是用 Cookie 帶著 session ID。

---

## 📌 重點整理

- **範圍三兄弟**：LAN < MAN < WAN；越大越慢、越要租線。
- **架構**：主從式（集中、好管理、但伺服器有單點故障）vs P2P（去中心、無單點故障、但難管理不安全）。
- **拓樸**：Bus（省但主幹一斷全倒）、Ring（用 token 不碰撞）、Star（最常見、中央是單點故障）、Mesh（最可靠最貴）。
- **HTTP vs HTTPS**：port **80 / 443**；HTTPS ＝ HTTP ＋ SSL/TLS（加密＋驗身分）。
- **Stateless**：HTTP 不記得上一次請求；要靠 Cookie／Session 記狀態。
- **Cookie vs Session**：Cookie 在客戶端、Session 在伺服器端；常用「Cookie 帶 session ID」。

---

## ⚠️ 常見陷阱

- **分類依據別搞混**：LAN／MAN／WAN 是依**範圍**分，不是依速度或某種技術。
- **HTTP vs HTTPS 的 port 別記反**：HTTP＝**80**、HTTPS＝**443**；且 HTTPS 不是全新協定，而是「HTTP ＋ SSL/TLS」。
- **Cookie／Session 存哪端別對調**：Cookie＝**客戶端**、Session＝**伺服器端**。
- **P2P 不是全面比較好**：它沒有單點故障、成本低，但**安全性差、難管理、資源品質不一**——別誤以為 P2P 全面優於主從式。
- **「單點故障」不只在主從式**：星狀（Star）的**中央節點**、匯流排（Bus）的**主幹線**壞掉，同樣會整網癱瘓。

**Q1.** 一間跨國企業要把台北、東京、紐約三地的辦公室網路串起來，這屬於 LAN、MAN 還是 WAN？
<details><summary>看解答</summary>

**WAN（廣域網路）**。跨城市、跨國的連線屬於 WAN，通常要租用電信業者的線路，速度相對慢、延遲較高。
</details>

**Q2.** BitTorrent、區塊鏈屬於主從式還是 P2P？這種架構有什麼優點與缺點？
<details><summary>看解答</summary>

屬於 **P2P（點對點）**。優點：無單點故障、成本低、參與者越多資源越多；缺點：難管理、安全性差、資源品質不一。
</details>

**Q3.** 現代家庭／公司最常見的網路拓樸是哪一種？它的最大風險是什麼？
<details><summary>看解答</summary>

**Star 星狀**（大家都連到一台 hub／switch）。優點是好管理、單機故障不影響別人；最大風險是**中央節點的單點故障**——中央那台一壞，底下全斷。
</details>

**Q4.** 既然 HTTP 是「無狀態（stateless）」的，為什麼你登入網站後換頁不用一直重新登入？
<details><summary>看解答</summary>

靠 **Cookie／Session** 這類額外機制。伺服器給瀏覽器一個 **session ID**（常透過 Cookie 保存），之後每次請求自動帶上，伺服器就能認出「這是剛剛登入的那個人」。
</details>

**Q5.** HTTPS 相較於 HTTP 多了什麼？走哪個 port？
<details><summary>看解答</summary>

HTTPS ＝ **HTTP ＋ SSL/TLS 加密**，多了「加密」與「身分驗證」，走 **port 443**（HTTP 走 80）。所以 HTTPS 被攔截也只是亂碼，較安全。
</details>
