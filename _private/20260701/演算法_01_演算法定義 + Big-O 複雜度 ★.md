# 演算法定義 + Big-O 複雜度 ★

> 科目：演算法｜這是整個資料結構與演算法的**地基**，幾乎每份考卷都會出。定義與 5 條件屬【硬背】，Big-O 判斷屬【理解】——只要抓到「資料量 n 變大時，動作成長多快」這個直覺，選項再怎麼變都能判斷。
>
> 學習方式：5 條件用表格記；Big-O 練到看程式就能講出級距。考試最愛把「定義／5 條件／Big-O 判斷」混在同一題選項裡。

## 🎯 開場題目

> 考題常這樣問：

> 1. 「一個演算法**可以沒有輸入**嗎？**輸出**最少要幾個？」
> 2. 「**3n² + 5n + 100** 的時間複雜度用 Big-O 表示是什麼？」
> 3. 「Big-O 選擇題若沒特別說，通常是在描述**最好**還是**最壞**情況？」

先別急著看答案，試著自己回答看看。

## 🤔 先想想

給你三個提示，幫你建立直覺：

- 演算法是「解決問題的一組**明確、有限**步驟」——關鍵字是明確與有限。
- Big-O **不是在算實際秒數**，而是看資料量 n 變大時，執行次數或額外空間成長得多快。
- 化簡 Big-O 只做一件事：**只留成長最快的那一項，其他全丟**。

帶著這三點，我們來拆解。

## 📖 觀念拆解

### 一、演算法定義與 5 條件　【硬背】

**演算法（Algorithm）** 是解決問題的一組明確、有限步驟。演算法 5 條件是**輸入、輸出、明確性、有限性、有效性**。

| 條件 | 考點 |
|---|---|
| 輸入 Input | 可有 0 個或多個輸入；沒有輸入也可以是演算法。 |
| 輸出 Output | 至少要有 1 個輸出，否則無法得到結果。 |
| 明確性 Definiteness | 每個步驟都要清楚，不可含糊。 |
| 有限性 Finiteness | 有限步驟後必須停止，不能無限迴圈。 |
| 有效性 Effectiveness | 每個步驟都要基本且可實際執行。 |

📌 **白話：** 最常被拿來考的兩個陷阱是——輸入**可以是 0 個**（例如印出固定訊息的程式也算演算法），但輸出**至少要 1 個**（沒有結果就沒意義）。「有限性」則是為什麼「無窮迴圈」不算演算法的原因。

### 二、Big-O 的核心想法　【理解】

1. Big-O 用來描述**執行次數或記憶體使用量隨 n 成長的數量級**。
2. 只保留成長最快的**最高次項**，丟掉常數、係數與低次項。
3. 例如 **3n² + 5n + 100 會化成 O(n²)**。
4. **相加取最高次**；**巢狀迴圈通常相乘**。

常見成長順序（由成長慢到快）：

> **O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)**

📌 **白話：** 為什麼可以丟常數與係數？因為 n 夠大時，n² 這一項會遠遠壓過 5n 與 100。就像比誰跑得快，只看「加速度最猛」的那一位，起跑的一點點差距可以忽略。

### 三、看程式判斷複雜度

| 程式長相 | 複雜度 | 理解方式 |
|---|---|---|
| 固定次數、沒有迴圈 | O(1) | 例如加法、陣列索引存取。 |
| 一層迴圈跑 n 次 | O(n) | 資料量加倍，執行次數約加倍。 |
| 兩層各跑 n 次的巢狀迴圈 | O(n²) | 外層 n 乘內層 n。 |
| 每次把問題減半 | O(log n) | 例如二分搜尋。 |
| 分治且每層處理 n 筆 | O(n log n) | 例如合併排序。 |

📌 **白話：** 判斷訣竅——先數迴圈**層數**與**每層跑幾次**。同層先後執行相加、巢狀相乘；只要看到「每次砍一半」就往 log 想。

### 四、最佳、平均、最壞與空間

1. **最佳 Best Case** 是輸入最有利時的表現。
2. **平均 Average Case** 是一般輸入分布下的表現。
3. **最壞 Worst Case** 是最不利輸入下的上界；**Big-O 選擇題常指這個**。
4. **時間複雜度**看執行次數成長；**空間複雜度**看額外記憶體成長。

常見取捨是 **time-space tradeoff**：想更快可能要用更多空間，想省空間可能會犧牲速度。

📌 **白話：** 同一個演算法，運氣好（最佳）和運氣差（最壞）成本可能差很多；考題沒特別講時，Big-O 預設在講「上界＝最壞」。

📌 **三種漸進符號（常混考）：** **Big-O 是上界**（最壞頂多這麼慢）、**Big-Ω 是下界**（最好至少這麼快）、**Big-Θ 是上下界同級距**（緊界）。題目問「下界」選 **Ω**、問「上下界一致」選 **Θ**。

### 五、逐步範例：把式子與迴圈化成 Big-O

**範例 A（多項式）：** 化簡 T(n) = 3n² + 5n + 100
1. 找最高次項：n²、n、常數 → 最高是 **n²**。
2. 丟掉低次項 5n 與常數 100。
3. 丟掉係數 3。
4. 結果：**O(n²)**。

**範例 B（巢狀迴圈）：**

```java
for (int i = 0; i < n; i++) {        // 外層跑 n 次
    for (int j = 0; j < n; j++) {    // 內層跑 n 次
        sum += arr[i] + arr[j];      // O(1) 動作
    }
}
```

1. 內層 O(1) 動作跑 n 次 → 內層 O(n)。
2. 外層再乘 n 次 → n × n = **n²**。
3. 結果：**O(n²)**。

### 六、常見複雜度速查

| 複雜度 | 名稱 | 典型例子 |
|---|---|---|
| O(1) | 常數 | 陣列用索引取值、一次加法。 |
| O(log n) | 對數 | 二分搜尋。 |
| O(n) | 線性 | 一層迴圈、線性搜尋。 |
| O(n log n) | 線性對數 | 合併排序、快速排序平均情況。 |
| O(n²) | 平方 | 兩層巢狀迴圈、氣泡排序、選擇排序、插入排序。 |
| O(2ⁿ) | 指數 | 窮舉所有子集。 |
| O(n!) | 階乘 | 全排列。 |

## ✅ 回到題目：解答

1. **可以沒有輸入嗎？輸出最少幾個？** → **可以沒有輸入**（0 個或多個都行）；但**輸出至少要 1 個**。
2. **3n² + 5n + 100 的 Big-O？** → **O(n²)**（只留最高次項、丟係數與低次項）。
3. **Big-O 選擇題預設看哪種情況？** → 通常指**最壞（Worst Case）**，也就是上界。

---

## 📌 重點整理

- 演算法 5 條件：**輸入、輸出、明確性、有限性、有效性**；輸入可 0 個、輸出至少 1 個。
- Big-O 化簡：**只留最高次項，丟常數、係數、低次項**；相加取最高次、巢狀相乘。
- 成長順序：**O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)**。
- 「每次砍一半」→ O(log n)；「兩層 n」→ O(n²)；「分治每層 n 筆」→ O(n log n)。
- 沒特別說時，Big-O 指**最壞情況**；時間看執行次數、空間看額外記憶體，兩者常有 tradeoff。

---

## ⚠️ 常見陷阱

- **輸入 vs 輸出別記反**：輸入可以是 0 個，輸出至少要 1 個。
- **係數不能留**：O(2n)、O(3n²) 都是錯寫法，應寫成 O(n)、O(n²)。
- **相加 vs 相乘**：兩段先後執行的迴圈是相加（取最高次）；巢狀迴圈才是相乘。
- **最佳當最壞**：Big-O 選擇題沒特別說時是最壞情況，別拿最佳情況去答。
- **時間 ≠ 空間**：時間複雜度算執行次數，空間複雜度算額外記憶體，兩者要分開看。

## 📝 練習題（含解答）

**Q1.** 一段程式先跑一個「n 次的迴圈」，接著再跑一個「n×n 的巢狀迴圈」，整體時間複雜度是？
<details><summary>看解答</summary>

O(n) 與 O(n²) 相加，取最高次 → **O(n²)**。兩段先後執行是相加，不是相乘。
</details>

**Q2.** 化簡 T(n) = 2n³ + 1000n + 50 為 Big-O。
<details><summary>看解答</summary>

最高次是 n³，丟掉低次項與常數、再丟係數 2 → **O(n³)**。
</details>

**Q3.** 二分搜尋每次把搜尋範圍砍半，時間複雜度是？屬於哪個級距名稱？
<details><summary>看解答</summary>

**O(log n)**，名稱是**對數**。每次資料量減半，砍到剩 1 的次數約為 log₂n。
</details>

**Q4.** 下列哪個成長最快：O(n log n)、O(2ⁿ)、O(n²)？
<details><summary>看解答</summary>

**O(2ⁿ)** 最快（指數）。順序：O(n log n) < O(n²) < O(2ⁿ)。
</details>

**Q5.** 「無窮迴圈、永遠不會停」的程式，違反了演算法 5 條件的哪一個？
<details><summary>看解答</summary>

違反**有限性 Finiteness**——演算法必須在有限步驟後停止。
</details>
