# OS 的結構(Operating System Structure)

> 科目：計算機概論 · 作業系統｜這章談 OS「長什麼樣、怎麼被呼叫」：使用者與程式各自的入口（Command vs System Call）、核心要塞多少東西（單核心 vs 微核心），以及在一台機器上變出多台電腦（Virtual Machine）。
>
> 學習方式：三組都是**對比題**，抓住「誰用、放哪、快慢與穩不穩」的取捨，選擇題就很好處理。

---

## 🎯 開場題目

> 考題常這樣問：
>
> 1. 「`open()`、`fork()` 這類讓程式取得 OS 服務的介面叫什麼？跟使用者在終端機打 `ls`、`cd` 有何不同？」
> 2. 「把大部分 OS 服務移到核心外、只留最必要功能的架構叫什麼？優缺點為何？」
> 3. 「用軟體在一台實體機器上模擬出多台獨立電腦，負責分配硬體資源的元件叫什麼？」

---

## 🤔 先想想

- 進入 OS 服務有兩個入口，差別在**服務對象**：一個給**人**、一個給**程式**。
- 單核心 vs 微核心，只差一件事：**核心裡塞了多少 OS 服務**。塞越多越快但越脆；塞越少越穩但要多花溝通成本。
- 虛擬機器的重點是「**一台變多台、彼此隔離**」，代價是**多一層、會變慢**。

---

## 📖 觀念拆解

### 一、Command（Shell）vs System Call

兩者都是進入 OS 服務的入口，差別在**服務對象不同**：Command 給人用，System Call 給程式用。

| | Command（Shell） | System Call |
|---|---|---|
| 是誰的介面 | 人與 OS | 程式與 OS 核心 |
| 怎麼用 | 使用者打指令 | 程式碼呼叫 |
| 角色 | 解讀指令、轉交 OS 執行 | 請求 OS 提供服務 |
| 例子 | cmd、bash、ls、cd、copy | open()、read()、fork()、exec() |

📌 **白話比喻：** Shell 像**餐廳點餐的服務生**（你用人話點菜，他翻譯給廚房）；System Call 則是**廚房內部的標準單據**（程式直接開單向 OS 要服務）。

Java 小例：你在 Java 呼叫 `new FileInputStream("a.txt")` 讀檔，底層最終會走到 OS 的 **`open()`／`read()` system call**——程式不必自己碰硬碟，交給 OS 代勞：

```java
// 應用程式呼叫函式庫，函式庫再對 OS 發出 system call（open/read）
try (var in = new java.io.FileInputStream("a.txt")) {
    int b = in.read();   // 實際觸發 OS 的 read() system call
}
```

### 二、Kernel vs Microkernel

Kernel（核心）是 OS 最底層的核心程式，管理 CPU、記憶體、裝置、檔案等資源。**單核心與微核心的差別在於：核心裡塞多少 OS 服務。**

| | 單核心 Monolithic | 微核心 Microkernel |
|---|---|---|
| 核心包含 | 全部 OS 服務 | 只留最必要，例如 IPC、基本排程、基本記憶體 |
| 其他服務放哪 | 都在核心內 | 移到核心外，當使用者層服務 |
| 優點 | 執行快、呼叫直接、效率高 | 小、模組化、穩定、易擴充與移植 |
| 缺點 | 龐大，一處出錯易拖垮全系統，難維護 | 服務間靠訊息傳遞，overhead 高、較慢 |
| 例子 | 傳統 UNIX、Linux | Mach、QNX、MINIX |

📌 **記憶鉤子：單核心「全包，快但脆」；微核心「精簡，穩但慢」。**

比喻：單核心像**一間大公司什麼都自己做**，內部溝通快，但某部門出包可能牽連全公司；微核心像**核心只留總機，其餘外包**，某個外包倒了不影響核心，但每件事都要打電話（訊息傳遞）溝通，比較慢。

📌 **另兩種 OS 結構也常入題：分層式（Layered）**——把 OS 切成多層、每層只能呼叫下一層，優點是易於除錯與驗證，缺點是效率較低、分層不易（代表：THE 系統）；**模組化（Modular）**——核心精簡、其餘功能做成可動態載入的模組（如 Linux 的**可載入核心模組 LKM**）。

### 三、Virtual Machine

Virtual Machine（虛擬機器）是用軟體在一台實體機器上模擬出多台獨立的虛擬電腦，每台都以為自己獨佔硬體；**Hypervisor（虛擬機器監視器）** 負責分配實體資源。

📌 **Hypervisor 兩型（常考）：第一型（Type 1／裸機型）** 直接跑在硬體上、不需地主 OS，效能好、多用於伺服器與雲端（如 VMware ESXi、Xen、Hyper-V）；**第二型（Type 2／寄居型）** 跑在地主 OS 之上、像一般應用程式，安裝方便但多一層、較慢（如 VirtualBox、VMware Workstation）。

| Virtual Machine | 內容 |
|---|---|
| 優點 | 隔離性高、資源彈性分配、一機可跑多種 OS、方便測試/開發/部署 |
| 缺點 | 多一層虛擬化造成效能損耗、資源開銷大、實作較複雜 |
| 例子 | VMware、VirtualBox、雲端虛擬主機 |

比喻：一棟大樓（實體機）隔成很多套房（VM），每戶都以為自己有整套水電；**房東（Hypervisor）** 負責把總水電分配給各戶。好處是隔離、彈性；代價是多一層管理、效率略降。

---

## ✅ 回到題目：解答

1. **`open()`/`fork()` 是什麼？** → **System Call**（程式與 OS 核心的介面）。而 `ls`、`cd` 是 **Command（Shell）**——人打的指令，由 shell 解讀再轉交 OS。差別在「**服務對象是程式還是人**」。
2. **服務移到核心外、只留最必要？** → **微核心 Microkernel**。優點：小、模組化、穩定、易擴充/移植；缺點：服務間靠訊息傳遞、overhead 高、較慢。
3. **一台變多台、分配資源的元件？** → 這是 **Virtual Machine**，分配實體資源的是 **Hypervisor（虛擬機器監視器）**。

---

## 📌 重點整理

- **入口二分**：Command（Shell）給**人**、用指令；System Call 給**程式**、用程式碼呼叫（open/read/fork/exec）。
- **核心二分**：單核心全包→**快但脆、難維護**；微核心精簡→**穩、易擴充但較慢**（服務靠訊息傳遞）。
- 微核心核心通常只留：**IPC、基本排程、基本記憶體**。
- **VM**：一機模擬多台、彼此隔離；**Hypervisor** 分配資源；代價是效能損耗與開銷。

---

## ⚠️ 常見陷阱

- **Shell 不是 OS 本體**：Shell 只是「解讀指令、轉交 OS」的介面，真正做事的是核心。
- **Linux 是單核心**：常被誤認模組化就是微核心。Linux 屬**單核心（Monolithic）**；微核心代表是 **Mach、QNX、MINIX**。
- **Windows／macOS 不是純微核心**：兩者其實是**混合核心（Hybrid Kernel）**——效能接近單核心，又借用部分微核心的模組化設計。
- **微核心比較「慢」不是比較「差」**：它換到的是**穩定、模組化、易移植**，慢在於服務間靠**訊息傳遞**。
- **VM 一定有效能損耗**：多一層虛擬化，不可能「零開銷」。

**Q4.** 為什麼單核心「執行快但風險高」？

</details>

</details>
