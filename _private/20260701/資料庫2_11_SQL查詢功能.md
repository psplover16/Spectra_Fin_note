# SQL 查詢功能（JOIN · 彙總 · 子查詢 · 集合運算）

> 科目：資料庫｜SQL 查詢是**申論與實作的高頻考點**。前面正規化為了消除重複，把一份資料拆成好幾張表；查詢時就得靠 **JOIN** 把它們依關聯欄位接回來，再加上**彙總**、**子查詢**、**集合運算**，才算真正會「把資料撈成想要的形狀」。

## 🤔 先想想

- 正規化把資料「拆散」到多張表，所以查詢時**幾乎一定要 JOIN**：想像左表、右表是兩個圓，JOIN 就是決定「要保留哪一塊」。

## 📖 觀念拆解

### 一、JOIN 連接（最重要）

**為什麼需要 JOIN？** 正規化為了消除重複，把資料拆成多張表；查詢時要用 **JOIN** 依「關聯欄位（通常是外來鍵）」把它們**接回來**。

把左表、右表想成兩個部分重疊的圓，**深色部分就是該 JOIN 會保留的列**，交疊處＝兩表對得上的列：

| JOIN 型別 | 保留哪些列 |
|---|---|
| **INNER JOIN** | 只保留兩表**都對得上**的列（交集） |
| **LEFT (OUTER) JOIN** | 左表**全部** ＋ 右表對得上的；對不上補 NULL |
| **RIGHT (OUTER) JOIN** | 右表**全部** ＋ 左表對得上的；對不上補 NULL |
| **FULL (OUTER) JOIN** | 兩表**全部**；對不上的一邊補 NULL |
| **CROSS JOIN** | 笛卡兒積：每列兩兩相配，**無 ON 條件** |

**語法與範例**（員工表 emp 接部門表 dept）：

```sql
SELECT emp.name, dept.name
FROM emp
INNER JOIN dept ON emp.dept_id = dept.id;
```

```sql
SELECT emp.name, dept.name
FROM emp
LEFT JOIN dept ON emp.dept_id = dept.id;
-- 沒部門的員工也會列出，dept.name 顯示 NULL
```

> 💡 **INNER 與 LEFT 差在哪？** 同一筆查詢，**INNER** 會把「對不上的列」丟掉；**LEFT** 會保留左表那些對不上的列（右邊欄位補 NULL）。想「不漏掉左表任何一列」就用 LEFT。

> 💡 **自我連接（Self JOIN）**：一張表**跟自己 JOIN**（用**別名**當成兩張表看待），常用來比較同表的列，如「列出每位員工與其主管」（emp 接 emp）。它不是新的 JOIN 型別，而是把上述 JOIN 套在同一張表。

### 二、彙總函式與 GROUP BY / HAVING

**彙總函式（Aggregate）** 把「一整組列」壓成「一個統計值」：

- `COUNT` 計數、`SUM` 總和、`AVG` 平均、`MAX` 最大、`MIN` 最小。

**GROUP BY（分組）** 與 **HAVING（分組後篩選）** 搭配使用：

```sql
SELECT dept_id, COUNT(*) AS 人數, AVG(salary) AS 平均薪
FROM emp
GROUP BY dept_id
HAVING COUNT(*) >= 3;
```

語意：依 `dept_id` 分組，對每組算人數與平均薪，再只留「人數 ≥ 3」的組。

> 💡 **GROUP BY 規則（常錯）**：`SELECT` 清單裡的**非彙總欄位**，都必須出現在 `GROUP BY` 中，否則語意不明、多數系統會報錯（如 `SELECT dept_id, name, COUNT(*) … GROUP BY dept_id` 就不合法，`name` 沒被分組也沒被彙總）。

> 💡 **WHERE 與 HAVING 的差別（必考）**：**WHERE** 在分組**前**逐列篩選（此時還算不出 `COUNT`／`AVG`，故 WHERE **不能**放彙總函式）；**HAVING** 在分組**後**對「每一組」篩選，可用彙總函式。

### 三、子查詢（Subquery）

把一個 **SELECT 巢狀**在另一個查詢裡，常放在 `WHERE`，搭配 `IN`、`EXISTS` 或比較運算子：

```sql
SELECT name FROM emp
WHERE dept_id IN (
  SELECT id FROM dept WHERE name = '研發部'
);
```

語意：先查出「研發部」的部門 id，再撈出屬於這些部門的員工。像「先算出一個清單，再拿這個清單去篩」。

### 四、集合運算

把兩個查詢的結果「上下疊」起來合併：

| 運算 | 意義 |
|---|---|
| **UNION** | 合併兩查詢結果，**去除重複** |
| **UNION ALL** | 合併但**保留重複**（較快） |
| **INTERSECT** | 交集（兩邊都有的列） |
| **EXCEPT**（Oracle 為 **MINUS**） | 差集（左有右無的列） |

**條件**：上下兩個查詢的**欄位數量與型別需相容**。

```sql
SELECT name FROM emp_taipei
UNION
SELECT name FROM emp_taichung;
```

> 💡 為什麼有 `UNION ALL`？因為「去除重複」要多做一次比對排序，較慢；若你確定沒有重複、或不在意重複，用 `UNION ALL` 較快。

### 五、常用運算子與其他

| 運算子 | 意義 | 例 |
|---|---|---|
| **BETWEEN a AND b** | 範圍（含端點） | `salary BETWEEN 30000 AND 50000` |
| **IN (…)** | 屬於清單之一 | `dept_id IN (1, 2, 3)` |
| **LIKE** | 模糊比對 | `name LIKE '王%'` |
| **IS NULL** | 判斷空值 | `addr IS NULL` |
| **DISTINCT** | 去除重複列 | `SELECT DISTINCT city` |

- **LIKE 萬用字元**：`%` ＝ 任意多個字元、`_` ＝ 剛好一個字元。
- **別名**用 `AS`（給欄位或表取簡名）。

```sql
SELECT name, salary FROM emp
WHERE salary BETWEEN 30000 AND 50000
  AND name LIKE '王%'
  AND dept_id IS NOT NULL;
```

> 💡 **空值不能用 `=` 比**：判斷空值要用 `IS NULL` ／ `IS NOT NULL`，**不能**寫 `= NULL`（因為 `NULL` 代表「未知」，和任何值比較都不成立）。

## ✅ 回到題目：解答

1. **INNER 與 LEFT 差在哪？** → INNER 只保留兩表**都對得上**的列（交集）；LEFT 會保留**左表全部**，右表對不上就補 NULL。想「不漏掉左表任何一列」用 **LEFT JOIN**。
2. **為什麼 WHERE 不能放彙總函式？** → WHERE 在**分組前**逐列篩選，那時還沒分組、算不出 `COUNT`／`AVG`。要對「每組的統計結果」篩選，須用**分組後**的 **HAVING**。
3. **UNION vs UNION ALL？可以寫 `= NULL` 嗎？** → UNION **去除重複**、UNION ALL **保留重複（較快）**；判斷空值只能用 **`IS NULL`**，不能寫 `= NULL`。

## 📌 重點整理

- **JOIN 的用途**：把正規化拆散的表，依關聯欄位（外來鍵）接回來。
- **五種 JOIN**：INNER（交集）、LEFT／RIGHT（保留某一邊全部）、FULL（雙邊全部）、CROSS（笛卡兒積，無 ON）。
- **彙總函式**：COUNT／SUM／AVG／MAX／MIN；配 **GROUP BY** 分組、**HAVING** 分組後篩選。
- **WHERE vs HAVING**：WHERE 分組前（不可用彙總）、HAVING 分組後（可用彙總）。
- **邏輯執行順序**：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY。
- **集合運算**：UNION 去重、UNION ALL 留重、INTERSECT 交集、EXCEPT／MINUS 差集；欄位數與型別要相容。
- **運算子**：BETWEEN（含端點）、IN、LIKE（`%` 多字元、`_` 單字元）、IS NULL、DISTINCT；別名用 AS。

## ⚠️ 常見陷阱

- **WHERE 放彙總函式**是錯的——要用 HAVING。WHERE 分組前、HAVING 分組後。
- **`COUNT(*)` 算列數；`COUNT(欄位)` 不計 NULL**，兩者結果可能不同；`SUM`／`AVG`／`MAX`／`MIN` 也**一律忽略 NULL**，其中 `AVG` 是「總和 ÷ **非 NULL 筆數**」（不是除以總列數）。
- **UNION 會去重、UNION ALL 保留重複**，別記反；差集在 Oracle 叫 **MINUS**（不是 EXCEPT）。
- **判斷空值用 `IS NULL`**，寫 `= NULL` 永遠不成立（NULL 是「未知」）。
- **LIKE 的 `%` 是任意多字元、`_` 是單一字元**，別和其他語言的萬用字元搞混。
- **CROSS JOIN 沒有 ON 條件**，會產生笛卡兒積（列數暴增），通常不是你要的結果。

## 📝 練習題（含解答）

**Q1.** 五種 JOIN 分別保留哪些列？
<details><summary>看解答</summary>

INNER＝兩表都對得上的列（交集）；LEFT＝左表全部＋右表對得上（對不上補 NULL）；RIGHT＝右表全部＋左表對得上；FULL＝兩表全部（對不上補 NULL）；CROSS＝笛卡兒積（每列兩兩相配，無 ON 條件）。
</details>

**Q2.** 想列出「所有員工，即使某員工沒有對應到任何部門」，該用哪種 JOIN？
<details><summary>看解答</summary>

用 **LEFT JOIN**（emp 在左）。左表（emp）全部保留，沒部門的員工其 dept 欄位顯示 NULL；若用 INNER JOIN 會把沒部門的員工丟掉。
</details>

**Q3.** 為什麼 `WHERE COUNT(*) >= 3` 是錯的？正確該怎麼寫？
<details><summary>看解答</summary>

WHERE 在**分組前**逐列篩選，那時還沒分組、算不出 `COUNT(*)`，所以不能在 WHERE 放彙總函式。應改用**分組後**的 HAVING：`GROUP BY dept_id HAVING COUNT(*) >= 3`。
</details>

**Q4.** `UNION` 和 `UNION ALL` 差在哪？哪個較快？
<details><summary>看解答</summary>

UNION 會**去除重複**列；UNION ALL **保留重複**。因為 UNION 要多做去重（比對），所以 **UNION ALL 較快**。兩者都要求上下查詢的欄位數量與型別相容。
</details>

**Q5.** `LIKE '王%'` 與 `LIKE '王_'` 差在哪？判斷欄位是否為空為什麼不能用 `= NULL`？
<details><summary>看解答</summary>

`%` 代表任意多個字元，`'王%'` 比對「王」開頭的任意長度字串；`_` 代表剛好一個字元，`'王_'` 只比對兩個字、且第一字是「王」。判斷空值只能用 `IS NULL`／`IS NOT NULL`，因為 NULL 是「未知」，和任何值（含 NULL）用 `=` 比較都不成立。
</details>
