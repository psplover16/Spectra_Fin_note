ANSI/SPARC 三層架構為美國國家標準協會（ANSI）所屬 SPARC 委員會於 1975 年提出。
它將資料庫系統的描述劃分為三個抽象層次，非別為 外部層、概念層、內部層，其核心目的在於達成「資料獨立性」。
採用此架構之目的為: 
一. 資料獨立性：
 將資料之邏輯定義與實體儲存方式分離，使下層之變動不致影響上層，此為最主要之目的。
二. 多重視界：
 同一份資料得針對不同使用者呈現不同之外部視界。
三. 安全與隱私：
 透過外部視界限制使用者僅能存取其權限範圍內之資料。
四. 抽象化與分工：
 隱藏系統複雜性,使資料庫管理師、應用程式設計師與系統各司其職。

三個抽象層次
一. 外部層：
  1. 最接近使用者的觀點，又可稱為 視界層。
  2. 其對象為個別使用者及應用程式設計師。
  3. 其內容為各使用者所見之部分資料庫視界，僅呈現與其相關之欄位與資料。
  4. 其特色為三層中唯一可同時存在多個綱要之層級；透過隱藏不相關之資料而提供安全性，並可使同一份資料以不同方式呈現給不同使用者。
 例如: 學生於選課系統中僅能查詢自身成績，而無法看見其他同學之成績。實作上查已SQL之View達成。
二. 概念層：
  1. 概念層又稱邏輯層。
  2. 其對象為資料庫管理師。
  3. 其內容為 整個資料庫的邏輯結構，包含哪些表、欄位、關係、限制，但不包括實體之存取方式。
  4. 其特色為全資料庫僅有唯一之概念綱要，並整合所有外部視界。
 例如：以實體關係圖描述整體結構，或定義「學生(學號, 姓名, 系所)」此一表格之邏輯內容。
三. 內部層：
  1. 內部層又稱實體層或儲存層。
  2. 其對象為資料庫管理系統及系統程式設計師。
  3. 其內容為資料實際之儲存方式，包括 儲存結構、索引、壓縮、加密。
  4. 其特色為全資料庫僅有唯一之內部綱要，且為三層中最接近實體儲存之層級。
 例如：指定學生資料以 B+ 樹建立索引儲存，或規定特定之檔案配置與壓縮格式。

三層之間以兩個「對應（Mapping）」連接，各提供一種資料獨立性：
1. 外部／概念對應，邏輯資料獨立性，當概念層改變時，不影響外部視觀與應用程式，此種獨立性較難達成。
2. 概念／內部對應，實體資料獨立性，當內部層改變（如更換索引、改變檔案組織）時，不影響概念層。此種獨立性較易達成。

資料庫四種模型
一. 階層式資料庫，
  1. 樹狀，
  2. 一對多，1:N，
  3. 以指標沿樹狀路徑存取。
  4. 結構簡單、查詢快；但無法表達 M:N、結構僵硬、資料易重複。
二. 網路式資料庫，
  1. 圖狀，
  2. 可M:N，
  3. 以指標連結。
  4. 較階層式靈活；但結構更複雜、指標維護困難、程式與結構耦合高。
三. 關聯式資料庫，
  1. 二維表格，
  2. 以「值」（外來鍵）建立表間關聯，而非指標。
  3. 簡單直覺、理論嚴謹、資料獨立性高、查詢彈性強；但複雜關聯需大量 JOIN、不擅長非結構化資料、大規模水平擴展較難。
四. 物件導向式資料庫，
  1. 以物件儲存，
  2. 支援封裝、繼承、多型，每個物件有唯一識別碼。
  3. 直接對應物件導向程式、解決阻抗不匹配、擅長複雜資料；但標準不統一、學習曲線高、市場接受度低。

阿姆斯壯公理
反身律
Y ⊆ X ⇒ X → Y，一個集合可決定它的子集（顯然相依）
擴充律
X → Y ⇒ XZ → YZ，兩邊同時加入屬性，相依仍成立
遞移律
X → Y, Y → Z ⇒ X → Z，相依可串接

屬性閉包，給定一組屬性，從它「能推導出的所有屬性」的集合，就是它的閉包。
怎麼算(演算法)
  零. 核心 = 所有 L(只在左邊) ＋ 都沒出現的
  一. 先把 X 自己放進結果集(任何屬性都能決定自己)
  二. 掃描每一條相依 A → B:如果箭頭左邊 A 已經整組在結果集裡,就把右邊 B 也加進來
  三.重複掃描,只要有新屬性被加入就再掃一輪
直到掃一整輪都沒有新東西加入 → 停,此時的結果集就是 X⁺

正規化: 將原始表格分解，但好的分解有兩大特質
一 無損分解，分解後的表格，用自然合併組回去，結果與原表完全一樣，沒有遺失資料，也沒有多出虛假的資料組合。
 自然合併，以兩表中的同名且同型的欄位為合併條件，把這些欄位值相同的列組合起來，用來合併的同名欄位在結果中只保留一份。
 沒有同名欄位 >>>> 笛卡兒成績
二. 功能相依性保持(最好)，分解前擁有的所有功能相依，於分解後的各子表中仍能保留與檢察。
缺乏相依保持「不會」在分解當下產生虛假資料，但會讓後續的寫入／更新中，某些規則難以驗證與維持。

處理（無法保持時）：(1) 反正規化退回較低正規化（如 3NF）；或 (2) 在應用程式或觸發器（trigger）額外撰寫邏輯，於寫入／更新時檢查。

1NF. 關聯表中每一個屬性的值皆具原子性，也就是非多值、非複合屬性。
 處理方式，多值，分解成多列 或 另立表；複合屬性 則可拆為簡單屬性。
2NF. 
部分相依只可能發生在「複合鍵」主鍵若是單一屬性，沒有「一部分」可被相依，自動滿足 2NF。
 每個非鍵屬性都「完全功能相依」於鍵（即沒有部分相依）。
 處理方式，把部分相依的非鍵屬性，連同其決定因素抽出、建立新關聯（決定因素當新表主鍵），原表刪除該相依因素，並設外來鍵。
3NF. 
非鍵屬性之間不存在功能相依 (也就是 不存在非鍵屬性遞移相依於鍵)
 處理方式：把遞移相依中「非鍵的決定因素＋其相依因素」抽出、建立新關聯，原表刪除相依因素，並設外來鍵。
BCNF，
若一張表只有單一候選鍵（尤其是單一屬性），那它只要是 3NF 就自動是 BCNF。
 要求每一條非顯然功能相依的決定因素皆為超鍵。
 非顯然功能相依，功能相依 X → Y 中,箭頭右邊 Y 至少包含一個不屬於左邊 X 的屬性,稱為非顯然功能相依。
 處理方式；找出違反的函數相依 X → Y（X 非超鍵），將 {X 及 Y} 取出另立新關聯（X 為主鍵），原關聯刪除 Y、保留 X 作為外來鍵。此分解保證無損，但可能犧牲相依保存。

4NF，不存在多值相依。
 多值相依：一個鍵決定某屬性的「一組值」，且該組值與另一獨立屬性互不相干
5NF，不存在無法由候選鍵推得的合併相依。

CREATE TABLE student_profile (
  profile_id  INT           PRIMARY KEY,                         -- 整數＋主鍵
  student_id  CHAR(8)      NOT NULL UNIQUE,                      -- 一欄多約束
  name        VARCHAR(20)  NOT NULL,                             -- 變長文字＋非空
  gender      CHAR(1)      DEFAULT 'F' CHECK (gender IN ('M', 'F')),
  score       DECIMAL(5,2) DEFAULT 0 CHECK (score BETWEEN 0 AND 100),
  birth_date  DATE          NOT NULL,
  created_at  DATETIME      DEFAULT '2026-01-01 09:00:00',
  FOREIGN KEY (student_id) REFERENCES student(id) 
 ON DELETE CASCADE（子表一起刪）、SET NULL（子表設為空）、RESTRICT（禁止刪除）。
);
