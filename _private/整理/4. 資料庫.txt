ANSI/SPARC
一、 核心概念
ANSI/SPARC 是一種三層式資料庫架構，核心目的在於將「使用者應用程式」與「實體資料儲存」完全分離，藉此達成「資料獨立性」（Data Independence）。
二、 三層架構解析
由上（使用者端）至下（實體儲存端）劃分為三層：
  1. 外部層 (External Level / View Level)，又稱「視界層」。
    最接近使用者。僅呈現特定使用者所需要的局部資料，隱藏其餘無權或不須知道的部分，以簡化操作並提升安全性。
  2. 概念層 (Conceptual Level / Logical Level)，又稱「邏輯層」。
    描述整個資料庫的邏輯全貌（包含資料實體、關聯性與限制條件）。它整合了所有外部需求，隱藏底層儲存細節，通常由資料庫管理員 (DBA) 負責設計。
  3. 內部層 (Internal Level / Physical Level)，又稱「實體層」。
    最接近硬體。描述資料在磁碟上的實際儲存方式，包含檔案結構、資料壓縮、存取路徑與索引技術，以追求系統效能最佳化。
三、 兩層對應 (Mapping) 與資料獨立性
系統透過層與層之間的「對應機制」來達成資料獨立性：
  1. 外部/概念對應 (External/Conceptual Mapping)
    欲達成目標為「邏輯資料獨立性」。
    當「概念層」的邏輯結構發生變更（如新增資料表或欄位）時，只需修改此對應關係，使用者的「外部層」與應用程式皆無須修改。
  2. 概念/內部對應 (Conceptual/Internal Mapping)
    欲達成目標為「實體資料獨立性」。
    當「內部層」的實體儲存結構變更（如更換儲存設備、更改索引方式）時，只需修改此對應關係，「概念層」與「外部層」皆無須修改。此種獨立性較易達成。

資料庫優缺點及種類：
一. 資料庫問世前，資料分散儲存於各應用程式的獨立檔案中，造成資料重複與不一致；資料庫系統將資料集中管理，以解決上述問題。
二. 優缺點
  優點
    1. 降低資料重複（Reduce Redundancy）：資料集中存放，避免同一資訊重複儲存。
    2. 維持資料一致性（Consistency）：減少重複，即降低前後不一致的風險。
    3. 資料共享（Data Sharing）：多使用者、多應用程式可同時存取同一份資料。
    4. 維護資料完整性（Integrity）：以完整性限制（如鍵、CHECK）確保資料正確。
    5. 強化安全性（Security）：以權限控管限制不同使用者的存取範圍。
    6. 提供資料獨立性（Data Independence）：分為邏輯與實體獨立性（見講義 01）。
    7. 備份與復原（Backup & Recovery）：故障後可回復至一致狀態。
    8. 並行控制（Concurrency Control）：多使用者同時操作而不互相破壞。
  缺點：
    1. 成本高：軟硬體、授權費用與專業人員（DBA）成本可觀。
    2. 系統複雜：設計、調校與維護需要專業知識。
    3. 效能負擔（Overhead）：為兼顧安全、一致與並行控制，會犧牲部分效能。
    4. 集中化風險：資料集中導致單點故障（Single Point of Failure），一旦損毀影響範圍大。
三. 種類
  1. 階層式資料庫，
    1. 樹狀，
    2. 一對多，1:N，
    3. 以指標沿樹狀路徑存取。
    4. 結構簡單、查詢快；但無法表達 M:N、結構僵硬、資料易重複。
  2. 網路式資料庫，
    1. 圖狀，
    2. 可M:N，
    3. 以指標連結。
    4. 較階層式靈活；但結構更複雜、指標維護困難、程式與結構耦合高。
  3. 關聯式資料庫，
    1. 二維表格，
    2. 以「值」（外來鍵）建立表間關聯，而非指標。
    3. 簡單直覺、理論嚴謹、資料獨立性高、查詢彈性強；但複雜關聯需大量 JOIN、不擅長非結構化資料、大規模水平擴展較難。
  4. 物件導向式資料庫，
    1. 以物件儲存，
    2. 支援封裝、繼承、多型，每個物件有唯一識別碼。
    3. 直接對應物件導向程式、解決阻抗不匹配、擅長複雜資料；但標準不統一、學習曲線高、市場接受度低。
      (阻抗不匹配，物件導向程式的「物件」與關聯式的「表格」結構不一致，存取時須來回轉換)

基礎
一. 鍵（Key）是用來唯一識別關聯表中某一列（tuple／紀錄）的欄位或欄位組合。
  1. 超鍵(Superkey)能唯一識別資料表中每一筆紀錄的欄位集合（可能包含多餘欄位）。
  2. 候選鍵(Candidate Key) 具備「最小性」的超鍵（不含多餘欄位）
  3. 主鍵(Primary Key) 設計者從「候選鍵」中挑選出一個，作為代表該表唯一識別的鍵（絕對不可為 NULL）。
  4. 替代鍵(Alternate Key) 未被選為主鍵的其餘「候選鍵」。
  5. 外來鍵(Foreign Key)用來參照另一個資料表主鍵的欄位，目的是建立兩表關聯，並確保「參考完整性」。
  6. 複合鍵(Composite Key) 由「兩個或兩個以上」欄位所組合而成的鍵。
二.
主屬性（Prime Attribute）屬於某個候選鍵的屬性
非主屬性（Non-prime Attribute）：不屬於任何候選鍵的屬性
---------------------------------------------------------------------------
阿姆斯壯公理
反身律
Y ⊆ X ⇒ X → Y，一個集合可決定它的子集（顯然相依）
擴充律
X → Y ⇒ XZ → YZ，兩邊同時加入屬性，相依仍成立
遞移律
(X → Y、Y → Z) ⇒ X → Z

資料庫設計概念：
A. 實體關聯模型(ERD)：
  1. 實體：資料庫要儲存的對象
    1. 實體：矩形(橢圓邊的長方形)
    2. 弱實體：雙線矩形，需依附其他實體。 ex. 公司人員分布表中，員工家屬
  2. 屬性：描述實體的特徵
    1. 一般屬性：橢圓
    2. 多值屬性：雙線橢圓，ex. 電話
    3. 導出屬性：虛線橢圓，可由其他值推算 ex. 年齡
    4. 主鍵屬性：橢圓內的文字加底線。
  3. 關係：實體與實體之間的關聯
    1. 關係：菱形，實體間的關聯
    2. 識別關係：雙線菱形，連接弱實體
----
B. 轉換成 關聯表的規則：
  一. 實體：
    1. 強實體：直接轉換成一個獨立的資料表。實體中的屬性變成欄位，原本的鍵值屬性(主屬性，組成候選鍵的欄位)變成該表的主鍵。
    2. 弱實體：轉換成資料表，但它的主鍵必須由「自己的部分鍵 (Partial Key)」加上「所依附之強實體的主鍵」合併組成（複合主鍵）。
      ex. 員工眷屬表：員工編號、眷屬姓名 兩者複合主鍵，員工編號是外鍵
  二. 屬性：
    1. 單值屬性：直接變成資料表的欄位。
    2. 複合屬性：必須拆解成獨立欄位。例如：「地址」不該是一個欄位，要拆成「縣市」、「區」、「街道」等三個欄位。
    3. 多值屬性：必須為它建立一個「新的資料表」，新表的主鍵由「原實體的主鍵」加上「多值屬性本身」共同組成。
    4. 衍生屬性：通常不存入資料庫中（例如：「年齡」可由「生日」計算得出）。
  三. 關係：
    1. 1:1：將其中一方的主鍵 (PK) 放入另一方作為外鍵 (FK)
    2. 1:N：永遠將「1」那一方的主鍵，放進「N」那一方的資料表中作為外鍵。
      ex. 顧客表：訂單表
    3. M:N：必須建立一張新的「中介表」。將兩方的主鍵都拉進這張新表作為外鍵，且這兩個外鍵通常會共同組成新表的複合主鍵。
      ex. 專案表(專案代號、專案名稱)-一個專案可以有很多員工參與，一個員工也能參與多個專案。
        所以需要 參與專案表，(員工編號、專案代號)都是主鍵
----
C. 界定功能相依性：將文字轉化為嚴謹的FD方程式，利用箭頭表示 一對一 或 一對多的關係
ex. FD1(小寫1): 醫生代號 → {姓名, 診間號碼}，表示醫生代號決定 姓名、診間號碼
----
D. 推導各表的候選鍵(利用屬閉包，把每一個表的候選鍵都選出來)
屬性閉包，給定一組屬性，從它「能推導出的所有屬性」的集合，就是它的閉包。
若一個屬性 K 在關係 R 的閉包 K^+ 包含 R 的所有屬性，且其任何真子集（Proper Subset）的閉包都不包含所有屬性，則 K 稱為候選鍵。
ex. 資料表 R(A,B,C,D,E,F)，函數相依集F(A>B,B>C,AC>D)。計算屬性集合 {A}的閉包，求A^+ ?
ABCD
----
正規化檢驗：
一. 好的正規化特質：
  1. 無損分解，分解後的表格，用自然合併組回去，結果與原表完全一樣，沒有遺失資料，也沒有多出虛假的資料組合。
    * 自然合併，以兩表中的同名且同型的欄位為合併條件，把這些欄位值相同的列組合起來，用來合併的同名欄位在結果中只保留一份。
  2. 功能相依性保持(最好)，分解前擁有的所有功能相依，於分解後的各子表中仍能保留與檢察。
    * 缺乏相依保持「不會」在分解當下產生虛假資料，但會讓後續的寫入／更新中，某些規則難以驗證與維持。
    * 處理（無法保持時，以下擇一處理）：
      (1) 反正規化退回較低正規化（如 3NF）；
      (2) 在應用程式或觸發器（trigger）額外撰寫邏輯，於寫入／更新時檢查。
二. 正規化階梯：
  * 1NF. 關聯表中每一個屬性的值皆具原子性(不可再分得基元值)，也就是非多值、非複合屬性。
      處理方式，多值，分解成多列 或 另立表；複合屬性 則可拆為簡單屬性。
  * 2NF. 
      1. 消除非鍵屬性對主鍵的部分功能相依，確保所有非鍵屬性皆完全相依於整個（複合）主鍵。
      2. 自動符合的情況：
        1. 主鍵只有一個欄位，自動符合。
        2. 沒有非主鍵欄位，自動符合。 
      3. 處理方式，把部分相依的非鍵屬性，連同其決定因素抽出、建立新關聯（決定因素當新表主鍵），原表刪除該相依因素，並設外來鍵。
  * 3NF. 
      1. 消除非鍵屬性對鍵的遞移功能相依（每一個非鍵屬性，都只能直接依賴主鍵，不能依賴其他非鍵屬性）
      2. 自動符合：
        1. 最多只有「一個」非主鍵欄位，自動符合。
        2. 沒有非主鍵欄位（全表皆為主鍵），自動符合。
      3. 處理方式：把遞移相依中「非鍵的決定因素＋其相依因素」抽出、建立新關聯，原表刪除相依因素，並設外來鍵。
  * BCNF，
    1. 確保每一條非顯然功能相依的決定因素，皆為超鍵。(所有的功能相依（箭頭左邊）皆為該表的候選鍵)
        非顯然功能相依，功能相依 X → Y 中,箭頭右邊 Y 至少包含一個不屬於左邊 X 的屬性,稱為非顯然功能相依。
    2. 自動符合
      1. 若一張表只有單一候選鍵（尤其是單一屬性），那它只要是 3NF 就自動是 BCNF。
      2. 資料表總共只有兩個欄位
    3. 處理方式；找出違反的函數相依 X → Y（X 非超鍵），將 {X 及 Y} 取出另立新關聯（X 為主鍵），原關聯刪除 Y、保留 X 作為外來鍵。此分解保證無損，但可能犧牲相依保存。
  * 4NF，不存在多值相依。
   多值相依：一個鍵決定某屬性的「一組值」，且該組值與另一獨立屬性互不相干
  * 5NF，消除合併相依，確保資料表不能再被無損分解為更小的表。
三. 反正規化：
  1. 正規化的缺點：
    1. 查詢效能低落，高度正規化會將資料過度拆解至多張表，當程序需要檢視完整資訊時，需要大量表格連接(join)，會造成查詢速度變慢。
    2. 系統結構過度複雜，過度拆解很容易造成，會導致開發與維護成本大幅提升。
  2. 使用時機：
    1. 讀取時機多、但寫入時機少；
    2. 需要頻反存取"衍生欄位"，比如訂單系統的總金額，若嚴格遵守，每次查詢動態計算，太耗費資源。

資料庫物件
1. 表格 (Table)：資料庫中最基本、用來實體儲存資料的二維結構，由「欄位 (Column)」與「資料列 (Row)」組成。
-- 建立一個名為「員工表」的表格，包含編號、姓名與薪水欄位
CREATE TABLE Employees (
    -- 欄位名稱 | 型別 | 其他
    EmpID INT PRIMARY KEY, -- EmpID 是欄位名稱 | INT 代表整數 | PRIMARY KEY 代表主鍵（唯一且不能空白）
    EmpName VARCHAR(50),   -- EmpName 是欄位名稱 | VARCHAR(50) 代表最多 50 個字的字串
    Salary DECIMAL(10, 2)  -- Salary 是欄位名稱 | DECIMAL(10,2) 代表總共 10 位數、含 2 位小數的數字
);
2. 檢視表 (View)：一個不儲存實體資料的「虛擬表格」，其內容是由一段預先寫好的 SELECT 查詢語句即時產生的結果。
  用法：
    1. 資安控管：隱藏機密欄位（如薪水、密碼），只開放特定欄位給使用者看。
    2. 簡化複雜度：將非常複雜的跨表查詢（JOIN）包裝成一個 View，以後查詢就變得很簡單。
-- 建立一個只包含姓名，隱藏薪水的員工檢視表
CREATE VIEW Safe_Employees_View AS -- 建立一個名叫 Safe_Employees_View 的虛擬表格，內容來源是...
SELECT EmpID, EmpName              -- 只挑選這兩個欄位（刻意把薪水 Salary 藏起來）
FROM Employees;                    -- 來源是 Employees 表格
WHERE EmpID >= 60;                 -- 且ID要在60之後

3. 索引 (Index)：一種附加在表格欄位上的資料結構（通常是 B-Tree），用來大幅加快資料檢索的速度。
  用法：當表格資料量極大時，建立在常被用來查詢（WHERE 條件）的欄位上，可以避免全表掃描，提升查詢效能。
  -- 在員工表的「姓名」欄位上建立一個加速搜尋的索引
CREATE INDEX idx_emp_name -- 建立一個名叫 idx_emp_name 的索引（加速搜尋用）
ON Employees (EmpName);   -- 把這個加速器安裝在 Employees 表格的 EmpName 欄位上

4. 預存程序 (Stored Procedure)：將一段或多段 SQL 語句集合打包、編譯並儲存在資料庫中的程式區塊，可接受傳入參數。
  用法：將複雜的商業邏輯（例如：月底結算、扣庫存加開發票）寫在資料庫端，減少應用程式與資料庫之間的網路傳輸，並提升執行效率。
-- 建立一個幫特定員工加薪的預存程序
CREATE PROCEDURE GiveRaise (       -- 建立一個名為 GiveRaise 的預存程序（類似自訂的 SOP 指令）
    IN p_EmpID INT,                    -- 輸入參數 1：要幫哪位員工加薪
    IN p_RaiseAmount DECIMAL(10, 2)    -- 輸入參數 2：要加多少錢
    IN p_RaiseAmount DECIMAL(10, 2)  -- 輸入參數 2：要加多少薪水（填入數字）
)
BEGIN                              -- 以下開始執行內部的動作
    UPDATE Employees               -- 去修改 Employees 表格
    SET Salary = Salary + p_RaiseAmount -- 把原本的薪水加上要加的金額
    WHERE EmpID = p_EmpID;         -- 指定條件：只修改對應的那位員工編號
END;                               -- 結束這個預存程序

-- 呼叫 GiveRaise 這個預存程序，並依序帶入參數：員工編號 7、加薪 5000
CALL GiveRaise(7, 5000);

5. 觸發器 (Trigger)：一種特殊的預存程序，它不能被手動呼叫，而是綁定在某個 Table 上。當該 Table 發生 INSERT、UPDATE 或 DELETE 事件時，就會「被動」自動執行。
  用法：強制執行資料稽核（例如：誰在什麼時候刪除了資料，自動寫入 Log 表）、自動計算連動數據。
-- 建立一個觸發器，當新增員工時，自動在日誌表新增一筆紀錄
CREATE TRIGGER trg_AfterInsertEmployee -- 建立一個名為 trg_AfterInsertEmployee 的觸發器（自動警報器）
AFTER INSERT ON Employees          -- 觸發時機：當 Employees 表格被成功「新增資料 (INSERT)」的「之後 (AFTER)」
FOR EACH ROW                       -- 每一筆新增的資料都要觸發一次
BEGIN                              -- 觸發後開始執行以下動作
    INSERT INTO AuditLog (ActionText, ActionTime) -- 自動在日誌表新增一筆紀錄
    VALUES ('一位新員工被新增了', CURRENT_TIMESTAMP); -- 填入提示文字與當下的系統時間
END;                               -- 結束觸發器

6. 序列 (Sequence)：一個獨立的資料庫物件，專門用來產生連續不斷、保證不重複的整數數值。
  用法： 產生流水號（如訂單編號、收據號碼）。即使在極高併發的環境下，也能確保編號的唯一性。（註：有些資料庫如 MySQL 習慣用 AUTO_INCREMENT 欄位屬性來替代此功能）。
-- 建立一個名為訂單編號的發號機，從 1 開始，每次加 1
CREATE SEQUENCE OrderID_Seq  -- 建立一個名為 OrderID_Seq 的序列（像是抽號碼牌機）
    START WITH 1             -- 從數字 1 開始發號碼
    INCREMENT BY 1;          -- 每次發號碼，數字就自動加 1（1, 2, 3...）

SQL四大種類
1. DDL(資料定義語言)：定義／修改資料庫結構
  1. CREATE：建立物件（表、檢視表、索引等）
  
  2. ALTER：修改物件結構（如新增欄位）
-- 在 Employees 表格中新增一個 Email 欄位
ALTER TABLE Employees 
ADD Email VARCHAR(100), -- 增加EMAIL欄位、最大100個字串
RENAME COLUMN Email TO _deprecated_Email, -- 把欄位 EMAIL名稱改成 _deprecated_Email
ALTER COLUMN Email SET INVISIBLE,
DROP COLUMN Email;

  3. DROP：刪除整個物件（含結構與資料）
-- 直接刪除 Employees 這張表，如果這張表有被其他表關聯（例如有外來鍵 Foreign Key 綁著），直接刪會失敗，資料庫會拒絕，保護你不會不小心害其他系統崩潰。
DROP TABLE Employees;
-- 如果 Employees 這張表存在，就刪除它；如果不存在就算了，不會報錯
DROP TABLE IF EXISTS Employees;

  * View 與 預存程序(PROCEDURE)比較安全，可以直接刪除

  4. TRUNCATE：清空表中"所有"資料，但保留表結構，速度快，不可加 WHERE
  -- 清空Employees 表格資料
  TRUNCATE TABLE Employees;

***** DDL 指令通常會自動提交（auto-commit），執行後即生效。
資料庫裡修改資料，通常是暫時存在記憶體或暫存區裡，唯有下了 COMMIT 才會永久寫入硬碟。
*****「不能 rollback」（因視為 DDL、自動提交）
Rollback 是將資料庫尚未永久存檔（未 Commit）的所有變更全部作廢並還原到初始狀態的「後悔/復原」機制。
  1. 必須在「交易（Transaction）」的保護傘之內
  2. 資料尚未被提交（Not Committed）
  3. 該操作必須支援復原（例如 DML，而非 DDL）
  
2. DML(資料操作語言)：對表中的資料進行存取	
  1. INSERT 新增
  2. UPDATE 修改
  3. DELETE 刪除
  4. SELECT 查詢

DCL(資料控制語言)：控制使用者權限
	1. GRANT
  -- 賦予使用者在可以從任何外部 IP 對 username 對 employees 這張表進行查詢與新增、修改、刪除
  GRANT SELECT,INSERT,UPDATE,DELETE ON employees TO 'username'@'%';
-- 賦予使用者 username 在本地端對 employees 這張資料庫表的所有操作權限
GRANT ALL PRIVILEGES ON employees TO 'username'@'localhost';
-- 賦予使用者 username 在特定IP連線進入，才能對 employees 這張資料庫表的所有操作權限。且還能把這些權限轉發給其他人
GRANT ALL PRIVILEGES ON employees TO 'username'@'l192.168.1.50' WITH GRANT OPTION;

  2. REVOKE
  -- 收回使用者 username 對 employees 表的新增權限
  REVOKE INSERT ON employees FROM 'username'@'localhost';
-- 徹底清除該帳號的特定存取與轉發權力
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'username'@'localhost';
-- 收回使用者 username 對 employees 表權限轉發給他人的權利
REVOKE GRANT OPTION FOR SELECT ON employees FROM 'username'@'localhost';

*** '帳號名稱'@'主機來源' 是一個不可分割的「完整帳號身分（Identity）」

TCL(交易控制語言)：管理交易
1. START TRANSACTION / BEGIN (開啟交易)：標記一個新交易的開始，讓後續的 DML 操作被包在同一個安全防護網內。
2. COMMIT(提交)：將交易期間所有的 DML 變更永久寫入資料庫硬碟中，無法再反悔。
3. ROLLBACK（回滾/復原）： 將交易期間所有尚未提交的變更全部作廢，回到交易開始前的狀態。

4. SAVEPOINT（儲存點）： 在交易中設定一個中繼檢查點，允許在發生錯誤時部分回滾(把進度退到該檢查點上)，不用全部重來。

ex1. (若中間發生錯誤，則執行 ROLLBACK; 將金額扣款與加款全部作廢)
START TRANSACTION; -- 開始交易
UPDATE accounts SET balance = balance - 500 WHERE id = 1;
UPDATE accounts SET balance = balance + 500 WHERE id = 2;
-- 檢查一切順利，永久存檔
COMMIT;

ex2.
START TRANSACTION;
INSERT INTO logs (action) VALUES ('Step 1');

SAVEPOINT sp1; -- 設定儲存點 1

-- 新增一筆資料到 logs 表中，指定填寫 action 欄位，內容是字串 'Step 2 (Failed)'。
INSERT INTO logs (action) VALUES ('Step 2 (Failed)');
-- 發現 Step 2 有問題，但想保留 Step 1
ROLLBACK TO sp1; 

COMMIT; -- 最後只會永久保留 Step 1

建表：
*** CHAR VS VARCHAR
1. 資料短，CHAR省空間；資料長，VARCHAR省空間。
2. 更新資料，CHAR原地更新，速度極快；VARCHAR則可能會將整筆資料搬到合適的儲存位置，需要動整筆資料
3. 運算速度，CHAR有規律，查詢極快。

CREATE TABLE student_profile (
  -- 【INT】: 整數型別。
  -- 【PRIMARY KEY (主鍵約束)】: 代表此欄位是表格每一筆資料的「唯一識別碼」。它自動具備「不可重複 (UNIQUE)」且「不可為空 (NOT NULL)」的特性。
  profile_id  INT           PRIMARY KEY,                         

  -- 【CHAR(8)】: 固定占8格的定長文字（如果輸入不到8字元，系統會補空白；若超過則可能報錯）。
  -- 【NOT NULL (非空約束)】: 此欄位必須有值，不能存入 NULL（空值）。
  -- 【UNIQUE (唯一約束)】: 此欄位的值在整張表中不可重複，確保每個 student_id 都是獨一無二的。
  student_id  CHAR(8)      NOT NULL UNIQUE,                      

  -- 【VARCHAR(20)】: 最大長度為 20 的變長文字（與 CHAR 不同，輸入幾個字就占多少空間，較節省容量）。
  name        VARCHAR(20)  NOT NULL,                             

  -- 【DEFAULT (預設值約束)】: 如果新增資料時沒有特別填寫這個欄位，系統會自動幫它填入 'F'。
  -- 【CHECK (檢查約束)】: 限定這個欄位能被輸入的值。這裡限制只能輸入 'M' 或 'F'，輸入其他字元會被資料庫拒絕。
  gender      CHAR(1)      DEFAULT 'F' CHECK (gender IN ('M', 'F')),

  -- 【DECIMAL(5,2)】: 精確的小數數值。「5」代表總共可容納五個數字，「2」代表小數點後佔兩位。也就是說最大可輸入 999.99。
  -- 【CHECK (檢查約束)】: 限制輸入的分數必須落在 0 到 100 之間（包含 0 與 100）。
  score       DECIMAL(5,2) DEFAULT 0 CHECK (score BETWEEN 0 AND 100),

  -- 【DATE】: 日期型別，格式通常為 YYYY-MM-DD（僅有年月日，不含時間）。
  birth_date  DATE          NOT NULL,

  -- 【DATETIME】: 日期與時間型別，包含年月日與時分秒（YYYY-MM-DD HH:MM:SS）。
  -- 【DEFAULT (預設值約束)】: 實務上也常使用 DEFAULT CURRENT_TIMESTAMP 讓系統自動抓取當下時間）
  created_at  DATETIME      DEFAULT '2026-01-01 09:00:00',

  -- 【FOREIGN KEY (外來鍵約束)】: 建立兩張表格之間的關聯。這裡規定本表的 `student_id` 欄位，其值必須存在於另一張父表 `student` 的 `id` 欄位中，確保「沒有憑空捏造的學生」。
  -- 【ON DELETE 行為設定】: 決定當父表 (student) 中的某一筆學生資料被刪除時，這張子表 (student_profile) 該如何應對：
  --   1. CASCADE：連動刪除（父表資料刪除了，這張表裡的對應資料也自動跟著一起刪除）。
  --   2. SET NULL：設為空值（父表資料刪除了，這張表裡的 student_id 會變成 NULL，但前提是該欄位沒有 NOT NULL 約束）。
  --   3. RESTRICT：限制刪除（只要這張子表裡還有該學生的資料，資料庫就會「禁止」你刪除父表的那筆學生資料，這也是預設行為）。
  FOREIGN KEY (student_id) REFERENCES student(id) ON DELETE CASCADE
);

模組二：SQL 語法與 CRUD 實作 (SQL & CRUD)
* 2-1 DDL (資料定義語言)：CREATE, ALTER, DROP, TRUNCATE (快速複習與比較)。
* 2-2 DML (資料操作語言) 與 CRUD：
