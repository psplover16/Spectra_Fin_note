機器指令: CPU 直接看得懂的二進位命令
指令週期流程: 
取指令(Fetch)>解碼(Decode)>取運算元／算位址(Operand Fetch / Address Calculation)>執行(Execute)>寫回(Write Back / Store)
Opcode : 要執行的操作
Operand : 被操作的資料、暫存器或位置
Effective Address : 真正要存取的記憶體位置
第一步(取指令)： CPU 先把「PC(下一道指令的位址)」複製一份送到 MAR (記憶體位址暫存器)，去記憶體把「指令」拿回來放到 MDR (記憶體資料暫存器)，再存進 IR 準備解碼。
第二步(算位址)： CPU 解碼後，根據指令規定的「定址模式」，計算出資料真正的所在位置，稱為「有效位址 (EA)」。
第三步(拿資料)： CPU 把算出來的「EA」送到 MAR，去記憶體把「真正的資料」拿回來放到 MDR。
最後一步(執行)： 拿到資料後，CPU 就能完成加減乘除等運算。

Pipeline 與 Hazard
【管線化與效能極限】
管線化的時脈週期時間，由耗時最長的階層決定。
管線化極限是 CPI 等於 1，因為同一個週期最多只能發行一個指令。
n 個指令的非管線化總時間為 nkt。
n 個指令的管線化總時間為 (k+n-1)*t。
超純量架構，讓 CPU 在單一硬體時脈週期內，將多道指令同時分發到多個獨立的執行單元進行並行運算，藉此大幅提升整體的資料處理效能。
超純量架構打破了管線化極限，CPI 小於 1，因為同一個週期可以發行多個指令。

【結構危險】
IF  >  ID  >  EX  >  MEM  >  WB
結構危險的起因是硬體資源不夠，最常考的是 IF 和 MEM 階段同時搶用一塊記憶體。
結構危險的完美解法是哈佛架構，直接把指令快取與資料快取實體分離。
如果沒有哈佛架構，結構危險只能靠插入氣泡暫停(Stall)來解決。

【資料危險】
資料危險的起因是後面的指令需要前面還沒寫回暫存器的資料(RAW)。
資料危險的完美解法是前饋(Forwarding)，不寫回暫存器，直接從 ALU 拉線給下一個指令。
資料危險的最大特例與陷阱是 Load-Use 危險。
當 LOAD 指令後面"緊接" 其他指令 時，就算有前饋機制，也必須強制暫停 1 個週期。

【控制危險】
控制危險的起因是遇到分支跳躍指令，CPU 不知道下一行在哪裡而抓錯指令。
控制危險的硬體解法是分支預測，軟體(編譯器)解法是分支延遲槽。
分支延遲槽，編譯器會刻意在分支指令後方，放入「無論有沒有跳躍都必須執行」的指令，以榨取效能
只要分支預測猜錯，管線一定要把提早拿進來的錯誤指令全部沖刷(Flush)作廢。
BTB 分支目標緩衝器用來記住上次跳躍的目標位址，直接抄捷徑免計算。

【實際 CPI 必背公式】
實際 CPI 等於 理想 CPI 加上 停頓週期。
停頓週期 等於 分支指令比例 * 預測錯誤率 * 錯誤懲罰週期。

RISC VS CISC
CISC指令複雜，硬體線路難做且難除錯，改以微程式(ROM存微碼)翻譯執行。
RISC：指令簡，IC↑、CPI↓ (接近1)
CISC：指令繁，IC↓、CPI↑ (不規則)
CISC 代表架構: x86 (Intel/AMD), Motorola 68000, VAX(巔峰)
RISC 代表架構: ARM (手機), RISC-V (開源架構), MIPS, SPARC, PowerPC

CPU Time = Instruction Count × CPI(每指令平均週期數) × Clock Cycle Time(時脈週期時間)
CPU Time = Instruction Count × CPI / Clock Rate
MIPS = Instruction Count / (Execution Time × 10^6)
MIPS = Clock Rate / (CPI × 10^6)

RAM：執行中、可快讀寫、斷電多消失。
ROM：放韌體、放開機程式、斷電多保留。
---
SRAM：靜態隨機存取記憶體。正反器構成。不需週期性充電，只要通電資料就在。貴、小、快。專做CPU快取記憶體(Cache)。
DRAM：動態隨機存取記憶體。電容與電晶體構成。電容會漏電，必須週期性充電才能保存資料。便宜、大、慢。專做系統主記憶體(RAM)。
---
PROM：高電壓燒斷內部保險絲、只能寫入一次、寫錯即報廢。
EPROM：紫外線照射石英視窗、須拔下晶片、可整片擦除後再燒錄、不方便。
EEPROM：電壓訊號線上抹除、不需拔晶片、以Byte為單位局部改寫、速度慢、存BIOS。
Flash：電壓訊號、以Block為單位整塊快速擦寫、容量大成本低、做SSD與隨身碟。

暫存器(Register)：CPU內部極小極快的儲存空間。
PC(程式計數器)：存放下一個要執行的指令位址。
IR(指令暫存器)：存放目前正在執行的指令。

Flag Register(旗標暫存器)：記錄運算結果狀態(如零、進位、溢位)。
AC(累加器)：暫存ALU運算的中間或最終結果。

AMAT公式：命中時間 + 未命中率 * 懲罰時間
---Cache 在面對「寫入 (Write)」動作--
命中 (Write Hit) 策略，當 CPU 要寫入的資料已經存在於 Cache 中:
Write Through：同步寫入Cache與主記憶體
Write Back：先寫Cache，替換時才寫回主記憶體

未命中 (Write Miss) 策略，當 CPU 要寫入的資料不在 Cache 中:
Write Allocate (寫入配置)：未命中先載入Cache再寫入。適合反覆存取。
No Write Allocate (非寫入配置)：未命中直接寫下層，不載入Cache。避免占空間。

分頁與分段記憶體管理

邏輯位址 (Logical Address) / 虛擬位址 (Virtual Address):程式自己看到的位址,從 0 開始編。程式以為自己獨佔整片記憶體。
實體位址 (Physical Address):資料真正放在實體記憶體 (RAM) 的位址。
MMU (Memory Management Unit,記憶體管理單元):一個硬體,負責在程式執行時,把邏輯位址即時轉成實體位址。

外部碎裂 (External Fragmentation):空閒空間加起來夠,但被切成零碎、不連續的小塊,無法滿足一個較大的需求。

頁: 
邏輯記憶體(程式)切成固定大小的小塊,叫頁 (Page)。
實體記憶體 (RAM) 切成同樣大小的小格,叫頁框 (Frame)。
頁表 (Page Table):記錄「第幾頁 → 放在第幾個頁框」的對照表,每個程序一份。
*******框號 × 框大小 ＋ 偏移(偏移照抄)
TLB (Translation Look-aside Buffer,轉譯後備緩衝區)——一塊很快的小快取,專門存「最近用過的 頁號 → 頁框號」對照
TLB 命中 (hit):要找的頁號在 TLB 裡 → 直接拿到頁框號,只要再讀一次記憶體(讀資料)。
*******TLB 未命中 (miss):TLB 裡沒有 → 得先去記憶體讀頁表,再讀資料,共兩次記憶體存取。
*******EAT(有效存取時間) = 
命中率 × 命中所需時間(讀資料時間 + 查TLB時間) + 
未命中率 × 未命中所需時間(讀資料時間 + 讀頁表時間 + 查TLB時間)

內部碎裂 (Internal Fragmentation):配置出去的空間比實際需要的大,多出來、用不到的部分就是內部碎裂(平均每個程序浪費約半頁)。

分段，按照程式的邏輯單位來切: 
段表 (Segment Table):
 基底 (Base):這段在實體記憶體的起始位址。
 界限 (Limit):這段的長度(有多大)。
邏輯位址 = ( 段號 s , 段內偏移 d )
*******查段表拿到 base 與 limit → 先檢查 d < limit → 沒超過就 實體位址 = base + d。

緊縮 (Compaction) :把散落在記憶體各處、已經在用的段全部搬到記憶體的一邊、緊緊靠在一起,讓原本零散的小空洞合併成一整塊連續的大空間。
解決外部碎裂、可重定位 (relocatable)、緊縮(成本高)

分段：段大小不一、要連續擺 → 有外部碎裂、無內部碎裂。
分頁：頁一律等大、可散放 → 有內部碎裂、無外部碎裂。

段頁式 邏輯位址 = ( 段號 s , 頁號 p , 偏移 d )
段號查「段表」找到這段專屬的頁表 → 頁號查該「頁表」換成框號 → 框號 × 框大小 + 偏移
沒有外部碎裂(因為底層是分頁)，是實務上常用的折衷。






類別 (Class) 
屬性 (Attribute) / 欄位 (Field):物件的「資料」,例如車子的顏色、車速。
方法 (Method):物件能做的「動作」,例如車子的加速、煞車。
---
物件 (Object) 用類別做出來的實體,也叫實例 (Instance)

四大特性: 
封裝 (Encapsulation)
1. 把「資料 + 方法」包在一起成為一個類別
2. 資訊隱藏 (Information Hiding)，把內部細節藏起來，只對外開放必要的操作介面
存取修飾子:
private——只有同一個類別內能碰
default(不寫修飾子)——又叫 package-private(套件私有) 同一個套件內的類別都能碰,跨套件不行。
protected——在 default 之上,再多一個「其他套件的子類別」。
public——任何地方都能碰(最寬)。
--
繼承 (Inheritance) 讓一個新類別直接擁有既有類別的屬性和方法,不必重寫,還能再加自己的或修改。
新類別直接擁有既有類別的屬性和方法,不必重寫,還能再加自己的或修改
子類別繼承父類別 = is-a; has-a 要用組合(Composition)。
Java 不支援類別多重繼承(用介面替代),C++ 支援。繼承的好處是重用。
--
多型 (Polymorphism) 同一個方法名稱(同一個訊息),套在不同物件上,會有不同的行為。
多載 / 重載 (Overloading)——編譯期多型，同一個類別裡,有多個同名方法,靠參數不同(個數、型別、順序)來區分
覆寫 (Overriding)——執行期多型，子類別把父類別「已經有」的方法,重新定義一次(方法簽章完全相同)
--
抽象 (Abstraction) 抽取出物件重要、共通的特徵,隱藏不必要的實作細節,只對外呈現必要的介面。
實作方法: 抽象類別 (Abstract Class) VS 介面 (Interface)
可有已實作 + 抽象方法 (傳統)只有宣告,無實作
可有一般變數(有狀態) 只能是常數(public static final)
皆不能實例化
extends  implements
只能繼承一個 可實作多個
is-a(你是什麼) can-do(你能做什麼)
有建構子 無建構子
