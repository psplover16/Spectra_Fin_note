# 作業系統 3-7：Process Communication（你朋友標「跳過」）

> 科目：計算機原理 — 作業系統
> 這章你朋友原筆記標「**這章我跳過**」，所以不出完整筆記，改成「**為什麼跳 + 你該不該跟 + 真要碰只抓這些**」。

## 一、他為什麼跳過（分析）

最可能是 **頻率低 × 難度高 ＝ CP 值低**，再加時間取捨：

- **頻率低**：經濟部資訊的 OS 重頭戲是排程、記憶體、虛擬記憶體、死結、磁碟；IPC／同步（號誌、監視器、經典同步問題）在經濟部出得比研究所少，不是穩定高頻。
- **難度高**：同步是 OS 裡最燒腦的一塊——號誌程式碼、臨界區問題、哲學家用餐都要細想，投入大。
- **部分重疊**：死結已在 3-6 講完、並行/平行的基礎在 3-1 提過，IPC 有一部分風景其實別處碰過了。
- **時間取捨**：時間有限時，砍掉「難又少考」的章節、把時間灌到高頻計算題，是合理的策略。

## 二、你該不該跟？（建議：大致跟，但撿便宜的）

跟著跳大致 OK（資訊類複試加額 80% 很寬，你又零基礎、時間緊）。但 IPC **不是零頻率**——「概念層級」的小題偶爾會出。所以走**中間路線**：

- **花約 20 分鐘撿便宜分**：把下面「概念層級」的東西認得、分得清就好（低成本、偶爾換到送分題）。
- **跳過昂貴的**：號誌的程式碼、實際解經典同步問題、監視器（Monitor）實作細節——又難又少考，跟著放掉。

## 三、真要碰，只抓這些（認得就好）

**【理解】兩種 IPC 模型：**
- **共享記憶體 Shared Memory**：開一塊共用記憶體互相讀寫，**快**，但要**自己處理同步**。
- **訊息傳遞 Message Passing**：透過 OS 送收訊息，**慢**一點，但**同步由 OS 代管**、較安全。

**【理解】幾個關鍵名詞：**
- **Race condition（競爭情況）**：多個 process 同時動共享資料，結果**取決於誰先誰後** → 出錯。
- **Critical Section（臨界區）**：存取共享資料的那段程式碼，規定**一次只能一個** process 進入。
- **Semaphore（號誌）**：一個整數 + `wait`／`signal` 操作，用來控制進臨界區；分 **binary（0/1，≈ mutex）** 與 **counting**。
- **Mutex**：互斥鎖，≈ binary semaphore，把臨界區鎖起來。

**【硬背】三個經典同步問題（認得名字即可，不用會解）：**
- 生產者-消費者（Producer-Consumer）
- 讀者-寫者（Readers-Writers）
- 哲學家用餐（Dining Philosophers）
