## 名詞解釋

### I/O

I/O 是 Input/Output 的縮寫，意思是「輸入與輸出」。在電腦系統中，CPU 和記憶體是處理資料的核心，但資料通常會來自鍵盤、滑鼠、磁碟、網路卡、印表機等周邊裝置，這些周邊和電腦之間的資料交換就稱為 I/O。

白話來說，I/O 就是電腦和外部世界溝通的方式。例如你按鍵盤輸入文字，是輸入；電腦把檔案寫入硬碟，是輸出；網路卡接收封包，也是輸入。

### CPU

CPU 是中央處理器，負責執行程式指令與控制電腦運作。它很快，但 I/O 裝置通常比較慢，所以作業系統必須安排 CPU 和 I/O 裝置之間的配合方式，避免 CPU 把大量時間浪費在等待裝置。

### Polling

Polling 通常翻成「輪詢」或「查詢式 I/O」。意思是 CPU 主動、反覆去問 I/O 裝置：「你準備好了嗎？」如果裝置還沒準備好，CPU 就繼續問，直到裝置可以進行資料傳輸。

Polling 的優點是設計簡單，流程直覺；缺點是浪費 CPU 時間。因為 CPU 可能一直在檢查狀態，卻沒有做其他有用的工作。

### Interrupt

Interrupt 是「中斷」。意思是 I/O 裝置在需要 CPU 處理時，主動通知 CPU。CPU 不必一直詢問裝置狀態，而是可以先去執行其他工作，等裝置發出中斷訊號時，再暫停目前工作並執行中斷服務程式。

白話來說，Polling 像是一直跑去櫃台問餐好了沒；Interrupt 像是店員叫號，等輪到你再去取餐。

### Interrupt Service Routine

Interrupt Service Routine 常縮寫為 ISR，中文可稱為「中斷服務程式」。當中斷發生時，CPU 會轉去執行對應的處理程式，例如接收鍵盤輸入、處理磁碟完成訊號、處理網路封包等。

ISR 的重點是「中斷發生後真正負責處理事件的程式」。

### DMA

DMA 是 Direct Memory Access，中文是「直接記憶體存取」。它讓 DMA controller 直接在 I/O 裝置和記憶體之間搬資料，不需要 CPU 一個位元組或一個字一個字地搬。

CPU 在 DMA 中主要負責設定傳輸資訊，例如來源位置、目的位置、資料長度和傳輸方向。等 DMA 傳輸完成後，DMA controller 通常會用中斷通知 CPU。

### DMA Controller

DMA controller 是負責執行 DMA 傳輸的硬體控制器。它可以接管資料搬移工作，讓 CPU 不必親自處理大量資料傳輸。

國考常考重點是：DMA 不代表完全不需要 CPU，而是 CPU 只負責開始前設定和完成後處理，中間大量資料搬移由 DMA controller 負責。

### NMI

NMI 是 Non-Maskable Interrupt，中文是「不可遮蔽中斷」。不可遮蔽的意思是 CPU 不能用一般方式忽略或關閉它。它通常用在嚴重硬體錯誤，例如記憶體同位元錯誤、電源故障警告等。

NMI 的考點是「不可遮蔽」和「嚴重硬體事件」。

### Trap

Trap 是由程式執行所造成的同步中斷。同步的意思是它和目前執行中的指令有直接關係，通常是在執行某一行程式或某一個指令時發生。

常見例子包括 system call、除以零、breakpoint。Trap 不一定都是錯誤，system call 就是程式主動請求作業系統服務。

### System Call

System call 是「系統呼叫」。一般程式不能直接操作硬體或核心資源，所以需要透過 system call 請作業系統幫忙，例如開檔、讀檔、寫檔、建立行程、使用網路等。

在中斷分類中，system call 常被歸在 Trap，因為它是程式執行時主動造成的同步事件。

## 核心想法

I/O 與中斷的核心問題是：CPU 很快，I/O 裝置很慢，系統要怎麼讓 CPU 不要浪費太多時間等待裝置？

最基本的方法是 Polling。CPU 主動檢查裝置狀態，知道裝置準備好後才進行資料傳輸。這種方式容易理解，也容易實作，但如果裝置很久才準備好，CPU 就會一直忙著檢查，造成浪費。

比較有效率的方法是 Interrupt。CPU 不必一直等裝置，而是先去做其他事情。等裝置完成工作或需要服務時，再發出中斷通知 CPU。CPU 收到中斷後，會暫停目前工作，保存必要狀態，執行中斷服務程式，最後再回到原本的工作。

如果資料量很大，只靠 CPU 搬資料仍然不划算，因此會使用 DMA。DMA controller 可以直接在 I/O 裝置與記憶體之間傳輸大量資料。CPU 只要設定傳輸參數，不必親自搬每一筆資料。資料傳完後，再透過中斷通知 CPU 做後續處理。

所以三者可以用一句話串起來：

Polling 是 CPU 一直問；Interrupt 是裝置主動通知 CPU；DMA 是大量資料由 DMA controller 幫忙搬，CPU 只負責設定與收尾。

## 具體範例

### 鍵盤輸入

假設使用者按下一個鍵。

如果使用 Polling，CPU 需要不斷檢查鍵盤控制器，看看是否有按鍵資料。如果使用者很久都沒有按鍵，CPU 的檢查動作就大多是白忙一場。

如果使用 Interrupt，CPU 可以先執行其他程式。當使用者按鍵時，鍵盤控制器發出中斷，CPU 再去執行鍵盤的中斷服務程式，把按鍵資料讀進來。

鍵盤輸入通常資料量小，所以常用中斷處理即可，不需要特別用 DMA 搬大量資料。

### 磁碟讀取檔案

假設程式要從磁碟讀取一大段資料到記憶體。

如果完全由 CPU 搬資料，CPU 需要花很多時間在磁碟與記憶體之間移動資料，無法有效執行其他工作。

使用 DMA 時，CPU 會先告訴 DMA controller：要從哪個裝置讀資料、要放到記憶體哪裡、資料長度是多少。設定完成後，DMA controller 直接把資料從磁碟控制器搬到記憶體。搬完後，DMA controller 發出中斷通知 CPU：「資料已經傳好了。」

這就是國考常見的 DMA 流程：CPU 設定，DMA 傳輸，中斷通知完成。

### 網路卡接收大量資料

網路卡收到資料封包時，可以透過中斷通知 CPU。但是如果每收到一小段資料都中斷一次，CPU 可能會被太多中斷打斷。

因此實務上常會搭配緩衝區、批次處理或 DMA。網路卡可以把資料放到記憶體中的緩衝區，再通知 CPU 處理。這樣能減少 CPU 的搬移負擔，提高整體效率。

## 國考常見考法

國考很常要求分辨 Polling、Interrupt、DMA 的差異。題目可能會問：「哪一種方式會讓 CPU 不斷查詢裝置狀態？」答案是 Polling。也可能問：「哪一種方式由裝置在需要服務時通知 CPU？」答案是 Interrupt。若題目強調大量資料直接在 I/O 裝置與記憶體間傳輸，通常就是 DMA。

另一個常見考法是中斷分類。NMI 是不可遮蔽中斷，常與嚴重硬體錯誤連在一起。一般 Interrupt 可包含外部中斷與內部中斷。Trap 則是由程式執行造成的同步中斷，常見例子是 system call、除以零和 breakpoint。

考題也可能考「同步」與「非同步」。Trap 通常是同步的，因為它和正在執行的指令有關；外部 I/O 中斷通常是非同步的，因為它不一定剛好和目前執行的指令本身有關，而是外部裝置在某個時間點發出通知。

還有一種常見陷阱是把 DMA 說成「完全不需要 CPU」。這是不精確的。DMA 傳輸過程中大量資料搬移不需要 CPU 逐筆參與，但 CPU 仍需要設定 DMA controller，也需要在傳輸完成後處理中斷或後續工作。

## 必要比較表與易混淆整理

### Polling、Interrupt、DMA 比較表

| 項目 | Polling | Interrupt | DMA |
|---|---|---|---|
| 基本想法 | CPU 主動反覆查詢裝置狀態 | 裝置需要服務時通知 CPU | DMA controller 直接在裝置與記憶體間搬資料 |
| CPU 角色 | 一直檢查裝置是否準備好 | 平常做其他事，被通知後再處理 | 設定傳輸參數，完成後處理 |
| 適合情境 | 簡單系統、裝置狀態很快就緒 | 裝置事件不固定、希望提高 CPU 使用效率 | 大量資料傳輸 |
| 優點 | 實作簡單、控制流程直覺 | 比 Polling 省 CPU | 大幅減少 CPU 搬資料負擔 |
| 缺點 | 浪費 CPU 時間 | 中斷太多會增加切換負擔 | 硬體較複雜，需 DMA controller |
| 國考關鍵字 | 主動查詢、忙碌等待 | 通知 CPU、中斷服務程式 | 直接記憶體存取、大量資料、DMA controller |

### 三種中斷比較表

| 類型 | 中文意義 | 是否可遮蔽 | 主要來源 | 常見例子 |
|---|---|---|---|---|
| NMI | 不可遮蔽中斷 | 不可遮蔽 | 嚴重硬體事件 | 嚴重硬體錯誤、電源故障警告 |
| Interrupt | 一般中斷 | 通常可遮蔽 | 外部裝置或系統事件 | 鍵盤、滑鼠、磁碟完成、計時器 |
| Trap | 陷阱、中陷 | 通常由程式執行引發 | 目前執行中的程式或指令 | system call、除以零、breakpoint |

### 外部中斷、內部中斷、Trap 的差異

外部中斷通常來自 CPU 外部的硬體裝置，例如鍵盤、磁碟、網路卡或計時器。它常被視為非同步事件，因為它發生的時間不一定由目前正在執行的指令決定。

內部中斷常和 CPU 執行指令時發生的狀況有關，例如運算錯誤或例外狀況。不同教材對「內部中斷」和「Trap」的用語可能略有差異，但國考常見的重點是：Trap 是程式執行造成的同步中斷。

Trap 最常被考的例子是 system call、除以零、breakpoint。看到這三個例子時，要立刻想到「程式造成」、「同步」、「Trap」。

### 容易混淆整理

Polling 和 Interrupt 最容易混淆。判斷方法是看「誰主動」。如果 CPU 主動一直問，就是 Polling；如果裝置主動通知 CPU，就是 Interrupt。

Interrupt 和 DMA 也容易混淆。Interrupt 的重點是通知 CPU 有事件要處理；DMA 的重點是大量資料傳輸不由 CPU 逐筆搬移。DMA 完成後常會用 Interrupt 通知 CPU，所以 DMA 和 Interrupt 可以一起出現，不是互相排斥。

NMI 和一般 Interrupt 的差異在於能不能被遮蔽。NMI 不可遮蔽，通常代表很嚴重、不能被忽略的硬體事件。一般 Interrupt 通常可以被 CPU 根據中斷遮蔽設定暫時忽略或延後處理。

Trap 和一般 I/O 中斷的差異在於來源。Trap 來自程式執行，例如 system call 或除以零；一般 I/O 中斷多半來自外部裝置，例如磁碟完成或鍵盤輸入。

## 國考答題句

Polling 是由 CPU 主動反覆查詢 I/O 裝置狀態，實作簡單，但會浪費 CPU 時間。

Interrupt 是由 I/O 裝置在完成工作或需要服務時通知 CPU，使 CPU 不必一直等待，可提高 CPU 使用效率。

DMA 是由 DMA controller 直接在 I/O 裝置與記憶體之間傳輸大量資料，CPU 只負責設定傳輸參數與完成後處理。

NMI 是不可遮蔽中斷，通常用於嚴重硬體錯誤或緊急事件。

Trap 是由程式執行所造成的同步中斷，常見例子包括 system call、除以零與 breakpoint。

DMA 並非完全不需要 CPU，而是資料傳輸期間不需要 CPU 逐筆搬移資料。

## 容易考的判斷題

1. Polling 由 CPU 主動檢查 I/O 裝置狀態。  
   答：對。Polling 的特色就是 CPU 不斷查詢裝置是否準備好。

2. Polling 通常比 Interrupt 更節省 CPU 時間。  
   答：錯。Polling 可能讓 CPU 一直等待或檢查，Interrupt 通常較能節省 CPU 時間。

3. Interrupt 是裝置在需要服務時通知 CPU。  
   答：對。這正是中斷機制的主要精神。

4. DMA 適合大量資料傳輸。  
   答：對。DMA 的目的就是減少 CPU 在大量資料搬移上的負擔。

5. DMA 傳輸過程完全不需要 CPU 做任何事情。  
   答：錯。CPU 仍需設定 DMA controller，傳輸完成後也可能要處理中斷與後續工作。

6. NMI 是可遮蔽中斷。  
   答：錯。NMI 的全名是 Non-Maskable Interrupt，意思是不可遮蔽中斷。

7. 嚴重硬體錯誤常使用 NMI 通知 CPU。  
   答：對。NMI 常用於不能被忽略的嚴重硬體事件。

8. Trap 通常是由外部裝置隨機發出的非同步中斷。  
   答：錯。Trap 通常由程式執行造成，是同步中斷。

9. System call 可視為 Trap 的一種例子。  
   答：對。System call 是程式主動請求作業系統服務，常歸類為 Trap。

10. 除以零可能造成 Trap。  
    答：對。除以零是程式執行指令時發生的例外狀況，常被列為 Trap 例子。

11. DMA 完成資料傳輸後，可能用中斷通知 CPU。  
    答：對。DMA 與 Interrupt 常搭配使用，DMA 負責搬資料，中斷負責通知完成。

12. Interrupt 和 DMA 是完全互斥的兩種機制，不會一起出現。  
    答：錯。DMA 完成後常透過中斷通知 CPU，因此兩者可以搭配。

## 考前速記小抄

Polling：CPU 一直問裝置好了沒。關鍵字是主動查詢、簡單、浪費 CPU。

Interrupt：裝置主動通知 CPU。關鍵字是中斷訊號、中斷服務程式、提高效率。

DMA：DMA controller 幫忙搬大量資料。關鍵字是直接記憶體存取、I/O 裝置與記憶體、CPU 設定與收尾。

NMI：不可遮蔽中斷。看到嚴重硬體錯誤、不能忽略、不可遮蔽，就選 NMI。

Trap：程式造成的同步中斷。看到 system call、除以零、breakpoint，就想到 Trap。

記憶口訣：

「Polling 一直問，Interrupt 來通知，DMA 幫忙搬。」

「NMI 很嚴重不能擋，Trap 是程式自己闖。」
