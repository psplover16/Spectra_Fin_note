## 名詞解釋

### 硬體保護

硬體保護是指作業系統利用硬體提供的機制，限制一般程式可以做的事情，避免某個程式破壞系統、影響其他程式，或長時間霸占電腦資源。

白話來說，電腦同時跑很多程式，如果每個程式都能直接控制硬碟、印表機、記憶體和 CPU，系統很容易被錯誤程式或惡意程式搞壞。因此作業系統必須靠硬體幫忙，替資源加上保護規則。

### 作業系統核心

作業系統核心又稱 kernel，是作業系統最重要的部分，負責管理 CPU、記憶體、I/O 裝置、檔案系統與行程。

新手可以把 kernel 想成系統的管理員。一般應用程式不能自己任意碰硬體，必須向 kernel 提出請求，由 kernel 判斷是否允許並代為執行。

### User Mode

User Mode 是一般應用程式執行時使用的模式，權限較低。

在 User Mode 下，程式不能直接執行特權指令，也不能任意存取所有記憶體或控制 I/O 裝置。這樣做是為了避免一般程式一出錯就拖垮整個系統。

### Kernel Mode

Kernel Mode 是作業系統核心執行時使用的模式，權限較高。

在 Kernel Mode 下，CPU 允許執行特權指令，因此作業系統可以設定記憶體保護、啟動 I/O、處理中斷、切換行程等。因為權限很大，所以只有受信任的作業系統核心程式應該在 Kernel Mode 中執行。

### Dual Mode

Dual Mode 是指 CPU 至少提供兩種執行模式：User Mode 與 Kernel Mode。

Dual Mode 的重點不是「有兩個作業系統」，而是「同一顆 CPU 會依目前執行的是一般程式或核心程式，切換不同權限」。國考常考它用來支援保護機制，防止使用者程式直接執行危險操作。

### Mode Bit

Mode Bit 是 CPU 內用來表示目前執行模式的位元。

如果 mode bit 顯示目前在 User Mode，CPU 會禁止特權指令；如果顯示目前在 Kernel Mode，CPU 才允許作業系統執行特權指令。考題不一定會問 mode bit 的細節，但常用它說明 dual mode 如何被硬體支援。

### 特權指令

特權指令是只有在 Kernel Mode 才能執行的指令。

這類指令通常會影響整個系統，例如啟動 I/O 裝置、修改記憶體管理表格、設定 timer、關閉中斷或切換 CPU 模式。若一般程式在 User Mode 執行特權指令，CPU 會阻止，通常產生 trap 或 exception，交給作業系統處理。

### 系統呼叫

系統呼叫是一般程式向作業系統請求服務的正式入口。

例如程式想讀檔、寫檔、配置記憶體或建立行程，不能直接操作硬體，而是透過 system call 進入 Kernel Mode，由作業系統檢查請求是否合法，再代為執行。

### I/O Protection

I/O Protection 是對輸入輸出裝置的保護。

I/O 指令會控制硬碟、鍵盤、螢幕、網路卡、印表機等裝置，因此不應讓一般程式直接執行。典型做法是把 I/O 指令設為特權指令，只能在 Kernel Mode 執行。

### Memory Protection

Memory Protection 是記憶體保護，用來防止程式存取不屬於自己的記憶體區域。

如果沒有記憶體保護，某個程式可能不小心改到作業系統核心資料，或改到另一個程式的資料，造成系統當機、資料錯亂或安全問題。

### Base Register

Base Register 是基底暫存器，記錄某個程式可用記憶體範圍的起始位置。

白話說，它像是「這個程式的房間從哪裡開始」。程式存取記憶體時，硬體會參考 base register，避免程式跑到不該去的區域。

### Limit Register

Limit Register 是界限暫存器，記錄某個程式可用記憶體範圍的大小或上限。

白話說，它像是「這個程式的房間有多大」。CPU 會檢查記憶體位址是否落在合法範圍內，若超出範圍就產生錯誤並交給作業系統處理。

### Page Table

Page Table 是分頁表，用來記錄虛擬頁面與實體記憶體頁框之間的對應關係，也可記錄每頁的存取權限。

在分頁式記憶體管理中，程式看到的是虛擬位址，不是直接看到實體記憶體。硬體透過 page table 轉換位址，並檢查該頁是否可讀、可寫或可執行。

### Segment Table

Segment Table 是分段表，用來記錄每個段的起始位置、長度與權限。

分段通常依程式的邏輯區塊來看，例如程式碼段、資料段、堆疊段。硬體會利用 segment table 檢查程式是否越界或違反權限。

### CPU Protection

CPU Protection 是 CPU 保護，用來避免單一程式長時間霸占 CPU。

如果沒有 CPU 保護，一個無窮迴圈程式可能永遠不交出 CPU，導致其他程式和作業系統得不到執行機會。典型做法是使用 timer interrupt，讓作業系統定期取回控制權。

### Timer Interrupt

Timer Interrupt 是計時器中斷。

作業系統會先設定一段時間，當時間到時，硬體計時器會發出中斷，使 CPU 暫停目前程式，轉去執行作業系統的中斷處理程序。這讓作業系統可以進行排程，決定目前程式繼續跑，或換另一個程式執行。

### Interrupt

Interrupt 是中斷，表示硬體或外部事件通知 CPU 暫停目前工作，改去執行對應的處理程序。

中斷不是單純的錯誤，它是一種控制權轉移機制。I/O 完成、timer 時間到、裝置請求服務，都可能透過中斷讓作業系統介入。

### Trap 或 Exception

Trap 或 Exception 是因程式執行某些事件而進入作業系統的機制，例如除以零、非法記憶體存取、在 User Mode 執行特權指令，或主動發出 system call。

對國考來說，記住重點即可：一般程式若做了不被允許的操作，硬體會阻止並把控制權交給作業系統。

## 核心想法

硬體保護的中心觀念是：一般程式不能被完全信任，作業系統必須掌握重要資源的最終控制權。

電腦裡最重要的三種保護是 I/O 保護、記憶體保護與 CPU 保護。I/O 保護防止一般程式直接控制裝置；記憶體保護防止程式越界存取；CPU 保護防止單一程式霸占處理器。三者合起來，才能讓多個程式在同一台電腦上安全、公平地執行。

Dual Mode 是這些保護的基礎。一般程式平常在 User Mode 執行，所以不能直接執行危險操作；當程式需要作業系統服務時，會透過 system call 進入 Kernel Mode，由作業系統代為處理。處理完後，系統再回到 User Mode 繼續執行一般程式。

特權指令是國考必背關鍵。凡是會改變系統狀態、影響硬體資源或破壞隔離性的操作，通常都應該是特權指令。I/O 指令、設定 timer、修改 page table 或 segment table，都屬於容易被考到的例子。

記憶體保護的精神是「每個程式只能碰自己的範圍」。早期或簡化模型常用 base/limit register 檢查界限；較完整的記憶體管理則可能透過 page table 或 segment table 同時做到位址轉換與權限檢查。無論用哪一種機制，目的都是防止越界與非法存取。

CPU 保護的精神是「作業系統不能失去控制權」。Timer interrupt 讓作業系統即使面對無窮迴圈，也能定期重新取得 CPU 控制權，進行行程排程與資源管理。

## 具體範例

### 範例一：一般程式想讀取硬碟資料

假設文字編輯器想開啟一個檔案。它不能直接對硬碟下 I/O 指令，因為如果一般程式能任意讀寫硬碟，可能會破壞檔案系統或偷讀其他使用者資料。

正確流程是文字編輯器發出 system call，請作業系統幫忙讀檔。CPU 會從 User Mode 轉入 Kernel Mode，作業系統檢查權限與檔案狀態後，再由 kernel 執行必要的 I/O 操作。這就是 I/O Protection 的典型例子。

### 範例二：程式不小心存取超出範圍的記憶體

假設某程式只被分配到某段記憶體，但因為陣列索引錯誤，試圖寫入另一個行程的記憶體位置。硬體會利用 base/limit register、page table 或 segment table 檢查該位址是否合法。

如果位址不合法，CPU 不會讓寫入成功，而是產生例外並交給作業系統處理。作業系統可能終止該程式，或回報記憶體存取錯誤。這就是 Memory Protection 的目的。

### 範例三：程式陷入無窮迴圈

假設某程式寫成 `while(true)` 且永遠不主動結束。若系統沒有 timer interrupt，該程式可能一直占用 CPU，其他程式甚至作業系統都沒有機會執行。

有了 timer interrupt 後，作業系統會先設定計時器。時間一到，硬體中斷目前程式，讓作業系統重新取得控制權。作業系統接著可以進行排程，讓其他行程也有機會使用 CPU。這就是 CPU Protection。

### 範例四：User Mode 執行特權指令

假設一般程式嘗試直接設定 timer 或直接啟動 I/O 裝置。因為它正在 User Mode，CPU 會判斷這是非法操作，不允許該指令真正執行。

這種情況會使控制權轉移到作業系統，由作業系統判斷要終止程式、回報錯誤，或採取其他處理。這說明 Dual Mode 與特權指令是硬體保護的基礎。

## 國考常見考法

### 考法一：問 I/O 指令為何要設為特權指令

這類題目的核心答案是：I/O 裝置屬於系統共享資源，若使用者程式可直接控制，會破壞系統安全與穩定，所以 I/O 指令必須只能在 Kernel Mode 執行。

答題時不要只寫「為了安全」。應該補上「防止一般程式直接操作裝置」以及「必須透過作業系統代為執行」。

### 考法二：問 Memory Protection 的常見硬體機制

常見答案包括 base register、limit register、page table、segment table。

如果題目偏基本概念，可以寫 base/limit register 用來檢查位址是否落在合法範圍內。如果題目提到虛擬記憶體或分頁，通常要想到 page table；如果題目提到分段或邏輯區段，則要想到 segment table。

### 考法三：問如何避免程式霸占 CPU

答案要抓住 timer interrupt。

重點是作業系統設定 timer，時間到後硬體產生中斷，讓作業系統取得控制權並進行排程。若只寫「用排程」還不夠完整，因為排程需要 timer interrupt 讓作業系統能定期介入。

### 考法四：問 Dual Mode 的用途

Dual Mode 常被拿來考保護機制的基礎。標準回答是 CPU 提供 User Mode 與 Kernel Mode，讓一般程式在低權限模式執行，作業系統核心在高權限模式執行；特權指令只能在 Kernel Mode 執行，以防止使用者程式破壞系統。

### 考法五：問 system call 和直接執行 I/O 的差別

system call 是合法請求作業系統服務的方式；直接執行 I/O 指令則是一般程式不應被允許的行為。

考題若問「使用者程式如何進行 I/O」，答案不是「直接執行 I/O 指令」，而是「透過 system call 進入 kernel，由作業系統執行 I/O」。

### 考法六：問三種硬體保護分別保護什麼

I/O Protection 保護 I/O 裝置，Memory Protection 保護記憶體空間，CPU Protection 保護 CPU 控制權與公平使用。

這題常以配對題、選擇題或簡答題出現。最好把關鍵字一起背：I/O 對應 privileged instruction，Memory 對應 base/limit、page table、segment table，CPU 對應 timer interrupt。

## 必要比較表與易混淆整理

### 三種硬體保護總整理

| 保護種類 | 要保護的資源 | 主要危險 | 常見硬體機制 | 國考關鍵字 |
| --- | --- | --- | --- | --- |
| I/O Protection | I/O 裝置 | 一般程式直接控制裝置，破壞資料或系統 | 將 I/O 指令設為特權指令 | privileged instruction、kernel mode |
| Memory Protection | 記憶體 | 程式越界存取，改到 OS 或其他程式資料 | base/limit register、page table、segment table | 越界、位址檢查、權限檢查 |
| CPU Protection | CPU 使用權 | 單一程式長時間霸占 CPU | timer interrupt | 計時器中斷、排程、取回控制權 |

### User Mode 與 Kernel Mode 比較

| 比較項目 | User Mode | Kernel Mode |
| --- | --- | --- |
| 執行者 | 一般應用程式 | 作業系統核心 |
| 權限 | 較低 | 較高 |
| 可否執行特權指令 | 不可 | 可以 |
| 常見操作 | 一般計算、呼叫函式、提出 system call | I/O 控制、記憶體管理、行程排程、中斷處理 |
| 保護意義 | 限制一般程式，避免破壞系統 | 讓 OS 能管理重要資源 |

### Base/Limit、Page Table、Segment Table 比較

| 機制 | 白話理解 | 主要用途 | 容易考的重點 |
| --- | --- | --- | --- |
| Base Register | 記錄合法範圍的起點 | 限制程式從哪裡開始存取 | 常與 limit register 一起考 |
| Limit Register | 記錄合法範圍的大小或上限 | 防止位址超出範圍 | 超過範圍會產生錯誤 |
| Page Table | 記錄頁面對應與權限 | 分頁式記憶體管理與保護 | 可檢查讀、寫、執行等權限 |
| Segment Table | 記錄段的起點、長度與權限 | 分段式記憶體管理與保護 | 常見段包含 code、data、stack |

### 易混淆一：Timer Interrupt 不是單純讓程式變快

Timer interrupt 的重點不是提升單一程式速度，而是讓作業系統能定期取回 CPU 控制權。它服務的是公平性、排程與系統控制，不是讓無窮迴圈自動變有效率。

### 易混淆二：Memory Protection 不是只保護作業系統

Memory Protection 同時保護作業系統與各個使用者程式。它防止一般程式寫入 kernel 記憶體，也防止程式彼此破壞資料。

### 易混淆三：System Call 不是一般函式呼叫

一般函式呼叫通常仍在同一個模式中執行；system call 則會讓控制權進入作業系統核心，涉及 User Mode 到 Kernel Mode 的轉換。

### 易混淆四：特權指令不是只有 I/O 指令

I/O 指令是典型特權指令，但不是唯一例子。修改記憶體管理資料、設定 timer、控制中斷等，也通常屬於特權指令，因為這些操作會影響整個系統。

### 易混淆五：Page Table 與 Segment Table 都可用於保護

Page Table 常出現在分頁式記憶體管理，Segment Table 常出現在分段式記憶體管理。兩者形式不同，但都能配合硬體檢查位址與權限，達到記憶體保護。

## 國考答題句

1. I/O Protection 是將 I/O 指令設為特權指令，使其只能在 Kernel Mode 執行，避免使用者程式直接控制 I/O 裝置而破壞系統。

2. Memory Protection 是利用 base/limit register、page table 或 segment table 檢查記憶體位址與權限，防止程式越界存取作業系統或其他行程的記憶體。

3. CPU Protection 是利用 timer interrupt 讓作業系統定期取回 CPU 控制權，避免單一程式長時間霸占 CPU。

4. Dual Mode 將 CPU 執行狀態分為 User Mode 與 Kernel Mode，一般程式在低權限模式執行，作業系統核心在高權限模式執行，以支援特權指令與系統保護。

5. 使用者程式若需要 I/O 服務，應透過 system call 請求作業系統，由 kernel 檢查後代為執行，而不是直接執行 I/O 指令。

6. 當使用者程式在 User Mode 執行特權指令時，硬體會阻止該操作並將控制權交給作業系統處理。

7. Timer interrupt 是行程排程的重要基礎，因為它讓作業系統即使在程式不主動讓出 CPU 時，仍能重新取得控制權。

## 容易考的判斷題

1. I/O 指令通常應設為特權指令，只能在 Kernel Mode 執行。  
   答案：正確。I/O 裝置是共享且敏感的資源，若一般程式能直接控制，可能破壞資料或影響其他程式。

2. User Mode 可以直接執行所有特權指令，只要程式設計師有需要即可。  
   答案：錯誤。特權指令只能在 Kernel Mode 執行，User Mode 若嘗試執行會被硬體阻止。

3. Memory Protection 的目的之一，是防止程式存取不屬於自己的記憶體。  
   答案：正確。它可避免程式破壞作業系統或其他程式的資料。

4. Base register 與 limit register 可用來檢查程式的記憶體存取是否越界。  
   答案：正確。base 表示合法範圍起點，limit 表示大小或界限，硬體可用兩者做範圍檢查。

5. Timer interrupt 的主要目的是防止單一程式永久霸占 CPU。  
   答案：正確。時間到時硬體中斷目前程式，讓作業系統重新取得控制權。

6. CPU Protection 主要依靠 page table 來完成。  
   答案：錯誤。page table 主要用於記憶體管理與保護；CPU Protection 的典型機制是 timer interrupt。

7. Page table 或 segment table 可用於 Memory Protection。  
   答案：正確。兩者都可記錄位址對應與權限資訊，用來防止非法存取。

8. Kernel Mode 權限較低，適合執行一般應用程式。  
   答案：錯誤。Kernel Mode 權限較高，主要供作業系統核心執行。

9. System call 是使用者程式請求作業系統服務的方式。  
   答案：正確。使用者程式透過 system call 進入 kernel，由作業系統提供受控服務。

10. 如果沒有 timer interrupt，無窮迴圈程式可能使作業系統難以重新取得 CPU 控制權。  
    答案：正確。這正是 CPU Protection 要解決的問題。

11. Dual Mode 有助於區分一般程式與作業系統核心的權限。  
    答案：正確。User Mode 與 Kernel Mode 的權限差異，是保護機制的重要基礎。

12. I/O Protection、Memory Protection、CPU Protection 都只需要軟體規定，不需要硬體支援。  
    答案：錯誤。這些保護都需要硬體機制配合，例如 mode bit、特權指令、位址檢查與 timer interrupt。

## 考前速記小抄

硬體保護記三類：I/O、Memory、CPU。

I/O Protection 記一句：I/O 指令設為 privileged instruction，只能在 Kernel Mode 執行。

Memory Protection 記一句：用 base/limit register、page table 或 segment table 防止越界與非法存取。

CPU Protection 記一句：用 timer interrupt 防止單一程式霸占 CPU。

Dual Mode 記兩個模式：User Mode 權限低，跑一般程式；Kernel Mode 權限高，跑作業系統核心。

看到「特權指令」要想到 Kernel Mode；看到「一般程式要做 I/O」要想到 system call；看到「越界存取」要想到 Memory Protection；看到「無窮迴圈霸占 CPU」要想到 timer interrupt。

最短必背版：

| 關鍵字 | 立刻聯想 |
| --- | --- |
| I/O Protection | I/O 指令是特權指令 |
| Memory Protection | base/limit、page table、segment table |
| CPU Protection | timer interrupt |
| Dual Mode | User Mode 與 Kernel Mode |
| User Mode | 權限低，不能執行特權指令 |
| Kernel Mode | 權限高，可執行特權指令 |
| System Call | 使用者程式請 OS 服務 |
| Timer Interrupt | OS 定期取回 CPU 控制權 |

考場答題時，若題目問「為什麼需要硬體保護」，可以寫：硬體保護可防止使用者程式直接操作敏感資源、越界存取記憶體或霸占 CPU，使作業系統能維持安全、穩定與公平的執行環境。
