## 一、I/O 中斷方式：Polling / Interrupt / DMA　【理解】

核心問題：慢速裝置（磁碟、鍵盤）準備資料很慢，**CPU 怎麼知道裝置好了？資料又由誰來搬？** 三種做法效率一個比一個好。

**Polling（輪詢）**
CPU 主動、不斷去問裝置「好了沒？好了沒？」——一直迴圈檢查狀態，直到就緒，再自己搬資料。
- 流程：CPU 反覆問狀態 → 裝置就緒 → CPU 親自搬 → 重複
- 缺點：CPU 一直空轉問（忙碌等待 busy-waiting），浪費超多 CPU 時間
- 比喻：你站在微波爐前一直問「好了沒」，什麼別的都不能做

**Interrupt（中斷）**
CPU 不用一直問。先去做別的事，裝置就緒時**主動發中斷訊號**通知 CPU；CPU 暫停手邊工作、跳去執行中斷服務程式（ISR）處理，處理完再回來。
- 流程：CPU 做別的事 → 裝置發中斷 → CPU 存現場、執行 ISR 搬資料 → 還原、繼續
- 優點：CPU 不用空等，比 polling 有效率
- 缺點：每一筆資料仍是 CPU 親自搬、每筆都中斷，量大時中斷太頻繁
- 比喻：微波爐「叮」一聲叫你，你才去拿，中間能做別的

**DMA（Direct Memory Access，直接記憶體存取）**
加一個 **DMA 控制器**專門搬資料。CPU 只下指令（搬哪、搬多少），DMA 就**直接在裝置和記憶體之間搬一整塊**，全部搬完才發**一次**中斷通知 CPU。
- 流程：CPU 設定 DMA（來源/目的/大小） → DMA 自己搬整塊 → 搬完發一次中斷 → CPU 收尾
- 優點：CPU 幾乎不插手，大量資料傳輸效率最高
- 適合：磁碟、網路等大量資料
- 比喻：請一個助理幫你把整批搬好，搬完才叫你一聲

對照表：

| | Polling 輪詢 | Interrupt 中斷 | DMA |
|---|---|---|---|
| CPU 怎麼知道裝置好了 | 自己一直問 | 裝置發中斷 | DMA 搬完才中斷 |
| 誰搬資料 | CPU 親自 | CPU 親自 | **DMA 控制器** |
| 中斷次數 | 無（一直問） | 每筆一次 | 整塊**只一次** |
| CPU 浪費 | 最多 | 中等 | 最少 |
| 適合 | 少量、簡單 | 中量、互動 | **大量**（磁碟/網路） |

> 一句話記：**效率 Polling < Interrupt < DMA**；CPU 插手程度也是 Polling 最多、DMA 最少。

## 二、三種中斷類型：依「來源」分　【理解】

判斷主軸：**是「別人（外部裝置）打斷你」，還是「你自己（指令）造成的」？**

- **外部中斷（硬體中斷）**：外部裝置引發，跟程式執行**非同步**（隨時可能來）。
  - 可遮罩（Maskable）：CPU 可暫時忽略。例：鍵盤、I/O 完成、計時器。
  - **不可遮罩（NMI）**：**不准忽略**，用於緊急嚴重事件。例：電源失效、硬體故障、記憶體錯誤。
- **內部中斷（例外 Exception）**：正在執行的**指令本身**引發，跟程式**同步**。
  - **Trap（陷阱）**：程式**故意**觸發的，預期內。例：系統呼叫（system call）、除錯中斷點。
  - **Fault（錯誤）**：非預期的執行錯誤。例：除以零、page fault、非法指令。

對照表：

| 類型 | 來源 | 同步? | 例子 |
|---|---|---|---|
| 外部－可遮罩 | 外部裝置 | 非同步 | 鍵盤、I/O 完成、計時器 |
| 外部－**NMI** | 外部嚴重事件 | 非同步 | 電源失效、硬體故障、記憶體錯誤 |
| 內部－**Trap** | 程式**故意**觸發 | 同步 | 系統呼叫、除錯中斷點 |
| 內部－Fault | 指令出錯 | 同步 | 除以零、page fault、非法指令 |

> 關鍵字記法：**外部 = 別人打斷（非同步）、內部 = 自己造成（同步）；NMI = 緊急到不准忽略；Trap = 故意的（system call）。**

## 三、硬體保護：I/O / Memory / CPU Protection　【理解】

為什麼要保護：多工/多人系統裡，要防止一個（出包或惡意的）程式搞壞別人或 OS。共同精神：**危險動作只准 OS（核心模式）做，硬體負責把關，出事就 trap 給 OS。**

| 保護 | 防止什麼 | 硬體機制（運作） |
|---|---|---|
| **I/O Protection** | 程式亂下 I/O 指令，搞亂裝置或偷別人資料 | 把 I/O 指令設成**特權指令**，只能核心模式執行；使用者要 I/O 得透過系統呼叫請 OS 代勞 |
| **Memory Protection** | 程式讀寫到別人或 OS 的記憶體 | 用**基底暫存器（Base）+ 限長暫存器（Limit）** 界定合法範圍；每次存取硬體檢查位址是否落在 [Base, Base+Limit) 內，越界就中斷 |
| **CPU Protection** | 程式無窮迴圈、霸佔 CPU 不放 | 用**計時器（Timer）**；OS 設時間，時間到就中斷、把 CPU 收回重新排程 |

> 一句話記法：**I/O 靠「特權指令」、Memory 靠「Base/Limit」、CPU 靠「Timer」。** 三者都是「硬體把關 ＋ 出事交給 OS」。
