## 名詞解釋

### 作業系統結構

作業系統結構指的是作業系統內部如何分工、哪些功能放在核心裡、哪些功能放在核心外，以及使用者程式要如何透過作業系統取得硬體資源。國考常考的重點不是要背某一套實作細節，而是要知道「使用者、應用程式、系統呼叫、核心、硬體」之間的關係。

可以先用一句話理解：作業系統站在使用者程式與硬體之間，負責提供安全、方便且有效率的服務。

### Command / Shell

Command 是使用者輸入給電腦的命令，例如列出檔案、建立資料夾、執行程式。Shell 是接收命令並與作業系統溝通的命令介面。

白話來說，Shell 像是使用者和作業系統之間的櫃台人員。使用者不需要直接碰硬體，只要輸入命令，Shell 會解讀命令，再請作業系統完成工作。

常見觀念是：Shell 本身不是作業系統核心，而是讓使用者可以操作作業系統的一種介面。

### System Call

System Call 稱為系統呼叫，是使用者程式向作業系統請求服務的介面。一般應用程式不能直接任意操作硬體或核心資源，因此需要透過 System Call 請作業系統代為處理。

例如程式要開檔、讀檔、建立行程、配置記憶體、做輸入輸出，都會透過 System Call 向作業系統提出請求。

白話來說，System Call 像是正式申請表。應用程式不能自己闖進核心區改資料，而是要透過規定好的入口，請作業系統幫忙。

### Kernel

Kernel 是作業系統核心，負責最重要、最接近硬體與系統資源管理的工作。它通常負責行程管理、記憶體管理、檔案系統、輸入輸出、保護機制與排程。

白話來說，Kernel 像是作業系統的中樞。它決定哪個程式可以使用 CPU、記憶體如何分配、檔案如何存取，以及裝置輸入輸出如何被管理。

國考常把 Kernel 和 Shell 混在一起考。要記得：Shell 是使用者操作介面，Kernel 是真正管理系統資源的核心部分。

### Monolithic Kernel

Monolithic Kernel 通常翻成單體式核心。它把許多作業系統服務放在核心空間中，例如行程管理、記憶體管理、檔案系統、裝置驅動程式等。

它的好處是功能集中，核心內部呼叫速度快，所以效能通常較好。缺點是核心比較龐大，若核心內某個模組發生錯誤，可能影響整個系統的穩定性。

白話來說，Monolithic Kernel 像是把很多重要部門都放在同一棟管制大樓內，溝通很快，但大樓裡任何重要區域出問題，影響範圍也可能很大。

### Microkernel

Microkernel 稱為微核心。它的設計思想是讓核心盡量小，只保留最基本、最必要的功能，例如低階行程管理、基本記憶體管理、基本通訊機制等。其他服務如檔案系統、部分裝置驅動程式，會盡量移到使用者空間執行。

它的優點是模組化、可靠性與可維護性較好。因為許多服務不在核心內，即使某個服務失敗，也比較不容易直接拖垮整個核心。缺點是服務之間常需要透過 IPC 溝通，因此可能增加額外成本。

IPC 是 Inter-Process Communication，意思是行程間通訊。當檔案系統、驅動程式等服務被移到使用者空間後，它們需要和核心或其他服務互相傳訊息，這些訊息傳遞會花時間。

### User Space 與 Kernel Space

User Space 是一般應用程式執行的區域，權限較低，不能任意操作硬體或核心資料。Kernel Space 是核心執行的區域，權限較高，可以管理硬體與系統資源。

這種分隔是為了保護系統。若一般程式可以直接修改核心資料，一個錯誤或惡意程式就可能讓整台電腦失控。

白話來說，User Space 像一般辦公區，Kernel Space 像機房和總控室。一般人可以提出申請，但不能直接進去亂動設備。

### Virtual Machine

Virtual Machine 稱為虛擬機器，是在實體硬體上模擬出一個或多個虛擬硬體環境，讓每個虛擬機器可以像一台獨立電腦一樣安裝與執行作業系統。

白話來說，一台實體電腦可以透過虛擬化技術切出多台「看起來像獨立電腦」的環境。每個虛擬機器有自己的作業系統、應用程式與資源配置。

虛擬機器的核心價值是隔離與彈性。不同虛擬機器彼此隔開，適合測試、伺服器整併、跨平台執行與降低硬體使用浪費。

## 核心想法

作業系統結構最重要的概念，是分清楚「誰負責跟誰溝通」。

使用者通常不會直接操作 Kernel，而是透過 Shell 或圖形介面下達命令。應用程式要使用檔案、記憶體、行程或輸入輸出資源時，會透過 System Call 請求 Kernel 服務。Kernel 再負責管理 CPU、記憶體、磁碟、螢幕、鍵盤、網路卡等硬體資源。

因此，可以把基本流程記成：

使用者或應用程式提出需求，透過 Shell 或 System Call 進入作業系統服務，Kernel 負責協調硬體與系統資源，最後把結果交回使用者或應用程式。

另一個核心想法，是不同作業系統結構會在「效能」與「可靠、模組化」之間取捨。Monolithic Kernel 把很多功能放在核心內，溝通快、效能好，但核心龐大。Microkernel 把核心縮小，把許多服務移到核心外，可靠與維護性較佳，但因為需要更多訊息傳遞，可能有 IPC 成本。

虛擬機器則是另一種重要結構觀念。它不是單純的 Shell 或 Kernel，而是透過虛擬化，在同一套實體硬體上建立多個隔離的執行環境。它常被用來測試不同作業系統、隔離服務、整併伺服器與提升部署彈性。

## 具體範例

### 範例一：使用 Shell 列出檔案

假設使用者在命令列輸入列出資料夾內容的命令。Shell 會先解析這個命令，知道使用者想查看某個目錄底下的檔案。接著，相關程式會透過 System Call 向 Kernel 請求讀取檔案系統資訊。

Kernel 收到請求後，會檢查權限，確認使用者是否可以讀取該目錄，再透過檔案系統與磁碟裝置取得資料。最後，結果回到程式並顯示在畫面上。

這個例子要看懂三個角色：Shell 負責接收命令，System Call 是請求服務的入口，Kernel 負責真正管理與存取系統資源。

### 範例二：程式開啟檔案

一個文字編輯器想開啟檔案時，不會直接控制磁碟讀取資料。它會呼叫作業系統提供的檔案開啟服務，也就是透過 System Call 要求 Kernel 協助。

Kernel 會檢查檔案是否存在、權限是否允許、目前系統資源是否足夠，然後建立檔案存取所需的資料結構。若成功，程式就能讀取檔案內容；若失敗，作業系統會回傳錯誤訊息。

這類題目常用來考 System Call 的功能範圍：檔案、行程、記憶體、I/O 都是典型服務。

### 範例三：Microkernel 中的檔案服務

在 Microkernel 設計中，檔案系統可能不是放在 Kernel Space，而是作為 User Space 的服務執行。當應用程式要讀檔時，可能需要透過核心的訊息傳遞機制，把請求送到檔案系統服務，再由服務處理後回傳。

這樣的好處是，如果檔案系統服務發生問題，理論上較容易重新啟動或隔離錯誤，不一定會直接破壞整個核心。缺點是請求需要經過更多訊息傳遞，比起核心內直接呼叫可能多出成本。

### 範例四：用虛擬機器測試新系統

假設一位工程師想測試新的作業系統版本，但不想破壞原本電腦環境，就可以建立一台虛擬機器，在裡面安裝測試用的作業系統。

如果測試失敗，通常只要刪除或還原虛擬機器即可，不會直接影響實體主機的主要系統。這就是虛擬機器隔離性與易於測試的典型優點。

## 國考常見考法

國考常先考名詞定義，再考比較。最基本的題型是問 Shell、System Call、Kernel 的差異。遇到這種題目時，要先判斷題目問的是「使用者介面」、「程式請求服務的介面」，還是「作業系統核心」。

如果題目問「使用者與作業系統互動的命令介面」，答案通常是 Command 或 Shell。如果題目問「使用者程式向作業系統要求服務的介面」，答案通常是 System Call。如果題目問「負責行程、記憶體、檔案系統、I/O、保護與排程」，答案通常是 Kernel。

第二種常見考法是比較 Monolithic Kernel 和 Microkernel。題目常用關鍵字提示：功能集中、效能佳、核心龐大，多半指 Monolithic Kernel；核心最小化、服務移到 User Space、模組化、可靠性較高、IPC 成本較高，多半指 Microkernel。

第三種常見考法是虛擬機器的優缺點。若題目提到隔離、可移植、易於測試、伺服器整併，通常是在描述虛擬機器優點。若題目提到額外效能負擔、資源需求高、管理複雜，通常是在描述虛擬機器缺點。

第四種考法是敘述判斷。題目可能說「Microkernel 一定比 Monolithic Kernel 效能好」，這通常是錯的，因為 Microkernel 雖然可靠與模組化較佳，但 IPC 成本可能降低效能。題目也可能說「Shell 就是 Kernel」，這也是錯的，因為 Shell 是介面，Kernel 是核心。

## 必要比較表與易混淆整理

### Shell、System Call、Kernel 比較

| 名詞 | 白話定位 | 主要功能 | 常見考點 |
| --- | --- | --- | --- |
| Shell | 使用者操作作業系統的命令介面 | 接收並解讀使用者命令 | 它不是核心，而是互動介面 |
| System Call | 應用程式請求作業系統服務的入口 | 讓程式請求檔案、行程、記憶體、I/O 等服務 | 它是 user program 和 OS 之間的重要介面 |
| Kernel | 作業系統核心 | 管理行程、記憶體、檔案系統、I/O、保護與排程 | 它負責真正的資源管理 |

### Monolithic Kernel 與 Microkernel 比較

| 比較項目 | Monolithic Kernel | Microkernel |
| --- | --- | --- |
| 核心大小 | 較大，許多服務集中在核心內 | 較小，只保留最基本功能 |
| 服務位置 | 檔案系統、驅動等常在 Kernel Space | 檔案系統、驅動等盡量移到 User Space |
| 效能 | 通常較好，核心內呼叫成本較低 | 可能因 IPC 產生額外成本 |
| 可靠性 | 某個核心模組出錯可能影響整體 | 服務較分離，可靠性通常較佳 |
| 維護性 | 核心龐大，維護較複雜 | 模組化程度高，較容易維護 |
| 國考關鍵字 | 功能集中、效能好、核心龐大 | 核心最小化、模組化、可靠、IPC 成本 |

### Virtual Machine 優缺點比較

| 類別 | 內容 | 白話理解 |
| --- | --- | --- |
| 優點 | 隔離性 | 每台虛擬機器像獨立環境，彼此影響較小 |
| 優點 | 可移植 | 虛擬機器映像較容易搬到其他主機執行 |
| 優點 | 易於測試 | 測試失敗時可還原或重建環境 |
| 優點 | 伺服器整併 | 多個服務可放在同一台實體主機上的不同虛擬機器 |
| 缺點 | 額外效能負擔 | 多一層虛擬化管理，執行可能較慢 |
| 缺點 | 資源需求高 | 每台虛擬機器都需要 CPU、記憶體、儲存空間等資源 |
| 缺點 | 管理較複雜 | 虛擬機器數量多時，設定、監控與維護成本上升 |

### 易混淆整理

Shell 和 System Call 都是「介面」，但面向不同。Shell 面向使用者，讓人可以操作作業系統；System Call 面向程式，讓程式可以請求作業系統服務。

Kernel 和 Microkernel 不是同一層級的普通名詞。Kernel 泛指作業系統核心；Microkernel 是一種核心設計方式，強調讓核心盡量小。

Monolithic Kernel 和 Microkernel 的比較，不是單純誰一定比較好，而是設計取捨不同。Monolithic Kernel 常在效能上有優勢；Microkernel 常在可靠性、模組化、可維護性上有優勢。

Virtual Machine 不是把 Shell 複製很多份，也不是只開很多使用者帳號。它是模擬出虛擬硬體環境，讓多個作業系統或隔離環境能在同一台實體硬體上運作。

## 國考答題句

Shell 是使用者與作業系統互動的命令介面，負責接收並解讀使用者輸入的命令。

System Call 是使用者程式向作業系統核心請求服務的介面，常用於檔案、行程、記憶體與 I/O 操作。

Kernel 是作業系統核心，負責管理行程、記憶體、檔案系統、I/O、保護與排程等系統資源。

Monolithic Kernel 將多數作業系統服務集中於核心中，通常效能較佳，但核心龐大且錯誤影響範圍可能較大。

Microkernel 將核心功能最小化，並把部分服務移至 User Space，以提升模組化、可靠性與可維護性，但可能增加 IPC 成本。

Virtual Machine 是在實體硬體上模擬出的虛擬硬體環境，可提升隔離性、可移植性與測試便利性，但會帶來額外效能負擔與較高資源需求。

## 容易考的判斷題

1. Shell 是使用者與作業系統互動的命令介面。  
   答：對。Shell 負責接收使用者命令並協助操作作業系統。

2. System Call 是使用者程式向作業系統請求服務的介面。  
   答：對。程式要存取檔案、建立行程或進行 I/O 時，通常需要透過 System Call。

3. Kernel 的主要工作是管理行程、記憶體、檔案系統、I/O、保護與排程。  
   答：對。這些都是作業系統核心常見職責。

4. Shell 就是 Kernel。  
   答：錯。Shell 是使用者介面，Kernel 是作業系統核心。

5. 一般使用者程式可以直接任意操作硬體，不需要透過作業系統。  
   答：錯。為了保護與管理資源，使用者程式通常要透過 System Call 請求作業系統服務。

6. Monolithic Kernel 通常把許多服務集中在核心內，因此核心較龐大。  
   答：對。這是單體式核心的重要特徵。

7. Monolithic Kernel 一定比 Microkernel 更可靠。  
   答：錯。Monolithic Kernel 效能可能較好，但 Microkernel 因模組化與服務分離，可靠性通常較佳。

8. Microkernel 將核心功能最小化，並把部分服務移到 User Space。  
   答：對。這正是微核心設計的重點。

9. Microkernel 完全沒有任何效能成本。  
   答：錯。Microkernel 可能因 IPC 與訊息傳遞增加額外成本。

10. Virtual Machine 可以用於測試不同作業系統環境。  
    答：對。虛擬機器提供隔離環境，常用於測試與部署。

11. Virtual Machine 的優點包含隔離性與伺服器整併。  
    答：對。多個虛擬機器可在同一台實體主機上執行，並彼此隔離。

12. Virtual Machine 沒有任何資源負擔。  
    答：錯。虛擬機器需要 CPU、記憶體、儲存空間等資源，也可能有額外效能負擔。

## 考前速記小抄

Shell：人用的命令介面。看到「使用者與 OS 互動」就想到 Shell。

System Call：程式用的正式請求入口。看到「使用者程式向 OS 請求服務」就想到 System Call。

Kernel：作業系統核心。看到「行程、記憶體、檔案系統、I/O、保護、排程」就想到 Kernel。

Monolithic Kernel：核心大、功能集中、效能好，但錯誤影響可能大。

Microkernel：核心小、服務外移、模組化、可靠性較好，但 IPC 成本可能較高。

Virtual Machine：一台實體機器模擬多台虛擬硬體環境。優點是隔離、可移植、易測試、伺服器整併；缺點是效能負擔、資源需求高、管理較複雜。

最常用判斷口訣：

Shell 給人用，System Call 給程式用，Kernel 管資源。

單體式核心重效能，微核心重模組與可靠，但要小心 IPC 成本。

虛擬機器重隔離與彈性，但不是免費，會吃資源也會增加管理成本。
