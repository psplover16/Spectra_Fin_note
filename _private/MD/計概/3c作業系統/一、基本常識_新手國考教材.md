## 名詞解釋

**作業系統（Operating System, OS）**：作業系統是電腦中負責「管理硬體資源」與「提供使用者或應用程式操作介面」的系統軟體。白話來說，使用者不需要直接控制 CPU、記憶體、硬碟、印表機等硬體，而是透過作業系統幫忙安排誰先用、用多久、怎麼用。

**CPU（Central Processing Unit，中央處理器）**：CPU 是電腦執行指令與運算的核心。國考常把 CPU 想成「主要工作者」，但 CPU 速度通常比 I/O 設備快很多，因此作業系統必須想辦法減少 CPU 空等。

**I/O（Input/Output，輸入輸出）**：I/O 指資料進出電腦的動作或設備，例如鍵盤輸入、螢幕輸出、磁碟讀寫、印表機列印、網路傳輸。I/O 設備通常速度較慢，所以作業系統常用緩衝、快取、排隊等方法改善效率。

**工作（Job）**：工作是交給電腦處理的一個任務，例如列印一份文件、編譯一個程式、執行一批薪資計算。批次系統常以「工作」為單位安排處理順序。

**使用者（User）**：使用者是操作系統資源的人或程式。分時系統常強調多個使用者同時共享同一台主機，因此作業系統必須公平分配 CPU 時間並維持回應速度。

**回應時間（Response Time）**：回應時間是使用者送出請求後，到系統開始或完成回應所花的時間。分時系統重視回應時間，因為使用者希望輸入指令後很快看到結果。

**截止時間（Deadline）**：截止時間是某項工作必須完成的期限。即時系統重視 deadline，因為太晚完成可能造成嚴重後果，尤其是 hard real-time 系統。

**批次系統（Batch System）**：批次系統是把大量工作收集起來，再由系統依序或成批處理。它的特色是互動性低，使用者通常不會邊執行邊和系統對話，適合大量、固定、可排程的工作。

**分時系統（Time-Sharing System）**：分時系統是讓多個使用者或多個程式共享 CPU。作業系統會把 CPU 時間切成很短的時間片，輪流分配給不同工作，使大家感覺像是同時使用電腦。

**即時系統（Real-Time System）**：即時系統重點不是單純追求最快，而是必須在規定時間內完成工作。國考常考它與一般系統不同：一般系統重視平均效率，即時系統重視是否準時。

**硬式即時系統（Hard Real-Time System）**：硬式即時系統是 deadline 絕對不能錯過的系統。一旦逾時，可能造成生命、設備或任務重大損失，例如飛航控制、汽車安全氣囊控制、醫療儀器控制。

**軟式即時系統（Soft Real-Time System）**：軟式即時系統希望盡量準時，但偶爾延遲不會造成災難，只會降低服務品質，例如影音串流、線上遊戲、視訊會議。

**分散式系統（Distributed System）**：分散式系統是由多台電腦透過網路連接並協同工作，對使用者而言可能像是一個整體系統。它的重點在於多台機器分工、通訊與資源共享。

**嵌入式系統（Embedded System）**：嵌入式系統是放在專用設備中的作業系統或控制系統，通常只負責特定功能，例如家電、汽車電子設備、路由器、提款機、智慧手錶。

**行動作業系統（Mobile OS）**：行動作業系統是為手機、平板等行動裝置設計的作業系統，例如 Android、iOS。它通常特別重視觸控操作、電池管理、行動網路、感測器與應用程式權限。

**網路作業系統（Network Operating System）**：網路作業系統重點在提供網路資源共享與管理，例如檔案共享、印表機共享、帳號權限控管、遠端登入與網路服務管理。

**並行（Concurrency）**：並行是指多個工作在同一段時間內交錯推進。它不保證同一瞬間真的有多個工作同時執行；在單核心 CPU 上，也可以透過快速切換造成「看起來一起做」的效果。

**平行（Parallelism）**：平行是指多個工作在同一時刻真的同時執行。通常需要多核心 CPU、多處理器或多台機器，因為同一時間必須有多個運算單元可以一起工作。

**離線作業（Offline Operation）**：離線作業是把 I/O 或資料準備工作與主機執行分開處理，讓主機不必一直等待慢速設備。它的精神是「先在旁邊準備好，再交給主機處理」。

**假離線技術（Spooling）**：Spooling 是用磁碟模擬慢速或獨占設備的排隊功能，最典型例子是列印佇列。使用者送出列印後，資料先存到磁碟佇列，印表機再依序列印，使用者不必一直占用程式等待印完。

**緩衝（Buffering）**：緩衝是使用一塊暫存區，吸收資料生產者與資料消費者之間的速度差。例如鍵盤輸入速度、人看螢幕速度、磁碟讀寫速度都可能不同，buffer 可以讓資料暫時停放，避免一方太快或太慢造成阻塞。

**快取（Cache）**：快取是把近期常用或可能很快再用到的資料，放在速度較快的位置，以減少下次存取時間。快取的關鍵是「利用常用資料會再被使用的可能性」來換取速度。

## 核心想法

作業系統的基本常識可以用一句話抓住：**作業系統負責管理有限資源，讓不同工作能有效率、可控制、可預期地使用電腦**。CPU、記憶體、磁碟、網路與各種 I/O 設備都不是無限的，作業系統必須安排誰先執行、誰等待、資料暫存在哪裡，以及如何讓使用者覺得系統順暢。

OS 分類通常不是在問「哪一種比較高級」，而是在問「這種系統最重視什麼」。批次系統重視大量工作處理，分時系統重視多使用者互動與回應時間，即時系統重視 deadline，分散式系統重視多台電腦協同，嵌入式系統重視特定設備功能，行動作業系統重視行動裝置需求，網路作業系統重視網路資源管理。

並行與平行是國考很愛混淆的基本題。並行強調「同一段時間內都在推進」，重點是工作之間交錯進行；平行強調「同一時刻真的同時執行」，重點是有多個處理單元一起做。單核心電腦可以做並行，但通常不能做到真正的 CPU 平行運算。

Offline、Spooling、Buffering、Cache 都和「速度落差」有關，但解法不同。Offline 是把作業切開，讓主機少等 I/O；Spooling 是用磁碟建立佇列，讓慢速設備依序處理；Buffering 是用暫存區平衡兩端速度；Cache 是保留常用資料以加速再次存取。考試若只背中文翻譯很容易錯，必須抓住它們各自解決的問題。

## 具體範例

批次系統像是公司月底薪資計算。人事部門先把大量員工資料準備好，再交給系統一次處理。這種情境不需要每筆資料都即時互動，只要系統能大量、穩定、依序完成即可，因此很符合 batch 的精神。

分時系統像是多位學生同時登入同一台主機寫程式。CPU 其實在很短時間內輪流服務不同使用者，但因為切換速度很快，每個人都覺得系統有在回應自己。這種系統的重點不是單一工作最快完成，而是讓多個使用者都有合理的互動體驗。

即時系統像是汽車安全氣囊控制。碰撞發生時，系統必須在極短時間內做出反應；如果延遲，即使最後算出正確結果也沒有意義。這就是 hard real-time 的典型特色：結果正確還不夠，時間也必須正確。

軟式即時系統像是影片串流。影片播放時偶爾延遲或畫質下降會影響體驗，但通常不會造成災難。它仍然重視時間限制，只是 deadline 沒有 hard real-time 那麼絕對。

分散式系統像是雲端服務背後由多台伺服器共同提供服務。使用者可能只看到一個網站或 App，但背後可能有多台機器分別負責資料庫、檔案儲存、登入驗證、負載平衡。考題看到「多台電腦協同工作」時，通常要想到 distributed。

嵌入式系統像是微波爐或路由器內部的控制程式。它不是為了讓使用者自由安裝各式各樣的大型軟體，而是為了讓特定設備完成固定功能，因此常有資源有限、功能專用、穩定性要求高等特色。

行動作業系統像 Android 與 iOS。手機不只要執行 App，也要處理觸控、相機、GPS、行動網路、電池續航與應用程式權限。國考若問手機和平板常見 OS 類型，就要答行動作業系統。

網路作業系統像是管理公司內部檔案伺服器的系統。它可以讓不同使用者依權限存取共享資料夾，也可以管理印表機、帳號、群組與遠端連線。重點在「網路資源共享與管理」。

並行與平行可用廚師煮菜理解。一位廚師一下切菜、一下煮湯、一下炒菜，雖然同一瞬間只能做一件事，但多道菜在同一段時間內都有進展，這是 concurrency。多位廚師同時各自做一道菜，才是 parallelism，因為同一時刻真的有多個工作同時進行。

Spooling 最常見例子是列印。假設很多人同時列印文件，印表機一次只能印一份，如果每個程式都等印表機印完才繼續，效率會很差。Spooling 讓列印資料先進入磁碟佇列，程式可以較快釋放，印表機再慢慢依序列印。

Buffering 像是看影片時先載入一小段資料。網路傳輸速度可能忽快忽慢，播放器先把一部分資料放入 buffer，播放端就不必每秒都完全依賴即時下載速度。Buffer 不一定讓資料變得更常用，它主要是吸收速度不一致。

Cache 像是瀏覽器把常看的圖片或網頁資料暫存在本機。下次再開同一頁時，如果資料沒有改變，就可以從本機較快讀取，不必每次都重新從網路下載。Cache 的重點是加速重複存取。

## 國考常見考法

第一種考法是給情境問 OS 類型。看到「大量工作、互動少、集中處理」通常選批次系統；看到「多使用者共享 CPU、重視回應時間」通常選分時系統；看到「必須在期限內完成」通常選即時系統；看到「多台電腦協同」通常選分散式系統。

第二種考法是問 hard real-time 與 soft real-time 的差別。hard real-time 的 deadline 不能錯過，錯過就是系統失敗；soft real-time 的 deadline 可以偶爾錯過，但服務品質會下降。考題若出現飛航控制、醫療控制、汽車安全控制，多半偏 hard real-time；若出現影音串流、線上遊戲、視訊會議，多半偏 soft real-time。

第三種考法是混淆 concurrency 與 parallelism。題目若強調「交錯執行」「同一段時間內推進」「不一定同時」，答案是 concurrency；若強調「同一時刻同時執行」「多核心」「多處理器」，答案是 parallelism。

第四種考法是比較 Offline、Spooling、Buffering、Cache。題目若說把慢速輸出工作排在磁碟佇列，多半是 Spooling；若說用暫存區調和速度差，多半是 Buffering；若說保存常用資料以便下次更快讀取，多半是 Cache；若說讓資料準備或 I/O 與主機分離，減少主機等待，多半是 Offline。

第五種考法是問採用這些技術的理由。常見答案包括解決 CPU 與 I/O 速度落差、提高 CPU 使用率、提高 I/O 設備利用率、降低等待時間、改善系統吞吐量或回應效率。不要只答「比較快」，因為國考通常要看到資源利用率與等待時間的概念。

### Hard Real-Time 與 Soft Real-Time 比較表

| 比較項目 | Hard Real-Time | Soft Real-Time |
|---|---|---|
| Deadline 嚴格程度 | 絕對不能錯過 | 盡量不要錯過 |
| 錯過後果 | 系統失敗或造成嚴重損害 | 服務品質下降 |
| 典型例子 | 飛航控制、安全氣囊、醫療控制 | 影音串流、線上遊戲、視訊會議 |
| 考試判斷 | 時間錯了就算答案正確也沒用 | 偶爾延遲可容忍 |

### 常見易混淆重點

批次系統與分時系統都可能處理很多工作，但批次系統偏向「收集後成批處理」，使用者互動少；分時系統偏向「多使用者即時互動」，重視每個人都能得到快速回應。

分散式系統與網路作業系統都和網路有關，但分散式系統強調多台電腦共同完成任務；網路作業系統強調透過網路管理與共享資源，例如檔案、印表機、帳號與權限。

Buffering 與 Cache 都會用到暫存空間，但目的不同。Buffering 是為了解決兩端速度不一致，Cache 是為了讓常用資料下次更快取得。若題目出現「生產者與消費者速度差」，通常是 buffering；若出現「近期常用資料」，通常是 cache。

Spooling 與 Buffering 都可能暫存資料，但 spooling 常使用磁碟形成佇列，處理慢速或獨占設備，列印是最典型例子；buffering 則不一定是排隊裝置，重點是讓資料傳送兩端速度更平順。

## 國考答題句

- 作業系統是管理電腦硬體資源並提供使用者與應用程式操作介面的系統軟體。
- 批次系統將大量工作集中成批處理，互動性低，適合大量且可排程的作業。
- 分時系統利用時間片讓多個使用者共享 CPU，重點在公平分配與縮短回應時間。
- 即時系統要求工作在 deadline 前完成，重點是準時性而不只是平均速度。
- Hard real-time 系統錯過 deadline 即視為失敗；soft real-time 系統偶爾延遲只會降低服務品質。
- 分散式系統由多台電腦透過網路協同工作並共享資源。
- 嵌入式系統是用於專用設備中的系統，通常功能固定且資源有限。
- Concurrency 是多工作在同一時間段內交錯進行，不一定同時執行。
- Parallelism 是多工作在同一時刻真正同時執行，通常需要多核心或多處理器。
- Spooling 使用磁碟作為佇列，常用於列印等慢速或獨占設備。
- Buffering 使用緩衝區吸收生產者與消費者之間的速度差。
- Cache 保存近期常用資料，以提升後續存取速度。

## 容易考的判斷題

1. 批次系統的特色是高度互動，使用者可以即時與每個工作對話。  
   **錯。**批次系統通常互動性低，重點在大量工作集中處理。

2. 分時系統讓多個使用者共享 CPU，因此特別重視回應時間。  
   **對。**分時系統透過時間片輪流服務多個使用者，讓互動操作不會等太久。

3. 即時系統的重點一定是讓平均執行速度最快。  
   **錯。**即時系統重點是能否在 deadline 前完成，而不是只看平均速度。

4. Hard real-time 系統若錯過 deadline，即使最後結果正確，也可能算系統失敗。  
   **對。**Hard real-time 的時間限制是正確性的一部分。

5. Soft real-time 系統完全不重視時間限制。  
   **錯。**Soft real-time 仍重視時間，只是偶爾延遲通常不會造成災難。

6. Concurrency 一定需要多核心 CPU。  
   **錯。**單核心也能透過快速切換達成並行效果。

7. Parallelism 表示多個工作在同一時刻真正同時執行。  
   **對。**平行的重點是真正同時，常需要多核心、多處理器或多台機器。

8. 一位廚師交替切菜、煮湯、炒菜，是 parallelism 的例子。  
   **錯。**這是 concurrency，因為同一瞬間仍只有一位廚師在做一件事。

9. Spooling 常用磁碟作為佇列，列印佇列是典型例子。  
   **對。**印表機一次只能處理有限工作，用磁碟佇列可減少程式等待。

10. Buffering 的主要目的之一是吸收生產者與消費者的速度差。  
    **對。**Buffer 讓資料先暫存，減少速度不一致造成的停頓。

11. Cache 的目的主要是保存近期常用資料，以加快再次存取。  
    **對。**快取利用資料重複使用的可能性提升速度。

12. Buffering 和 Cache 完全相同，只是名稱不同。  
    **錯。**Buffering 重點是速度差，Cache 重點是常用資料的快速再存取。

13. 分散式系統一定只有一台電腦。  
    **錯。**分散式系統的核心就是多台電腦協同工作。

14. Android 與 iOS 屬於行動作業系統。  
    **對。**它們主要用於手機、平板等行動裝置。

15. 網路作業系統的重點是提供網路資源共享與管理。  
    **對。**例如共享檔案、印表機、帳號權限與遠端服務。

## 考前速記小抄

**OS 本質**：管理硬體資源，提供使用者與程式操作介面。

**批次系統**：大量工作、集中處理、互動性低。

**分時系統**：多使用者、共享 CPU、時間片、重視回應時間。

**即時系統**：重視 deadline；hard 不能逾時，soft 可偶爾延遲但品質下降。

**分散式系統**：多台電腦透過網路協同工作。

**嵌入式系統**：專用設備、固定功能、資源常受限。

**行動作業系統**：Android、iOS；手機平板、觸控、電池、感測器。

**網路作業系統**：網路資源共享與管理，常見檔案、印表機、帳號、權限。

**Concurrency**：同一段時間交錯推進，不一定同時；一位廚師交替做多道菜。

**Parallelism**：同一時刻真的同時執行；多位廚師同時做菜。

**Offline**：I/O 或資料準備與主機執行分離，減少主機等待。

**Spooling**：磁碟佇列，最常考列印佇列。

**Buffering**：緩衝區吸收速度差，重點是生產者與消費者速度不同。

**Cache**：保存近期常用資料，加速下次存取。

**最常見陷阱**：並行不等於平行；即時不等於最快；buffer 不等於 cache；分散式不等於單純有網路。
