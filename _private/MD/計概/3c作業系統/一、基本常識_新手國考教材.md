# 作業系統 1：OS 基礎概念

> 科目：計算機原理 — 作業系統（背誦型：概念 + 對照表）

---

## 一、OS 分類比較表

| 類型 | 定義（一句話） | 優點 | 缺點 | 實例 |
|---|---|---|---|---|
| **批次處理 Batch** | 把工作集中成一批，依序自動處理，**無使用者互動** | 吞吐量高、自動化 | 不能互動、回應慢、除錯難 | 早期主機月結帳 |
| **多元程式 Multiprogramming** | 記憶體同時放多個工作，某個在等 I/O 時 CPU 改做另一個 | **CPU 利用率高** | 排程、記憶體管理複雜 | 早期多工主機 |
| **分時 Time-sharing** | 把 CPU 時間切成小片，輪流給多個使用者，可即時互動 | 多人互動、回應快 | 切換有 overhead、需保護機制 | UNIX、Linux |
| **即時 Real-time** | 必須在**時限內**完成回應 | 即時、可預測 | 彈性低、設計嚴格 | 硬性：飛彈/醫療；軟性：串流影音 |
| **分散式 Distributed** | 多台電腦透過網路共享資源、協同運算 | 資源共享、可靠、易擴充 | 複雜、依賴網路、安全議題 | 雲端、叢集運算 |

> 即時系統再細分：**硬性即時**（錯過時限 = 失敗，如醫療、飛彈）、**軟性即時**（盡量達成，偶爾遲到可接受，如影音串流）。

## 二、Concurrency（並行）vs Parallelism（平行）

這兩個最容易混，用「廚師煮菜」一次記住：

| | **Concurrency 並行** | **Parallelism 平行** |
|---|---|---|
| 一句話 | 交錯處理多件事（**看起來**同時） | **真的**同時做多件事 |
| 廚師比喻 | **一個廚師**輪流顧多道菜：切 A → 顧 B → 回來弄 A，快速切換，但同一瞬間只做一件 | **多個廚師**各炒一道菜，真的同時進行 |
| 硬體需求 | 單核 CPU 就能做（靠快速切換） | 需要**多核 / 多 CPU** |
| 重點是 | 「如何**結構化**地處理多工」 | 「同時**執行**」 |

> 記憶鉤子：**並行 = 一個廚師輪流煮；平行 = 多個廚師同時煮。** 並行不一定平行（單核也能並行），平行一定是並行的一種實現。

## 三、Offline / Spooling / Buffering / Cache（定義 + 為何要用）

| 技術 | 定義 | 為何用（解決什麼） |
|---|---|---|
| **Offline 離線** | I/O 不直接接 CPU，先把資料存到中間媒介（如磁帶），CPU 之後再處理 | 早期讓慢速 I/O 與 CPU 分離，但兩者**不重疊** |
| **Spooling** | 用**磁碟**當緩衝池，讓慢速裝置（印表機）與 CPU **重疊**作業，多個工作可排隊 | 讓 CPU 不必空等慢速裝置，且支援多工排隊（如列印佇列） |
| **Buffering 緩衝** | 在**記憶體**開一塊區暫存資料，當生產/消費速度不一致時不用互相等 | 平衡速度差、讓 I/O 與計算重疊 |
| **Cache 快取** | 把常用資料放在更快、離 CPU 更近的儲存，下次直接取 | 利用 locality（區域性）加速「**重複存取**」 |

> Spooling 是 **S**imultaneous **P**eripheral **O**perations **O**n-**L**ine 的縮寫。

易混淆一次釐清：

- **Offline**：完全分開、**不重疊**（最舊的解法）。
- **Spooling**：**重疊**、用**整個磁碟**當池子、可**排隊**。
- **Buffering**：用**記憶體小區**、平衡**資料流**速度。
- **Cache**：為了「**重複**存取」而加速。
