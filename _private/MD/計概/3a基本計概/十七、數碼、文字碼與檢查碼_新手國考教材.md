# 十七、數碼、文字碼與檢查碼

定義
- 數碼：用 bits 表示數字，例如 BCD、Gray Code。
- 文字碼：用編號表示文字，例如 ASCII、EBCDIC、Unicode、UTF-8。
- 檢查碼：額外加檢查資訊，用來偵測或更正錯誤，例如 Parity、CRC、Hamming Code。

先背一句：

```text
數碼管數字，文字碼管文字，檢查碼管有沒有錯。
```

## BCD
1. BCD（Binary-Coded Decimal）是用二進位編每一個十進位數字。
2. 最常見是 8421 BCD： 第 1 個 bit 權重 = 8；第 2 個 bit 權重 = 4；第 3 個 bit 權重 = 2；第 4 個 bit 權重 = 1
3. BCD 有效範圍：0000 到 1001
4. 針對每一個十進位數字進行拆分，組合
ex. (259)10 轉成 8421BCD，
      2 = 0010
      5 = 0101
      9 = 1001
259 的 8421 BCD = 0010 0101 1001


## Gray Code

Gray Code 特色：相鄰兩個碼只差 1 個 bit。

用途：
- 位置偵測。
- 旋轉編碼器。
- 減少狀態切換時讀錯的機率。

      ### Binary 轉 Gray

      規則：
      1. 最高位不變。
      2. 其餘 Gray 位元 = 左邊 binary XOR 目前 binary。 (XOR表示相異才為true)

      例子：Binary `1011`
      Binary：1 0 1 1
      Gray：  1 (1 XOR 0) (0 XOR 1) (1 XOR 1)
            = 1 1 1 0
      Binary 1011 = Gray 1110


      ### Gray 轉 Binary

      規則：
      1. 最高位不變。
      2. 其餘 Binary 位元 = 前一個已求出的 Binary XOR 目前 Gray。


      例子：Gray `1110`
      Gray：  1 1 1 0
      Binary：1
      下一位：1 XOR 1 = 0
      下一位：0 XOR 1 = 1
      下一位：1 XOR 0 = 1

      Gray 1110 = Binary 1011


## 文字碼

| 名稱 | 重點 | 新手提醒 |
| --- | --- | --- |
| ASCII | 標準 7 bits，可表示 128 種編號 | 英文、數字、控制字元常見 |
| Extended ASCII | 常見 8 bits，可有 256 種編號 | 128 到 255 不一定全球一致 |
| EBCDIC | 8 bits，IBM 系統常見字元碼 | 看到 IBM / 大型主機想到它 |
| Unicode | 統一多語言字元的碼位系統 | 是字元集 / 碼位，不是單一儲存格式 |
| UTF-8 | Unicode 的常見可變長度編碼 | 英文常 1 byte，其他文字可能 2 到 4 bytes |

備註：
1. Unicode 是「字元編號」。
2. UTF-8 是「把 Unicode 編號存成 bytes 的方式」。
3. UTF-8 相容 ASCII；ASCII 裡的 0 ~ 127，在 UTF-8 裡仍然用 1 byte 表示，而且編碼值相同。


## Parity Check（同位元檢查）

Parity Check 是加一個檢查位元，讓 1 的總數符合規則；檢查位元位置發送方與接收方協調好即可。
奇同位、偶同位，也可以翻譯成 奇校驗、偶校驗。

| 類型 | 規則 |
| --- | --- |
| 偶同位(Even Parity) | 加上檢查位後，1 的總數為偶數 |
| 奇同位(Odd Parity) | 加上檢查位後，1 的總數為奇數 |

## CRC
一.
CRC（Cyclic Redundancy Check，循環冗餘檢查）常用在網路傳輸與儲存裝置。主要用來偵測錯誤，不是一般拿來更正錯誤。
二.
CRC 傳送資料前，先根據資料算出一串「檢查位元」，附加在資料後面一起傳送。 接收端收到後，再重新計算一次，看結果是否正確。
三. 算法
1. 看生成多項式長度。 ex. 1011
2. CRC 位數 = 生成多項式長度 - 1
3. 原資料後面補相同數量的 0
4. 用生成多項式做模 2 除法 (不用進位、不用借位、減法等於 XOR)
5. 最後餘數就是 CRC
6. 原資料 + CRC = 實際傳送資料
7. 接收端再除一次，餘數為 0 表示通過

## Hamming Code（漢明碼）

1. Hamming Code 用多個「校驗位(檢查位)」來定位錯誤。
2. 校驗位 = 額外加的檢查位元；要先決定是 奇校驗 還是 偶校驗 (同位元檢查)。

3. 編碼步驟（發送端：算出要傳什麼）
      3-1. 算需要幾個校驗位 r
      公式：`2^r ≥ m + r + 1`（m = 資料位數）
      3-2. 排位置（編號從左到右、從 1 開始）
            - 第 1, 2, 4, 8…（2 的次方）位 → 放校驗位 P1, P2, P4…
            - 其餘位置 → 依序填原始資料

            Hamming(7,4) : 7 個總位元 4 個資料位元 3 個檢查位元
            > 例：原始 1011
            > ```
            > 位置:      1   2   3   4   5   6   7
            > 位置2進制:001 010 011 100 101 110 111
            > 內容:      P1  P2  1   P3  0   1   1
            > ```
            > （資料 1-0-1-1 填進位置 3,5,6,7）
      3-3. 算每個校驗位
            P1 檢查「位置編號轉成二進位後，最右邊是 1」的位置。   ex  1/3/5/7 位置，檢查他們全部的值，P1要符合校驗
            P2 檢查「位置編號轉成二進位後，最中間是 1」的位置。   ex. 2/3/6/7 位置，檢查他們全部的值，P2要符合校驗
            P3 檢查「位置編號轉成二進位後，最右邊是 1」的位置。   ex. 4/5/6/7 位置，檢查他們全部的值，P3要符合校驗
      此步驟可以得出全部漢明碼

      3-4. 驗證，把漢明碼的值，重新檢查 P1、P2、P4 負責的範圍 是否符合校驗。
      當真正資料位元出錯時，Hamming Code 可以透過校驗位 / 檢查位元找出錯誤位置，然後把那一個 bit 反轉回來，因此可以恢復原本資料。


Syndrome（症候值/症狀碼/校驗子）：
收到資料漢明碼
→ 重新檢查 P1、P2、P4 的範圍
→ 檢查通過記 0，檢查失敗記 1
→ 得到 S1、S2、S4
→ 組成 S4 S2 S1，得到 Syndrome
→ 轉成十進位，就是錯誤位置


## [必背] 漢明距

漢明距（Hamming Distance）是兩個碼字不同 bit 的數量。也就是說 兩組資料中，不一樣的位置有幾個，漢明距離就是幾。



錯誤能力公式：

| 需求 | 最小漢明距 |         用table
| --- | --- |
| 偵測 d 個錯誤 | `Dmin >= d + 1` |
| 更正 t 個錯誤 | `Dmin >= 2t + 1` |
| 已知 Dmin，最多偵測 | `Dmin - 1` |
| 已知 Dmin，最多更正 | `floor((Dmin - 1) / 2)` |



## [易錯] 常見陷阱  用table做

| 容易錯的地方 | 正確觀念 |
| --- | --- |
| BCD 是把整個十進位數轉二進位 | 錯，BCD 是每個十進位數字分開編 |
| `1010` 是有效 BCD | 錯，單一 BCD 只允許 0000 到 1001 |
| Binary 轉 Gray 和 Gray 轉 Binary 用同一規則 | 錯，兩個方向規則不同 |
| Unicode 和 UTF-8 是同一件事 | 錯，Unicode 是碼位，UTF-8 是編碼方式 |
| Parity 可以更正錯誤 | 通常錯，Parity 多半只能偵測 |
| CRC 是錯誤更正碼 | 國考通常視為錯誤偵測碼 |
| 偵測 d 個錯誤需要 `2d + 1` | 錯，那是更正常見公式的型態 |

## [必背] 國考答題句

1. BCD 是用 4 bits 表示一個十進位數字；8421 BCD 的權重為 8、4、2、1。
2. Gray Code 的特色是相鄰碼只差 1 bit，可減少狀態轉換時的讀取錯誤。
3. 二進位轉 Gray 時最高位不變，其餘位元為相鄰二進位位元 XOR。
4. Gray 轉二進位時最高位不變，其餘位元為前一個二進位位元 XOR 目前 Gray 位元。
5. 標準 ASCII 為 7 bits，可表示 128 種編號；延伸 ASCII 常為 8 bits。
6. EBCDIC 是 IBM 系統常見的字元編碼。
7. Unicode 用於統一表示多語言字元；UTF-8 是 Unicode 的常見可變長度編碼方式。
8. 同位元檢查可偵測奇數個 bit 錯誤，但通常不能定位或更正錯誤。
9. CRC 透過產生多項式做模 2 除法取得餘數，常用於錯誤偵測。
10. 漢明碼的檢查位通常放在 1、2、4、8 等 2 的冪次位置。
11. 偵測 d 個錯誤需要最小漢明距至少 `d + 1`；更正 t 個錯誤需要最小漢明距至少 `2t + 1`。
