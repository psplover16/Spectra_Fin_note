## 名詞解釋

### 數碼

數碼是「用一組位元來表示數字」的方法。電腦真正能處理的是 0 和 1，但人類常用十進位，所以需要約定一套表示方式。考題常問某種碼是拿來表示十進位數字、減少讀取錯誤，還是表示文字。

### 文字碼

文字碼是「用數字編號代表文字、符號或控制字元」的方法。例如英文字母 A、數字字元 0、換行符號，都可以被指定成某個編號。電腦儲存文字時，實際存的是這些編號的位元表示。

### 檢查碼

檢查碼是「額外加上的檢查用位元或資料」，目的不是表示原本資料，而是幫助接收端判斷資料在傳輸或儲存過程中有沒有出錯。有些檢查碼只能偵測錯誤，有些可以進一步定位並更正部分錯誤。

### 位元與位元組

位元 bit 是最小資料單位，只能是 0 或 1。位元組 byte 通常是 8 bits。國考題目常用 bits 問編碼長度，用 bytes 問儲存容量，兩者不能混在一起。

### XOR

XOR 是「互斥或」運算，兩個輸入不同時結果為 1，相同時結果為 0。常見規則如下：

| 運算 | 結果 |
|---|---:|
| 0 XOR 0 | 0 |
| 0 XOR 1 | 1 |
| 1 XOR 0 | 1 |
| 1 XOR 1 | 0 |

Gray Code 轉換與 CRC 多項式除法都會用到 XOR，所以要先熟悉「相同得 0、不同得 1」。

### BCD

BCD 是 Binary-Coded Decimal，意思是「用二進位來編每一個十進位數字」。最常見的是 8421 BCD，也就是每個十進位數字用 4 bits 表示，四個位置的權重依序是 8、4、2、1。

BCD 的重點是「一個十進位數字對一組 4 bits」，不是把整個十進位數一次轉成二進位。例如十進位 59 的 BCD 是 `0101 1001`，不是十進位 59 的純二進位。

### Gray Code

Gray Code 是一種數碼，特色是「相鄰兩個碼只差 1 個 bit」。這種設計常用在旋轉編碼器、位置偵測等情境，因為機械或電子訊號在切換瞬間可能讀到中間狀態；若一次只變 1 bit，就能降低多位元同時變動造成的錯誤。

### ASCII

ASCII 是常見的英文與控制字元編碼，標準 ASCII 使用 7 bits，因此可表示 128 種編號。延伸 ASCII 常用 8 bits，因此可有 256 種可能編號，但延伸 ASCII 不是全球唯一標準，不同系統可能對 128 到 255 的部分有不同解釋。

### EBCDIC

EBCDIC 是 IBM 系統常見的字元編碼，歷史上常見於大型主機。國考通常把它當作「IBM 系統常見編碼」來考，不太會要求背每個字元的實際碼值。

### Unicode

Unicode 是為了統一表示多語言文字而設計的字元集。它替世界各種文字、符號、表情符號等指定統一的碼位。要注意，Unicode 是「抽象編號系統」，不等於某一種實際儲存位元格式。

### UTF-8

UTF-8 是 Unicode 常見的實作編碼方式，屬於可變長度編碼。常見英文 ASCII 字元在 UTF-8 中使用 1 byte，其他文字可能使用 2 到 4 bytes。國考最容易考的觀念是：UTF-8 是 Unicode 的一種編碼方式，不是另一套和 Unicode 無關的字元集。

### 同位元檢查

同位元檢查 Parity Check 是在資料後加一個檢查位元，讓整組資料中的 1 的個數符合規則。偶同位要求 1 的總數為偶數，奇同位要求 1 的總數為奇數。它能偵測奇數個 bit 錯誤，尤其能偵測 1 bit 錯誤，但通常不能指出錯在哪一位，也不能保證更正錯誤。

### CRC

CRC 是 Cyclic Redundancy Check，常譯為循環冗餘檢查。它把資料視為二進位多項式，用指定的產生多項式做模 2 除法，所得餘數就是檢查碼。CRC 常用於網路傳輸與儲存裝置的錯誤偵測，重點通常是偵測能力強，但一般題目不把它當成錯誤更正碼。

### 漢明碼

漢明碼 Hamming Code 是一種可以用檢查位元定位部分錯誤的編碼方法。基本漢明碼常用於更正單一 bit 錯誤；題目若問檢查位位置，通常記得檢查位放在 1、2、4、8 等 2 的冪次位置。

### Syndrome

Syndrome 可翻成症候值或錯誤症候，是接收端重新做檢查後得到的結果。若 syndrome 為 0，表示沒有偵測到錯誤；若不是 0，在基本單錯誤漢明碼中，syndrome 的數值通常指出錯誤位元的位置。

### 漢明距

漢明距 Hamming Distance 是兩個碼字之間「不同 bit 的數量」。例如 `10110` 和 `10001` 有 3 個位置不同，所以漢明距是 3。整個碼集合的最小漢明距越大，越能偵測或更正更多錯誤。

## 核心想法

數碼、文字碼與檢查碼都在處理同一件事：電腦只看得懂 0 和 1，所以人類必須規定「哪些 0 和 1 代表什麼」。BCD、Gray Code 偏向表示數字；ASCII、EBCDIC、Unicode、UTF-8 偏向表示文字；Parity、CRC、Hamming Code 則偏向檢查資料是否正確。

BCD 的核心是「每個十進位數字分開編」。如果題目看到 0 到 9 的每一位十進位數字，就想到 4 bits 的 8421 BCD。它容易閱讀與處理十進位，但比純二進位更浪費位元。

Gray Code 的核心是「相鄰只差一位」。一般二進位從 `0111` 變到 `1000` 時會有 4 個 bits 同時改變；若硬體讀取時間稍有不同，可能讀到錯誤中間值。Gray Code 透過一次只變一個 bit，降低這種轉換錯誤。

文字碼的核心是「字元先被編號，再被儲存」。ASCII 適合早期英文環境；EBCDIC 常與 IBM 大型主機連在一起；Unicode 解決多語言統一表示問題；UTF-8 則是 Unicode 在網路與檔案中非常常見的儲存格式。

檢查碼的核心是「多放一些檢查資訊，換取錯誤偵測或更正能力」。同位元檢查最簡單，但能力有限；CRC 偵測能力較強，常用在傳輸與儲存；漢明碼可以透過檢查位組合出 syndrome，進一步定位單一錯誤。

漢明距是判斷錯誤能力的總公式來源。若最小漢明距為 `Dmin`，最多可偵測 `Dmin - 1` 個錯誤，最多可更正 `floor((Dmin - 1) / 2)` 個錯誤。反過來說，要偵測 d 個錯誤，最小距離至少要 `d + 1`；要更正 t 個錯誤，最小距離至少要 `2t + 1`。

## 具體範例

### 範例一：8421 BCD 表示十進位 59

十進位 59 有兩個十進位數字：5 和 9。8421 BCD 要把每個數字分開轉成 4 bits。

| 十進位數字 | 8421 BCD |
|---:|---|
| 5 | `0101` |
| 9 | `1001` |

所以十進位 59 的 BCD 是：

```text
59 = 0101 1001
```

請注意，十進位 59 的純二進位是 `111011`，這和 BCD 的 `0101 1001` 不同。國考常用這一點考「BCD 不是一般二進位轉換」。

### 範例二：判斷 BCD 是否有效

8421 BCD 每 4 bits 只能代表十進位 0 到 9，因此只允許：

```text
0000 到 1001
```

像 `1010`、`1011`、`1100`、`1101`、`1110`、`1111` 在單一 8421 BCD 數字中都不是有效十進位數字。若題目問 `0101 1010` 是否為有效 BCD，答案是否定的，因為後半段 `1010` 代表十進位 10，不是單一十進位數字。

### 範例三：二進位轉 Gray Code

規則是：最高位元不變，其餘 Gray 位元等於「左邊的二進位位元 XOR 目前的二進位位元」。

將二進位 `1011` 轉成 Gray Code：

```text
二進位：1 0 1 1
Gray ：1 (1 XOR 0) (0 XOR 1) (1 XOR 1)
      =1 1 1 0
```

所以：

```text
Binary 1011 = Gray 1110
```

### 範例四：Gray Code 轉二進位

規則是：最高位元不變，其餘二進位位元等於「前一個已求出的二進位位元 XOR 目前 Gray 位元」。

將 Gray `1110` 轉回二進位：

```text
Gray ：1 1 1 0
Binary 最高位 = 1
下一位 = 1 XOR 1 = 0
下一位 = 0 XOR 1 = 1
下一位 = 1 XOR 0 = 1
```

所以：

```text
Gray 1110 = Binary 1011
```

這裡最容易錯的是把 Gray 轉二進位也當成相鄰 Gray 位元互相 XOR。正確作法一定要用「前一個已求出的二進位位元」。

### 範例五：偶同位與奇同位

資料為 `1011001`。先數 1 的個數：

```text
1011001 中有 4 個 1
```

若使用偶同位，整組資料的 1 的總數要是偶數。現在已經有 4 個 1，所以同位元應加 `0`：

```text
偶同位：1011001 0
```

若使用奇同位，整組資料的 1 的總數要是奇數。現在有 4 個 1，所以同位元應加 `1`，讓總數變成 5：

```text
奇同位：1011001 1
```

如果傳輸途中剛好錯 1 個 bit，1 的總數奇偶性會改變，因此同位元檢查可以偵測到。但是如果剛好錯 2 個 bits，奇偶性可能又變回原狀，因此同位元檢查不一定能偵測偶數個 bit 錯誤。

### 範例六：CRC 的基本計算概念

CRC 題目常給資料與產生多項式。假設資料是 `1101`，產生多項式對應的位元是 `1011`。因為產生多項式長度是 4 bits，所以餘數長度是 3 bits。

步驟如下：

1. 在資料後面補 3 個 0：

```text
1101 000
```

2. 用 `1011` 做模 2 除法。模 2 除法沒有借位，減法等同 XOR。

```text
1101000 ÷ 1011 的餘數 = 001
```

3. 把餘數接回原資料後面：

```text
CRC 碼字 = 1101 001
```

考試若不要求完整長除法，至少要記得三件事：先補 0，補的數量是產生多項式次數；除法用 XOR；最後的餘數就是 CRC 檢查碼。

### 範例七：漢明碼檢查位位置

基本漢明碼常把檢查位放在 2 的冪次位置：

```text
位置：1 2 3 4 5 6 7
種類：P P D P D D D
```

其中 `P` 是檢查位，`D` 是資料位。位置 1、2、4 是檢查位；位置 3、5、6、7 是資料位。

若有 4 個資料位，需要幾個檢查位才能更正 1 bit 錯誤？使用公式：

```text
2^r >= m + r + 1
```

其中 m 是資料位數，r 是檢查位數。若 m = 4：

```text
r = 2 時：2^2 = 4，不足以 >= 4 + 2 + 1 = 7
r = 3 時：2^3 = 8，剛好 >= 4 + 3 + 1 = 8
```

所以 4 個資料位需要 3 個檢查位，形成常見的 Hamming(7,4)。

### 範例八：Hamming(7,4) 編碼與 syndrome

以下用偶同位示範，位置由左到右標為 1 到 7。資料位為 `1011`，依序放入位置 3、5、6、7。

| 位置 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---:|---|---|---|---|---|---|---|
| 類型 | P1 | P2 | D1 | P4 | D2 | D3 | D4 |
| 值 | ? | ? | 1 | ? | 0 | 1 | 1 |

檢查位負責的位置如下：

| 檢查位 | 負責位置 | 偶同位計算 | 檢查位 |
|---|---|---|---:|
| P1 | 1、3、5、7 | P1、1、0、1 的 1 總數要為偶數 | 0 |
| P2 | 2、3、6、7 | P2、1、1、1 的 1 總數要為偶數 | 1 |
| P4 | 4、5、6、7 | P4、0、1、1 的 1 總數要為偶數 | 0 |

因此完整碼字為：

```text
0 1 1 0 0 1 1
```

如果接收到的碼字第 6 位錯了，收到：

```text
0 1 1 0 0 0 1
```

重新檢查：

| 檢查組 | 位置 | 1 的個數 | 結果 |
|---|---|---:|---|
| S1 | 1、3、5、7 | 2 | 正常，記 0 |
| S2 | 2、3、6、7 | 3 | 錯誤，記 1 |
| S4 | 4、5、6、7 | 1 | 錯誤，記 1 |

syndrome 的值是：

```text
S1 * 1 + S2 * 2 + S4 * 4
= 0 * 1 + 1 * 2 + 1 * 4
= 6
```

所以錯誤位置是第 6 位，把第 6 位反轉即可更正。

### 範例九：漢明距與偵錯能力

比較兩個碼字：

```text
碼字 A：10110
碼字 B：10001
```

逐位比較：

| 位置 | 1 | 2 | 3 | 4 | 5 |
|---:|---|---|---|---|---|
| A | 1 | 0 | 1 | 1 | 0 |
| B | 1 | 0 | 0 | 0 | 1 |
| 是否不同 | 否 | 否 | 是 | 是 | 是 |

不同的位置有 3 個，所以漢明距是 3。

若某一碼集合的最小漢明距是 3：

```text
最多可偵測 2 個錯誤
最多可更正 1 個錯誤
```

因為偵測 d 個錯誤需要 `Dmin >= d + 1`，更正 t 個錯誤需要 `Dmin >= 2t + 1`。

## 國考常見考法

### 考法一：問某種碼的用途

題目可能問「何者常用於 IBM 大型主機？」答案通常是 EBCDIC；問「何者可統一表示多國文字？」答案是 Unicode；問「何者相鄰碼只差一位？」答案是 Gray Code。這類題目重點是辨認關鍵字，不一定需要計算。

### 考法二：BCD 與純二進位混淆

國考常給一個十進位數，要求轉成 BCD，或問某個 BCD 是否有效。作答時要把每一個十進位數字分開處理。看到十進位 27，BCD 是 `0010 0111`；不要直接把 27 轉成純二進位 `11011`。

### 考法三：Binary 與 Gray Code 互轉

二進位轉 Gray 時，最高位不變，其餘位元做相鄰二進位 XOR。Gray 轉二進位時，最高位不變，其餘位元要用「前一個已求出的二進位位元」和目前 Gray 位元 XOR。兩個方向的規則不同，是最常見陷阱。

### 考法四：同位元檢查能偵測什麼

同位元檢查可偵測奇數個 bit 錯誤，尤其是單一 bit 錯誤。它無法保證偵測偶數個 bit 錯誤，也不能定位錯誤位元。題目若說 parity 可更正錯誤，通常是錯的。

### 考法五：CRC 的定位

CRC 常被考成「錯誤偵測」而不是「錯誤更正」。看到產生多項式、模 2 除法、餘數、網路傳輸、磁碟或儲存檢查，通常都和 CRC 有關。

### 考法六：漢明碼檢查位與 syndrome

漢明碼常考檢查位位置，也就是 1、2、4、8 等位置。若題目給 syndrome，通常要把 syndrome 當成二進位或加權值來找錯誤位置。若 syndrome 是 0，表示沒有偵測到錯誤。

### 考法七：漢明距公式

題目常問「要偵測 d 個錯誤，最小漢明距至少多少？」答案是 `d + 1`。問「要更正 t 個錯誤，最小漢明距至少多少？」答案是 `2t + 1`。這兩條公式一定要背熟。

## 必要比較表與易混淆整理

### 數碼與文字碼比較

| 名稱 | 主要用途 | 常考關鍵字 | 新手提醒 |
|---|---|---|---|
| BCD | 用 4 bits 表示一個十進位數字 | 8421、十進位數字、每位分開編 | `12` 的 BCD 是 `0001 0010`，不是 `1100` |
| Gray Code | 讓相鄰碼只差 1 bit | 相鄰、1 bit、減少轉換錯誤 | 常考 Binary 與 Gray 互轉 |
| ASCII | 表示英文、數字字元與控制字元 | 7 bits、128 種、延伸 8 bits | 標準 ASCII 是 7 bits |
| EBCDIC | IBM 系統常見字元碼 | IBM、大型主機 | 常考辨認，不常考碼值 |
| Unicode | 統一表示多語言字元 | 多國文字、統一碼、碼位 | 是字元集，不等於 UTF-8 |
| UTF-8 | Unicode 的常見編碼方式 | 可變長度、1 到 4 bytes、網路常見 | 對 ASCII 相容，英文常用 1 byte |

### 檢查碼比較

| 方法 | 主要功能 | 能否定位錯誤 | 能否更正常見錯誤 | 常見用途或考點 |
|---|---|---|---|---|
| 同位元檢查 | 偵測奇數個 bit 錯誤 | 通常不能 | 通常不能 | 奇同位、偶同位、單一 bit 錯誤 |
| CRC | 強化錯誤偵測 | 通常不定位 | 通常不更正 | 模 2 除法、產生多項式、網路與儲存 |
| 漢明碼 | 偵測並更正部分錯誤 | 可用 syndrome 定位部分錯誤 | 基本型常更正 1 bit | 檢查位位置、syndrome、漢明距 |

### 偵測與更正公式整理

| 需求 | 最小漢明距條件 | 例子 |
|---|---|---|
| 偵測 d 個錯誤 | `Dmin >= d + 1` | 偵測 2 個錯誤需 `Dmin >= 3` |
| 更正 t 個錯誤 | `Dmin >= 2t + 1` | 更正 1 個錯誤需 `Dmin >= 3` |
| 已知最小距離 Dmin，最多偵測 | `Dmin - 1` | `Dmin = 4` 可偵測 3 個錯誤 |
| 已知最小距離 Dmin，最多更正 | `floor((Dmin - 1) / 2)` | `Dmin = 5` 可更正 2 個錯誤 |

### 易混淆一：Unicode 與 UTF-8

Unicode 是「字元被分配到哪個碼位」的規則，UTF-8 是「把 Unicode 碼位存成哪些 bytes」的規則。可以把 Unicode 想成字典中的編號系統，把 UTF-8 想成實際寫進檔案或傳到網路上的位元格式。

### 易混淆二：偵測與更正

偵測錯誤只需要知道「有錯」，更正錯誤還要知道「錯在哪裡，以及正確值應該怎麼改」。所以更正比偵測需要更大的漢明距。這就是為什麼偵測 d 個錯誤是 `d + 1`，更正 t 個錯誤卻要 `2t + 1`。

### 易混淆三：Parity 與 Hamming Code

同位元檢查只有一個整體奇偶規則時，通常只能知道奇偶性不對，不能定位錯誤。漢明碼使用多個檢查位，每個檢查位檢查不同位置組合，才能把檢查結果合成 syndrome，指出可能的錯誤位置。

### 易混淆四：Binary 轉 Gray 與 Gray 轉 Binary

Binary 轉 Gray 是看「相鄰二進位位元」；Gray 轉 Binary 是看「前一個已求出的二進位位元」和目前 Gray 位元。若兩邊都用同一套相鄰 XOR，通常會算錯。

## 國考答題句

BCD 是用 4 bits 表示一個十進位數字；8421 BCD 的權重為 8、4、2、1。

Gray Code 的特色是相鄰碼只差 1 bit，因此可減少位置或狀態轉換時的讀取錯誤。

二進位轉 Gray 時最高位不變，其餘位元為相鄰二進位位元 XOR。

Gray 轉二進位時最高位不變，其餘位元為前一個二進位位元 XOR 目前 Gray 位元。

標準 ASCII 為 7 bits，可表示 128 種編號；延伸 ASCII 常為 8 bits。

EBCDIC 是 IBM 系統常見的字元編碼。

Unicode 用於統一表示多語言字元；UTF-8 是 Unicode 的常見可變長度編碼方式。

同位元檢查可偵測奇數個 bit 錯誤，但通常不能定位或更正錯誤。

CRC 透過產生多項式做模 2 除法取得餘數，常用於網路與儲存的錯誤偵測。

漢明碼的檢查位通常放在 1、2、4、8 等 2 的冪次位置。

Syndrome 不為 0 時，在基本單錯誤漢明碼中可指出錯誤位元位置。

偵測 d 個錯誤需要最小漢明距至少 `d + 1`；更正 t 個錯誤需要最小漢明距至少 `2t + 1`。

## 容易考的判斷題

1. 「BCD 是把整個十進位數直接轉成二進位。」  
   錯。BCD 是每個十進位數字分開用 4 bits 表示。

2. 「十進位 12 的 8421 BCD 是 `0001 0010`。」  
   對。1 是 `0001`，2 是 `0010`。

3. 「8421 BCD 中，`1010` 可表示單一十進位數字 10。」  
   錯。BCD 的單一數字只允許 0 到 9，`1010` 不是有效單一 BCD 數字。

4. 「Gray Code 的相鄰碼只會有 1 bit 不同。」  
   對。這是 Gray Code 最重要的特色。

5. 「二進位轉 Gray 時，最高位元不變。」  
   對。其餘 Gray 位元才用相鄰二進位位元 XOR 計算。

6. 「Gray 轉二進位時，只要把相鄰 Gray 位元互相 XOR 即可。」  
   錯。必須使用前一個已求出的二進位位元 XOR 目前 Gray 位元。

7. 「標準 ASCII 使用 7 bits。」  
   對。標準 ASCII 可表示 128 種編號。

8. 「EBCDIC 是 IBM 系統常見的編碼。」  
   對。這是 EBCDIC 最常見的考試關鍵字。

9. 「Unicode 和 UTF-8 完全是同一件事。」  
   錯。Unicode 是字元集或碼位系統，UTF-8 是 Unicode 的一種可變長度編碼方式。

10. 「偶同位檢查要求資料加檢查位後，1 的總數為偶數。」  
    對。奇同位則要求 1 的總數為奇數。

11. 「同位元檢查一定能偵測任意偶數個 bit 錯誤。」  
    錯。偶數個錯誤可能讓奇偶性恢復原狀，因此不一定能偵測。

12. 「CRC 常用於錯誤偵測。」  
    對。國考通常把 CRC 歸類為偵測碼，而非更正碼。

13. 「漢明碼的檢查位常放在 1、2、4、8 等位置。」  
    對。這些位置是 2 的冪次。

14. 「若最小漢明距為 3，最多可更正 1 個錯誤。」  
    對。因為更正 t 個錯誤需要 `Dmin >= 2t + 1`。

15. 「若要偵測 3 個錯誤，最小漢明距至少要 6。」  
    錯。偵測 d 個錯誤需要 `d + 1`，所以偵測 3 個錯誤至少需要 4。

16. 「若要更正 2 個錯誤，最小漢明距至少要 5。」  
    對。更正 t 個錯誤需要 `2t + 1`，所以更正 2 個錯誤需要 5。

## 考前速記小抄

BCD：一個十進位數字用 4 bits，最常見是 8421 BCD。

BCD 陷阱：`25` 的 BCD 是 `0010 0101`，不是純二進位。

BCD 有效範圍：每組 4 bits 只能是 `0000` 到 `1001`。

Gray Code：相鄰碼只差 1 bit，用來減少轉換錯誤。

Binary 轉 Gray：最高位不變；其餘 = 左邊 binary XOR 目前 binary。

Gray 轉 Binary：最高位不變；其餘 = 前一個 binary XOR 目前 Gray。

ASCII：標準 7 bits，128 種；延伸 ASCII 常見 8 bits。

EBCDIC：看到 IBM、大型主機就想到它。

Unicode：統一多語言字元的碼位系統。

UTF-8：Unicode 的常見可變長度編碼，英文 ASCII 常用 1 byte。

Parity：偶同位讓 1 的總數為偶數，奇同位讓 1 的總數為奇數。

Parity 能力：可偵測奇數個 bit 錯誤；通常不能定位、不能更正。

CRC：資料後補 0，用產生多項式做模 2 除法，餘數當檢查碼。

Hamming Code：檢查位在 1、2、4、8；syndrome 可指出單一錯誤位置。

檢查位數公式：若資料位為 m、檢查位為 r，單錯誤更正常用 `2^r >= m + r + 1`。

漢明距：兩碼字不同 bit 的數量。

偵測公式：偵測 d 個錯誤，`Dmin >= d + 1`。

更正公式：更正 t 個錯誤，`Dmin >= 2t + 1`。

已知 Dmin：最多偵測 `Dmin - 1`，最多更正 `floor((Dmin - 1) / 2)`。
