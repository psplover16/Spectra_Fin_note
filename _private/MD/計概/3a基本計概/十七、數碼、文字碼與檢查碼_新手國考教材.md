# 十七、數碼、文字碼與檢查碼

定義
- 數碼：用 bits 表示數字，例如 BCD、Gray Code。
- 文字碼：用編號表示文字，例如 ASCII、EBCDIC、Unicode、UTF-8。
- 檢查碼：額外加檢查資訊，用來偵測或更正錯誤，例如 Parity、CRC、Hamming Code。

先背一句：

```text
數碼管數字，文字碼管文字，檢查碼管有沒有錯。
```

## [必背] BCD

BCD（Binary-Coded Decimal）是用二進位編每一個十進位數字。

最常見是 8421 BCD：

```text
每一個十進位數字 = 4 bits
權重 = 8、4、2、1
```

例子：十進位 `59`

```text
5 = 0101
9 = 1001
```

所以：

```text
59 的 BCD = 0101 1001
```

注意：

```text
BCD 不是把整個 59 轉成二進位。
59 的純二進位是 111011。
```

BCD 有效範圍：

```text
0000 到 1001
```

`1010` 到 `1111` 不是有效的單一 8421 BCD 數字。

## [必背] Gray Code

Gray Code 特色：

```text
相鄰兩個碼只差 1 個 bit。
```

用途：
- 位置偵測。
- 旋轉編碼器。
- 減少狀態切換時讀錯的機率。

### Binary 轉 Gray

規則：

```text
最高位不變。
其餘 Gray 位元 = 左邊 binary XOR 目前 binary。
```

例子：Binary `1011`

```text
Binary：1 0 1 1
Gray：  1 (1 XOR 0) (0 XOR 1) (1 XOR 1)
      = 1 1 1 0
```

所以：

```text
Binary 1011 = Gray 1110
```

### Gray 轉 Binary

規則：

```text
最高位不變。
其餘 Binary 位元 = 前一個已求出的 Binary XOR 目前 Gray。
```

例子：Gray `1110`

```text
Gray：  1 1 1 0
Binary：1
下一位：1 XOR 1 = 0
下一位：0 XOR 1 = 1
下一位：1 XOR 0 = 1
```

所以：

```text
Gray 1110 = Binary 1011
```

## [必背] 文字碼

| 名稱 | 重點 | 新手提醒 |
| --- | --- | --- |
| ASCII | 標準 7 bits，可表示 128 種編號 | 英文、數字、控制字元常見 |
| Extended ASCII | 常見 8 bits，可有 256 種編號 | 128 到 255 不一定全球一致 |
| EBCDIC | IBM 系統常見字元碼 | 看到 IBM / 大型主機想到它 |
| Unicode | 統一多語言字元的碼位系統 | 是字元集 / 碼位，不是單一儲存格式 |
| UTF-8 | Unicode 的常見可變長度編碼 | 英文常 1 byte，其他文字可能 2 到 4 bytes |

最容易混淆：

```text
Unicode 是「字元編號」。
UTF-8 是「把 Unicode 編號存成 bytes 的方式」。
```

## [必背] Parity Check（同位元檢查）

Parity Check 是加一個檢查位元，讓 1 的總數符合規則。

| 類型 | 規則 |
| --- | --- |
| 偶同位 | 加上檢查位後，1 的總數為偶數 |
| 奇同位 | 加上檢查位後，1 的總數為奇數 |

例子：資料 `1011001`

```text
1 的個數 = 4
```

偶同位：

```text
已經是偶數，所以補 0
1011001 0
```

奇同位：

```text
要變奇數，所以補 1
1011001 1
```

能力：

```text
可以偵測奇數個 bit 錯誤。
通常不能定位錯誤，也不能更正錯誤。
```

## [必背] CRC

CRC（Cyclic Redundancy Check，循環冗餘檢查）常用在網路傳輸與儲存裝置。

國考抓三件事：

```text
1. 用產生多項式。
2. 做模 2 除法。
3. 餘數就是檢查碼。
```

模 2 除法的減法等同 XOR：

```text
相同得 0，不同得 1。
```

CRC 重點：

```text
CRC 主要用來偵測錯誤，不是一般拿來更正錯誤。
```

## [必背] Hamming Code（漢明碼）

Hamming Code 用多個檢查位來定位錯誤。

檢查位常放在：

```text
1、2、4、8、16...
```

也就是 2 的冪次位置。

若資料位為 `m`，檢查位為 `r`，要能更正 1 bit 錯誤，常用條件：

```text
2^r >= m + r + 1
```

例子：資料位 `m = 4`

```text
r = 2：2^2 = 4，不夠 >= 4 + 2 + 1 = 7
r = 3：2^3 = 8，可以 >= 4 + 3 + 1 = 8
```

所以 4 個資料位需要 3 個檢查位，也就是常見 Hamming(7,4)。

Syndrome（症候值）：

```text
syndrome = 0：沒有偵測到錯誤
syndrome 不為 0：基本漢明碼中通常指出錯誤位元位置
```

## [必背] 漢明距

漢明距（Hamming Distance）是兩個碼字不同 bit 的數量。

例子：

```text
10110
10001
```

不同的位置有 3 個，所以漢明距是 3。

錯誤能力公式：

| 需求 | 最小漢明距 |
| --- | --- |
| 偵測 d 個錯誤 | `Dmin >= d + 1` |
| 更正 t 個錯誤 | `Dmin >= 2t + 1` |
| 已知 Dmin，最多偵測 | `Dmin - 1` |
| 已知 Dmin，最多更正 | `floor((Dmin - 1) / 2)` |

例子：

```text
Dmin = 3
最多偵測 2 個錯誤
最多更正 1 個錯誤
```

## [易錯] 常見陷阱

| 容易錯的地方 | 正確觀念 |
| --- | --- |
| BCD 是把整個十進位數轉二進位 | 錯，BCD 是每個十進位數字分開編 |
| `1010` 是有效 BCD | 錯，單一 BCD 只允許 0000 到 1001 |
| Binary 轉 Gray 和 Gray 轉 Binary 用同一規則 | 錯，兩個方向規則不同 |
| Unicode 和 UTF-8 是同一件事 | 錯，Unicode 是碼位，UTF-8 是編碼方式 |
| Parity 可以更正錯誤 | 通常錯，Parity 多半只能偵測 |
| CRC 是錯誤更正碼 | 國考通常視為錯誤偵測碼 |
| 偵測 d 個錯誤需要 `2d + 1` | 錯，那是更正常見公式的型態 |

## [必背] 國考答題句

1. BCD 是用 4 bits 表示一個十進位數字；8421 BCD 的權重為 8、4、2、1。
2. Gray Code 的特色是相鄰碼只差 1 bit，可減少狀態轉換時的讀取錯誤。
3. 二進位轉 Gray 時最高位不變，其餘位元為相鄰二進位位元 XOR。
4. Gray 轉二進位時最高位不變，其餘位元為前一個二進位位元 XOR 目前 Gray 位元。
5. 標準 ASCII 為 7 bits，可表示 128 種編號；延伸 ASCII 常為 8 bits。
6. EBCDIC 是 IBM 系統常見的字元編碼。
7. Unicode 用於統一表示多語言字元；UTF-8 是 Unicode 的常見可變長度編碼方式。
8. 同位元檢查可偵測奇數個 bit 錯誤，但通常不能定位或更正錯誤。
9. CRC 透過產生多項式做模 2 除法取得餘數，常用於錯誤偵測。
10. 漢明碼的檢查位通常放在 1、2、4、8 等 2 的冪次位置。
11. 偵測 d 個錯誤需要最小漢明距至少 `d + 1`；更正 t 個錯誤需要最小漢明距至少 `2t + 1`。
