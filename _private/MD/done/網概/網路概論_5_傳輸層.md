## 一、Circuit Switching vs Packet Switching　【理解】

| | 電路交換 Circuit Switching | 封包交換 Packet Switching |
|---|---|---|
| 方式 | 先建立一條**專屬實體路徑**，全程獨佔（像打電話） | 資料切成**封包**各自獨立傳，可走不同路徑、目的地重組 |
| 優點 | 連線穩定、保證頻寬、延遲固定 | 線路**共享**、效率高、可繞路容錯 |
| 缺點 | 獨佔線路（沒傳也佔著）、浪費、建立慢 | 延遲不固定（可能塞車／亂序）、需重組 |
| 例子 | 傳統電話網路 PSTN | 網際網路（IP） |

> 一句話：**電路交換＝獨佔專線（穩但浪費）；封包交換＝共享分封（省但延遲不定）。**

---

## 二、TCP + 三方交握 + 四方交握　【理解】＋【硬背】

**TCP（傳輸控制協定）特性**：**連線導向**（先建立連線）、**可靠**（確認 ACK、遺失重傳）、**有序**（按序到達）、有**流量控制**與**壅塞控制**。適合要求正確的應用（網頁、email、檔案）。

**三方交握（建立連線）** — SYN → SYN-ACK → ACK：
1. Client → Server：**SYN**（我想連線）
2. Server → Client：**SYN ＋ ACK**（好，我也要連，並確認你）
3. Client → Server：**ACK**（確認）→ 連線建立

**四方交握（結束連線）** — FIN → ACK → FIN → ACK：
1. Client → Server：**FIN**（我要關了）
2. Server → Client：**ACK**（收到）
3. Server → Client：**FIN**（我這邊也關了）
4. Client → Server：**ACK**（收到）→ 連線結束

> 為什麼結束要**四次**？因為 TCP 是**全雙工**，兩個方向要**各自關閉**，所以比建立多一步。

## 三、SYN Flood Attack　【理解】

- **手法**：攻擊者狂送大量 **SYN**（常偽造來源 IP），但**不回最後的 ACK**，讓伺服器留下一堆**半開連線（half-open）**，佔滿連線資源 → 正常使用者連不進來（**DoS 阻斷服務攻擊**）。
- **防範**：**SYN cookies**、限制半開連線數、防火牆過濾。

---

## 四、流量控制 vs 壅塞控制（超常考辨別）　【理解】

兩個都是 TCP 在「控制送多快」，但**保護對象不同**：

| | 流量控制 Flow Control | 壅塞控制 Congestion Control |
|---|---|---|
| 保護誰 | **接收方**（別淹沒對方緩衝區） | **整個網路**（別塞爆路由器） |
| 看誰的狀況 | 接收方的接收能力 | 網路的壅塞程度 |
| 機制 | **滑動視窗**（接收方告知還能收多少 rwnd） | **慢啟動、壅塞避免、快速重傳／恢復**（cwnd） |

> 記憶鉤子：**流量控制保護「接收方」、壅塞控制保護「網路」。**

---

## 五、UDP + TCP vs UDP　【理解】＋【硬背】

**UDP（使用者資料包協定）**：**非連線**（不先建立）、**不可靠**（不確認、不重傳）、**快、開銷小**。適合即時、可容忍少量遺失的應用（串流、遊戲、DNS、VoIP）。

| | TCP | UDP |
|---|---|---|
| 連線 | 連線導向（先三方交握） | 非連線 |
| 可靠性 | 可靠（確認、重傳、有序） | 不可靠 |
| 速度 | 較慢（開銷大） | **快**（開銷小） |
| Header | 較大（最小 **20** bytes） | 較小（**8** bytes） |
| 流量／壅塞控制 | **有** | 無 |
| 適用 | 網頁、email、檔案（要正確） | 串流、遊戲、DNS、VoIP（要即時） |

> 記憶鉤子：**TCP ＝ 可靠但慢（先握手）；UDP ＝ 快但不保證（直接送）。**

---

## 六、重點整理（背這張）

- 交換：**電路交換獨佔專線、封包交換共享分封。**
- TCP：連線導向、可靠、有序；**建立＝三方交握（SYN／SYN-ACK／ACK）、結束＝四方交握（FIN／ACK／FIN／ACK）**。
- **SYN Flood ＝ 灌半開連線的 DoS**；防範 SYN cookies。
- **流量控制保護接收方、壅塞控制保護網路。**
- **TCP 可靠慢（header 20B）、UDP 快不保證（header 8B）。**
