## 一、觀念：虛擬記憶體 / Demand Paging / Page Fault　【理解】

- **虛擬記憶體 Virtual Memory**：讓 process 可**比實體記憶體還大**的技術——不用把整個程式載入，只把「當下用到的部分」放記憶體，其餘留在硬碟（swap），要用再載。好處：程式可比 RAM 大、能同時跑更多 process、載入快。
- **Demand Paging 需求分頁**：只在**真正用到某一頁**時，才把它從硬碟載入（不用就不載）。靠 page table 的 **valid／invalid bit** 標示某頁在不在記憶體。
- **Page Fault 分頁錯誤**：要存取的頁**不在記憶體**（invalid）時觸發。
  - 處理：暫停 process → 從硬碟找到該頁 → 載入空閒 frame（沒空閒就用 **page replacement** 換一頁出去）→ 更新 page table → 重新執行該指令。
  - page fault 要動到硬碟、**很慢**，所以越少越好。
  - **影響 page fault 率的因素**：① frame 數量（越多 fault 越少）② page replacement 演算法好不好 ③ 程式的 **locality**（區域性越好 fault 越少）。

## 二、Effective Memory Access Time（EMAT）　【練流程】

**公式**：設 `p` ＝ page fault 機率、`ma` ＝ 記憶體存取時間、`fault 時間` ＝ 處理一次 page fault 要多久（含讀硬碟）。

> **EMAT ＝ (1 − p) × ma ＋ p × (fault 時間)**

### 範例 1：給 p，求 EMAT
ma ＝ 200 ns，fault 時間 ＝ 8 ms ＝ 8,000,000 ns，p ＝ 0.001（千分之一）。

- EMAT ＝ (1 − 0.001) × 200 ＋ 0.001 × 8,000,000
- ＝ 0.999 × 200 ＋ 8,000
- ＝ 199.8 ＋ 8,000 ＝ **8,199.8 ns**

> 重點：只要 **0.1% 的 fault 率**，存取時間就從 200 ns 暴增到約 8,200 ns（慢約 40 倍）！page fault 超貴，這就是為什麼要拚命壓低它。

### 範例 2：給效能要求，反推 p（常考變型）
若要求「效能下降不超過 10%」（即 EMAT ≤ 220 ns），p 最大多少？

- 220 ≥ (1 − p) × 200 ＋ p × 8,000,000
- 220 ≥ 200 ＋ 7,999,800 p
- 20 ≥ 7,999,800 p
- **p ≤ 20 ÷ 7,999,800 ≈ 2.5 × 10⁻⁶**（約每 40 萬次存取才能錯 1 次）

## 三、Page Replacement 頁面替換　★【練流程】

記憶體滿了、又要載新頁時，挑一個「犧牲頁」換出去。三種演算法：

| 演算法 | 換出誰 | 特點 |
|---|---|---|
| **FIFO** | **最早載入**的頁（先進先出） | 簡單；會有 **Belady's Anomaly** |
| **Optimal（OPT）** | **未來最久才會用到**的頁 | fault 最少（最佳），但需預知未來 → **無法實作**，只當標竿 |
| **LRU** | **最久沒被用到**的頁（看過去） | 近似 Optimal、效果好；**無 Belady's Anomaly** |

### 範例：參考字串 `A B C A B D A B E`，3 個 frame

**FIFO（逐步）：**
- A→fault {A}｜B→fault {A,B}｜C→fault {A,B,C}
- A→**hit**｜B→**hit**
- D→fault，趕最早的 A → {B,C,D}
- A→fault，趕最早的 B → {C,D,A}
- B→fault，趕最早的 C → {D,A,B}
- E→fault，趕最早的 D → {A,B,E}
- **FIFO ＝ 7 次 fault**（命中 2 次）

**Optimal：** D 要進來時（之後還會用到 A、B、E），{A,B,C} 裡 **C 之後再也不用 → 趕 C**；E 進來時剩下的都不再用，隨意趕一個。
- **OPT ＝ 5 次 fault**（命中 4 次）

**LRU：** D 進來時，{A,B,C} 裡最久沒用的是 C → 趕 C；E 進來時最久沒用的是 D → 趕 D。
- **LRU ＝ 5 次 fault**（命中 4 次）

> 共 9 次存取：FIFO 命中率 2/9 ≈ 22%、OPT／LRU 命中率 4/9 ≈ 44%。同字串下 **FIFO 最差，OPT／LRU 較好**。

### Belady's Anomaly（貝雷迪異常）— FIFO 才有

直覺上「frame 給越多、fault 應越少」，但 **FIFO 有時反而 frame 越多、fault 越多**，這叫 Belady's Anomaly。

經典字串 `1 2 3 4 1 2 5 1 2 3 4 5`、用 FIFO：
- **3 個 frame → 9 次 fault**
- **4 個 frame → 10 次 fault**（frame 變多，fault 反而增加！）

> 重點：**Belady's Anomaly 只發生在 FIFO 這類演算法；LRU、Optimal（堆疊演算法）不會**——它們 frame 越多，fault 一定不增加。

## 四、Thrashing（輾轉現象）　【理解】

- **定義**：系統花在**換頁（swap in/out）的時間比真正執行還多**——CPU 一直在處理 page fault、忙著搬頁，實際工作做很少，效能崩潰。
- **怎麼發生（惡性循環）**：同時跑的 process 太多（multiprogramming 太高）→ 每個 process 分到的 frame 太少 → page fault 暴增 → CPU 利用率下降 → OS 誤以為「該再多塞 process」→ 更多 process → 每人 frame 更少 → fault 更多… → CPU 利用率**斷崖式下跌**。
- **過程圖（常考）**：橫軸 ＝ multiprogramming 程度，縱軸 ＝ CPU 利用率。先隨 process 增多上升，**過了臨界點後因 thrashing 急速崩跌**。
- **解法**：
  - **Working Set Model（工作集）**：追蹤每個 process「最近用到的頁集合」，確保它有足夠 frame 裝下工作集；不夠就別再加 process。
  - **Page Fault Frequency（PFF）**：監控 fault 率，太高就多給 frame／降低 multiprogramming，太低就收回 frame。

---

## 五、重點整理（背這張）

**公式：** EMAT ＝ (1 − p) × ma ＋ p × fault 時間。

| 概念 | 一句話 |
|---|---|
| Demand Paging | 用到才載入（lazy） |
| Page Fault | 要的頁不在記憶體 → 去硬碟載（很慢） |
| FIFO | 趕最早進來的；**有 Belady** |
| Optimal | 趕未來最久才用的；最佳但**不可實作** |
| LRU | 趕最久沒用的；近似最佳、**無 Belady** |
| Belady's Anomaly | **FIFO 才有**：frame 變多 fault 反而變多 |
| Thrashing | 忙著換頁沒空做事；解法 **working set／PFF** |
