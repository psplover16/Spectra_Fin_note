# 作業系統 3-4：OS 的結構

> 科目：計算機原理 — 作業系統
> 本篇全屬 **【理解】**：都是有邏輯的概念，懂核心就記得，不用硬背。

---

## 一、Command（Shell）vs System Call　【理解】

兩個都是「進入 OS 服務的入口」，差別在**服務對象不同**：一個給「人」、一個給「程式」。

- **Command（命令直譯器 / Shell）**：是**人**跟 OS 溝通的介面。你打一條指令（`ls`、`cd`、`copy`），它負責解讀，再轉交 OS 執行。
- **System Call（系統呼叫）**：是**程式**跟 OS 核心溝通的介面。程式想用 OS 的服務（讀檔、配記憶體、開行程），就呼叫一個 system call，通常透過 trap 進入核心模式。

| | Command（Shell） | System Call |
|---|---|---|
| 是誰的介面 | **人** ↔ OS | **程式** ↔ OS 核心 |
| 怎麼用 | 使用者打指令 | 程式碼呼叫 |
| 角色 | 解讀指令、轉交 OS 執行 | 請求 OS 提供服務 |
| 例子 | cmd、bash | `open()`、`read()`、`fork()`、`exec()` |

> 記憶鉤子：**Command 給「人」打指令、System call 給「程式」呼叫。**

## 二、Kernel vs Microkernel　【理解】

先懂「核心（Kernel）」是什麼：OS 最底層的核心程式，管 CPU、記憶體、裝置、檔案等資源，常駐記憶體、跑在核心模式。差別在「**核心裡塞多少東西**」。

- **單核心（Monolithic Kernel）**：把所有 OS 服務（行程管理、記憶體、檔案系統、驅動程式…）**全包進核心**，一大塊。
- **微核心（Microkernel）**：核心只留**最必要**的（行程間通訊 IPC、基本排程、基本記憶體管理），其他服務**移到核心外**，當成使用者層的獨立服務。

| | 單核心 Monolithic | 微核心 Microkernel |
|---|---|---|
| 核心包含 | 全部 OS 服務 | 只留最必要（IPC、基本排程、記憶體） |
| 其他服務放哪 | 都在核心內 | 移到核心外，當使用者層服務 |
| 優點 | 執行快、呼叫直接、效率高 | 小、模組化、穩定、易擴充與移植 |
| 缺點 | 龐大、一處出錯易拖垮全系統、難維護 | 服務間靠訊息傳遞，overhead 高、較慢 |
| 例子 | 傳統 UNIX、Linux | Mach、QNX、MINIX |

> 記憶鉤子：**單核心「全包、快但脆」；微核心「精簡、穩但慢」。**

## 三、Virtual Machine（虛擬機器）　【理解】

- **定義**：用軟體在**一台實體機器**上，模擬出**多台獨立的虛擬電腦**，每台都以為自己獨佔硬體、可各跑各的 OS。靠 **Hypervisor（虛擬機器監視器）** 分配實體資源。
- 具體例子：VMware、VirtualBox、雲端的虛擬主機。

| Virtual Machine | 內容 |
|---|---|
| 優點 | **隔離性高**（一台當掉不影響別台）、資源彈性分配、一機可跑多種 OS、方便測試/開發/部署 |
| 缺點 | 多一層虛擬化 → **效能有損耗**、資源開銷大、實作較複雜 |

> 記憶鉤子：**VM = 一台機器「假裝」成很多台，靠 Hypervisor 分配硬體。** 換來隔離與彈性，代價是效能。
