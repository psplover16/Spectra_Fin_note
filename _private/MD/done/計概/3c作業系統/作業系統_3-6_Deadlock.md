# 作業系統 3-6：Deadlock（死結）★

## 一、死結是什麼 + 四個必要條件　【理解】

**死結（Deadlock）**：一組 process 互相等待對方手上的資源，結果全部卡住、誰也動不了，永遠等下去。
比喻：兩台車在獨木橋對向相遇，各不相讓、都等對方先退 → 卡死。

**四個必要條件（四個「同時」成立才會死結）：**

| 條件 | 意思 |
|---|---|
| **互斥 Mutual Exclusion** | 資源一次只能給一個 process 用，不能共享 |
| **持有並等待 Hold and Wait** | 手上握著資源，同時又在等別的資源 |
| **不可搶奪 No Preemption** | 資源不能被強搶，只能持有者自己放掉 |
| **循環等待 Circular Wait** | 形成等待環：P1 等 P2 的、P2 等 P3 的…最後繞回 P1 |

> 關鍵：這四個是**必要條件**——**四個全成立才可能死結；打破任一個就不會死結**。這正是「預防」的依據。

---

## 二、三種處理策略 + 安全狀態　【理解】

| 策略 | 時機 | 做法 | 代表 / 缺點 |
|---|---|---|---|
| **預防 Prevention** | 事前 | 直接**破壞四條件之一**，讓死結不可能發生 | 如：資源照編號遞增申請（破循環等待）。缺點：限制多、利用率低 |
| **避免 Avoidance** | 事中 | 每次配置前先判斷「配下去會不會進入不安全狀態」，安全才配 | 代表 = **銀行家演算法**；需事先知道最大需求 |
| **偵測與復原 Detection & Recovery** | 事後 | 允許死結發生，定期用等待圖找環，發現了再復原（殺 process、搶資源、rollback） | 抓出來再救 |

破壞四條件的具體手段（預防）：
- 破**互斥**：資源盡量設計成可共享（但有些天生不行）。
- 破**持有並等待**：一次拿齊全部、或拿新的前先放掉舊的。
- 破**不可搶奪**：拿不到就連手上的一起放掉（允許被搶）。
- 破**循環等待**：資源編號，規定只能依**遞增順序**申請。

**安全狀態（Safe State）**：若存在一個**安全序列**——能讓所有 process 依序拿到資源、跑完、釋放，全程不卡住——這個狀態就是安全的。
- **安全 → 一定不死結**；**不安全 → 可能死結**（不一定，但有風險，所以避免策略不准進入不安全狀態）。

## 三、銀行家演算法（Banker's Algorithm）　【練流程】

**用途**：屬「避免」策略。把 OS 當銀行、資源當錢，每次有人要借，先檢查「借出去後是否還能讓所有人都順利完成」，能才借——確保系統永遠停在安全狀態。

**四個資料表：**
- **Allocation**：目前已配給每個 process 的資源
- **Max**：每個 process 最多會用到的資源
- **Need ＝ Max − Allocation**：還差多少才能完成
- **Available**：系統目前剩多少可配

**安全演算法流程（找安全序列）：**
1. `Work ＝ Available`；每個 process 標 `Finish ＝ false`
2. 找一個 **還沒完成、且 Need ≤ Work** 的 process
3. 找到就假設它跑完並釋放資源：`Work ＝ Work + Allocation`，標 `Finish ＝ true`，記入序列
4. 重複 2–3。全部 Finish → **安全**（序列即安全序列）；找不到符合的 → **不安全**

---

### 手把手範例

系統有 3 種資源 A、B、C，總量 A=10、B=5、C=7。目前狀態：

| 行程 | Allocation (A B C) | Max (A B C) |
|---|---|---|
| P0 | 0　1　0 | 7　5　3 |
| P1 | 2　0　0 | 3　2　2 |
| P2 | 3　0　2 | 9　0　2 |
| P3 | 2　1　1 | 2　2　2 |
| P4 | 0　0　2 | 4　3　3 |

**步驟 1：算 Available**
已配出 A：0+2+3+2+0=7、B：1+0+0+1+0=2、C：0+0+2+1+2=5。
Available ＝ 總量 − 已配 ＝ (10−7, 5−2, 7−5) ＝ **(3, 3, 2)**。

**步驟 2：算 Need ＝ Max − Allocation**

| 行程 | Need (A B C) |
|---|---|
| P0 | 7　4　3 |
| P1 | 1　2　2 |
| P2 | 6　0　0 |
| P3 | 0　1　1 |
| P4 | 4　3　1 |

**步驟 3：跑安全演算法，Work 從 (3,3,2) 開始**

| 順序 | 挑誰 | Need ≤ Work？ | 跑完後 Work ＝ Work + Allocation |
|---|---|---|---|
| 1 | **P1** | (1,2,2) ≤ (3,3,2) ✓ | (3,3,2)+(2,0,0) ＝ (5,3,2) |
| 2 | **P3** | (0,1,1) ≤ (5,3,2) ✓ | (5,3,2)+(2,1,1) ＝ (7,4,3) |
| 3 | **P0** | (7,4,3) ≤ (7,4,3) ✓ | (7,4,3)+(0,1,0) ＝ (7,5,3) |
| 4 | **P2** | (6,0,0) ≤ (7,5,3) ✓ | (7,5,3)+(3,0,2) ＝ (10,5,5) |
| 5 | **P4** | (4,3,1) ≤ (10,5,5) ✓ | (10,5,5)+(0,0,2) ＝ (10,5,7) |

（過程中 P0 一開始 Need 太大被跳過，等 P1、P3 釋放後 Work 變大才輪到。）

**結論：全部跑完 → 系統處於安全狀態。安全序列：P1 → P3 → P0 → P2 → P4。**
（安全序列**可能不只一個**，找到任一個合法序列即可。）

---

### 補充：如果有人「請求資源」怎麼判斷

P_i 提出請求 Request 時，三步：
1. `Request ≤ Need[i]`？否 → 出錯（要的比宣告的還多）。
2. `Request ≤ Available`？否 → 資源不夠，**等待**。
3. **假裝先配給它**：`Available −= Request`、`Allocation[i] += Request`、`Need[i] −= Request`，再**重跑安全演算法**：
   - 安全 → 真的配給。
   - 不安全 → 撤銷這次假裝配置，讓它**等待**。

## 四、公式與對照表（背這張）

**公式：**
- **Need ＝ Max − Allocation**
- **Available ＝ 總資源 − Σ Allocation**
- 安全演算法：`Work = Available` → 反覆找 `Need ≤ Work` 的 process → 跑完 `Work += Allocation` → 全跑完即安全。

**重點口訣：**
- 死結四條件：**互斥、持有並等待、不可搶奪、循環等待**（打破任一個就不會死結）。
- 三策略：**預防（事前破條件）／避免（事中判斷，銀行家）／偵測復原（事後抓）**。
- 銀行家是「**避免**」；判斷依據是「找得到安全序列 ＝ 安全」。
- 請求判斷：先比 **Need**、再比 **Available**、最後**假裝配置跑一次安全演算法**。
