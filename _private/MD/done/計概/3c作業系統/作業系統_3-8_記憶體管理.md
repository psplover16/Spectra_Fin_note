## 一、四種配置法：First / Next / Best / Worst Fit　【練流程】

**用途**：連續配置下，process 要記憶體時，OS 要從一堆**空洞（free hole）**裡挑一個塞進去。四種挑法：

| 配置法 | 挑哪個洞 |
|---|---|
| **First Fit 最先適配** | 從頭找，第一個**夠大**的洞（快） |
| **Next Fit 循環適配** | 同 First，但從**上次停的位置**接著找（不每次從頭） |
| **Best Fit 最佳適配** | 夠大之中**最小**的洞（最貼需求；要找遍全部） |
| **Worst Fit 最差適配** | **最大**的洞（想讓剩下的洞還夠大可用） |

**一句話流程**：看需求大小 → 依規則從空洞清單挑一個 → 放進去（剩下的變新空洞）。

### 手把手範例

記憶體空洞（依位址順序）：**100K、500K、200K、300K、600K**。

**(1) 一個 process 需要 212K，四種 fit 各選哪個？**

先框出「夠大（≥212K）」的洞：**500、300、600**（100、200 太小）。

- **First Fit**：位址順序第一個夠大的 → **500K**
- **Next Fit**：從頭找（同 First）→ **500K**
- **Best Fit**：夠大之中最小 → min(500, 300, 600) ＝ **300K**
- **Worst Fit**：最大 → **600K**

**(2) 換成需要 426K（各自獨立看原始空洞）：**

夠大的洞：**500、600**。
- First Fit → **500K**；Best Fit → min(500, 600) ＝ **500K**；Worst Fit → **600K**

> 重點：同一個需求，四種 fit 可能挑到**完全不同**的洞。考試常給你空洞清單和需求，問各 fit 配到哪、或剩多少。

## 二、Fragmentation（碎裂）　【理解】

| | External 外部碎裂 | Internal 內部碎裂 |
|---|---|---|
| 問題 | 空洞**夠用但散落、不連續**，湊不出一塊連續空間給 process | 配給的空間**比實際需要大**，多出來用不到、浪費 |
| 發生在 | 連續配置（大小不一的洞） | 固定大小分配（如分頁的頁框） |
| 例子 | 三個 100K 散洞，來個要 250K 連續的就配不了 | 頁 4KB，process 需 9KB → 配 3 頁(12KB)，最後一頁只用 1KB，浪費 3KB |
| 解法 | **Compaction（緊縮）** 把已用的挪在一起合併空洞；或用 **paging** 免連續 | 把頁／塊切小一點（但增加管理成本） |

> 一句話分辨：**External ＝ 空間夠但「散」用不上；Internal ＝ 給太多、「內部」用不滿。**
> 補充：Best Fit 容易留下一堆**超小碎洞**（外部碎裂多）；Worst Fit 剩的洞較大、較可能再用。

## 三、Paging vs Segmentation　【理解】

| | Paging 分頁 | Segmentation 分段 |
|---|---|---|
| 怎麼切 | 切成**固定大小**的塊（page／frame） | 切成**大小不一**、依程式邏輯的段（code、data、stack…） |
| 對應表 | Page Table（頁號 → 頁框號） | Segment Table（base ＋ limit） |
| 邏輯位址 | (頁號, 頁內偏移) | (段號, 段內偏移) |
| 碎裂 | **無外部碎裂**、但**有內部碎裂**（最後一頁用不滿） | **有外部碎裂**、但**無內部碎裂** |
| 優點 | 不需連續、好管理 | 符合邏輯、方便以「段」為單位共享與保護 |

> 一句話分辨：**Paging 固定大小、不管意義；Segmentation 大小不一、依邏輯切。** 碎裂剛好相反（分頁內部碎裂、分段外部碎裂）。

## 四、TLB（Translation Lookaside Buffer）　【理解】

> **名詞修正**：TLB 是 **Translation** Lookaside Buffer（轉譯後備緩衝區），**不是**「Transaction」——你原筆記寫成 Transaction 是筆誤。

- **問題**：分頁下，每次存取資料都得先去記憶體查 **page table** 拿頁框號，再去拿資料 → 等於**每次要兩次記憶體存取**（查表 ＋ 拿資料），慢。
- **TLB**：一塊放在 CPU 裡的**超快小快取**，存「**最近用過的 頁號 → 頁框號**」對應。存取時先查 TLB：
  - **TLB hit（命中）**：直接拿到頁框號，**省掉查記憶體裡的 page table**。
  - **TLB miss（未命中）**：TLB 沒有，才去記憶體查 page table，並把這筆對應**放進 TLB**（下次就快）。
- **作用**：利用區域性（locality），大幅減少查表的記憶體存取，**加速位址轉換**。

> 這個 hit／miss 概念，下一篇 3-9 算 **Effective Memory Access Time** 會直接用到。
