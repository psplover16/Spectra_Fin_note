# 系統分析與設計 1：SDLC + SSDLC

> 科目：系統分析與設計（歸在資訊管理底下）
> 學習方式：大多屬【理解】（你工作上做過完整開發流程）；**開發模型、階段名稱**屬【硬背】。
> 你朋友提醒：這科很散，先補知識點，再去刷歷屆確認範圍。

---

## 一、SDLC 系統開發生命週期　【理解】

**SDLC（System Development Life Cycle）**：開發資訊系統的**標準階段流程**，從規劃到維護。
（你工作上其實跑過：需求 → 設計 → 開發 → 測試 → 上線 → 維護，這裡只是對上正式名稱。）

| 階段 | 在做什麼 | 誰主導 |
|---|---|---|
| **① 規劃 Planning** | 確定目標、**可行性分析** | 管理層 |
| **② 分析 Analysis** | **蒐集需求**、了解現況 | **系統分析師**（這科主角） |
| **③ 設計 Design** | 設計系統架構、資料庫、介面 | 設計師 |
| **④ 實作 Implementation** | **寫程式**、coding | 程式設計師 |
| **⑤ 測試 Testing** | 驗證功能正確 | 測試 |
| **⑥ 導入 Deployment** | 系統**上線** | — |
| **⑦ 維護 Maintenance** | 修錯、更新（**佔生命週期成本最大**） | — |

> （有些教材把測試併入實作，階段數略有不同；重點是這條**流程順序**。）

## 二、常見開發模型（常一起考）　【理解】＋【硬背】

| 模型 | 特點 | 優 / 缺 |
|---|---|---|
| **瀑布 Waterfall** | 一階段做完才下一階段，**線性、不回頭** | 文件清楚、好管理／**難應對需求變更**、後期才發現問題 |
| **雛形 Prototyping** | 先做**簡單原型**給使用者看、反覆修 | **早確認需求**／可能東拼西湊 |
| **螺旋 Spiral** | 瀑布＋原型＋**風險分析**，反覆迭代 | 重視風險、適合**大型高風險**／複雜、成本高 |
| **敏捷 Agile** | **小步快跑、反覆交付**（Scrum／Sprint） | **適應變更快**／文件少、需高度協作 |

> 你前端工作大概是 **Agile**（一個個 Sprint 交付）。

## 三、SSDLC 安全系統開發生命週期　【理解】＋【硬背】

**SSDLC（Secure SDLC）**：在 SDLC 的**每個階段都融入資安**，而不是系統做完才補。
- 核心理念：**Security by Design（資安從一開始就內建）**、**Shift Left（越早處理，修復成本越低）**。

| SDLC 階段 | 融入的資安 |
|---|---|
| 規劃／分析 | **安全需求**、風險評估 |
| 設計 | **威脅建模（Threat Modeling）**、安全架構 |
| 開發 | **安全編碼（Secure Coding）**、程式碼審查 |
| 測試 | **滲透測試、漏洞掃描**（SAST／DAST） |
| 導入／維護 | 安全設定、**持續監控**、修補 |

> 對比：傳統 SDLC 資安常是**事後補**；SSDLC 是**全程內建**。

---

## 四、重點整理（背這張）

- **SDLC** 流程：**規劃 → 分析 → 設計 → 實作 → 測試 → 導入 → 維護**；**分析階段是系統分析師主場**、**維護佔成本最大**。
- 開發模型：**瀑布**（線性不回頭）、**雛形**（原型反覆修）、**螺旋**（重風險、大型）、**敏捷**（小步快跑、應變快）。
- **SSDLC**：每階段**內建資安**（Security by Design、Shift Left）；威脅建模、安全編碼、滲透測試。
