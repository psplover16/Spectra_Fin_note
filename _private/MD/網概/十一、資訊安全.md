## 資訊安全是什麼

資訊安全（Information Security）是保護資訊與資訊系統的觀念與方法，目的不是只有「防駭客」，而是讓資料在儲存、傳輸、處理時，都能維持正確、保密且可正常使用。

白話來說，資訊安全要回答三個問題：

1. 不該看到資料的人，有沒有被擋住？
2. 資料有沒有被偷改、亂改或傳錯？
3. 合法使用者需要系統時，系統有沒有正常服務？

例如網路銀行中，帳戶餘額不能被陌生人看到，轉帳金額不能被竄改，使用者也不能因為網站被攻擊而完全無法登入。這些都屬於資訊安全的範圍。

國考常把資訊安全考成名詞辨識與情境判斷。看到「資料外洩」通常聯想到機密性；看到「資料被竄改」通常聯想到完整性；看到「服務中斷」通常聯想到可用性。

## CIA 三要素與其他安全目標

CIA 三要素是資訊安全最核心的必背架構。CIA 不是指情報機構，而是機密性（Confidentiality）、完整性（Integrity）、可用性（Availability）。

### 機密性

機密性（Confidentiality）是指資料只能讓被授權的人看到，未經授權者不能讀取或取得資料。

核心想法是「防止不該看的人看到」。常見做法包含加密（Encryption）、存取控制（Access Control）、身分驗證（Authentication）、權限控管與資料遮罩。

例如公司薪資表只能讓人資與主管查看，不能讓一般員工任意下載。若薪資資料被寄到外部信箱，就是機密性被破壞。

國考常見考法：題目若出現「資料外洩」、「未授權讀取」、「竊聽封包內容」，多半是在考機密性。

### 完整性

完整性（Integrity）是指資料保持正確、完整，沒有被未授權竄改、刪除或插入。

核心想法是「資料不能被亂改」。常見做法包含雜湊（Hash）、訊息驗證碼（Message Authentication Code, MAC）、數位簽章（Digital Signature）、交易紀錄與權限控管。

例如學生分數從 80 分被未授權者改成 98 分，就是完整性被破壞。若下載檔案後用雜湊值比對，確認檔案沒有被竄改，就是在檢查完整性。

國考常見考法：看到「資料被竄改」、「檔案是否被修改」、「傳輸過程有無遭改動」，通常是在考完整性。

### 可用性

可用性（Availability）是指合法使用者在需要時，可以正常使用系統與資料。

核心想法是「該用時要能用」。常見做法包含備援、負載平衡、備份、災難復原、DDoS 防護、監控與容量規劃。

例如政府網站因大量惡意流量而無法連線，合法民眾無法查詢服務，就是可用性被破壞。

國考常見考法：看到「服務中斷」、「系統當機」、「阻斷服務攻擊」，通常是在考可用性。

### 不可否認性

不可否認性（Non-repudiation）是指某人做過某件事後，不能事後否認。例如寄件者不能否認自己送出某份電子文件，交易者不能否認自己下過訂單。

核心想法是「做過就留下可驗證證據」。常見做法是數位簽章（Digital Signature）與時間戳記。

國考常見考法：若題目問「如何防止交易雙方事後否認」，常見答案是數位簽章，而不是單純加密。

### 認證性或真實性

認證性（Authentication）是確認使用者、設備或系統的身分。真實性（Authenticity）是確認資料或訊息確實來自宣稱的來源。

核心想法是「你真的是你嗎？」例如登入系統輸入帳號密碼、使用一次性密碼、憑證驗證網站身分，都屬於認證性或真實性的應用。

國考常見考法：看到「確認身分」、「驗證來源」、「證明是本人送出」，就要想到認證、憑證或數位簽章。

## 常見攻擊與防護措施

資訊安全攻擊很多，但國考常考的是基本特徵與對應防護。讀的時候不要只背英文縮寫，要能分辨攻擊在破壞哪一個安全目標。

### 惡意程式

電腦病毒（Computer Virus）是需要依附宿主程式的惡意程式，通常會感染檔案，當宿主程式被執行時一起活動。

核心想法是「像寄生在檔案上的程式」。例如使用者下載被感染的執行檔，執行後病毒開始感染其他檔案。防護方式包含防毒軟體、端點防護、不要執行來路不明檔案、定期更新系統。

蠕蟲（Worm）是不一定需要宿主程式，能自我複製並透過網路散播的惡意程式。

核心想法是「自己會擴散」。例如蠕蟲利用系統漏洞在區域網路中快速感染其他主機。防護方式包含修補漏洞、網段隔離、防火牆規則與入侵防護。

木馬（Trojan）是偽裝成正常或有用程式的惡意程式，誘使使用者自行安裝或執行。

核心想法是「看起來正常，其實暗藏惡意」。例如偽裝成破解軟體，實際上會竊取帳密。防護方式包含軟體來源控管、應用程式白名單、端點偵測。

勒索軟體（Ransomware）是會加密或鎖住資料，再要求受害者支付贖金的惡意程式。

核心想法是「把資料鎖起來勒索」。最重要防護包含備份 3-2-1 原則、權限最小化、端點防護、郵件過濾與教育訓練。

### 社交工程與釣魚

釣魚（Phishing）是攻擊者利用偽造信件、網站、簡訊或訊息，誘騙使用者交出帳號、密碼、信用卡或其他敏感資料。

核心想法是「騙人比破解系統便宜」。例如收到一封假冒銀行的信件，要求點連結重新登入，使用者輸入帳密後被竊取。

防護措施包含多因素認證（Multi-Factor Authentication, MFA）、郵件過濾、網址檢查、教育訓練與不要在不明連結輸入帳密。

國考常見考法：釣魚主要利用人性與信任，不一定需要技術漏洞。

### Web 應用攻擊

跨站腳本攻擊（Cross-Site Scripting, XSS）是攻擊者把惡意腳本注入網頁，使其他使用者瀏覽時執行。

核心想法是「把惡意 JavaScript 塞進別人的網頁」。例如留言板沒有過濾輸入，攻擊者留言中放入腳本，其他使用者打開頁面後 cookie 被竊取。防護方式包含輸入驗證、輸出編碼、內容安全政策（Content Security Policy, CSP）與避免直接插入未處理的使用者輸入。

SQL 注入（SQL Injection）是攻擊者把惡意 SQL 指令插入輸入欄位，使資料庫執行非預期查詢或修改。

核心想法是「把輸入變成資料庫指令」。例如登入欄位沒有妥善處理，攻擊者輸入特殊字串繞過驗證。防護方式包含參數化查詢、預備語句、輸入驗證與最小資料庫權限。

跨站請求偽造（Cross-Site Request Forgery, CSRF）是攻擊者誘使已登入的使用者在不知情下送出請求。

核心想法是「借用使用者已登入的身分做事」。例如使用者已登入網銀，又點到惡意網站，該網站偷偷送出轉帳請求。防護方式包含 CSRF Token、SameSite Cookie、重新驗證重要操作。

國考常見考法：XSS 是讓受害者瀏覽器執行惡意腳本；SQL Injection 是攻擊資料庫查詢；CSRF 是冒用已登入狀態送請求。

### 阻斷服務與網路欺騙

阻斷服務攻擊（Denial of Service, DoS）是讓系統無法提供正常服務。分散式阻斷服務攻擊（Distributed Denial of Service, DDoS）則是從大量來源一起發動攻擊。

核心想法是「讓合法使用者用不了」。例如大量請求灌爆網站頻寬或伺服器資源。防護方式包含流量清洗、速率限制、CDN、負載平衡、擴充容量與監控告警。

中間人攻擊（Man-in-the-Middle, MITM）是攻擊者插在雙方通訊之間，竊聽、攔截或竄改通訊內容。

核心想法是「你以為在跟對方說話，其實中間有人偷看或改話」。防護方式包含 TLS/HTTPS、憑證驗證、VPN 與避免使用不安全公共 Wi-Fi。

ARP 欺騙（ARP Spoofing）是攻擊者在區域網路中偽造 ARP 對應關係，使流量被導向攻擊者。

DNS 欺騙（DNS Spoofing）是攻擊者偽造 DNS 回應，使使用者連到錯誤或惡意網站。

國考常見考法：ARP Spoofing 常發生在區域網路層次；DNS Spoofing 是把網域名稱解析導向錯誤 IP。

## 防禦設備與安全架構

### 防火牆與相關設備

防火牆（Firewall）是依照規則允許或阻擋網路流量的設備或軟體。

核心想法是「守門員」。例如只允許外部連到公司網站的 443 連接埠，不允許外部直接連進資料庫。

次世代防火牆（Next-Generation Firewall, NGFW）是在傳統防火牆之外，加入應用程式識別、入侵防護、威脅情報等功能。

Web 應用程式防火牆（Web Application Firewall, WAF）是專門防護 HTTP/HTTPS Web 應用攻擊的設備或服務。

入侵偵測系統（Intrusion Detection System, IDS）是偵測可疑行為並告警，重點在「發現與通知」。

入侵防護系統（Intrusion Prevention System, IPS）是偵測可疑行為後主動阻擋，重點在「發現與阻擋」。

| 名詞 | 主要功能 | 國考關鍵字 |
|---|---|---|
| 防火牆（Firewall） | 依規則允許或阻擋流量 | 封包、連接埠、規則 |
| 次世代防火牆（NGFW） | 加入應用識別、IPS、威脅情報 | 應用層、進階防護 |
| WAF（Web Application Firewall） | 防護 Web 應用攻擊 | XSS、SQL Injection、HTTP/HTTPS |
| IDS（Intrusion Detection System） | 偵測並告警 | 只警告、不主動擋 |
| IPS（Intrusion Prevention System） | 偵測並阻擋 | 會主動阻擋 |

### Proxy、VPN 與 DMZ

代理伺服器（Proxy Server）是代替用戶端或伺服器轉送請求的系統，可用於快取、過濾、匿名化、控管或反向代理。

核心想法是「中間代理」。例如公司要求員工上網必須經過 Proxy，以便過濾惡意網站並記錄流量。

虛擬私人網路（Virtual Private Network, VPN）是在不可信任網路上建立加密通道，讓遠端使用者像在內部網路一樣安全連線。

核心想法是「在公網上建立加密隧道」。例如員工在家透過 VPN 連回公司內部系統。PPTP（Point-to-Point Tunneling Protocol）是早期 VPN 協定，安全性較弱，考試了解其屬於 VPN 協定即可。

非軍事區（Demilitarized Zone, DMZ）是放置對外服務的隔離網段，用來降低內部網路暴露風險。

核心想法是「對外服務放中間隔離區」。例如公司把 Web Server 放在 DMZ，而資料庫放在內部網路，避免外部直接碰到核心內網。

### 端點偵測與託管偵測

端點偵測與回應（Endpoint Detection and Response, EDR）是安裝在端點設備上，用來偵測、調查並回應可疑行為的資安工具。

託管式偵測與回應（Managed Detection and Response, MDR）是由外部服務商或專業團隊協助監控、偵測與回應資安事件。

核心想法：EDR 偏工具與端點能力，MDR 偏服務與託管營運。

## 密碼學基礎

密碼學（Cryptography）是利用數學方法保護資料安全的技術。國考常考加密、雜湊、數位簽章、憑證與 PKI 的差異。

### 對稱式加密

對稱式加密（Symmetric Encryption）是加密與解密使用同一把金鑰（Key）的加密方式。

核心想法是「同一把鑰匙鎖門，也用同一把鑰匙開門」。優點是速度快，適合大量資料加密；缺點是金鑰配送（Key Distribution）困難，因為雙方必須先安全取得同一把金鑰。

例如兩個人事先約好同一組密碼，之後用這組密碼加密與解密檔案。若金鑰在傳遞時被偷，安全性就會出問題。

國考常見考法：看到「速度快」、「同一把 key」、「大量資料加密」，多半是對稱式加密。

### 非對稱式加密

非對稱式加密（Asymmetric Encryption）是使用一組公鑰（Public Key）與私鑰（Private Key）。公鑰可以公開，私鑰必須保密。

核心想法是「一把公開給大家，一把自己保管」。若用接收者的公鑰加密，只有接收者的私鑰能解密，因此可解決金鑰配送問題；缺點是速度較慢。

例如網站憑證中的公鑰可讓瀏覽器建立安全通訊，而私鑰由網站伺服器保管。

國考常見考法：看到「public/private key」、「解決 key distribution」、「速度較慢」，多半是非對稱式加密。

### 雜湊

雜湊（Hash）是把任意長度資料轉成固定長度摘要（Digest）的單向函數。雜湊不是加密，因為正常設計下不能由摘要還原原文。

核心想法是「資料指紋」。只要原文有一點變動，雜湊值通常就會大幅不同。因此雜湊常用於完整性檢查。

例如網站提供安裝檔與 SHA-256 雜湊值，使用者下載後自行計算並比對，若值相同，表示檔案大致可判斷未被修改。

國考常見考法：題目若說「單向」、「摘要」、「檢查完整性」、「不是加密」，答案通常是雜湊。

### 數位簽章

數位簽章（Digital Signature）是用私鑰簽章，公鑰驗證的技術，可提供完整性、身分驗證與不可否認性。

核心想法是「用自己的私鑰蓋章，別人用你的公鑰驗章」。實務上通常不是直接簽整份文件，而是先對文件做雜湊，再對摘要簽章。

例如甲用自己的私鑰對電子合約簽章，乙用甲的公鑰驗證。若驗證成功，代表合約未被竄改，且可確認是甲的私鑰所簽。

國考常見考法：數位簽章不是為了保密內容，主要是完整性、身分驗證與不可否認性。

### 憑證與 PKI

數位憑證（Digital Certificate）是用來把「公鑰」與「身分」綁在一起的電子文件。它通常由憑證授權中心（Certificate Authority, CA）簽發。

公開金鑰基礎建設（Public Key Infrastructure, PKI）是一套管理公鑰、憑證與信任關係的制度與技術，通常包含 CA、憑證、憑證撤銷清單（Certificate Revocation List, CRL）與線上憑證狀態協定（Online Certificate Status Protocol, OCSP）。

核心想法是「我怎麼相信這把公鑰真的屬於某個網站或某個人？」例如瀏覽器連到 HTTPS 網站時，會檢查網站憑證是否由可信任 CA 簽發、是否過期、是否被撤銷。

國考常見考法：PKI 不是單一演算法，而是一套信任架構；CA 負責簽發與管理憑證；CRL/OCSP 用於查詢憑證是否被撤銷。

### 加密、雜湊、簽章、憑證比較

| 技術 | 先定義 | 主要目的 | 是否可還原原文 | 常見考點 |
|---|---|---|---|---|
| 加密（Encryption） | 將明文轉成密文 | 保密 | 可用金鑰解密還原 | 機密性 |
| 雜湊（Hash） | 將資料轉成固定長度摘要 | 完整性檢查 | 不可逆 | 不是加密 |
| 數位簽章（Digital Signature） | 私鑰簽章、公鑰驗證 | 完整性、身分驗證、不可否認性 | 不用來還原原文 | 防止否認 |
| 憑證（Certificate） | 綁定公鑰與身分 | 建立信任 | 不適用 | 由 CA 簽發 |
| PKI（Public Key Infrastructure） | 管理公鑰與憑證的架構 | 信任管理 | 不適用 | CA、CRL、OCSP |

## 電子商務安全需求

電子商務（Electronic Commerce, E-Commerce）安全需求是指線上交易環境必須具備的安全條件。常見需求包含機密性、完整性、不可否認性、可驗證性與存取控制。

1. 機密性（Confidentiality）：信用卡號、個資與交易內容不能被未授權者看到。
2. 完整性（Integrity）：訂單金額、收件地址與商品數量不能被竄改。
3. 不可否認性（Non-repudiation）：交易完成後，買賣雙方不能任意否認交易行為。
4. 可驗證性（Verifiability）：交易、身分或資料來源可以被驗證。
5. 存取控制（Access Control）：不同使用者只能做自己被授權的操作。

國考常見考法：電子商務常和數位簽章、憑證、PKI、HTTPS、不可否認性一起考。

## 近年常見資安觀念

零信任（Zero Trust）是一種安全架構觀念，核心是「永不信任、持續驗證、最小權限」。它不是單一產品，而是一套安全思維。

例如即使使用者已經在公司內網，也不能自動相信他；系統仍要檢查身分、設備狀態、存取權限與行為風險。

多因素認證（Multi-Factor Authentication, MFA）是使用兩種以上因素驗證身分。常見因素包含知道的東西，例如密碼；擁有的東西，例如手機或硬體金鑰；本身特徵，例如指紋或臉部辨識。

最小權限原則（Least Privilege）是使用者、程式或系統只取得完成工作所需的最低權限。

縱深防禦（Defense in Depth）是用多層防護降低單點失敗風險。例如同時使用防火牆、WAF、MFA、EDR、監控、備份與教育訓練。

備份 3-2-1 原則（Backup 3-2-1 Rule）是至少保留 3 份資料、使用 2 種不同媒介、其中 1 份放在異地。它常用來降低勒索軟體、硬體故障或災難造成的損失。

NIST（National Institute of Standards and Technology）是美國國家標準與技術研究院，常見於資安框架與標準來源。

ISO/IEC 27001:2022 是資訊安全管理系統（Information Security Management System, ISMS）的要求標準，重點在組織如何建立、執行、維持與持續改善資訊安全管理制度。

## 國考常見考法

### 考法一：給情境，問破壞哪個安全目標

如果題目說「網站被攻擊導致無法連線」，答案通常是可用性（Availability）。如果題目說「客戶個資外洩」，答案通常是機密性（Confidentiality）。如果題目說「交易金額被改掉」，答案通常是完整性（Integrity）。

### 考法二：問 IDS 與 IPS 差異

入侵偵測系統（IDS）偏向偵測與告警；入侵防護系統（IPS）偏向偵測後主動阻擋。考試常用「是否主動阻擋」作為分界。

### 考法三：問 WAF 與 Firewall 差異

防火牆（Firewall）常以網路流量、位址、連接埠與規則為主；Web 應用程式防火牆（WAF）專門防護 HTTP/HTTPS 應用層攻擊，例如 XSS 與 SQL Injection。

### 考法四：問加密、雜湊、數位簽章

加密（Encryption）重點是保密，雜湊（Hash）重點是完整性檢查，數位簽章（Digital Signature）重點是完整性、身分驗證與不可否認性。

### 考法五：問 PKI 組成

公開金鑰基礎建設（PKI）常見組成包含憑證授權中心（CA）、數位憑證（Digital Certificate）、憑證撤銷清單（CRL）與線上憑證狀態協定（OCSP）。

## 易混淆整理

| 易混淆項目 | 正確理解 |
|---|---|
| 雜湊是不是加密？ | 不是。雜湊是單向摘要，不能正常解回原文。 |
| 數位簽章是不是保密？ | 不是主要目的。它主要提供完整性、身分驗證與不可否認性。 |
| 對稱式加密是不是比較慢？ | 不是。對稱式加密通常比較快，但金鑰配送較困難。 |
| 非對稱式加密是不是不用保管金鑰？ | 錯。私鑰必須嚴格保密，公鑰才可公開。 |
| IDS 會不會主動阻擋？ | 通常不會，主要是偵測與告警。 |
| IPS 和 IDS 差在哪？ | IPS 會主動阻擋，IDS 主要告警。 |
| WAF 和一般防火牆一樣嗎？ | 不一樣。WAF 專門保護 Web 應用層。 |
| DoS 和 DDoS 差在哪？ | DDoS 是大量分散來源一起攻擊，規模通常更大。 |
| EDR 和 MDR 差在哪？ | EDR 偏端點工具與回應能力；MDR 偏託管式偵測回應服務。 |
| CA 和 PKI 一樣嗎？ | 不一樣。CA 是 PKI 中負責簽發憑證的重要角色。 |

## 國考必背整理

1. 機密性（Confidentiality）：防止未授權讀取。
2. 完整性（Integrity）：防止未授權竄改。
3. 可用性（Availability）：合法使用者需要時可使用。
4. 不可否認性（Non-repudiation）：行為者事後不能否認。
5. 認證性（Authentication）：確認身分。
6. 防火牆（Firewall）：依規則允許或阻擋流量。
7. 次世代防火牆（NGFW）：加入應用識別、IPS、威脅情報等。
8. Web 應用程式防火牆（WAF）：防護 HTTP/HTTPS 應用攻擊。
9. 入侵偵測系統（IDS）：偵測並告警。
10. 入侵防護系統（IPS）：偵測並主動阻擋。
11. 對稱式加密（Symmetric Encryption）：同一把金鑰加解密，速度快，金鑰配送困難。
12. 非對稱式加密（Asymmetric Encryption）：公鑰與私鑰成對，解決金鑰配送問題，但速度較慢。
13. 雜湊（Hash）：單向摘要，不是加密，常用於完整性檢查。
14. 數位簽章（Digital Signature）：私鑰簽章，公鑰驗證。
15. 公開金鑰基礎建設（PKI）：包含 CA、憑證、CRL/OCSP 等。
16. 虛擬私人網路（VPN）：建立加密通道。
17. 非軍事區（DMZ）：隔離對外服務區，降低內網暴露。
18. 零信任（Zero Trust）：永不信任、持續驗證、最小權限。
19. 多因素認證（MFA）：使用兩種以上因素驗證身分。
20. 備份 3-2-1 原則：3 份資料、2 種媒介、1 份異地。

## 容易考的判斷題

1. 「雜湊可以用來解密回原文。」錯。雜湊是單向摘要，不是加密。
2. 「數位簽章可提供不可否認性。」對。因為簽章使用私鑰產生，可用公鑰驗證。
3. 「對稱式加密加解密使用不同金鑰。」錯。對稱式加密使用同一把金鑰。
4. 「非對稱式加密通常比對稱式加密快。」錯。非對稱式加密通常較慢。
5. 「IDS 主要負責偵測與告警。」對。
6. 「IPS 可在偵測攻擊後主動阻擋。」對。
7. 「WAF 常用於防護 SQL Injection 與 XSS。」對。
8. 「DDoS 主要破壞可用性。」對。
9. 「DMZ 可降低內部網路直接暴露於外部的風險。」對。
10. 「Zero Trust 代表公司內網使用者一律可信。」錯。Zero Trust 的核心是永不信任、持續驗證。
11. 「MFA 只要多輸入幾次密碼就算多因素。」錯。多因素必須來自不同類型因素。
12. 「勒索軟體只會偷看資料，不會影響可用性。」錯。勒索軟體常加密資料，使資料不可用。

|---|---|

| 偵測阻擋 | IPS（Intrusion Prevention System） |
| 加密通道 | VPN（Virtual Private Network） |
