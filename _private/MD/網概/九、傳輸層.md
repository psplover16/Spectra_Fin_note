## 傳輸層是什麼

傳輸層（Transport Layer）是網路模型中負責「主機上的行程對行程」通訊的層級。新手可以先把它想成：網路層（Network Layer）負責把資料送到正確的電腦，而傳輸層（Transport Layer）負責把資料交給那台電腦上正確的應用程式。

例如你同時開著瀏覽器、通訊軟體與線上遊戲，網路上的資料都會送到你的電腦，但不同資料要交給不同程式。這時候就需要傳輸層（Transport Layer）搭配連接埠（Port）來分辨資料該交給誰。

國考常把傳輸層（Transport Layer）考成一句判斷：它不是只負責主機到主機，而是更精確地負責端到端（End-to-End）或行程到行程（Process-to-Process）的通訊。

## 封包交換與電路交換

電路交換（Circuit Switching）是指通訊前先建立一條固定通道，通話或傳輸期間這條通道被保留給雙方使用。傳統電話系統常被拿來當例子。

封包交換（Packet Switching）是指把資料切成一個個封包（Packet），每個封包可以依照網路狀況分別傳送，最後再由接收端重新組合。網際網路（Internet）主要採用封包交換（Packet Switching）。

兩者的核心差異在於「是否先保留固定通道」。電路交換（Circuit Switching）像先包下一條專用車道，封包交換（Packet Switching）則像把貨物分成多個包裹，各自走當下可用的路線。

| 比較項目 | 電路交換（Circuit Switching） | 封包交換（Packet Switching） |
|---|---|---|
| 通訊前準備 | 先建立固定通道 | 不一定需要固定通道 |
| 資源使用 | 通道被保留，閒著也占用 | 資源共享，使用較有彈性 |
| 常見例子 | 傳統電話 | 網際網路（Internet） |
| 國考關鍵字 | 固定通道、專線感 | 切成封包、分別傳送 |

國考常見考法是問：「Internet 較接近哪一種交換方式？」答案通常是封包交換（Packet Switching），不是電路交換（Circuit Switching）。

## 封包、標頭與資料內容

封包（Packet）是網路傳輸時的資料單位，可以理解成「外面貼著寄件資訊、裡面裝著真正內容」的小包裹。

封包（Packet）通常包含兩個重要部分：

1. 標頭（Header）：放控制與識別資訊，例如位址、序號、控制旗標等。
2. 資料內容（Payload）：真正要傳送的資料，例如網頁內容、檔案片段或應用程式資料。

標頭（Header）的功能像信封上的地址與處理資訊；資料內容（Payload）才像信封裡的信。國考若問「封包的 Header 放什麼」，要想到位址、序號、控制資訊等；若問 Payload，則是實際承載的資料。

## TCP 與 UDP

傳輸控制協定（Transmission Control Protocol, TCP）是傳輸層（Transport Layer）的重要協定，特色是連接導向（Connection-Oriented）與可靠傳輸（Reliable Delivery）。使用 TCP 前，雙方會先建立連線，傳輸時會盡量確保資料正確、完整、依序抵達。

使用者資料包協定（User Datagram Protocol, UDP）也是傳輸層（Transport Layer）的重要協定，特色是非連接導向（Connectionless）與低開銷（Low Overhead）。UDP 不會先建立連線，也不保證資料一定抵達或依序抵達，但速度快、負擔小。

### TCP/UDP 比較表

| 比較項目 | TCP | UDP |
|---|---|---|
| 中文名稱 | 傳輸控制協定（Transmission Control Protocol, TCP） | 使用者資料包協定（User Datagram Protocol, UDP） |
| 連線特性 | 連接導向（Connection-Oriented） | 非連接導向（Connectionless） |
| 可靠性 | 可靠傳輸（Reliable Delivery） | 不保證可靠 |
| 資料順序 | 依序傳送與接收（Ordered Delivery） | 不保證順序 |
| 控制機制 | 有流量控制與壅塞控制 | 控制機制較少 |
| 傳輸速度 | 較慢，因為控制成本較高 | 較快，因為開銷較小 |
| 適合情境 | HTTP、FTP、SMTP | DNS、VoIP、串流、線上遊戲 |
| 國考關鍵字 | 可靠、連線、順序、控制 | 快速、無連線、不保證 |

要記住：TCP 不是因為「永遠不會出錯」才可靠，而是因為它設計了確認、重傳、排序、流量控制等機制，讓傳輸結果更可靠。UDP 也不是「不能用」，而是把可靠性留給應用程式或情境自行處理。

## Port 與連線

連接埠（Port）是傳輸層（Transport Layer）用來辨識應用程式或服務的編號。IP 位址可以找到哪一台主機，Port 則可以找到主機上的哪一個服務。

例如瀏覽網頁時，伺服器可能使用 HTTP 的 80 Port 或 HTTPS 的 443 Port；DNS 查詢常使用 53 Port。當封包送到主機後，作業系統會根據目的 Port 把資料交給對應的程式。

連線（Connection）在 TCP 中很重要。TCP 的連線通常可用四個資訊辨識：來源 IP、來源 Port、目的 IP、目的 Port。國考若問「Port 的作用」，不要答成實體插孔；在網路概論中，Port 通常是邏輯編號，用來區分服務或行程。

## TCP 三向交握與四向揮手

三向交握（Three-Way Handshake）是 TCP 建立連線的程序。因為 TCP 是連接導向（Connection-Oriented），正式傳資料前要先確認雙方都能收送資料。

三向交握（Three-Way Handshake）的步驟如下：

1. 用戶端（Client）送出 SYN 給伺服器（Server），表示想建立連線。
2. 伺服器（Server）回覆 SYN + ACK，表示收到請求，也同意建立連線。
3. 用戶端（Client）再回覆 ACK，表示確認收到伺服器的回應。

簡記就是：SYN、SYN + ACK、ACK。

國考常考「TCP 建立連線需要幾次？」答案是三向交握（Three-Way Handshake），也就是三個訊息步驟，不要和四向揮手混在一起。

四向揮手（Four-Way Handshake）是 TCP 結束連線的程序。因為 TCP 是雙向通訊，雙方各自都要表示「我這邊沒有資料要送了」，所以常見流程是 FIN、ACK、FIN、ACK。

四向揮手（Four-Way Handshake）的步驟如下：

1. 一方送出 FIN，表示想關閉自己的傳送方向。
2. 另一方回 ACK，表示收到關閉請求。
3. 另一方也送出 FIN，表示它也準備關閉。
4. 原本那一方回 ACK，連線結束。

國考口訣：建立連線看三向交握，關閉連線看四向揮手。

## TCP 的可靠性、流量控制與壅塞控制

可靠傳輸（Reliable Delivery）是 TCP 的核心特色，意思是 TCP 會透過確認、重傳、排序等方式，盡量讓資料完整且依序送達。若某段資料遺失，TCP 可以重新傳送；若資料先後順序不同，TCP 可以重新排序。

有序傳輸（Ordered Delivery）是指接收端看到的資料順序會符合傳送端原本的順序。這對網頁、檔案傳輸、電子郵件等應用很重要，因為資料順序錯了，內容就可能壞掉。

流量控制（Flow Control）是避免「接收端被塞爆」的機制。TCP 常透過滑動視窗（Sliding Window）與接收視窗（Receiver Window）控制傳送速度。接收端可以告訴傳送端：「我現在還能收多少」，傳送端就依照這個能力調整傳輸量。

壅塞控制（Congestion Control）是避免「網路本身被塞爆」的機制。它關心的不是單一接收端的能力，而是整個網路路徑是否太壅塞。常見名詞包含慢啟動（Slow Start）、壅塞避免（Congestion Avoidance）、快速重傳（Fast Retransmit）與快速恢復（Fast Recovery）。

國考最愛混淆流量控制（Flow Control）與壅塞控制（Congestion Control）：

| 比較項目 | 流量控制（Flow Control） | 壅塞控制（Congestion Control） |
|---|---|---|
| 主要目的 | 避免接收端來不及收 | 避免網路路徑過度壅塞 |
| 觀察重點 | 接收端能力 | 網路狀態 |
| 常見機制 | 滑動視窗、接收視窗 | Slow Start、Congestion Avoidance、Fast Retransmit、Fast Recovery |
| 記憶方式 | 怕對方收不下 | 怕路上太塞 |

## SYN Flood 攻擊

SYN Flood 攻擊（SYN Flood Attack）是一種利用 TCP 三向交握（Three-Way Handshake）的阻斷服務攻擊。攻擊者大量送出 SYN 請求，但不完成最後的 ACK，讓伺服器維持許多半開連線（Half-Open Connection），最後耗盡伺服器資源。

可以把它想成很多人打電話訂位，店家先把位置保留，但對方一直不確認。保留名額越來越多，真正的客人就可能訂不到。

常見防禦方式包括：

1. SYN Cookies：減少伺服器在握手未完成前需要保留的狀態。
2. 速率限制（Rate Limiting）：限制短時間內過多的連線請求。
3. 防火牆（Firewall）：過濾異常流量。
4. 調整 Backlog：增加或調整半開連線佇列的承受能力。

國考看到「大量 SYN、不送 ACK、半開連線、耗盡伺服器資源」，通常就要想到 SYN Flood 攻擊（SYN Flood Attack）。

## 國考常見考法

國考在傳輸層（Transport Layer）通常不是考很深的實作細節，而是考你能不能辨認關鍵字。

1. 看到可靠、連線導向、依序、流量控制、壅塞控制：選 TCP。
2. 看到無連線、速度快、低開銷、不保證可靠：選 UDP。
3. 看到 DNS、VoIP、串流、遊戲：常見答案偏 UDP。
4. 看到 HTTP、FTP、SMTP：常見答案偏 TCP。
5. 看到 SYN、SYN + ACK、ACK：考 TCP 三向交握。
6. 看到 FIN、ACK、FIN、ACK：考 TCP 四向揮手。
7. 看到接收端來不及收：考流量控制。
8. 看到網路路徑太壅塞：考壅塞控制。
9. 看到大量 SYN 但不完成握手：考 SYN Flood。

## 易混淆整理

| 易混淆觀念 | 正確理解 |
|---|---|
| TCP 比 UDP 快 | 錯。通常 UDP 開銷較小、速度較快；TCP 因可靠性機制較多，成本較高。 |
| UDP 完全沒用 | 錯。UDP 適合即時性高、可容忍少量遺失的情境，如 VoIP、串流、遊戲。 |
| Port 是硬體插孔 | 錯。網路中的 Port 通常是邏輯編號，用來識別服務或應用程式。 |
| 三向交握用來關閉連線 | 錯。三向交握用來建立 TCP 連線。 |
| 四向揮手用來建立連線 | 錯。四向揮手用來結束 TCP 連線。 |
| 流量控制等於壅塞控制 | 錯。流量控制看接收端，壅塞控制看網路壅塞。 |
| SYN Flood 是 UDP 攻擊 | 錯。SYN Flood 利用的是 TCP 建立連線時的 SYN 流程。 |

## 國考必背整理

1. 傳輸層（Transport Layer）負責端到端或行程到行程通訊。
2. 封包（Packet）包含標頭（Header）與資料內容（Payload）。
3. 標頭（Header）放位址、序號、控制資訊等。
4. TCP 是連接導向（Connection-Oriented）且可靠。
5. UDP 是非連接導向（Connectionless）且不保證可靠。
6. TCP 有流量控制（Flow Control）、壅塞控制（Congestion Control）與有序傳輸（Ordered Delivery）。
7. Port 是用來區分主機上的服務或行程。
8. TCP 三向交握：SYN、SYN + ACK、ACK。
9. TCP 四向揮手：FIN、ACK、FIN、ACK。
10. SYN Flood 攻擊會造成大量半開連線，可能耗盡伺服器資源。

## 容易考的判斷題

1. TCP 是連接導向協定。正確。
2. UDP 會保證封包一定依序抵達。錯誤。
3. TCP 的三向交握用於建立連線。正確。
4. TCP 的四向揮手用於結束連線。正確。
5. 流量控制主要是避免接收端被資料塞爆。正確。
6. 壅塞控制主要是避免網路路徑過度壅塞。正確。
7. DNS、VoIP、串流與遊戲常見使用 UDP。正確。
8. HTTP、FTP、SMTP 常見使用 TCP。正確。
9. SYN Flood 攻擊會大量送出 SYN 且不完成握手。正確。
10. 封包的 Payload 主要放控制資訊，Header 主要放真正資料。錯誤。

## 考前速記小抄

TCP 要背「連線、可靠、順序、流控、壅控」。UDP 要背「無連線、較快、低開銷、不保證」。Port 要背「同一台主機上分辨不同服務」。三向交握是 SYN、SYN + ACK、ACK；四向揮手是 FIN、ACK、FIN、ACK。

最後用一句話收束：TCP 像掛號信，慢一點但有確認與順序；UDP 像快速丟訊息，速度快但不保證每一則都到。
