## 應用層是什麼

應用層（Application Layer）是網路模型中最接近使用者的一層，負責讓應用程式可以使用網路服務。白話來說，當你開瀏覽器看網頁、用電子郵件收信、輸入網址、下載檔案、觀看串流影片時，背後都會用到應用層的協定。

應用層的重點不是負責把資料封包實際送過網路線，也不是負責規劃路由，而是定義「應用程式之間怎麼溝通」。例如瀏覽器要跟網站伺服器要一個網頁，就需要知道請求格式、回應格式、錯誤碼、資源位置，這些規則通常由超文字傳輸協定（HyperText Transfer Protocol, HTTP）或安全超文字傳輸協定（HyperText Transfer Protocol Secure, HTTPS）定義。

國考常把應用層放在「協定與用途配對」來考。看到「寄信」要想到簡單郵件傳輸協定（Simple Mail Transfer Protocol, SMTP），看到「網域名稱解析」要想到網域名稱系統（Domain Name System, DNS），看到「自動取得 IP」要想到動態主機設定協定（Dynamic Host Configuration Protocol, DHCP）。

## 常見應用層協定與用途

### HTTP 與 HTTPS

超文字傳輸協定（HyperText Transfer Protocol, HTTP）是全球資訊網（World Wide Web, WWW）常用的應用層協定，主要負責瀏覽器與 Web 伺服器之間的請求與回應。使用者在瀏覽器輸入網址後，瀏覽器會向伺服器發出 HTTP 請求，伺服器再回傳網頁、圖片、JSON 資料或錯誤訊息。

安全超文字傳輸協定（HyperText Transfer Protocol Secure, HTTPS）可以理解成「HTTP over TLS」。傳輸層安全性協定（Transport Layer Security, TLS）會提供加密、身分驗證與資料完整性保護，所以 HTTPS 比 HTTP 更適合登入、付款、個資傳輸等情境。

具體範例：你登入網路銀行時，網址通常會以 `https://` 開頭，代表瀏覽器與網站之間的內容會經過 TLS 保護。若使用一般 `http://`，帳號密碼就可能在傳輸過程中被攔截或竄改。

國考常考：

1. HTTP 是 Web 應用協定。
2. HTTPS 是 HTTP 加上 TLS 保護。
3. HTTP 預設使用 TCP 80 port；HTTPS 預設使用 TCP 443 port。
4. HTTPS 不等於網站絕對安全，它主要保護傳輸過程。

### DNS

網域名稱系統（Domain Name System, DNS）負責把人類容易記的網域名稱轉換成電腦使用的 IP 位址，這個動作稱為網域名稱解析（Name Resolution）。例如使用者輸入 `www.example.com`，DNS 會協助查出它對應的 IP 位址，瀏覽器才能連到正確的伺服器。

DNS 的核心想法是「名字轉地址」。人比較容易記住文字名稱，電腦網路傳輸則需要 IP 位址，因此 DNS 就像網路世界的電話簿。

具體範例：你輸入網站名稱時，通常不需要記住 `93.184.216.34` 這類數字位址，因為 DNS 會替你做查詢。

國考常考：

1. DNS 的用途是網域名稱解析。
2. DNS 常用 UDP 53 port；必要時也可使用 TCP 53 port。
3. DNS 不是用來自動分配 IP，這點要和 DHCP 分清楚。

### DHCP

動態主機設定協定（Dynamic Host Configuration Protocol, DHCP）負責自動分配網路設定給主機，常見內容包含 IP 位址（IP Address）、子網路遮罩（Subnet Mask）、預設閘道（Default Gateway）與 DNS 伺服器位址。

DHCP 的核心想法是「讓電腦自動拿到可以上網的基本設定」。如果沒有 DHCP，使用者可能要手動設定 IP、mask、gateway、DNS，既麻煩又容易設定錯誤。

具體範例：手機連上家中 Wi-Fi 後，通常會自動取得一組區域網路 IP，例如 `192.168.1.23`，這通常就是 DHCP 伺服器分配的結果。

國考常考：

1. DHCP 會自動分配 IP、mask、gateway、DNS。
2. DHCP 不是用來查網域名稱，查網域名稱的是 DNS。
3. DHCP 常用 UDP 67 與 UDP 68 port。

### FTP

檔案傳輸協定（File Transfer Protocol, FTP）是用來在用戶端與伺服器之間傳輸檔案的應用層協定。它的重點是檔案上傳、下載與目錄操作。

FTP 的核心想法是「專門處理檔案傳輸」。早期網站維護者常使用 FTP 把網頁檔案上傳到伺服器。不過傳統 FTP 本身不加密，帳號密碼與資料可能以明文傳輸，因此實務上常改用安全版本或其他安全傳輸方式。

具體範例：管理網站時，把本機的 `index.html` 上傳到遠端伺服器，這就是 FTP 常見情境。

國考常考：

1. FTP 的用途是檔案傳輸。
2. FTP 控制連線常用 TCP 21 port；資料連線常見 TCP 20 port。
3. 傳統 FTP 不等於加密傳輸。

### SMTP、POP3 與 IMAP

簡單郵件傳輸協定（Simple Mail Transfer Protocol, SMTP）負責寄信，也就是將郵件從寄件端送到郵件伺服器，或在郵件伺服器之間轉送。

郵局協定第 3 版（Post Office Protocol version 3, POP3）負責收信，傳統使用方式常把郵件下載到本機。網際網路訊息存取協定（Internet Message Access Protocol, IMAP）也負責收信，但重點是郵件保留在伺服器上，讓多台裝置可以同步信件狀態。

核心想法可以這樣記：SMTP 是「送出去」，POP3 與 IMAP 是「收進來」。POP3 偏向下載，IMAP 偏向同步。

具體範例：你用手機與電腦同時看同一個信箱，刪除或已讀狀態可以同步，通常會使用 IMAP。若是早期把信件下載到單一電腦後伺服器不再保留，則是 POP3 的典型印象。

國考常考：

1. SMTP：寄信。
2. POP3：收信，傳統上常下載到本機。
3. IMAP：收信，郵件保留在伺服器並同步多裝置狀態。
4. SMTP 常用 TCP 25 port；POP3 常用 TCP 110 port；IMAP 常用 TCP 143 port。

## URL 與 Web 請求

### URL

統一資源定位符（Uniform Resource Locator, URL）用來定位網路上的資源。它通常包含通訊方案（Scheme）、主機名稱（Host）、路徑（Path）、查詢字串（Query）等部分。

以 `https://www.example.com/search?q=network` 為例：

| 部分 | 範例 | 說明 |
|---|---|---|
| Scheme | `https` | 使用的協定或存取方式 |
| Host | `www.example.com` | 主機名稱或網域名稱 |
| Path | `/search` | 伺服器上的資源路徑 |
| Query | `q=network` | 傳給伺服器的查詢參數 |

核心想法是：URL 不是只有網址文字而已，它是在告訴瀏覽器「用什麼方式、去找哪台主機、取得哪個資源、附帶哪些參數」。

國考常考 URL 的組成，尤其是 scheme、host、path、query 的辨識。

### GET 與 POST

GET 方法（GET Method）常用來取得資源，參數常出現在 URL 的 query 中。它在設計上應具備冪等性（Idempotence），也就是同樣請求做一次或多次，理論上不應改變伺服器資源狀態。

POST 方法（POST Method）常用來提交資料，資料通常放在請求本體（Request Body）中，不要求具備冪等性。常見用途包含送出表單、建立資料、上傳內容。

| 比較項目 | GET | POST |
|---|---|---|
| 主要用途 | 取得資源 | 提交資料 |
| 參數常見位置 | URL query | Request body |
| 是否要求冪等 | 應具冪等性 | 不要求冪等 |
| 常見例子 | 搜尋、查詢頁面 | 登入、送出表單、新增留言 |

具體範例：搜尋關鍵字常見 `GET /search?q=exam`，因為只是查資料；送出註冊表單常用 POST，因為它可能會新增帳號資料。

國考常考 GET 與 POST 的差異，但要注意：POST 的資料放在 body 不代表一定安全；若沒有 HTTPS，仍可能被攔截。

## Port 與用途

連接埠（Port）是作業系統用來區分同一台主機上不同網路服務的號碼。IP 位址可以找到哪一台主機，port 則可以找到那台主機上的哪一個服務。

具體範例：同一台伺服器可以同時提供網站服務與郵件服務。瀏覽器連到 TCP 443 port 使用 HTTPS，郵件伺服器可能在 TCP 25 port 處理 SMTP。

常見 port 整理：

| 協定 | 常見 Port | 主要用途 |
|---|---:|---|
| FTP | TCP 20、21 | 檔案傳輸 |
| SSH | TCP 22 | 安全遠端登入 |
| SMTP | TCP 25 | 寄信 |
| DNS | UDP/TCP 53 | 網域名稱解析 |
| DHCP | UDP 67、68 | 自動分配 IP 等網路設定 |
| HTTP | TCP 80 | Web 傳輸 |
| POP3 | TCP 110 | 收信，常下載到本機 |
| IMAP | TCP 143 | 收信並保留在伺服器同步 |
| HTTPS | TCP 443 | 加密 Web 傳輸 |
| SNMP | UDP 161、162 | 網路管理與告警 |

國考常考「協定、用途、port」三者配對。準備時不要只背中文用途，也要能看到英文縮寫立刻反應。

## 網路管理、串流與新型網路概念

### SNMP

簡易網路管理協定（Simple Network Management Protocol, SNMP）是用來管理與監控網路設備的應用層協定。網管系統可以透過 SNMP 查詢路由器、交換器、伺服器等設備狀態，例如流量、CPU 使用率、介面是否正常。

核心想法是「集中監控網路設備」。如果某台交換器異常，SNMP 可以協助網管人員取得狀態或接收告警。

國考常考 SNMP 的用途是網路管理，不是寄信、不是檔案傳輸、也不是網域名稱解析。

### RTP、RTCP 與 RTSP

即時傳輸協定（Real-time Transport Protocol, RTP）用於即時傳輸音訊與視訊，例如語音通話、視訊會議等。RTP 關心的是即時媒體資料如何傳送。

RTP 控制協定（RTP Control Protocol, RTCP）通常搭配 RTP 使用，用來提供傳輸品質回饋與控制資訊，例如封包遺失率、延遲、抖動等統計。

即時串流協定（Real Time Streaming Protocol, RTSP）用於串流控制，常見概念包含播放、暫停、停止等控制動作。它比較像是遙控器，負責控制串流播放流程。

國考常考：

1. RTP：即時傳輸音訊與視訊。
2. RTCP：RTP 的控制與品質回饋。
3. RTSP：串流控制。

### Gateway

閘道器（Gateway）在應用層脈絡中常指協定轉換或應用層閘道。它可以讓不同協定、不同系統或不同網路環境之間互相溝通。

具體範例：某些郵件閘道可以在不同郵件系統之間轉換格式；某些應用層閘道可以檢查 HTTP 請求內容，作為安全控管的一部分。

國考看到 Gateway，要注意題目問的是哪一層、哪一種功能。若題目強調應用層，常見答案會偏向協定轉換或應用層服務轉接。

### CDN

內容傳遞網路（Content Delivery Network, CDN）是一種把內容快取在靠近使用者節點的技術架構。它的目的通常是降低延遲、分散流量、提升下載速度與服務可用性。

核心想法是「把常用內容放近一點」。如果台灣使用者要看某國外網站的圖片或影片，CDN 可能讓使用者從亞洲節點取得內容，而不是每次都連到很遠的原始伺服器。

國考常考 CDN 的用途是內容快取、加速傳遞、靠近使用者，而不是負責分配 IP 或解析網域名稱。

### SDN

軟體定義網路（Software-Defined Networking, SDN）是一種網路架構概念，重點是將控制平面（Control Plane）與資料平面（Data Plane）分離。控制平面負責決定資料如何轉送，資料平面負責實際轉送封包。

核心想法是「集中控制、彈性管理」。傳統網路設備常各自決定轉送規則；SDN 則可以由控制器統一管理網路行為，讓網路設定更自動化、可程式化。

國考常考 SDN 的關鍵字：控制平面與資料平面分離、集中控制、Software-Defined Networking。

## 國考常見考法

應用層在國考中常以記憶與理解混合出題，考法大致有四類。

第一類是「用途配對」。例如題目問哪個協定負責寄信，答案是 SMTP；哪個協定負責網域名稱解析，答案是 DNS；哪個協定負責自動取得 IP，答案是 DHCP。

第二類是「相似協定比較」。例如 POP3 與 IMAP 都能收信，但 IMAP 偏重伺服器保留與多裝置同步；GET 與 POST 都是 HTTP 方法，但 GET 偏查詢、POST 偏提交。

第三類是「port 配對」。常見題型會問 HTTP、HTTPS、DNS、FTP、SMTP、POP3、IMAP、DHCP 的 port。這類題目沒有太多推理空間，必須熟背。

第四類是「觀念判斷」。例如 HTTPS 是否代表網站一定可信？答案是否定的，HTTPS 主要保護傳輸過程，不保證網站內容本身一定合法或安全。

## 易混淆整理

| 容易混淆 | 正確理解 | 記憶方式 |
|---|---|---|
| DNS vs DHCP | DNS 解析名稱；DHCP 分配網路設定 | DNS 找地址，DHCP 發設定 |
| SMTP vs POP3/IMAP | SMTP 寄信；POP3/IMAP 收信 | S 可想成 Send |
| POP3 vs IMAP | POP3 傳統上下載到本機；IMAP 保留伺服器同步 | IMAP 適合多裝置 |
| HTTP vs HTTPS | HTTPS 是 HTTP over TLS | S 可想成 Secure |
| GET vs POST | GET 取得資源；POST 提交資料 | 查詢 GET，送出 POST |
| RTP vs RTCP vs RTSP | RTP 傳媒體；RTCP 控制品質；RTSP 控制播放 | P 傳資料，CP 控品質，SP 控串流 |
| CDN vs DNS | CDN 快取內容；DNS 解析網域 | CDN 加速內容，DNS 查 IP |
| Gateway vs Router | Gateway 可做協定轉換；Router 偏路由轉送 | 題目要看語境 |

1. DNS：網域名稱解析。
2. DHCP：自動分配 IP、子網路遮罩、預設閘道、DNS。
3. FTP：檔案傳輸。
4. URL：定位網路資源，常包含 scheme、host、path、query。
5. GET：取得資源，參數常在 URL，應具冪等性。
6. POST：提交資料，資料常在 body，不要求冪等。
7. SNMP：網路管理。
8. SDN：控制平面與資料平面分離。
9. RTP：即時傳輸音訊與視訊。
10. RTCP：RTP 控制協定，提供控制與品質回饋。
11. RTSP：串流控制。
12. HTTP：Web 應用協定。
13. HTTPS：HTTP over TLS。
14. Gateway：協定轉換或應用層閘道。
15. CDN：內容傳遞網路，靠近使用者快取內容。
16. SMTP：寄信。
17. IMAP：收信並保留在伺服器同步。
18. POP3：收信，傳統上常下載到本機。

## 容易考的判斷題

1. DNS 的主要功能是自動分配 IP 位址。  
   錯。DNS 是網域名稱解析；自動分配 IP 是 DHCP。

2. DHCP 可以分配 IP、子網路遮罩、預設閘道與 DNS 伺服器。  
   對。這是 DHCP 的典型功能。

3. SMTP 主要用於接收電子郵件。  
   錯。SMTP 主要用於寄信；收信常用 POP3 或 IMAP。

4. IMAP 適合多裝置同步郵件狀態。  
   對。IMAP 通常將郵件保留在伺服器上。

5. HTTPS 是 HTTP over TLS。  
   對。HTTPS 透過 TLS 保護 HTTP 傳輸。

6. GET 通常用於取得資源，POST 通常用於提交資料。  
   對。這是 HTTP 方法的基本比較。

7. CDN 的目的是讓內容靠近使用者，以提升傳遞效率。  
   對。CDN 常透過快取節點降低延遲。

8. RTP 負責串流播放控制，例如播放與暫停。  
   錯。RTP 主要傳輸即時音訊與視訊；RTSP 才偏向串流控制。

9. SDN 的重要概念是控制平面與資料平面分離。  
   對。這是 SDN 的核心關鍵字。

10. 傳統 FTP 一定會加密帳號密碼與資料內容。  
    錯。傳統 FTP 本身不保證加密。
