## 網路是什麼

網路（Network）是指多台電腦、伺服器、手機、印表機或其他設備，透過有線或無線方式連接起來，讓彼此可以交換資料與共享資源的系統。

在網路中傳遞的資料通常會被切成封包（Packet）。封包（Packet）可以理解成「被分裝好的資料小包裹」，每個封包會帶著必要資訊，例如來源、目的地與資料內容，讓網路設備知道該把它送到哪裡。

通訊協定（Protocol）是網路世界的共同規則。因為不同設備可能來自不同廠商、使用不同作業系統，所以必須靠通訊協定（Protocol）規定資料格式、傳輸方式與錯誤處理方式。白話來說，通訊協定就像交通規則；沒有規則，資料就算送出去了，對方也不一定看得懂。

國考常見的網路概論題目，通常不會只問「名詞是什麼」，而是會考你能不能分辨不同網路範圍、不同架構、不同傳輸方式，以及各自的優缺點。

## 網路依範圍分類：LAN、MAN、WAN

區域網路（Local Area Network, LAN）是範圍較小的網路，常見於家庭、辦公室、學校電腦教室或公司內部。區域網路（LAN）的特色是範圍小、速度通常較快、管理相對容易。

都會網路（Metropolitan Area Network, MAN）是範圍介於區域網路與廣域網路之間的網路，通常涵蓋一個城市或都會區。例如某個城市的政府機關、學校或公共服務系統之間互相連線，就可以視為都會網路（MAN）的概念。

廣域網路（Wide Area Network, WAN）是範圍最大的網路，可以跨城市、跨國家，甚至跨洲。網際網路（Internet）就是最典型的廣域網路（WAN）例子。

核心想法很簡單：考範圍時，從小到大記成 LAN、MAN、WAN。區域網路（LAN）偏向「一棟樓、一個校園、一間公司」；都會網路（MAN）偏向「一個城市」；廣域網路（WAN）偏向「跨城市、跨國、Internet」。

### 範圍比較表

| 類型 | 中文名稱 | 典型範圍 | 例子 | 國考關鍵字 |
| --- | --- | --- | --- | --- |
| LAN | 區域網路 | 小範圍 | 家庭、辦公室、校園 | 範圍小、速度快、易管理 |
| MAN | 都會網路 | 城市範圍 | 城市內機關或學校連線 | 都會區、城市 |
| WAN | 廣域網路 | 跨城市或跨國 | Internet | 範圍最大、跨國、跨區 |

## 網路服務架構：Client-Server 與 P2P

用戶端-伺服器架構（Client-Server Architecture）是指由伺服器（Server）提供服務，用戶端（Client）向伺服器提出請求。例如你用瀏覽器開網站時，瀏覽器是用戶端（Client），網站主機是伺服器（Server）。

這種架構的核心想法是「集中管理」。資料、權限與服務大多集中在伺服器端，因此比較容易維護、控管與保護。不過，如果太多人同時連到同一台伺服器，伺服器就可能變成瓶頸；如果伺服器故障，服務也可能中斷。

點對點網路（Peer-to-Peer, P2P）是指每個節點（Node）都可以同時扮演資源提供者與資源使用者。節點（Node）是網路中的一個連線設備或參與者，例如一台電腦。P2P 不一定依賴中央伺服器，節點彼此可以互相分享資料或資源。

P2P 的優點是擴充性高，因為加入的節點越多，理論上可提供的資源也越多。但它的缺點是管理與安全較困難，因為資源分散在許多節點上，不像 Client-Server 那樣容易集中控管。

### Client-Server 與 P2P 比較

| 架構 | 核心觀念 | 優點 | 缺點 | 常見考法 |
| --- | --- | --- | --- | --- |
| Client-Server | 伺服器集中提供服務 | 容易管理、權限控管清楚 | 伺服器可能成為瓶頸或單點故障 | 問「集中管理」通常選它 |
| P2P | 節點彼此分享資源 | 擴充性高、資源分散 | 管理與安全較困難 | 問「節點互相提供資源」通常選它 |

## Web 傳輸協定：HTTP 與 HTTPS

超文字傳輸協定（HyperText Transfer Protocol, HTTP）是瀏覽器與網站伺服器之間常用的通訊協定。HTTP 的主要用途是傳送網頁資料，例如 HTML、圖片、表單內容等。HTTP 預設連接埠（Port）是 80。

連接埠（Port）是用來區分同一台主機上不同服務的編號。可以把主機想成一棟大樓，而連接埠（Port）像不同房間號碼；網路資料抵達主機後，還需要靠 Port 找到正確服務。

HTTP 的重要缺點是明文傳輸。明文傳輸表示資料沒有經過加密，若在傳輸途中被攔截，內容可能被直接看懂。因此 HTTP 不適合傳送密碼、信用卡號、個人資料等敏感資訊。

超文字傳輸安全協定（HyperText Transfer Protocol Secure, HTTPS）可以理解為「HTTP over TLS」。傳輸層安全性協定（Transport Layer Security, TLS）提供加密與憑證驗證。HTTPS 預設連接埠（Port）是 443。

加密（Encryption）是把原本看得懂的資料轉成不容易被看懂的形式。憑證驗證（Certificate Authentication）則是用來確認網站身分，降低使用者連到假網站或被中間人攻擊的風險。

### HTTP 與 HTTPS 比較

| 項目 | HTTP | HTTPS |
| --- | --- | --- |
| 中文概念 | 超文字傳輸協定 | 安全版 HTTP |
| 預設 Port | 80 | 443 |
| 傳輸內容 | 明文 | 加密 |
| 安全性 | 較低 | 較高 |
| 主要保護 | 無加密保護 | 加密、憑證驗證 |
| 國考關鍵字 | 明文、80 | TLS、加密、憑證、443 |

## 無狀態 Stateless 的觀念

無狀態（Stateless）是指伺服器不會自動保存每次請求之間的狀態。請求（Request）是用戶端送給伺服器的要求，例如「我要看這個網頁」或「我要送出登入表單」。

HTTP 常被描述為無狀態（Stateless）協定。意思是伺服器收到一次請求、回覆一次資料後，不會天生記得「上一個請求是誰送的」或「這個使用者剛剛做了什麼」。

無狀態的優點是簡單、容易擴充。因為每次請求都可以獨立處理，伺服器之間比較容易分工，也比較方便做負載平衡（Load Balancing）。負載平衡（Load Balancing）是把請求分散到多台伺服器處理，避免單一伺服器壓力過大。

無狀態的缺點是，如果網站需要記住登入狀態、購物車內容或使用者偏好，就必須透過額外機制處理，例如 Cookie、Session 或 Token。

國考常考陷阱是把「HTTP 無狀態」誤解成「網站不能登入」。正確理解是：HTTP 本身不保存狀態，但應用程式可以用其他方法保存狀態。

## Cookie、Session、Token

Cookie（Cookie）是儲存在用戶端（Client）的小型資料，通常由瀏覽器保存，並在之後請求同一網站時自動帶給伺服器。Cookie 常用來保存識別資訊、偏好設定或 Session ID。

Session（Session）是伺服器端用來保存使用者狀態的機制。典型做法是伺服器保存狀態資料，而用戶端只保存一個 Session ID。當瀏覽器帶著 Session ID 回來時，伺服器就能查到對應的登入狀態或購物車資料。

Token（Token）是用來代表身分或授權資訊的一段資料，常見於應用程式介面（Application Programming Interface, API）。API 是讓不同程式彼此溝通的介面，例如手機 App 向後端服務要求資料。JSON Web Token（JWT）是一種常見 Token 格式。

Cookie、Session、Token 都可以用來補足 HTTP 無狀態的問題，但保存位置與管理方式不同。考試時最重要的是分清楚：Cookie 偏用戶端、Session 偏伺服器端、Token 常用於 API 授權。

### Cookie、Session、Token 比較

| 項目 | Cookie | Session | Token |
| --- | --- | --- | --- |
| 主要保存位置 | 用戶端瀏覽器 | 多數狀態在伺服器端 | 常由用戶端保存並隨請求送出 |
| 常見用途 | 偏好設定、識別資訊、Session ID | 登入狀態、購物車 | API 身分驗證與授權 |
| 優點 | 使用方便、瀏覽器自動帶送 | 伺服器較容易控管狀態 | 適合前後端分離與 API |
| 注意事項 | 可能被竊取或濫用，需安全設定 | 伺服器需保存狀態，規模大時要管理 | 要注意過期、簽章、撤銷問題 |
| 國考關鍵字 | 存在 client | server 保存狀態，client 存 session id | JWT、API、簽章、過期 |

## 網路拓樸：Bus、Ring、Star、Mesh

網路拓樸（Network Topology）是指網路中設備連接的形狀或結構。拓樸不是在問「網路用途」，而是在問「設備如何連在一起」。

匯流排拓樸（Bus Topology）是所有設備共用一條主要傳輸線。它的優點是成本較低、架設簡單；缺點是主幹線路如果故障，可能影響整個網路。

環狀拓樸（Ring Topology）是設備形成環狀連接，資料沿著環的方向傳遞。它的特色是資料依序傳遞，但如果某個節點或連線故障，可能影響整個環。

星狀拓樸（Star Topology）是所有設備都連到中心設備，例如交換器（Switch）或集線器（Hub）。交換器（Switch）是常見的區域網路設備，用來依目的位置轉送資料。星狀拓樸容易管理，單一節點故障通常不會影響其他節點；但中心設備故障時，整個網路可能受影響。

網狀拓樸（Mesh Topology）是節點之間有多條連線，甚至每個節點都可能與其他節點直接相連。它的可靠度高，因為某條路壞了還可能改走其他路；缺點是成本高、佈線與管理較複雜。

### 網路拓樸比較表

| 拓樸 | 中文名稱 | 核心特色 | 優點 | 缺點 | 國考關鍵字 |
| --- | --- | --- | --- | --- | --- |
| Bus | 匯流排拓樸 | 共用一條主幹 | 成本低、架設簡單 | 主幹故障影響大 | 主幹、共用線路 |
| Ring | 環狀拓樸 | 資料沿環傳遞 | 傳遞順序清楚 | 故障可能影響整環 | 環、依序傳遞 |
| Star | 星狀拓樸 | 連到中心設備 | 易管理、單點節點故障影響較小 | 中心設備故障影響大 | 中心設備、Switch |
| Mesh | 網狀拓樸 | 多重連線 | 可靠度高、容錯好 | 成本高、複雜 | 多路徑、高可靠 |

## 國考常見考法

1. 考網路範圍大小  
   常見問法是「下列何者範圍最大？」答案通常是廣域網路（WAN）。若題目提到 Internet，也要聯想到 WAN。

2. 考架構優缺點  
   題目若出現「集中管理、伺服器提供服務」，多半是用戶端-伺服器架構（Client-Server）。若出現「節點彼此分享資源」，多半是點對點網路（P2P）。

3. 考 Port 與安全性  
   HTTP 預設 Port 80，HTTPS 預設 Port 443。HTTP 是明文，HTTPS 有 TLS、加密與憑證驗證。

4. 考 Stateless  
   無狀態（Stateless）表示伺服器不保存每次請求間的狀態。若要記住登入或購物車，就要靠 Cookie、Session 或 Token。

5. 考拓樸故障影響  
   Bus 要注意主幹故障，Star 要注意中心設備故障，Ring 要注意整環受影響，Mesh 要注意高可靠但成本高。

## 易混淆比較表

| 易混淆項目 | 容易錯的想法 | 正確觀念 |
| --- | --- | --- |
| LAN 與 WAN | 只要能上網就是 LAN | LAN 是小範圍，Internet 是典型 WAN |
| HTTP 與 HTTPS | HTTPS 只是 HTTP 的新版 | HTTPS 是 HTTP 加上 TLS 安全保護 |
| Stateless | 無狀態代表不能登入 | HTTP 本身不記狀態，但可用 Cookie、Session、Token 補足 |
| Cookie 與 Session | Cookie 與 Session 都存在伺服器 | Cookie 在用戶端；Session 多數狀態在伺服器端 |
| Client-Server 與 P2P | P2P 一定比較安全 | P2P 擴充性高，但管理與安全較困難 |
| Star 與 Mesh | 都很可靠所以成本差不多 | Star 易管理但怕中心設備；Mesh 可靠高但成本高 |

## 國考必背整理

- 區域網路（LAN）：範圍小，例如公司、校園、家庭。
- 都會網路（MAN）：城市或都會區範圍。
- 廣域網路（WAN）：跨城市、跨國，Internet 是典型例子。
- 用戶端-伺服器架構（Client-Server）：伺服器集中提供服務，容易管理，但伺服器可能成瓶頸。
- 點對點網路（P2P）：節點彼此提供資源，擴充性高，但管理與安全較難。
- HTTP：明文傳輸，預設 Port 80。
- HTTPS：HTTP over TLS，提供加密與憑證驗證，預設 Port 443。
- 無狀態（Stateless）：伺服器不保存每次請求間的狀態。
- Cookie：存於用戶端，瀏覽器會帶給伺服器。
- Session：狀態多存於伺服器，用戶端保存 Session ID。
- Token：常見於 API，例如 JWT，要注意過期、簽章與撤銷問題。
- Bus：成本低，但主幹故障影響大。
- Ring：資料依環傳遞，故障可能影響整環。
- Star：中心設備連接，易管理，但中心故障影響大。
- Mesh：可靠度高，但成本高。

## 容易考的判斷題

1. HTTP 預設使用 Port 80。  
   答：對。HTTP 是明文傳輸，預設 Port 為 80。

2. HTTPS 不需要憑證也能提供網站身分驗證。  
   答：錯。HTTPS 的重要功能之一就是透過憑證協助驗證網站身分。

3. 無狀態（Stateless）表示伺服器不會自動保存每次請求之間的狀態。  
   答：對。

4. Cookie 主要儲存在伺服器端。  
   答：錯。Cookie 主要儲存在用戶端瀏覽器。

5. Session 常見做法是伺服器保存狀態，用戶端保存 Session ID。  
   答：對。

6. P2P 的節點只能下載資料，不能提供資料。  
   答：錯。P2P 的節點可以彼此提供資源。

7. Star 拓樸的中心設備故障可能影響整個網路。  
   答：對。

8. Mesh 拓樸可靠度高，但成本也高。  
   答：對。

9. Internet 是典型的區域網路（LAN）。  
   答：錯。Internet 是典型的廣域網路（WAN）。

10. Bus 拓樸的主幹線路故障可能造成大範圍影響。  
    答：對。

## 考前速記小抄

範圍大小記法：LAN 小、MAN 城市、WAN 最大。看到 Internet，先想到 WAN。

架構記法：Client-Server 是伺服器集中服務；P2P 是節點互相分享。

安全記法：HTTP 明文 80；HTTPS 加密 443。看到 TLS、憑證、加密，通常就是 HTTPS。

狀態記法：HTTP 無狀態，不代表不能登入；登入狀態要靠 Cookie、Session、Token 等機制補足。

保存位置記法：Cookie 在 client，Session 多在 server，Token 常見於 API。

拓樸記法：Bus 怕主幹，Ring 怕整環，Star 怕中心，Mesh 貴但可靠。
