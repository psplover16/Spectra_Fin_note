## 主題是什麼

這一章整理的是資料庫系統常見的補充考點。它們不一定是資料庫設計的主軸，但在國家考試中很常被拿來考「用途、優點、缺點、適用情境與安全風險」。

本章重點可以先用一句話掌握：

> 索引（Index）用來加速查詢；檢視表（View）用來簡化查詢與控管權限；預存程序（Stored Procedure）把程式邏輯放在資料庫端；觸發器（Trigger）會在資料異動時自動執行；SQL Injection 是把惡意 SQL 塞進輸入欄位的攻擊。

## 索引（Index）

索引（Index）是資料庫為了加快查詢速度所建立的輔助資料結構。可以把它想成書本後面的索引表：如果要找某個關鍵字，不必從第一頁翻到最後一頁，而是先查索引，再快速定位到相關頁面。

索引的核心想法是「用額外空間與維護成本，換取查詢速度」。當資料表很大，而且常常用某個欄位查詢、排序或連接時，在該欄位建立索引通常能提升效率。

例如有一個學生資料表：

```sql
Student(student_id, name, department)
```

如果系統常用 `student_id` 查詢學生資料，就可以在 `student_id` 上建立索引。如此一來，資料庫不必掃描整張表，而能更快找到符合條件的資料。

不過，索引不是越多越好。因為新增、修改、刪除資料時，資料庫除了要更新資料表，也要同步維護索引。因此索引會增加寫入成本、維護成本與儲存空間。

國考常見考法是問：「索引是否一定能提升所有操作效能？」答案是否定的。索引主要提升查詢效率，但可能降低寫入效率。

## 檢視表（View）

檢視表（View）是根據查詢結果所形成的虛擬表。它本身通常不直接儲存完整資料，而是把一段 SQL 查詢包裝成像資料表一樣可以使用的物件。

檢視表的核心想法是「把複雜查詢包起來，讓使用者看到需要看的資料」。它常用於簡化查詢、隱藏資料表細節，以及控制資料存取權限。

例如員工資料表中有薪資欄位：

```sql
Employee(emp_id, name, department, salary)
```

一般使用者可能只需要看到員工編號、姓名與部門，不應看到薪資。此時可以建立一個不包含 `salary` 的檢視表：

```sql
CREATE VIEW EmployeePublic AS
SELECT emp_id, name, department
FROM Employee;
```

使用者查詢 `EmployeePublic` 時，就像查資料表一樣，但看不到敏感欄位。這就是檢視表在權限控管上的典型用途。

國考常考「檢視表是不是實體表？」基本觀念是：檢視表是虛擬表，主要來自查詢結果。它可以簡化複雜查詢，也可以限制使用者接觸到的資料範圍。

## 預存程序（Stored Procedure）

預存程序（Stored Procedure）是預先定義並儲存在資料庫端的一組 SQL 指令或程序邏輯。應用程式可以呼叫它，讓資料庫執行固定流程。

預存程序的核心想法是「把常用的資料庫操作流程集中放在資料庫中管理」。這樣可以減少重複撰寫 SQL，也能讓複雜操作有一致的執行方式。

例如系統需要新增訂單，同時更新庫存。如果每個應用程式都自己寫一套 SQL，容易發生邏輯不一致。若改成預存程序，就能把新增訂單與扣庫存的流程包成一個固定程序，由資料庫統一執行。

國考常見考法是問預存程序的優點與缺點。優點是可重複使用、集中管理、減少應用程式端重複邏輯；缺點是可能增加資料庫端負擔，也可能使系統較依賴特定資料庫產品。

## 觸發器（Trigger）

觸發器（Trigger）是當資料表發生特定事件時，自動執行的資料庫程序。常見事件包括新增（INSERT）、修改（UPDATE）與刪除（DELETE）。

觸發器的核心想法是「資料一變動，資料庫自動做某些事」。它常用於稽核紀錄、資料一致性維護、連動更新或限制不合理的資料異動。

例如有一個帳戶資料表，當帳戶餘額被修改時，系統希望自動留下異動紀錄。此時可以設計觸發器，在 `Account` 資料表發生 `UPDATE` 時，自動把修改前後的資訊寫入 `AccountLog`。

觸發器很方便，但也要小心。因為它是自動執行，若設計不當，可能造成除錯困難、效能負擔，甚至觸發連鎖反應。

國考常考「觸發器與預存程序差在哪裡？」預存程序通常由使用者或應用程式主動呼叫；觸發器則是在資料事件發生時由資料庫自動觸發。

## SQL Injection 與防範

SQL Injection 是一種資料庫攻擊手法，中文常稱為 SQL 隱碼攻擊或 SQL 注入攻擊。它是指攻擊者把惡意 SQL 指令放進輸入欄位，使系統把輸入內容誤當成 SQL 的一部分執行。

SQL Injection 的核心問題是「程式把使用者輸入直接拼接成 SQL 指令」。只要使用者輸入沒有被安全處理，攻擊者就可能改變原本 SQL 的語意。

例如登入功能原本可能產生如下查詢：

```sql
SELECT *
FROM Users
WHERE account = '輸入帳號'
AND password = '輸入密碼';
```

如果程式直接把使用者輸入接進 SQL，攻擊者可能輸入特殊字串，使條件被扭曲，進而繞過登入或讀取不該讀的資料。

防範 SQL Injection 的重點包括：

1. 使用預備敘述（Prepared Statement）：先固定 SQL 結構，再把使用者輸入當成資料帶入。
2. 使用參數化查詢（Parameterized Query）：用參數傳入值，避免輸入內容被當成 SQL 指令。
3. 採用最小權限原則（Principle of Least Privilege）：資料庫帳號只給必要權限，降低攻擊成功後的損害。
4. 進行輸入驗證（Input Validation）：檢查輸入格式、長度與合理性。

國考常見考法是問「哪一種方式最能防 SQL Injection？」通常首選是預備敘述與參數化查詢。只做輸入驗證有幫助，但不應當成唯一防線。

## 易混淆比較整理

| 項目 | 定義 | 主要用途 | 常見優點 | 常見缺點 |
|---|---|---|---|---|
| 索引（Index） | 加速查詢的輔助資料結構 | 提升搜尋、排序、連接效率 | 查詢較快 | 增加寫入與維護成本 |
| 檢視表（View） | 由查詢結果形成的虛擬表 | 簡化查詢、控管權限 | 隱藏複雜度與敏感欄位 | 過度使用可能影響理解與效能 |
| 預存程序（Stored Procedure） | 儲存在資料庫端的程序 | 封裝固定資料庫操作流程 | 可重複使用、集中管理 | 可能增加資料庫負擔與產品相依性 |
| 觸發器（Trigger） | 資料異動時自動執行的程序 | 稽核、連動、維護一致性 | 自動化資料處理 | 除錯較困難，可能影響效能 |
| SQL Injection | 惡意 SQL 被插入輸入欄位 | 攻擊資料庫 | 攻擊者可能繞過限制 | 需用參數化查詢等方式防範 |

## 國考常見考法

1. 問索引的優缺點：要答出「加快查詢」與「增加寫入、維護、儲存成本」。
2. 問檢視表的用途：要答出「虛擬表、簡化查詢、權限控管」。
3. 問預存程序的意義：要答出「資料庫端預先定義程序，可由應用程式呼叫」。
4. 問觸發器的特色：要答出「資料變更時自動觸發」。
5. 問 SQL Injection 防範：要優先答「預備敘述、參數化查詢」，再補充最小權限與輸入驗證。

## 國考必背整理

- 索引（Index）：提高查詢速度，但會增加寫入與維護成本。
- 檢視表（View）：是虛擬表，可簡化查詢並控管權限。
- 預存程序（Stored Procedure）：是在資料庫端預先定義的程序。
- 觸發器（Trigger）：在資料新增、修改或刪除時自動執行。
- SQL Injection：把惡意 SQL 插入輸入欄位，可能竄改查詢語意。
- 防範 SQL Injection：預備敘述、參數化查詢、最小權限、輸入驗證。

## 容易考的判斷題

1. 索引一定會提升所有資料庫操作的效率。  
   錯。索引通常提升查詢效率，但會增加新增、修改、刪除時的維護成本。

2. 檢視表可以用來限制使用者看到的欄位。  
   對。檢視表能隱藏敏感欄位，達到權限控管效果。

3. 預存程序一定由資料表異動自動觸發。  
   錯。預存程序通常是被主動呼叫；自動觸發的是觸發器。

4. 觸發器常用於稽核紀錄與資料一致性維護。  
   對。它能在資料變更時自動執行指定動作。

5. 只要有輸入驗證，就完全不需要參數化查詢。  
   錯。防範 SQL Injection 應優先使用預備敘述與參數化查詢，輸入驗證是輔助措施。
