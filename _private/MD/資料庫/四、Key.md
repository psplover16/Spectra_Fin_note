## Key 是什麼

鍵（Key）是資料庫用來「識別資料列」或「建立資料表之間關聯」的重要概念。關聯式資料庫（Relational Database）中的資料通常放在資料表（Table）裡，而資料表中的每一列稱為 tuple，也常稱為資料列或紀錄。

最核心的想法很簡單：如果一張資料表裡有很多筆資料，我們需要某些欄位幫助我們準確找到「唯一一筆」資料。例如學生資料表中，姓名可能重複，但學號通常不會重複，所以學號很適合拿來識別學生。

在國家考試中，Key 很常考定義、分類與差異。尤其要分清楚超鍵（Super Key）、候選鍵（Candidate Key）、主鍵（Primary Key, PK）、替代鍵（Alternate Key）、外鍵（Foreign Key, FK）與複合鍵（Composite Key）。

## 超鍵、候選鍵與主鍵

### 超鍵（Super Key）

超鍵（Super Key）是指「可以唯一識別 tuple 的屬性集合」。這裡的屬性集合可以是一個欄位，也可以是多個欄位。

例如有一張學生資料表：

| 學號 | 身分證字號 | 姓名 | 系所 |
|---|---|---|---|
| S001 | A123456789 | 王小明 | 資管系 |
| S002 | B223456789 | 陳小華 | 資工系 |

如果「學號」不重複，那麼 `{學號}` 可以唯一識別一位學生，所以 `{學號}` 是超鍵。若「身分證字號」也不重複，`{身分證字號}` 也是超鍵。

但超鍵不一定要最精簡。`{學號, 姓名}` 也可以唯一識別學生，因為只看學號就已經夠了，多加姓名仍然可以唯一識別，所以它也是超鍵。這就是超鍵常考的地方：超鍵只要求能唯一識別，不要求最少欄位。

### 候選鍵（Candidate Key）

候選鍵（Candidate Key）是「最小的超鍵」。所謂最小，不是指欄位名稱最短，而是指不能再刪掉任何欄位；只要刪掉其中一個欄位，就不能保證唯一識別 tuple。

延續上面的例子，`{學號}` 是超鍵，而且不能再刪欄位，所以它是候選鍵。`{身分證字號}` 也是候選鍵。

但是 `{學號, 姓名}` 雖然是超鍵，卻不是候選鍵，因為「姓名」是多餘的。刪掉姓名後，`{學號}` 仍然能唯一識別學生，因此 `{學號, 姓名}` 不是最小超鍵。

國考常會用「最小 super key」來考候選鍵，看到這句話要立刻想到候選鍵（Candidate Key）。

### 主鍵（Primary Key, PK）

主鍵（Primary Key, PK）是「被選出來當作主要識別依據的候選鍵」。一張資料表可能有多個候選鍵，但通常只會選其中一個作為主鍵。

例如學生資料表中，`{學號}` 和 `{身分證字號}` 都可能是候選鍵。實務上學校通常選擇 `{學號}` 當主鍵，因為它比較符合學校管理與查詢需求。

主鍵的核心特色是用來唯一識別資料列，因此主鍵值不應重複，也不應為空值。考試若問「資料表中用來唯一識別每筆紀錄的主要鍵」，通常答案就是主鍵（Primary Key, PK）。

## 替代鍵、外鍵與複合鍵

### 替代鍵（Alternate Key）

替代鍵（Alternate Key）是「候選鍵中，沒有被選為主鍵的鍵」。

例如學生資料表中，`{學號}` 和 `{身分證字號}` 都是候選鍵。如果最後選 `{學號}` 當主鍵，那麼 `{身分證字號}` 就是替代鍵。

替代鍵的重點是：它本來也有資格當主鍵，只是沒有被選上。國考常把替代鍵和一般欄位混在一起考，判斷時要先看它是不是候選鍵；如果不是候選鍵，就不會是替代鍵。

### 外鍵（Foreign Key, FK）

外鍵（Foreign Key, FK）是「一個資料表中，用來參照另一個資料表主鍵的欄位」。外鍵的用途不是在本表中唯一識別資料列，而是建立資料表之間的關聯。

例如有兩張表：

學生資料表：

| 學號 | 姓名 |
|---|---|
| S001 | 王小明 |
| S002 | 陳小華 |

選課資料表：

| 選課編號 | 學號 | 課程代碼 |
|---|---|---|
| E001 | S001 | C101 |
| E002 | S002 | C102 |

在學生資料表中，「學號」是主鍵（Primary Key, PK）。在選課資料表中，「學號」用來參照學生資料表的學號，所以它是外鍵（Foreign Key, FK）。

外鍵常用來維護參考完整性（Referential Integrity）。白話來說，選課資料表中的學號應該要能在學生資料表中找到對應學生，不能憑空出現不存在的學生。

### 複合鍵（Composite Key）

複合鍵（Composite Key）是「由多個欄位組成的鍵」。它可以是主鍵，也可以是候選鍵，重點在於它不是單一欄位，而是多個欄位一起判斷。

例如選課資料表中，如果規定同一位學生不能重複選同一門課，可以用 `{學號, 課程代碼}` 共同識別一筆選課紀錄。

| 學號 | 課程代碼 | 成績 |
|---|---|---|
| S001 | C101 | 90 |
| S001 | C102 | 85 |
| S002 | C101 | 88 |

單看「學號」不能唯一，因為同一位學生可以選多門課。單看「課程代碼」也不能唯一，因為同一門課可以有很多學生修課。但 `{學號, 課程代碼}` 合在一起就能唯一識別一筆選課資料，所以它可以成為複合鍵。

## 國考常見考法

1. 考定義：問「可唯一識別 tuple 的屬性集合」是什麼，答案是超鍵（Super Key）。
2. 考最小性：問「最小 super key」是什麼，答案是候選鍵（Candidate Key）。
3. 考選擇關係：問「被選為主要識別依據的候選鍵」是什麼，答案是主鍵（Primary Key, PK）。
4. 考未被選上：問「未被選為主鍵的候選鍵」是什麼，答案是替代鍵（Alternate Key）。
5. 考表格關聯：問「參照其他 table primary key 的欄位」是什麼，答案是外鍵（Foreign Key, FK）。
6. 考多欄位組合：問「由多個欄位組成的 key」是什麼，答案是複合鍵（Composite Key）。

## 易混淆比較表

| 名詞 | 定義 | 是否要求唯一識別 | 是否要求最小 | 國考關鍵字 |
|---|---|---:|---:|---|
| 超鍵（Super Key） | 可唯一識別 tuple 的屬性集合 | 是 | 否 | 唯一識別、屬性集合 |
| 候選鍵（Candidate Key） | 最小的超鍵 | 是 | 是 | minimal super key |
| 主鍵（Primary Key, PK） | 被選為主要識別依據的候選鍵 | 是 | 是 | primary、主要識別 |
| 替代鍵（Alternate Key） | 沒有被選為主鍵的候選鍵 | 是 | 是 | 未被選為 PK |
| 外鍵（Foreign Key, FK） | 參照其他資料表主鍵的欄位 | 不一定 | 不一定 | reference、參照 |
| 複合鍵（Composite Key） | 由多個欄位組成的鍵 | 視情況 | 視情況 | 多欄位組合 |

## 國考必背整理

1. 超鍵（Super Key）：可唯一識別 tuple 的屬性集合。
2. 候選鍵（Candidate Key）：最小的超鍵。
3. 主鍵（Primary Key, PK）：被選為主要識別依據的候選鍵。
4. 替代鍵（Alternate Key）：沒有被選為主鍵的候選鍵。
5. 外鍵（Foreign Key, FK）：參照其他資料表主鍵的欄位。
6. 複合鍵（Composite Key）：由多個欄位組成的鍵。

## 容易考的判斷題

1. 「所有候選鍵都是超鍵。」正確。候選鍵本來就是最小的超鍵。
2. 「所有超鍵都是候選鍵。」錯誤。超鍵可能包含多餘欄位，不一定最小。
3. 「一張資料表只能有一個候選鍵。」錯誤。一張資料表可以有多個候選鍵。
4. 「一張資料表通常只能選一個主鍵。」正確。多個候選鍵中會選一個作為主鍵。
5. 「替代鍵是沒有被選為主鍵的候選鍵。」正確。
6. 「外鍵一定是本表的主鍵。」錯誤。外鍵的重點是參照其他資料表的主鍵，不一定是本表主鍵。
7. 「複合鍵一定由多個欄位組成。」正確。這就是複合鍵的定義。
8. 「複合鍵不能當主鍵。」錯誤。複合鍵也可以被選為主鍵。

## 考前速記小抄

看到「唯一識別」先想到超鍵（Super Key）；看到「最小唯一識別」就想到候選鍵（Candidate Key）；看到「被選出來當主要識別」就是主鍵（Primary Key, PK）；看到「沒被選上的候選鍵」就是替代鍵（Alternate Key）；看到「參照別張表的主鍵」就是外鍵（Foreign Key, FK）；看到「多個欄位一起組成」就是複合鍵（Composite Key）。

最容易混淆的是超鍵（Super Key）和候選鍵（Candidate Key）。請記住：超鍵可以有多餘欄位，候選鍵不能有多餘欄位。只要掌握「唯一」與「最小」兩個關鍵字，Key 的題目通常就能快速判斷。
