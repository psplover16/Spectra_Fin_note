## 資料庫是什麼

資料庫（Database）是有組織地存放資料的集合。它不是單純把資料隨便放在檔案裡，而是用一套規則來安排資料，讓使用者可以有效率地新增、查詢、修改與刪除資料。

資料庫管理系統（Database Management System, DBMS）是用來管理資料庫的軟體。也就是說，資料庫（Database）是資料本身與其結構，資料庫管理系統（DBMS）則是幫我們操作與保護資料的工具。常見的資料庫管理系統（DBMS）包括 MySQL、PostgreSQL、Oracle Database、Microsoft SQL Server 等。

用白話來說，資料庫像是整理好的大型資料櫃，資料庫管理系統（DBMS）像是管理資料櫃的管理員。使用者通常不會直接翻動底層資料，而是透過資料庫管理系統（DBMS）查詢或更新資料。

### 具體範例

假設一所補習班要管理學生資料。若只用許多 Excel 檔或文字檔，可能會出現同一位學生在不同檔案中資料不一致的問題，例如電話在 A 檔已更新，但 B 檔還是舊資料。若改用資料庫，就可以把學生、課程、繳費紀錄、出席紀錄等資料集中管理，並透過資料庫管理系統（DBMS）控制誰可以查看、修改或刪除資料。

### 國考考法

國考常問資料庫與傳統檔案處理的差異。看到題目提到「資料共享」、「降低資料重複」、「維持一致性」、「權限控管」、「備份與復原」、「交易管理」時，通常是在考資料庫系統的優點。

## 資料庫系統的核心組成

資料庫系統（Database System）通常包含資料庫（Database）、資料庫管理系統（DBMS）、使用者、應用程式與資料庫管理員（Database Administrator, DBA）。

1. 資料庫（Database）：有組織的資料集合，是被管理的資料本體。
2. 資料庫管理系統（Database Management System, DBMS）：管理資料庫的軟體，負責查詢、更新、安全、備份、復原與交易控制。
3. 使用者（User）：實際使用資料的人，例如櫃台人員、主管、一般民眾或系統管理者。
4. 應用程式（Application Program）：介於使用者與資料庫管理系統（DBMS）之間的程式，例如報名系統、銀行系統、戶政系統。
5. 資料庫管理員（Database Administrator, DBA）：負責管理資料庫系統的人員，工作包含權限設定、效能調校、備份策略與故障復原。

核心想法是：資料庫系統不是只有資料，也不是只有軟體，而是「資料、軟體、人員、規則與應用」一起運作的整體。

## 使用資料庫的優點

### 1. 資料共享（Data Sharing）

資料共享（Data Sharing）是指多個使用者或多個應用程式可以共同使用同一份資料。這是資料庫很重要的特色，因為資料不再分散在各自獨立的檔案中。

例如學校的註冊組、教務處與導師都可能需要學生資料。若大家使用同一個資料庫，就可以避免各自維護一份不同版本的學生名冊。

國考常把資料共享（Data Sharing）放在資料庫優點中考選擇題。只要題目問「資料庫相較於傳統檔案處理的優點」，資料共享通常是正確選項。

### 2. 降低資料重複（Reduce Data Redundancy）

資料重複（Data Redundancy）是指相同資料被存放在多個地方。降低資料重複是資料庫的重要目標之一。

例如同一位員工的姓名、電話與地址，如果在薪資檔、考勤檔、人事檔各存一份，就容易造成資料重複。資料庫可以透過設計，把員工基本資料集中在員工資料表中，其他資料只需要透過員工編號連結即可。

國考常會問：「資料庫是否完全消除資料重複？」要注意，資料庫的目標通常是降低或控制資料重複，不一定是完全消除。某些設計為了效能，也可能保留必要的重複資料。

### 3. 維持一致性（Data Consistency）

資料一致性（Data Consistency）是指同一筆事實在資料庫中應該保持相同，不應在不同地方出現互相矛盾的內容。

例如某學生的手機號碼已更新，系統中所有查詢到的學生電話都應該是新號碼。若不同部門看到不同電話，就代表一致性出了問題。

國考常把資料重複（Data Redundancy）與資料一致性（Data Consistency）一起考。重複資料越多，越容易造成不一致；資料庫透過集中管理與資料設計，可以降低這種風險。

### 4. 權限控管（Authorization Control）

權限控管（Authorization Control）是指資料庫管理系統（DBMS）可以限制不同使用者能做的操作，例如只能查詢、可以新增、可以修改，或可以刪除。

例如醫院資料庫中，掛號人員可能只能查看基本資料，醫師可以查看病歷，會計人員只能處理收費資料。這樣可以降低資料外洩與誤改的風險。

國考常用「安全性（Security）」或「存取控制（Access Control）」來描述這個概念。看到使用者權限、登入身分、資料保護時，要聯想到權限控管。

### 5. 備份與復原（Backup and Recovery）

備份（Backup）是指事先保存資料副本；復原（Recovery）是指系統發生故障後，把資料恢復到可用且正確的狀態。

例如資料庫硬碟損壞，若有定期備份與交易紀錄，就能盡量把資料恢復到故障前的狀態。這對銀行、戶政、稅務等系統尤其重要。

國考常問資料庫管理系統（DBMS）的功能，備份與復原通常是重要答案。

### 6. 交易管理（Transaction Management）

交易（Transaction）是指一組必須完整執行的資料庫操作。交易管理（Transaction Management）則是資料庫管理系統（DBMS）確保這組操作要嘛全部成功，要嘛全部不生效。

最常見的例子是轉帳。甲帳戶扣款與乙帳戶加款必須一起完成。若甲帳戶已扣款，但乙帳戶沒有加款，資料就會出錯。因此資料庫需要交易管理來保護資料正確性。

國考看到銀行轉帳、訂票、庫存扣減等情境，常常是在考交易管理。

## 使用資料庫的缺點

資料庫雖然強大，但不是沒有代價。國考常會用「下列何者不是資料庫的優點」或「資料庫系統可能的缺點」來考。

### 1. 系統複雜（System Complexity）

系統複雜（System Complexity）是指資料庫系統需要設計資料結構、權限、備份、效能與交易機制，因此比單純檔案處理更難建置與維護。

例如一個小型個人通訊錄也許用試算表就夠了，若硬要建置完整資料庫系統，反而會增加不必要的複雜度。

### 2. 成本高（High Cost）

成本高（High Cost）是指資料庫系統可能需要購買軟體、伺服器、儲存設備，並投入人力維護。

大型組織使用企業級資料庫時，除了授權費用，還需要備援設備、監控系統與專業人員，因此成本可能相當高。

### 3. 需要資料庫管理員（Need DBA）

資料庫管理員（Database Administrator, DBA）是負責資料庫管理、維護、安全與效能的人員。資料庫系統越重要，越需要專業的資料庫管理員。

國考可能會問資料庫管理員（DBA）的職責。備份復原、權限管理、效能調校、資料庫設計協助，都屬於常見職責。

### 4. 集中化風險（Centralized Risk）

集中化風險（Centralized Risk）是指資料集中管理雖然方便，但如果核心資料庫故障、遭攻擊或設定錯誤，影響範圍也會很大。

例如政府機關的核心資料庫若停機，相關線上服務可能都會受到影響。因此實務上常搭配備份、備援、權限控管與災難復原機制來降低風險。

## 資料庫的主要種類

資料庫可以依照資料模型（Data Model）分類。資料模型（Data Model）是指資料如何被組織、表示與連結的方式。不同資料庫種類的差異，主要就在於資料結構與資料關係的表達方式不同。

### 1. 階層式資料庫（Hierarchical Database）

階層式資料庫（Hierarchical Database）是用樹狀結構（Tree Structure）表示資料的資料庫。樹狀結構（Tree Structure）是指資料像家族族譜一樣，有明確的上層與下層關係。

它的核心想法是「一個父節點可以有多個子節點，但一個子節點通常只對應一個父節點」。因此它很適合表示上下層關係明確的資料。

具體例子是公司組織圖。公司底下有部門，部門底下有員工；或是磁碟目錄結構，一個資料夾底下可以有多個子資料夾。

國考常考階層式資料庫的關鍵字是「樹狀」、「父子關係明確」、「一對多」。若題目提到多對多關係，通常就不是階層式資料庫的強項。

### 2. 網路式資料庫（Network Database）

網路式資料庫（Network Database）是用圖狀結構（Graph Structure）表示資料的資料庫。圖狀結構（Graph Structure）是指資料之間可以有較複雜的連結，不一定只有單一父子階層。

它的核心想法是支援多對多（Many-to-Many）關係。多對多（Many-to-Many）關係是指一筆資料可以連到多筆資料，而對方也可以連回多筆資料。

具體例子是學生與課程。一位學生可以修多門課，一門課也可以有多位學生。這種關係若用階層式資料庫表示會比較彆扭，但網路式資料庫可以比較自然地表達。

國考常把網路式資料庫與階層式資料庫拿來比較。記憶重點是：階層式像樹，網路式像圖；階層式偏一對多，網路式能處理多對多。

### 3. 關聯式資料庫（Relational Database）

關聯式資料庫（Relational Database）是以資料表（Table）表示資料的資料庫，也是國考與實務中最常見的資料庫類型。

資料表（Table）是由列（Row）與欄（Column）組成的結構。列（Row）通常代表一筆資料紀錄，欄（Column）代表資料的屬性。例如學生資料表中，一列是一位學生，欄位可能包含學號、姓名、生日、電話。

關聯式資料庫的核心想法是把資料整理成多個表格，表格之間透過鍵（Key）建立關係。鍵（Key）是用來識別資料或連結資料的欄位，例如學號可以識別學生。

具體例子是學生資料表、課程資料表與選課資料表。學生資料表存學生基本資料，課程資料表存課程名稱與教師，選課資料表記錄哪位學生選了哪門課。

國考非常愛考關聯式資料庫，尤其是資料表、主鍵（Primary Key）、外鍵（Foreign Key）、正規化（Normalization）與 SQL。即使本章只講基礎，也要先記住：關聯式資料庫等於表格，是最常見類型。

### 4. 物件導向式資料庫（Object-Oriented Database）

物件導向式資料庫（Object-Oriented Database）是以物件（Object）儲存資料的資料庫。物件（Object）是物件導向程式設計中的基本單位，通常包含資料與操作資料的方法。

它的核心想法是讓資料庫能更自然地儲存複雜物件，例如圖片、影音、工程圖、地理資訊或程式中的物件結構。

具體例子是設計軟體儲存一個「零件物件」，這個物件可能同時包含尺寸、材質、圖片、繪圖資料與相關操作。若硬要拆成許多表格，有時會比較複雜。

國考常問物件導向式資料庫的特色。看到「物件」、「類別」、「封裝」、「複雜資料型態」時，要聯想到物件導向式資料庫。

### 5. NoSQL 資料庫（Not Only SQL Database）

NoSQL 資料庫（Not Only SQL Database）是指不以傳統關聯式資料表為唯一核心的資料庫類型。NoSQL 不是完全不能用 SQL，而是表示它通常不受傳統關聯式模型限制，適合大量、分散式、彈性結構或特定型態的資料。

常見 NoSQL 資料庫包含鍵值資料庫（Key-Value Database）、文件資料庫（Document Database）、欄族資料庫（Column-Family Database）與圖形資料庫（Graph Database）。

1. 鍵值資料庫（Key-Value Database）：用鍵（Key）對應值（Value），像字典一樣。適合快取、登入狀態、簡單查找。
2. 文件資料庫（Document Database）：用文件（Document）儲存資料，常見格式像 JSON。適合資料欄位常變動的應用。
3. 欄族資料庫（Column-Family Database）：以欄族方式儲存大量資料，常用於大數據場景。
4. 圖形資料庫（Graph Database）：用節點（Node）與邊（Edge）表示資料關係，適合社群網路、推薦系統、關係分析。

國考常考 NoSQL 的分類與適用情境。看到 key-value、document、column-family、graph database，要知道它們都是 NoSQL 的常見類型。

## 國考常見考法

### 考法一：問資料庫的優點

題目可能問：「下列何者為資料庫系統的優點？」常見正確方向包括資料共享、降低資料重複、維持一致性、權限控管、備份復原、交易管理。

看到「成本低」、「系統簡單」、「不需要管理人員」這類選項要小心，這些通常不是資料庫系統的優點。

### 考法二：問資料庫的缺點

題目可能問：「下列何者為資料庫系統可能造成的問題？」常見答案包括系統複雜、建置成本高、需要資料庫管理員（DBA）、集中化風險。

### 考法三：比較資料庫種類

題目會用關鍵字讓你判斷是哪一種資料庫：

1. 樹狀結構、父子關係：階層式資料庫（Hierarchical Database）。
2. 圖狀結構、多對多：網路式資料庫（Network Database）。
3. 資料表、列與欄、最常見：關聯式資料庫（Relational Database）。
4. 物件、類別、封裝：物件導向式資料庫（Object-Oriented Database）。
5. key-value、document、column-family、graph：NoSQL 資料庫（Not Only SQL Database）。

### 考法四：情境題

國考可能不直接問名詞，而是給一段情境。例如：「某系統要求轉帳時扣款與入帳必須同時成功，否則全部取消。」這是在考交易管理（Transaction Management）。

又例如：「某機關希望不同職務只能存取不同資料欄位。」這是在考權限控管（Authorization Control）或安全性（Security）。

## 易混淆比較表

| 概念 | 定義 | 關鍵字 | 國考提醒 |
|---|---|---|---|
| 資料庫（Database） | 有組織的資料集合 | 資料本體、資料集合 | 不等於管理軟體 |
| 資料庫管理系統（DBMS） | 管理資料庫的軟體 | 查詢、更新、安全、備份 | 是操作與管理資料庫的工具 |
| 資料共享（Data Sharing） | 多人或多系統共用資料 | 共用、整合 | 資料庫優點 |
| 資料重複（Data Redundancy） | 相同資料存放多份 | 重複、冗餘 | 資料庫可降低但未必完全消除 |
| 資料一致性（Data Consistency） | 同一事實不互相矛盾 | 正確、一致 | 常與資料重複一起考 |
| 備份（Backup） | 保存資料副本 | 預先保存 | 故障前準備 |
| 復原（Recovery） | 故障後恢復資料 | 還原、恢復 | 故障後處理 |
| 交易管理（Transaction Management） | 確保一組操作完整成功或失敗 | 轉帳、全部成功、全部取消 | 銀行情境很常考 |

## 國考必背整理

1. 資料庫（Database）是有組織的資料集合。
2. 資料庫管理系統（DBMS）是管理資料庫的軟體。
3. 資料庫的優點包括資料共享、降低資料重複、維持一致性、權限控管、備份復原與交易管理。
4. 資料庫的缺點包括系統複雜、成本高、需要資料庫管理員（DBA）與集中化風險。
5. 階層式資料庫（Hierarchical Database）使用樹狀結構，父子關係明確。
6. 網路式資料庫（Network Database）使用圖狀結構，支援多對多關係。
7. 關聯式資料庫（Relational Database）使用資料表，是最常見的資料庫類型。
8. 物件導向式資料庫（Object-Oriented Database）以物件儲存資料，適合複雜資料型態。
9. NoSQL 資料庫（Not Only SQL Database）常見類型有鍵值、文件、欄族與圖形資料庫。
10. 交易管理（Transaction Management）常用銀行轉帳作為考題情境。

## 容易考的判斷題

1. 資料庫可以提高資料共享程度。  
   答：對。資料共享（Data Sharing）是資料庫的重要優點。

2. 資料庫一定能完全消除所有資料重複。  
   答：錯。資料庫通常是降低或控制資料重複，不一定完全消除。

3. 關聯式資料庫以資料表表示資料。  
   答：對。關聯式資料庫（Relational Database）的核心就是資料表（Table）。

4. 階層式資料庫最適合表示多對多關係。  
   答：錯。多對多關係通常較適合用網路式資料庫（Network Database）或其他模型表示。

5. 資料庫系統一定比傳統檔案系統成本低。  
   答：錯。資料庫系統可能因軟硬體與管理需求而成本較高。

6. 資料庫管理員（DBA）通常負責備份、復原、權限與效能管理。  
   答：對。這些都是資料庫管理員（Database Administrator, DBA）的典型工作。

7. NoSQL 資料庫只包含一種資料模型。  
   答：錯。NoSQL 資料庫包含鍵值、文件、欄族、圖形等多種類型。

8. 交易管理可以避免轉帳只完成一半的問題。  
   答：對。交易管理（Transaction Management）要求相關操作完整成功或完整取消。

## 考前速記小抄

資料庫基礎可以用「共享、少重複、一致、安全、備復、交易」記資料庫優點。

1. 共享：資料共享（Data Sharing）。
2. 少重複：降低資料重複（Reduce Data Redundancy）。
3. 一致：資料一致性（Data Consistency）。
4. 安全：權限控管（Authorization Control）。
5. 備復：備份與復原（Backup and Recovery）。
6. 交易：交易管理（Transaction Management）。

資料庫缺點可以記「複雜、貴、要 DBA、怕集中」。

資料庫種類可以記：

1. 樹：階層式資料庫（Hierarchical Database）。
2. 圖：網路式資料庫（Network Database）。
3. 表：關聯式資料庫（Relational Database）。
4. 物件：物件導向式資料庫（Object-Oriented Database）。
5. 彈性多型：NoSQL 資料庫（Not Only SQL Database）。

考前最後一眼要記住：國考最常見的資料庫類型是關聯式資料庫（Relational Database），它用資料表（Table）表示資料；看到轉帳情境要想到交易管理（Transaction Management）；看到不同人有不同存取範圍要想到權限控管（Authorization Control）。
