# 基本計概 02：機器指令與指令週期

> 指令與 CPU 運作。

## 3. 機器指令與指令週期

> 機器指令是「工作單」，指令週期是「處理工作單的步驟」。

### 考前小抄
1. **機器指令**：CPU 直接看得懂的二進位命令。
2. **Opcode**：做什麼。
3. **Operand**：對誰做，或表示資料／位置資訊。
4. **位址欄位**：指令中用來指出資料位置的欄位。
5. **Effective Address**：真正要存取資料的位址。
6. **PC**：下一個指令位址。
7. **IR**：目前取出的指令。
8. **Fetch**：取指令。
9. **Operand Fetch**：取資料。
10. **Execute**：真的做動作。

### 機器指令範例
`ADD R1, R2`
| 部分 | 意義 |
|---|---|
| ADD | Opcode，表示加法 |
| R1、R2 | Operand，要被操作的暫存器 |

`LOAD R1, 1000`
| 部分 | 意義 |
|---|---|
| LOAD | Opcode，表示載入 |
| R1 | Operand，目的暫存器 |
| 1000 | 位址欄位／位址資訊，資料位置可能和 1000 有關 |

### 指令週期流程
機器指令透過指令週期執行所希望的動作：
1. **Fetch 取指令**：先把工作單拿來。
2. **Decode 解碼**：看懂工作單要做什麼。
3. **Operand Fetch / Address Calculation 取運算元或算位址**：準備要用的資料，或算出資料真正在哪。
4. **Execute 執行**：真的做加法、比較、跳躍、I/O 等動作。
5. **Write Back / Store 寫回**：把結果放回暫存器或記憶體。

| 階段 | 英文 | 核心問題 | 常考關鍵字 |
|---|---|---|---|
| 1. 取指令 | Fetch | 取得接下來要執行的那條機器指令所在位置 | PC、Memory、IR |
| 2. 解碼 | Decode | 這條指令要做什麼？ | Opcode、Control Unit、Addressing Mode |
| 3. 取運算元／算位址 | Operand Fetch / Address Calculation | 資料在哪裡？要拿什麼資料？ | Operand、Effective Address |
| 4. 執行 | Execute | 實際做什麼動作？ | ALU、Branch、I/O |
| 5. 寫回 | Write Back / Store | 結果放去哪裡？ | Register、Memory、Interrupt |

關鍵字：
- **I/O**：Input／Output，輸入與輸出（讀檔、寫檔、鍵盤、螢幕）。
- **ALU**：算術邏輯單元，負責計算與邏輯判斷（加減乘除、AND、OR、比較）。
- **Branch**：分支，改變程式接下來執行哪一條指令（if 判斷、跳到另一位址）。

### 易混淆比較
**Fetch vs Operand Fetch**
| 比較點 | Fetch | Operand Fetch |
|---|---|---|
| 取什麼 | 指令本身 | 指令要用的資料 |
| 依據 | PC 指出的指令位址 | Operand、位址欄位、定址模式 |
| 常見錯誤 | 以為 Fetch 是取資料 | 以為 Operand Fetch 是取下一條指令 |

**PC vs IR**
| 項目 | PC | IR |
|---|---|---|
| 中文 | 程式計數器 | 指令暫存器 |
| 存放內容 | 下一個要取出的指令位址 | 目前已取出的指令 |
| 白話 | 下一步去哪拿指令 | 剛拿到的指令先放這 |

**Decode vs Execute**
| 比較點 | Decode | Execute |
|---|---|---|
| 重點 | 看懂指令 | 做出動作 |
| 內容 | 判斷 Opcode、格式、定址模式 | 運算、比較、跳躍、I/O |

### 國考怎麼判斷
1. 「CPU 可直接執行、二進位形式」→ 機器指令。
2. 「指出要執行的操作」→ Opcode。
3. 「被操作的資料、暫存器或位置」→ Operand。
4. 「真正要存取的記憶體位置」→ Effective Address。
5. 「下一個指令位址」→ PC。
6. 「目前取出的指令」→ IR。
7. 「取指令」→ Fetch。
8. 「實際運算或跳躍」→ Execute。
