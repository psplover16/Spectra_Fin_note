## 程式基礎是什麼

程式（Program）是一組讓電腦依照順序執行的指令。對完全新手來說，可以先把程式想成「寫給電腦看的操作流程」：先準備資料，再依條件判斷要做什麼，必要時重複執行某些動作，最後得到結果。

國家考試常考的不是寫很長的程式，而是確認你是否理解幾個基礎觀念：程式如何被轉成電腦能執行的形式、變數與函式在做什麼、陣列與迴圈如何搭配、參數傳遞會不會改到原本的資料，以及 `static` 在不同語言中的意義。

## 程式語言轉換工具

電腦真正能直接執行的是機器碼（Machine Code）。機器碼（Machine Code）是由電腦硬體可直接理解的二進位指令組成。可是人類通常不會直接寫機器碼，而是寫組合語言或高階語言，因此需要轉換工具。

### 組譯器（Assembler）

組譯器（Assembler）是把組合語言（Assembly Language）轉成機器碼（Machine Code）的工具。組合語言（Assembly Language）是一種接近硬體指令的低階語言，通常和特定處理器架構有密切關係。

核心想法是：組合語言已經很接近機器指令，只是用較容易辨識的助記符號表示，例如用 `ADD` 表示加法指令。因此組譯器主要負責把這些助記符號轉成電腦能執行的二進位碼。

國考常見考法會問：「Assembler 是翻譯哪一種語言？」答案是組合語言，不是高階語言。

### 編譯器（Compiler）

編譯器（Compiler）是把高階語言（High-Level Language）整體或大段轉成目標碼（Object Code）或可執行程式的工具。高階語言（High-Level Language）是比較接近人類思考方式的程式語言，例如 C、C++、Java 等。

核心想法是：編譯器通常會先檢查整份程式或一大段程式，通過語法分析、最佳化，再產生目標碼。編譯完成後，程式執行時通常不需要逐行重新翻譯，因此執行效率常被視為較高。

具體範例：C 語言程式通常會經過編譯，產生目標檔或可執行檔，再由作業系統執行。

國考常問：「Compiler 的特色是什麼？」要抓住兩點：先翻譯再執行、通常以整體或大段程式為單位。

### 直譯器（Interpreter）

直譯器（Interpreter）是逐行或逐步解讀程式並執行的工具。直譯（Interpretation）指的是程式在執行過程中才被翻譯與執行。

核心想法是：直譯器比較像一邊看指令、一邊做動作。因為不一定先產生完整的可執行檔，所以除錯與互動性常較方便，但執行效率常可能比已編譯完成的程式低。

具體範例：許多腳本語言（Scripting Language）的執行方式常被拿來說明直譯概念，例如一行一行讀取指令並執行。

國考常問：「Interpreter 和 Compiler 差在哪裡？」重點是直譯器偏向逐行或逐步解讀執行，編譯器偏向先整體或大段翻譯。

## 程式的基本組成

### 變數（Variable）

變數（Variable）是用名稱代表一塊可以儲存資料的空間。你可以把變數想成貼上標籤的盒子：盒子裡可以放數字、文字或其他資料，而標籤就是變數名稱。

學變數時要注意兩個核心概念：型別（Type）與作用域（Scope）。型別（Type）是資料的種類，例如整數、浮點數、字元或布林值。作用域（Scope）是變數名稱可以被使用的範圍。

具體範例：`int score = 80;` 中，`score` 是變數，`int` 是整數型別，`80` 是存進去的值。

國考常考變數的生命週期、作用域，以及型別是否相容。例如在區塊內宣告的區域變數（Local Variable），通常離開區塊後就不能再用。

### 函式（Function）

函式（Function）是把一段可重複使用的程式邏輯封裝起來的單位。封裝（Encapsulation）在這裡可以先理解成「把一組動作包成一個名稱，需要時呼叫它」。

核心想法是：函式可以減少重複程式碼，也能讓程式結構更清楚。函式通常包含名稱、參數、回傳值與函式本體。

具體範例：計算兩數相加的函式，可以接收兩個數字作為參數，回傳相加結果。之後只要呼叫函式，就不用重寫加法流程。

國考常考函式呼叫、回傳值，以及參數傳遞方式是否會影響原始資料。

### 陣列（Array）

陣列（Array）是用同一個名稱儲存多個同型別資料的連續集合。連續集合的意思是，資料通常依序排列，並可用索引值（Index）存取。

核心想法是：如果要存很多個同類資料，例如 50 位考生分數，使用 50 個變數很麻煩；用陣列可以用一個名稱搭配索引值管理。

具體範例：`score[0]` 表示陣列中第 1 個元素，`score[1]` 表示第 2 個元素。很多程式語言的陣列索引從 0 開始，這點很容易考。

國考常考陣列索引、陣列長度、是否越界，以及陣列搭配迴圈逐一處理資料。

### 迴圈（Loop）

迴圈（Loop）是讓程式重複執行某段指令的控制結構。控制結構（Control Structure）是用來控制程式執行流程的語法。

常見迴圈有三種：

1. `for` 迴圈：常用在已知重複次數的情況。
2. `while` 迴圈：先判斷條件，條件成立才執行。
3. `do-while` 迴圈：先執行一次，再判斷條件。

核心想法是：迴圈必須有停止條件，否則可能形成無窮迴圈（Infinite Loop）。無窮迴圈（Infinite Loop）是指程式因條件永遠成立而不斷重複執行。

國考常考 `while` 與 `do-while` 的差異：`do-while` 至少會執行一次。

### 條件判斷（Conditional Statement）

條件判斷（Conditional Statement）是根據條件成立與否，決定程式要走哪一條路。常見語法包含 `if-else` 與 `switch`。

`if-else` 適合處理條件範圍或複雜判斷，例如分數是否及格。`switch` 適合處理固定選項，例如選單代號、月份或狀態碼。

國考常考條件式的真假判斷、分支是否會被執行，以及 `switch` 是否需要注意 `break` 造成的流程影響。

### 例外處理（Exception Handling）

例外處理（Exception Handling）是處理程式執行期間異常狀況的機制。例外（Exception）是程式執行時發生的不正常事件，例如除以零、檔案不存在、陣列索引超出範圍。

常見關鍵字包括：

1. `try`：放可能發生例外的程式碼。
2. `catch`：捕捉並處理例外。
3. `finally`：無論是否發生例外，通常都會執行的區塊。
4. `throw`：主動丟出例外。

核心想法是：例外處理不是讓錯誤消失，而是讓程式在遇到異常時能有規劃地處理，避免直接中斷或產生不可預期結果。

國考常考 `try-catch-finally` 的執行順序，以及 `finally` 常用來釋放資源。

## 參數傳遞方式

參數（Parameter）是函式定義中用來接收資料的名稱；引數（Argument）是呼叫函式時實際傳入的資料。國考常把參數傳遞方式拿來比較，重點在於「函式內修改資料，會不會影響外面的原值」。

### 傳值呼叫（Call by Value）

傳值呼叫（Call by Value）是把資料的值複製一份傳給函式。函式內拿到的是副本，因此在函式內修改參數，通常不會改到外面的原變數。

具體範例：外面有 `x = 10`，呼叫函式時把 `x` 的值傳入。函式內把參數改成 `20`，外面的 `x` 仍然是 `10`。

國考看到「函式內修改不影響原值」，通常要想到傳值呼叫。

### 傳位址呼叫（Call by Address）

傳位址呼叫（Call by Address）是把資料所在的記憶體位址傳給函式。位址（Address）是資料在記憶體中的位置。這種方式常見於 C 語言的指標（Pointer）。

指標（Pointer）是用來儲存記憶體位址的變數。函式若透過位址找到原本資料，就可能直接修改外面的原值。

具體範例：把 `x` 的位址傳給函式，函式透過指標找到 `x`，再把內容改成 `20`，外面的 `x` 就可能變成 `20`。

國考看到「傳入 address」「使用 pointer」「可能改到原值」，要想到傳位址呼叫。

### 傳參考呼叫（Call by Reference）

傳參考呼叫（Call by Reference）是把變數的參考傳給函式。參考（Reference）可以理解成原變數的另一個名字，因此函式內修改參考，可能影響原物件或原變數。

核心想法是：傳參考不像傳值那樣只拿到副本，而是讓函式能接觸到原本資料。不同語言對參考的細節可能不同，但考試通常抓大方向：可影響原資料。

國考常把傳位址呼叫與傳參考呼叫放在一起考。兩者都可能改到原值，但傳位址強調記憶體位址與指標，傳參考強調別名或參照關係。

### 傳名呼叫（Call by Name）

傳名呼叫（Call by Name）是把引數表達式延後到實際使用時才求值的概念。延遲求值（Delayed Evaluation）是指資料或表達式不是一開始就立刻計算，而是在需要時才計算。

這個概念在一般初學程式中較少直接使用，但國考可能考名詞辨識。遇到 Call by Name 時，重點記「延遲求值」與「使用時才代入或計算」。

## static 的意義

`static` 是程式語言中的關鍵字，但在不同語言與不同位置意義可能不同。國考常考的是 C/C++ 與 Java 的差異。

### C/C++ 區域 static 變數

C/C++ 的區域 static 變數（Local Static Variable）是在區塊內宣告，但生命週期（Lifetime）會延長到程式結束的變數。生命週期（Lifetime）是變數存在於記憶體中的期間。

核心想法是：它的作用域仍在原本區塊內，只有那個區塊能用它；但是它不會因為函式結束就消失，下次再呼叫函式時仍保留上次的值。

國考常考一句話：區域 `static` 變數「生命週期延長，但作用域不變」。

### C/C++ 檔案層級 static

C/C++ 的檔案層級 static（File-Scope Static）常用來限制連結性（Linkage）。連結性（Linkage）是指某個名稱能不能被其他檔案連結或存取。

核心想法是：在檔案層級使用 `static`，可以讓名稱限制在目前檔案內，避免其他檔案直接使用或衝突。

國考看到「限制 linkage」或「只在本檔案可見」，要想到 C/C++ 檔案層級 `static`。

### Java static

Java 的 `static` 表示成員屬於類別（Class），不屬於特定物件（Object）。類別（Class）是建立物件的藍圖；物件（Object）是依照類別建立出來的實體。

核心想法是：一般成員屬於各個物件，每個物件可以有自己的資料；`static` 成員屬於類別本身，通常由所有物件共用，或不需要建立物件就能透過類別使用。

國考常考 Java `static` 的一句話：屬於 class，不屬於特定 object。

## 國考常見考法

1. 問翻譯工具的差異：組譯器（Assembler）翻譯組合語言，編譯器（Compiler）翻譯高階語言並先產生目標碼，直譯器（Interpreter）逐行或逐步解讀執行。
2. 問變數的型別與作用域：型別決定資料種類，作用域決定名稱可使用範圍。
3. 問迴圈執行次數：特別注意 `while` 可能一次都不執行，`do-while` 至少執行一次。
4. 問函式參數是否會改到原值：傳值通常不會，傳位址與傳參考可能會。
5. 問 `static`：C/C++ 區域 `static` 延長生命週期，Java `static` 屬於類別。

## 國考必背整理

1. 變數（Variable）是儲存資料的命名空間，必須注意型別（Type）與作用域（Scope）。
2. 函式（Function）是封裝可重用邏輯的程式單位。
3. 陣列（Array）是同型別資料的連續集合，常用索引值（Index）存取。
4. 迴圈（Loop）用來重複執行程式碼，常見有 `for`、`while`、`do-while`。
5. 條件判斷（Conditional Statement）用來決定程式分支，常見有 `if-else`、`switch`。
6. 例外處理（Exception Handling）使用 `try`、`catch`、`finally`、`throw` 處理執行期間異常。
7. 傳值呼叫（Call by Value）不影響原值；傳位址呼叫（Call by Address）與傳參考呼叫（Call by Reference）可能影響原值。
8. C/C++ 區域 `static` 變數生命週期延長到程式結束，但作用域仍在區塊內。
9. Java `static` 屬於類別（Class），不屬於特定物件（Object）。

## 容易考的判斷題

1. 組譯器（Assembler）是將高階語言轉成目標碼。  
   錯。組譯器是將組合語言轉成機器碼。

2. 編譯器（Compiler）通常會先將程式整體或大段翻譯後再執行。  
   對。這是編譯器和直譯器的重要差異。

3. 直譯器（Interpreter）一定會先產生完整可執行檔才執行。  
   錯。直譯器強調逐行或逐步解讀執行。

4. 傳值呼叫（Call by Value）在函式內修改參數通常不會影響原變數。  
   對。因為函式拿到的是值的副本。

5. 傳位址呼叫（Call by Address）常見於 C 語言指標（Pointer）相關操作。  
   對。傳位址會把記憶體位址交給函式。

6. C/C++ 區域 static 變數離開函式後會立刻被銷毀。  
   錯。它的生命週期會延長到程式結束。

7. C/C++ 區域 static 變數的作用域會自動變成整個程式都可使用。  
   錯。它的作用域仍受宣告位置限制。

8. Java static 成員屬於類別（Class），不是某一個特定物件（Object）。  
   對。這是 Java `static` 的核心觀念。
