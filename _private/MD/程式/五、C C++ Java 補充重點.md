## C、C++、Java 是什麼

C 語言（C Programming Language）是一種偏低階、效率高、接近硬體的程式語言。這裡的低階不是指不好，而是指它能直接處理記憶體位址、指標與資料配置，因此常用在作業系統、嵌入式系統與需要高效能的程式。

C++（C Plus Plus）是在 C 語言基礎上加入物件導向程式設計（Object-Oriented Programming, OOP）能力的語言。它仍然保留 C 的高效率與記憶體控制能力，但多了類別、物件、建構子、解構子、標準樣板函式庫等功能。

Java（Java Programming Language）是一種強調跨平台、物件導向與自動記憶體管理的語言。Java 程式通常會先編譯成位元碼（Bytecode），再由 Java 虛擬機（Java Virtual Machine, JVM）執行，因此常被說成具有「一次撰寫，到處執行」的特色。

國考常把這三種語言放在一起比較，重點通常不是要你寫很長的程式，而是要能判斷：誰需要手動管理記憶體、誰有自動垃圾回收、誰靠虛擬機跨平台、誰的物件導向支援較完整。

## C 語言補充重點

### 指標

指標（Pointer）是用來儲存記憶體位址的變數。一般變數存的是資料值，例如整數 10；指標存的則是「某個資料放在哪裡」。

核心想法是：C 語言允許程式直接操作記憶體，所以指標非常重要。透過指標，可以傳遞大型資料、修改函式外部的變數、操作陣列，也可以配合動態記憶體配置使用。

例如，若 `int a = 10;`，則 `&a` 表示變數 `a` 的位址；若 `int *p = &a;`，表示指標 `p` 存放 `a` 的位址；而 `*p` 則代表透過指標取出該位址中的值。

國考常考指標時，會問 `&` 與 `*` 的差異。取址運算子（Address-of Operator）`&` 用來取得變數位址；間接運算子（Indirection Operator）`*` 用來透過指標取得或修改位址中的內容。

### 結構

結構（Structure, struct）是 C 語言中把多個不同型態資料組合在一起的資料型態。它很適合描述一個有多個屬性的資料，例如學生有姓名、座號、成績。

核心想法是：陣列（Array）通常存放相同型態的多筆資料，而結構可以把不同型態的欄位包在一起。若要表示一筆學生資料，不能只靠一個整數或一個字串，就可以用 `struct`。

例如，一個學生結構可以包含 `name`、`id`、`score` 三個欄位。程式便能用同一個變數表示完整學生資料，而不是把姓名、座號、成績分散在不同變數中。

國考常考結構與陣列的差異：陣列強調「多個同型態元素」，結構強調「多個不同型態欄位組成一筆資料」。

### 動態記憶體配置

動態記憶體配置（Dynamic Memory Allocation）是指程式執行期間才向系統要求記憶體。C 語言常用 `malloc` 取得記憶體，再用 `free` 釋放記憶體。

核心想法是：如果資料大小在編譯時還不知道，就可能需要動態配置。例如使用者輸入要建立 100 筆或 1000 筆資料，程式可以在執行時才決定要配置多少空間。

`malloc` 會配置一塊記憶體並回傳指向該記憶體的指標。使用完後，必須用 `free` 釋放，否則可能造成記憶體洩漏（Memory Leak）。記憶體洩漏是指已經不再使用的記憶體沒有被釋放，導致可用記憶體逐漸減少。

國考常考的是：C 語言需要程式設計師手動釋放動態配置的記憶體；Java 則主要由垃圾回收機制自動處理。

### 陣列與字串結尾

陣列（Array）是一串相同型態資料的連續集合。C 語言的字串（String）本質上是字元陣列（Character Array），並以空字元（Null Character）`'\0'` 作為結尾。

核心想法是：C 語言的字串不像某些高階語言有內建字串物件，它需要靠 `'\0'` 判斷字串到哪裡結束。

例如字串 `"cat"` 在記憶體中實際包含四個字元：`'c'`、`'a'`、`'t'`、`'\0'`。所以宣告字元陣列時，要記得多留一格給結尾的空字元。

國考常考陷阱是：字串長度與陣列所需空間不同。`"ABC"` 的可見字元長度是 3，但在 C 字串中至少需要 4 格空間，因為還要存放 `'\0'`。

## C++ 補充重點

### 類別與物件

類別（Class）是描述物件資料與行為的藍圖；物件（Object）是依照類別建立出來的實體。C++ 使用類別支援物件導向程式設計（Object-Oriented Programming, OOP）。

核心想法是：類別把資料成員（Data Member）與成員函式（Member Function）包在一起，讓程式更接近現實世界的描述方式。

例如 `Car` 類別可以有顏色、速度等資料，也可以有加速、煞車等行為。當程式建立一台實際的車，就是建立 `Car` 類別的物件。

國考常考類別與結構的概念差異：C 的 `struct` 主要用來組合資料；C++ 的 `class` 除了資料，也強調封裝行為與存取控制。

### 建構子與解構子

建構子（Constructor）是在物件建立時自動執行的特殊函式，常用來初始化物件。解構子（Destructor）是在物件生命週期結束時自動執行的特殊函式，常用來釋放資源。

核心想法是：物件不只是資料集合，它有生命週期。建立時需要準備好狀態，結束時也要把使用過的資源收好。

例如一個檔案處理物件在建構時開啟檔案，在解構時關閉檔案。這樣可以減少忘記釋放資源的風險。

國考常考：建構子名稱通常與類別名稱相同，沒有回傳型態；解構子名稱是在類別名稱前加上 `~`，例如 `~Car()`。

### RAII

資源取得即初始化（Resource Acquisition Is Initialization, RAII）是 C++ 常見的資源管理觀念。它的意思是：把資源的取得與物件建立綁在一起，把資源的釋放與物件銷毀綁在一起。

核心想法是：只要物件生命週期管理正確，資源就能跟著自動被管理。資源不只包含記憶體，也可能包含檔案、鎖、網路連線等。

例如智慧指標（Smart Pointer）可以在物件不再使用時自動釋放記憶體，減少手動 `delete` 的錯誤。

國考若看到 RAII，通常要想到 C++、解構子、資源管理、自動釋放，以及降低記憶體洩漏風險。

### 參考

參考（Reference）是某個變數的別名。它不像指標那樣直接存放位址給程式操作，使用方式更像原本變數本身。

核心想法是：參考常用來讓函式能修改傳入的變數，或避免複製大型物件造成效能浪費。

例如函式參數若使用參考傳遞（Pass by Reference），函式內對參數的修改會影響原本的變數。若使用常數參考（Const Reference），則可以避免複製資料，又不允許函式修改它。

國考常考指標與參考的差異：指標可以改指向別的位址，也可能是空指標；參考通常在宣告時就必須綁定某個物件，之後不能改成另一個物件的別名。

### STL

標準樣板函式庫（Standard Template Library, STL）是 C++ 提供的常用資料結構與演算法函式庫。它包含容器（Container）、迭代器（Iterator）與演算法（Algorithm）等部分。

核心想法是：STL 讓程式設計師不必每次都自己重新實作常見資料結構，例如動態陣列、堆疊、佇列、集合、映射等。

例如 `vector` 是可變長度陣列，`stack` 是堆疊，`queue` 是佇列，`map` 可用鍵值對應資料。

國考常考 STL 的定位：它是 C++ 的標準函式庫，提供泛型程式設計（Generic Programming）工具，不是 Java 的集合框架。

## Java 補充重點

### JVM 與位元碼

Java 虛擬機（Java Virtual Machine, JVM）是執行 Java 位元碼的環境。位元碼（Bytecode）是 Java 原始程式經編譯後產生的中介碼，不是特定 CPU 直接執行的機器碼。

核心想法是：Java 程式先編譯成位元碼，再交給不同平台上的 JVM 執行。只要該平台有對應的 JVM，就能執行同一份 Java 位元碼。

例如 Windows、macOS、Linux 都可以安裝自己的 JVM，而同一個 `.class` 檔可以在不同平台上執行。

國考常考 Java 跨平台原因：不是因為原始碼完全不需編譯，而是因為 Java 編譯成位元碼，再由 JVM 負責在各平台執行。

### 垃圾回收

垃圾回收（Garbage Collection, GC）是 Java 自動回收不再使用記憶體的機制。程式設計師通常不需要像 C 一樣手動呼叫 `free`。

核心想法是：當某個物件已經沒有任何參考指向它，JVM 就可能在適當時機回收它所佔用的記憶體。

例如程式建立一個物件後，如果所有指向它的變數都消失或改指向別處，該物件就可能成為垃圾回收的對象。

國考常考陷阱是：垃圾回收不是由程式設計師精準控制執行時間，也不代表 Java 絕對不會發生記憶體問題。若程式一直保留不必要的參考，仍可能造成記憶體使用過高。

### 類別與介面

類別（Class）是 Java 建立物件的藍圖，包含屬性與方法。介面（Interface）是一種規範，定義類別應該提供哪些方法。

核心想法是：類別描述「是什麼」與「怎麼做」，介面則偏向描述「應該能做什麼」。一個類別可以實作多個介面，藉此達成較彈性的設計。

例如 `Bird` 類別可能描述鳥的資料與行為；`Flyable` 介面則表示某個物件具有飛行能力。不是所有鳥都會飛，所以把飛行能力設計成介面會更彈性。

國考常考 Java 繼承限制：Java 類別通常只能繼承一個父類別，但可以實作多個介面。

### 例外

例外（Exception）是程式執行時發生異常狀況的處理機制。Java 使用 `try`、`catch`、`finally` 等語法來處理例外。

核心想法是：例外處理讓正常流程與錯誤處理分開，使程式比較清楚，也比較容易維護。

例如讀取檔案時，檔案可能不存在；連線資料庫時，網路可能中斷。這些情況都可以用例外處理機制處理。

國考常考 `finally` 的用途：它通常用於放置不論是否發生例外都希望執行的程式碼，例如關閉資源。

### 集合框架

集合框架（Collection Framework）是 Java 提供的一組資料結構與操作介面，常見包含 `List`、`Set`、`Map` 等。

核心想法是：集合框架讓程式能用一致的方式管理多筆物件資料，不必每次都自行建立資料結構。

例如 `List` 重視順序且可重複，`Set` 不允許重複元素，`Map` 使用鍵值對（Key-Value Pair）儲存資料。

國考常考 `List`、`Set`、`Map` 差異：`List` 像有順序的清單，`Set` 像不重複的集合，`Map` 則是用鍵找到對應的值。

## 三者比較與易混淆整理

| 比較項目 | C | C++ | Java |
|---|---|---|---|
| 主要特色 | 接近硬體、效率高 | 兼具效率與物件導向 | 跨平台、物件導向、自動記憶體管理 |
| 物件導向 | 不以物件導向為主 | 支援物件導向 | 以物件導向為核心 |
| 記憶體管理 | 常需手動 `malloc/free` | 可手動管理，也可用 RAII | 主要由 GC 自動回收 |
| 執行方式 | 通常編譯成機器碼 | 通常編譯成機器碼 | 編譯成 Bytecode，由 JVM 執行 |
| 常見資料組織 | 陣列、struct | class、STL 容器 | class、interface、collection framework |
| 跨平台重點 | 需依平台編譯 | 需依平台編譯 | JVM 執行 Bytecode |

容易混淆的第一組是 `malloc/free` 與垃圾回收（Garbage Collection, GC）。`malloc/free` 是 C 語言常見的手動配置與釋放記憶體方式；GC 則是 Java JVM 自動回收不再使用物件的機制。

容易混淆的第二組是 C++ 的 STL 與 Java 的集合框架（Collection Framework）。兩者都提供常用資料結構，但 STL 屬於 C++，集合框架屬於 Java。

容易混淆的第三組是指標（Pointer）與參考（Reference）。指標直接保存位址，操作彈性大但也較容易出錯；參考是別名，語法較直覺，常用於參數傳遞。

## 國考常見考法

1. 考語言特色比較：題目可能問哪一個語言透過 JVM 執行，答案通常是 Java。
2. 考記憶體管理：題目可能問哪一個語言常用 `malloc/free`，答案是 C。
3. 考字串結尾：題目可能問 C 字串以何者結尾，答案是空字元 `'\0'`。
4. 考 C++ 物件生命週期：題目可能問建構子與解構子的執行時機。
5. 考 RAII：題目可能問 C++ 如何利用物件生命週期管理資源。
6. 考 Java 跨平台：題目可能問 Java 為何可跨平台，重點是 Bytecode 與 JVM。
7. 考介面：題目可能問 Java 類別是否可以實作多個介面。
8. 考集合差異：題目可能問 `List`、`Set`、`Map` 的用途差異。

## 國考必背整理

- 指標（Pointer）：儲存記憶體位址的變數，是 C 語言重要特色。
- 結構（Structure, struct）：把多個不同型態欄位組成一筆資料。
- 動態記憶體配置（Dynamic Memory Allocation）：執行期間配置記憶體，C 常用 `malloc/free`。
- 空字元（Null Character）`'\0'`：C 字串結尾標記。
- 類別（Class）：建立物件的藍圖，C++ 與 Java 都大量使用。
- 建構子（Constructor）：物件建立時自動執行，用於初始化。
- 解構子（Destructor）：C++ 物件銷毀時自動執行，用於釋放資源。
- RAII（Resource Acquisition Is Initialization）：C++ 以物件生命週期管理資源的觀念。
- 參考（Reference）：變數別名，常用於 C++ 參數傳遞。
- STL（Standard Template Library）：C++ 的標準樣板函式庫。
- JVM（Java Virtual Machine）：執行 Java Bytecode 的虛擬機。
- 位元碼（Bytecode）：Java 編譯後給 JVM 執行的中介碼。
- 垃圾回收（Garbage Collection, GC）：Java 自動回收不再使用記憶體的機制。
- 介面（Interface）：Java 中規定類別應提供哪些方法的設計工具。
- 例外（Exception）：處理程式執行異常狀況的機制。
- 集合框架（Collection Framework）：Java 管理多筆物件資料的標準架構。

## 容易考的判斷題

1. C 語言的指標可以儲存變數的記憶體位址。  
   答案：對。

2. C 語言字串不需要結尾符號。  
   答案：錯。C 字串需要以空字元 `'\0'` 結尾。

3. `malloc` 配置的記憶體在 C 語言中通常需要用 `free` 釋放。  
   答案：對。

4. C++ 的建構子通常用於初始化物件。  
   答案：對。

5. C++ 的 RAII 與資源管理無關。  
   答案：錯。RAII 正是把資源管理與物件生命週期結合。

6. Java 原始碼會直接由 CPU 執行，所以能跨平台。  
   答案：錯。Java 通常先編譯成 Bytecode，再由 JVM 執行。

7. Java 的垃圾回收可以保證程式完全不會有記憶體問題。  
   答案：錯。若程式保留不必要的參考，仍可能造成記憶體使用過高。

8. Java 類別可以實作多個介面。  
   答案：對。

9. C++ 的 STL 與 Java 的 Collection Framework 是同一個函式庫。  
   答案：錯。兩者概念相似，但分屬不同語言。

10. Java 的 `Map` 是以鍵值對方式儲存資料。  
    答案：對。

## 考前速記小抄

| 關鍵字 | 看到要想到 |
|---|---|
| Pointer | C、位址、`&`、`*` |
| struct | C、不同型態欄位組成一筆資料 |
| malloc/free | C、手動配置與釋放記憶體 |
| `'\0'` | C 字串結尾 |
| class | C++ / Java、物件藍圖 |
| constructor | 物件建立、初始化 |
| destructor | C++、物件銷毀、釋放資源 |
| RAII | C++、生命週期、資源管理 |
| reference | C++、別名、參數傳遞 |
| STL | C++、容器、迭代器、演算法 |
| JVM | Java、執行 Bytecode |
| Bytecode | Java 中介碼、跨平台關鍵 |
| GC | Java、自動記憶體回收 |
| interface | Java、規範方法、可多重實作 |
| exception | Java、異常處理、try-catch-finally |
| collection framework | Java、List、Set、Map |

最後記法可以簡化成：C 重指標與手動記憶體，C++ 重物件生命週期與 STL，Java 重 JVM、Bytecode、GC、介面與集合框架。
