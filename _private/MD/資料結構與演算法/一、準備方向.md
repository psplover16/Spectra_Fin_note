## 這科到底在考什麼

資料結構（Data Structure）是「資料在電腦中如何安排、儲存與管理」的方法。演算法（Algorithm）是「解決問題的明確步驟」。這一科不是只考你會不會寫程式，而是考你能不能看懂資料怎麼被組織、步驟怎麼執行，以及這些步驟花多少時間。

國家考試常見的題目，通常會把「名詞理解」、「流程推演」和「效率分析」混在一起。例如題目可能給你一串數字，叫你用某種排序法（Sorting Algorithm）排一次；也可能給你一棵樹（Tree），問節點（Node）、高度（Height）、深度（Depth）或走訪順序（Traversal）。所以準備這科時，不能只背定義，也不能只練程式，要把觀念、圖形和流程一起讀。

這科的準備方向可以抓成一句話：名詞要背熟，流程要跑熟，複雜度要比熟。

## 重要名詞先懂再背

專有名詞是這科的基本分數來源。專有名詞（Technical Term）是某個領域中具有固定意義的詞，考試常用它來檢查你是否真的懂觀念。資料結構與演算法的名詞很多，尤其樹（Tree）相關名詞最容易密集出現。

樹（Tree）是一種階層式資料結構（Hierarchical Data Structure），資料像家族關係一樣由上往下展開。樹的最上方節點稱為根節點（Root），每個資料單位稱為節點（Node），節點之間的連線稱為邊（Edge）。沒有子節點的節點稱為葉節點（Leaf）。某節點往下連到的節點稱為子節點（Child），往上連到它的節點稱為父節點（Parent）。

這些名詞不能只看中文或只看英文，因為國考題目可能用中文敘述，也可能直接出英文。建議讀到重要名詞時，一律用「中文（English）」的方式記，例如資料結構（Data Structure）、演算法（Algorithm）、時間複雜度（Time Complexity）、二元樹（Binary Tree）、圖（Graph）、排序（Sorting）。

具體來說，如果題目問「下列何者為 Binary Tree 的性質」，你必須立刻知道二元樹（Binary Tree）是每個節點最多有兩個子節點的樹。若只是模糊記得「跟樹有關」，選擇題就很容易被相似名詞騙走。

國考考法常見為名詞配對、性質判斷、走訪結果、樹高計算，以及給圖形要求辨識資料結構種類。這類題目通常不難，但很吃熟悉度。

## 程式碼不要死背，要看懂流程

程式碼（Program Code）是用程式語言寫出的指令。虛擬碼（Pseudocode）是接近程式但不限定語言的演算法描述。準備這科時，最不建議死背完整程式碼，因為題目一改變變數名稱、迴圈方向或資料範圍，背好的程式就可能完全派不上用場。

真正要理解的是「這段程式在做什麼」。例如排序演算法（Sorting Algorithm）不是背一串迴圈，而是先知道它每一回合如何比較、交換、縮小範圍或建立結構。只要懂流程，就算考題給的是 C、Java、Python 或虛擬碼，你仍然能看出它是哪一種演算法。

以插入排序（Insertion Sort）為例，它的核心想法是把資料分成「已排序區」與「未排序區」，每次從未排序區拿一個元素，插入到已排序區的正確位置。你不需要一開始就背程式碼，而是先用數列 `5, 2, 4, 1` 手動跑：

1. 先看 `5`，已排序區是 `5`。
2. 拿 `2` 跟 `5` 比，插到前面，變成 `2, 5`。
3. 拿 `4`，插到 `2` 和 `5` 中間，變成 `2, 4, 5`。
4. 拿 `1`，一路往前插，變成 `1, 2, 4, 5`。

這樣理解後，再看虛擬碼就會清楚很多。國考若考填空、追蹤變數或判斷輸出結果，靠流程理解會比靠背誦穩定。

## 抽象觀念要畫圖

抽象觀念（Abstract Concept）是看不到實體、需要靠模型理解的觀念。資料結構與演算法有很多抽象內容，例如指標（Pointer）、遞迴（Recursion）、樹的旋轉（Tree Rotation）、圖的走訪（Graph Traversal）。這些內容只用文字讀，常常會覺得懂了，但遇到題目就卡住。

畫圖是最有效的方式。圖形化（Visualization）可以把資料的位置、連線和變化過程具體呈現出來。像樹的走訪，若只背前序走訪（Preorder Traversal）、中序走訪（Inorder Traversal）、後序走訪（Postorder Traversal）的順序，很容易混亂；但如果把樹畫出來，並在節點旁標上拜訪順序，就會清楚很多。

舉例來說，前序走訪（Preorder Traversal）是「根、左、右」，中序走訪（Inorder Traversal）是「左、根、右」，後序走訪（Postorder Traversal）是「左、右、根」。這裡的根（Root）不是整棵樹唯一的根，而是每一棵子樹的根。這也是國考很愛考的陷阱。

國考常把一棵樹畫出來，要求你寫出走訪序列；也可能反過來給你走訪序列，問能不能還原樹。這類題目一定要動手畫，不要只在腦中想。

## 時間複雜度一定要會比較

時間複雜度（Time Complexity）是用來描述演算法執行時間隨輸入資料量成長而如何變化的概念。它通常用大 O 記號（Big-O Notation）表示，例如 `O(1)`、`O(log n)`、`O(n)`、`O(n log n)`、`O(n^2)`。

這個單元幾乎是必考重點，因為它能快速比較演算法效率。輸入資料量 `n` 很小時，差異不一定明顯；但 `n` 很大時，效率差距會非常大。考試常問哪個演算法比較快、哪個成長率比較慢，或要求把複雜度由小排到大。

常見時間複雜度由快到慢大致如下：

| 複雜度 | 名稱 | 直覺理解 | 常見例子 |
|---|---|---|---|
| `O(1)` | 常數時間（Constant Time） | 不管資料多少，步驟差不多 | 陣列用索引取值 |
| `O(log n)` | 對數時間（Logarithmic Time） | 每次把問題縮小很多 | 二分搜尋 |
| `O(n)` | 線性時間（Linear Time） | 資料多一倍，步驟約多一倍 | 線性搜尋 |
| `O(n log n)` | 線性對數時間（Linearithmic Time） | 常見高效率排序等級 | 合併排序、堆積排序 |
| `O(n^2)` | 平方時間（Quadratic Time） | 兩層迴圈常見 | 氣泡排序、選擇排序 |
| `O(2^n)` | 指數時間（Exponential Time） | 成長非常快 | 部分暴力搜尋 |

具體範例：如果資料有 1,000 筆，`O(n)` 大約看 1,000 次，`O(n^2)` 可能到 1,000,000 次。這就是為什麼排序或搜尋不能只看「做得出來」，還要看「做得快不快」。

國考常見考法包括複雜度排序、判斷迴圈的時間複雜度、比較排序演算法效率，以及問最佳情況（Best Case）、平均情況（Average Case）、最壞情況（Worst Case）。

## 圖與排序的準備方法

圖（Graph）是由頂點（Vertex）和邊（Edge）組成的資料結構，用來表示物件之間的關係。排序（Sorting）是把資料依照特定規則重新排列，例如由小到大或由大到小。這兩個主題通常比基本陣列、串列或堆疊更難，因為它們很依賴流程推演。

讀圖（Graph）時，第一步要先看清楚它是有向圖（Directed Graph）還是無向圖（Undirected Graph）。有向圖的邊有方向，像 `A -> B`；無向圖的邊沒有方向，代表兩邊可互相連通。再來要看是否有權重（Weight），也就是邊上是否有成本、距離或時間。

圖的常見演算法包括廣度優先搜尋（Breadth-First Search, BFS）和深度優先搜尋（Depth-First Search, DFS）。廣度優先搜尋（BFS）是一層一層往外找，常搭配佇列（Queue）。深度優先搜尋（DFS）是一路往深處找，常搭配堆疊（Stack）或遞迴（Recursion）。準備時不要先背程式，要先照流程畫出拜訪順序。

排序（Sorting）初學時最重要的是把每一步每個元素的位置畫出來。以氣泡排序（Bubble Sort）為例，它會重複比較相鄰元素，若順序錯就交換。每一輪結束後，最大值通常會被推到最後面。只要你畫出每一輪變化，就能看出它為什麼常是 `O(n^2)`。

| 主題 | 建議讀法 | 常見考點 |
|---|---|---|
| 圖（Graph） | 先畫頂點與邊，再標拜訪順序 | BFS、DFS、最短路徑、生成樹 |
| 排序（Sorting） | 每一輪都寫出陣列變化 | 排序結果、比較次數、時間複雜度 |
| 虛擬碼（Pseudocode） | 先懂流程，再整理步驟 | 填空、判斷演算法類型 |
| 程式碼（Program Code） | 最後再練語法細節 | 追蹤變數、輸出結果 |

國考常把排序過程考成「第幾回合後陣列變成什麼」，也常把圖考成「從某頂點開始，BFS 或 DFS 的拜訪順序為何」。這兩類題目都很適合用手算訓練。

## 高等樹的準備重點

高等樹可以理解為比基本二元樹更進階的樹狀資料結構，常見例子包括堆積（Heap）、AVL 樹（AVL Tree）、B 樹（B-Tree）等。堆積（Heap）是一種通常用來快速取得最大值或最小值的樹狀結構。AVL 樹（AVL Tree）是一種會自動維持平衡的二元搜尋樹。B 樹（B-Tree）常用在資料庫和檔案系統中，適合大量資料搜尋。

準備高等樹時，重點不是一開始就背完整程式碼，而是要懂排序方式、插入方式、刪除後如何調整，以及能不能寫出核心虛擬碼。以堆積（Heap）為例，你要知道最大堆積（Max Heap）是父節點大於或等於子節點，最小堆積（Min Heap）是父節點小於或等於子節點。插入新元素後，可能需要往上調整；刪除根節點後，可能需要往下調整。

高等樹完整程式碼通常不是最優先的準備項目，但虛擬碼與操作流程仍然很重要。題目若給你一串插入順序，要求畫出最後的樹，這時只背定義不夠，必須會一步一步調整。

國考常見考法是給資料序列，要求建立堆積、判斷是否符合平衡條件、比較樹的高度，或看懂某段虛擬碼在做哪種樹操作。

## 國考常見考法

1. 名詞定義題：考資料結構（Data Structure）、演算法（Algorithm）、樹（Tree）、圖（Graph）、時間複雜度（Time Complexity）等基本概念。
2. 圖形推演題：給樹或圖，要求寫出走訪順序、搜尋順序或調整後結果。
3. 排序過程題：給一串資料，要求寫出某一輪排序後的狀態。
4. 複雜度比較題：比較 `O(log n)`、`O(n)`、`O(n log n)`、`O(n^2)` 等成長速度。
5. 虛擬碼判讀題：給一段虛擬碼，問它在做哪種演算法或輸出什麼。
6. 性質判斷題：判斷某資料結構是否符合定義，例如是否為二元搜尋樹（Binary Search Tree）。

遇到題目時，建議先判斷題型。若是名詞題，先回到定義；若是流程題，立刻畫圖或列表；若是複雜度題，先找迴圈層數、資料是否每次折半、是否有排序或遞迴。

## 易混淆整理

| 易混淆項目 | 差異重點 | 記憶方式 |
|---|---|---|
| 資料結構（Data Structure）與演算法（Algorithm） | 前者是資料安排方式，後者是解題步驟 | 一個是「放資料」，一個是「做事情」 |
| 陣列（Array）與鏈結串列（Linked List） | 陣列連續儲存，串列靠指標連接 | 陣列找位置快，串列插刪彈性高 |
| 堆疊（Stack）與佇列（Queue） | 堆疊後進先出，佇列先進先出 | Stack 像疊盤子，Queue 像排隊 |
| BFS 與 DFS | BFS 一層一層找，DFS 一路往深找 | BFS 常用 Queue，DFS 常用 Stack |
| 前序、中序、後序走訪 | 根節點出現位置不同 | 前序根在前，中序根在中，後序根在後 |
| 最佳、平均、最壞情況 | 分別看最順、一般、最不順的輸入 | 國考常考最壞情況 |

這些易混淆觀念要用題目練。只看表格會覺得簡單，但考題常會把它們藏在程式片段、圖形或選項敘述中。

## 國考必背整理

1. 資料結構（Data Structure）是資料的組織方式；演算法（Algorithm）是解題步驟。
2. 時間複雜度（Time Complexity）常見大小順序為 `O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(2^n)`。
3. 樹（Tree）的重要名詞包含根節點（Root）、節點（Node）、邊（Edge）、父節點（Parent）、子節點（Child）、葉節點（Leaf）、高度（Height）、深度（Depth）。
4. 二元樹（Binary Tree）是每個節點最多有兩個子節點的樹。
5. 二元搜尋樹（Binary Search Tree）通常符合左子樹較小、右子樹較大的規則。
6. 堆疊（Stack）是後進先出（Last In, First Out, LIFO）。
7. 佇列（Queue）是先進先出（First In, First Out, FIFO）。
8. 廣度優先搜尋（BFS）通常使用佇列（Queue）。
9. 深度優先搜尋（DFS）通常使用堆疊（Stack）或遞迴（Recursion）。
10. 排序（Sorting）要會推每一輪變化，也要會比較時間複雜度。

## 容易考的判斷題

1. 「資料結構只是在背程式碼。」錯。資料結構重點是資料如何組織與操作。
2. 「虛擬碼不限定特定程式語言。」對。虛擬碼重點是表達流程。
3. 「時間複雜度是用來描述演算法執行時間成長趨勢。」對。
4. 「所有排序演算法的時間複雜度都一樣。」錯。不同排序法的最佳、平均、最壞情況可能不同。
5. 「BFS 通常一層一層搜尋。」對。
6. 「DFS 一定只能用遞迴實作。」錯。DFS 也可以用堆疊實作。
7. 「二元樹每個節點最多只能有兩個子節點。」對。
8. 「樹的走訪只要背一次整棵樹的根即可。」錯。走訪規則要套用到每一棵子樹。
9. 「排序初學時，畫出每一步元素位置有助於理解。」對。
10. 「高等樹完全不用準備虛擬碼。」錯。完整程式碼未必最常考，但操作流程與虛擬碼仍要會。

## 考前速記小抄

- 名詞先背中文與英文：資料結構（Data Structure）、演算法（Algorithm）、時間複雜度（Time Complexity）、樹（Tree）、圖（Graph）、排序（Sorting）。
- 程式碼不要硬背，先問自己：這段流程在比較什麼、交換什麼、移動什麼、停止條件是什麼。
- 抽象觀念一定畫圖，尤其樹、圖、排序過程、遞迴呼叫。
- 複雜度比較要熟到不用想：`O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(2^n)`。
- 圖（Graph）先分有向或無向，再看有沒有權重，最後才跑 BFS 或 DFS。
- 排序（Sorting）每一輪都要寫出陣列狀態，特別注意交換次數與最後結果。
- 高等樹先懂調整規則，再練虛擬碼；不用一開始追求背完整程式。
- 遇到國考題時，先分題型：名詞題看定義，流程題畫圖，複雜度題看成長率。
