## 時間複雜度是什麼

時間複雜度（Time Complexity）是用來描述「演算法執行時間會如何隨著輸入資料變大而成長」的概念。它不是在問程式實際跑了幾秒，而是在問：當資料量從 10 筆變成 100 筆、1000 筆、10000 筆時，演算法需要做的工作量會增加多少。

輸入規模（Input Size）是指問題輸入資料的大小，通常用 `n` 表示。例如陣列有 `n` 個元素、字串長度是 `n`、圖形有 `n` 個節點，都可以把 `n` 視為輸入規模。

時間複雜度的核心想法是：國考通常不在意某台電腦跑得快不快，也不在意某一行程式實際花多少微秒，而是在意演算法本身的成長趨勢。資料量越大，成長慢的演算法越有優勢。

## 大 O 記號是什麼

大 O 記號（Big O Notation）是描述時間複雜度最常見的表示法，用來表示演算法在輸入規模變大時，執行時間的「上界成長趨勢」。白話說，就是用一個簡化後的式子，說明演算法最多大概會成長到什麼程度。

例如：

- `O(1)`：資料變多，時間大致不變。
- `O(n)`：資料變成兩倍，工作量大約也變成兩倍。
- `O(n^2)`：資料變成兩倍，工作量大約變成四倍。

大 O 記號重視的是長期成長趨勢，所以會忽略常數與低次項。

例如某演算法實際工作量是：

```text
3n^2 + 10n + 50
```

當 `n` 很大時，影響最大的是 `n^2`，所以它的時間複雜度寫成：

```text
O(n^2)
```

這也是國考很常考的觀念：大 O 看成長趨勢，不看常數與低次項。

## n、log 與括號內的式子代表什麼

`n` 是輸入規模（Input Size），代表資料量大小。它不是固定數字，而是用來表示「資料有多大」的變數。

例如：

1. 對長度為 `n` 的陣列做搜尋，`n` 就是陣列元素個數。
2. 對長度為 `n` 的字串逐字檢查，`n` 就是字串長度。
3. 對 `n` 筆學生成績排序，`n` 就是學生筆數。

對數（Logarithm，簡寫為 log）可以先理解成「要除以幾次才會變小到停止」。在資料結構與演算法中，常見的 `log n` 通常可以直覺理解為「每一步都把問題規模縮小一大半」。

例如二分搜尋（Binary Search）每次都把搜尋範圍砍半：

```text
16 -> 8 -> 4 -> 2 -> 1
```

從 16 個元素縮到 1 個元素，只需要大約 4 次，因為 16 可以連續除以 2 四次。這就是 `log n` 的直覺。

大 O 括號內放的是「成長函數」，也就是描述工作量如何隨 `n` 變大的式子。例如：

- `O(1)` 的括號內是 `1`，表示常數時間。
- `O(log n)` 的括號內是 `log n`，表示對數時間。
- `O(n)` 的括號內是 `n`，表示線性時間。
- `O(n log n)` 的括號內是 `n log n`，表示線性對數時間。
- `O(n^2)` 的括號內是 `n^2`，表示平方時間。

## 常見時間複雜度的意義與直覺

常數時間（Constant Time）是指演算法執行時間不會隨輸入規模明顯增加，表示為 `O(1)`。例如直接讀取陣列第 5 個元素，只要知道位置，就不需要從頭找到尾。

對數時間（Logarithmic Time）是指工作量隨資料量增加得很慢，表示為 `O(log n)`。典型例子是二分搜尋，因為每次都能排除一半資料。

線性時間（Linear Time）是指工作量與輸入規模成正比，表示為 `O(n)`。例如從頭到尾掃描陣列一次，陣列有 `n` 個元素，就大約檢查 `n` 次。

線性對數時間（Linearithmic Time）是指工作量約為 `n` 乘上 `log n`，表示為 `O(n log n)`。常見於有效率的排序演算法，例如合併排序（Merge Sort）。它通常比 `O(n^2)` 好很多，是排序題常見的標準答案。

平方時間（Quadratic Time）是指工作量與輸入規模的平方成正比，表示為 `O(n^2)`。常見於雙層巢狀迴圈，例如每個人都要和其他所有人比較一次。

常見成長速度由快到慢可背成：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)
```

這裡的「小於」表示成長較慢、通常效率較好；越右邊成長越快，資料量大時越容易無法承受。

## 如何計算時間複雜度

計算時間複雜度時，可以先不要急著看語法細節，而是問自己：這段程式會執行幾次主要操作？

### 單次操作通常是 O(1)

如果程式只做固定次數的操作，不管 `n` 多大都差不多，就是 `O(1)`。

```text
x = array[0]
y = array[1]
```

即使陣列有 10 筆或 10000 筆，這段程式都只是取固定位置的資料，所以是 `O(1)`。

### 單層迴圈通常是 O(n)

如果迴圈從 1 跑到 `n`，每次做固定工作，總工作量通常是 `O(n)`。

```text
for i = 1 to n:
    print(i)
```

這段會執行 `n` 次，因此時間複雜度是 `O(n)`。

若有兩個單層迴圈相加：

```text
for i = 1 to n:
    do something

for j = 1 to n:
    do something
```

總共約 `n + n = 2n` 次。大 O 會忽略常數，所以仍是 `O(n)`。

### 雙層巢狀迴圈通常是 O(n^2)

巢狀迴圈（Nested Loop）是指迴圈裡面又有迴圈。如果外層跑 `n` 次，內層每次也跑 `n` 次，總工作量就是 `n * n = n^2`。

```text
for i = 1 to n:
    for j = 1 to n:
        print(i, j)
```

因此時間複雜度是 `O(n^2)`。

### 每次問題規模減半通常是 O(log n)

如果每次都把資料量砍半，通常是 `O(log n)`。

```text
while n > 1:
    n = n / 2
```

因為不是每次只少 1，而是每次都少一半，所以成長速度比 `O(n)` 慢很多。

### 分治常見是 O(n log n)

分治法（Divide and Conquer）是把大問題切成小問題，解完後再合併。合併排序（Merge Sort）就是典型例子。

合併排序的直覺是：

1. 把資料一直切半，所以切分層數約為 `log n`。
2. 每一層都要合併全部 `n` 個元素，所以每層工作量約為 `n`。
3. 總工作量就是 `n * log n`，所以是 `O(n log n)`。

## 最好、平均、最差時間複雜度

最好時間複雜度（Best-case Time Complexity）是指在最順利的輸入情況下，演算法需要多少時間。

平均時間複雜度（Average-case Time Complexity）是指在一般或平均輸入情況下，演算法大約需要多少時間。

最差時間複雜度（Worst-case Time Complexity）是指在最不利的輸入情況下，演算法最多需要多少時間。

三者要分開看，不能混在一起。以線性搜尋（Linear Search）為例，若要在陣列中找某個值：

1. 最好情況：第一個元素就是答案，只找 1 次，為 `O(1)`。
2. 平均情況：大約找到中間才找到，仍以成長趨勢看成 `O(n)`。
3. 最差情況：找到最後一個才找到，或根本不存在，要檢查全部，為 `O(n)`。

國考題目如果問「最差時間複雜度」，就要用最不利情況判斷；如果問「平均時間複雜度」，就不能直接拿最好情況作答。

## 國考常見考法

國考常見第一種考法是排序複雜度。題目可能問合併排序的時間複雜度，常見答案是 `O(n log n)`；若問簡單雙層比較排序，例如氣泡排序（Bubble Sort）、選擇排序（Selection Sort），常見最差時間複雜度是 `O(n^2)`。

第二種考法是看程式片段判斷複雜度。看到單層迴圈通常先想到 `O(n)`，看到雙層巢狀迴圈通常先想到 `O(n^2)`，看到每次除以 2 或乘以 2 的迴圈通常先想到 `O(log n)`。

第三種考法是比較成長速度。要能判斷 `O(log n)` 比 `O(n)` 慢，`O(n log n)` 通常比 `O(n^2)` 好，`O(2^n)` 與 `O(n!)` 成長非常快。

第四種考法是刪除常數與低次項。例如：

| 原本工作量 | Big O |
|---|---|
| `5n + 20` | `O(n)` |
| `3n^2 + 10n + 7` | `O(n^2)` |
| `100log n + 50` | `O(log n)` |
| `n^2 + n log n + n` | `O(n^2)` |

## 易混淆整理

| 易混淆觀念 | 正確理解 |
|---|---|
| Big O 是實際秒數 | Big O 是成長趨勢，不是實際執行秒數 |
| `O(2n)` 比 `O(n)` 差很多 | 大 O 忽略常數，所以 `O(2n)` 簡化為 `O(n)` |
| `O(n^2 + n)` 要全部保留 | 大 O 保留最高影響項，所以是 `O(n^2)` |
| 兩個單層迴圈一定是 `O(n^2)` | 如果不是巢狀，而是前後相加，通常是 `O(n)` |
| 有迴圈就一定是 `O(n)` | 若每次規模減半，可能是 `O(log n)` |
| 最好、平均、最差都一樣 | 三者要依輸入情況分開判斷 |

## 國考必背整理

1. 大 O 記號（Big O Notation）用來描述演算法的成長趨勢。
2. 輸入規模（Input Size）通常用 `n` 表示。
3. 大 O 只保留成長最快的主要項，忽略常數與低次項。
4. 單次固定操作通常是 `O(1)`。
5. 每次問題規模減半通常是 `O(log n)`。
6. 單層迴圈通常是 `O(n)`。
7. 雙層巢狀迴圈通常是 `O(n^2)`。
8. 分治法常見時間複雜度是 `O(n log n)`，例如合併排序。
9. 最好時間、平均時間、最差時間要分開判斷。
10. 常見成長順序要背熟：`O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)`。

## 容易考的判斷題

1. 「Big O 主要用來表示演算法實際執行秒數。」錯。Big O 表示成長趨勢，不是實際秒數。
2. 「`3n + 100` 的時間複雜度可寫成 `O(n)`。」對。常數與低次影響會被忽略。
3. 「雙層巢狀迴圈一定要先想到可能是 `O(n^2)`。」對。若兩層都與 `n` 有關，通常是平方時間。
4. 「每次把問題規模減半，常見時間複雜度是 `O(log n)`。」對。這是二分搜尋常見直覺。
5. 「`O(n log n)` 一定比 `O(n^2)` 成長快。」錯。通常 `O(n log n)` 成長比 `O(n^2)` 慢，效率較好。
6. 「最好時間複雜度和最差時間複雜度一定相同。」錯。要看輸入情況，有些演算法差異很大。

## 考前速記小抄

看到固定次數操作，先想 `O(1)`。

看到每次砍半，先想 `O(log n)`。

看到從頭掃到尾，先想 `O(n)`。

看到有效率排序或分治合併，先想 `O(n log n)`。

看到雙層巢狀迴圈，先想 `O(n^2)`。

最後再檢查是否有常數、低次項、最好平均最差情況。國考最愛考的不是背公式而已，而是看你能不能把程式執行次數轉成正確的成長趨勢。
