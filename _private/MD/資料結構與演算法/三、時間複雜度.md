# 時間複雜度(Time Complexity)

## 這份教材要先解決什麼問題

很多人第一次看到 `O(log n)`、`O(n)`、`O(n^2)` 會卡住，不是因為演算法很難，而是符號本身沒有被講清楚。

你可以先把時間複雜度(Time Complexity)理解成一句話：

> 當資料量變大時，程式需要做多少步驟。

它不是在問「這支程式跑幾秒」，而是在問「資料量變大時，執行步驟成長得多快」。

例如：

- 資料 10 筆時做 10 次，大約是 `O(n)`。
- 資料 10 筆時做 100 次，大約是 `O(n^2)`。
- 資料 10 筆時每次砍半，大約是 `O(log n)`。

時間複雜度重點在「成長趨勢」，不是精確秒數。

## O 是什麼意思

`O` 是 Big O Notation，中文常稱為「大 O 記號」。

它用來描述演算法在輸入資料變大時，執行時間的成長上限或主要成長趨勢。

簡單說：

> `O(...)` 的意思是：這個演算法的執行步驟，大概會隨著括號內的函數成長。

例如：

- `O(1)`：資料變多，步驟數幾乎不變。
- `O(n)`：資料變成 2 倍，步驟數大約也變 2 倍。
- `O(n^2)`：資料變成 2 倍，步驟數大約變 4 倍。
- `O(log n)`：資料變很大時，步驟數增加得很慢。

Big O 不是拿來算精確時間，而是拿來比較演算法的成長速度。

## n 是什麼意思

`n` 代表輸入規模(input size)，也就是「資料量有多大」。

在不同題目裡，`n` 可能代表不同東西：

| 題目情境 | n 可能代表 |
| --- | --- |
| 陣列(Array) | 陣列元素個數 |
| 字串(String) | 字元數 |
| 串列(List) | 節點數 |
| 排序(Sorting) | 要排序的資料筆數 |
| 搜尋(Search) | 被搜尋的資料筆數 |
| 矩陣(Matrix) | 列數、欄數，或總元素數 |
| 圖(Graph) | 頂點數 `V`、邊數 `E` |

所以看到 `O(n)` 時，不要只背「n 是資料量」，要問：

> 這題的資料量到底是什麼？

例如一個長度為 `n` 的陣列，程式從頭掃到尾一次，那就是 `O(n)`。

如果有兩個陣列，一個長度是 `n`，另一個長度是 `m`，那複雜度可能會寫成 `O(n + m)`，因為兩個輸入規模不同。

## log 是什麼意思

`log` 是 logarithm，中文叫「對數」。

在時間複雜度裡，你可以先不要用數學課那種抽象定義理解它。先記這句：

> `log n` 可以理解成：把 n 不斷縮小成原本的一半，需要縮幾次才會到 1。

例如：

| n | 每次除以 2 到 1 需要幾次 | log2 n |
| --- | ---: | ---: |
| 1 | 0 次 | 0 |
| 2 | 1 次 | 1 |
| 4 | 2 次 | 2 |
| 8 | 3 次 | 3 |
| 16 | 4 次 | 4 |
| 32 | 5 次 | 5 |
| 1024 | 10 次 | 10 |

所以 `O(log n)` 的直覺是：

> 每一步都能大量縮小問題規模，通常是砍半、分半、折半。

常見形式：

- 每次 `n = n / 2`
- 每次 `n = n / 3`
- 每次只保留一半資料繼續處理

在 Big O 裡，`log2 n`、`log10 n`、`ln n` 通常都簡寫成 `log n`，因為不同底數只差一個常數倍，而 Big O 會忽略常數。

## 括號裡面放什麼

`O(...)` 括號裡放的是「步驟數如何隨輸入規模成長」的函數。

常見括號內容如下：

| 寫法 | 意思 |
| --- | --- |
| `O(1)` | 常數時間，不隨 n 成長 |
| `O(log n)` | 對數時間，每次大量縮小問題 |
| `O(n)` | 線性時間，資料有幾筆大概做幾次 |
| `O(n log n)` | 線性對數時間，常見於有效率排序 |
| `O(n^2)` | 平方時間，常見於雙層迴圈 |
| `O(n^3)` | 立方時間，常見於三層迴圈 |
| `O(2^n)` | 指數時間，常見於暴力列舉所有選或不選 |
| `O(n!)` | 階乘時間，常見於排列所有順序 |
| `O(n + m)` | 有兩個不同輸入規模 |
| `O(V + E)` | 圖論常見，V 是頂點數，E 是邊數 |

括號裡不是隨便放，而是放「主導成長速度的項」。

例如實際步驟是：

```text
3n + 10
```

Big O 會寫成：

```text
O(n)
```

因為當 `n` 很大時，`3n + 10` 的主要成長趨勢還是線性成長。

## 為什麼會忽略常數

Big O 會忽略常數倍與低階項。

例如：

```text
5n      -> O(n)
100n    -> O(n)
n + 50  -> O(n)
3n + 7  -> O(n)
```

原因是 Big O 關心資料量變大後的成長趨勢。

當 `n = 10`：

```text
n = 10
n^2 = 100
```

當 `n = 1,000,000`：

```text
n = 1,000,000
n^2 = 1,000,000,000,000
```

差距會被高階項拉開。常數在大資料量下通常不是主角。

## 為什麼會忽略低階項

如果實際步驟是：

```text
n^2 + n + 100
```

Big O 寫成：

```text
O(n^2)
```

因為 `n` 變大後，`n^2` 成長得比 `n` 和 `100` 快太多。

例如 `n = 10,000`：

```text
n^2 = 100,000,000
n = 10,000
100 = 100
```

所以主導整體成長的是 `n^2`。

國考常見簡化規則：

| 原式 | Big O |
| --- | --- |
| `7` | `O(1)` |
| `3n + 5` | `O(n)` |
| `n + log n` | `O(n)` |
| `n^2 + n` | `O(n^2)` |
| `2n^2 + 100n + 8` | `O(n^2)` |
| `n log n + n` | `O(n log n)` |

## 常見時間複雜度由快到慢

通常可以先背這條順序：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)
```

意思是，當 `n` 很大時，左邊通常比右邊成長慢。

| 複雜度 | 名稱 | 直覺 |
| --- | --- | --- |
| `O(1)` | 常數時間(Constant Time) | 查一次、取一次、不管資料量 |
| `O(log n)` | 對數時間(Logarithmic Time) | 每次砍半或大量縮小 |
| `O(n)` | 線性時間(Linear Time) | 從頭掃到尾 |
| `O(n log n)` | 線性對數時間(Linearithmic Time) | 分割加上每層掃描 |
| `O(n^2)` | 平方時間(Quadratic Time) | 兩層迴圈比對 |
| `O(n^3)` | 立方時間(Cubic Time) | 三層迴圈 |
| `O(2^n)` | 指數時間(Exponential Time) | 每個元素都有選或不選 |
| `O(n!)` | 階乘時間(Factorial Time) | 列出所有排列 |

## 如何計算時間複雜度

計算時間複雜度可以照這個流程：

1. 找出輸入規模是什麼。
2. 找出程式主要重複做的動作。
3. 看迴圈或遞迴執行幾次。
4. 加總不同區塊的成本。
5. 留下成長最快的項。
6. 忽略常數倍與低階項。

下面用常見情況練習。

## 情況一：固定次數操作是 O(1)

```java
int x = arr[0];
int y = arr[1];
int z = x + y;
```

不管陣列有 10 筆還是 100 萬筆，這段都只做固定幾個動作。

所以是：

```text
O(1)
```

`O(1)` 不是代表只做 1 次，而是代表「次數固定，不會隨 n 增加」。

## 情況二：單層迴圈通常是 O(n)

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}
```

`i` 從 `0` 跑到 `n - 1`，總共跑 `n` 次。

所以是：

```text
O(n)
```

如果每次加 2：

```java
for (int i = 0; i < n; i += 2) {
    System.out.println(i);
}
```

大約跑 `n / 2` 次。

Big O 忽略常數，所以還是：

```text
O(n)
```

## 情況三：兩個連續迴圈是 O(n)

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}

for (int j = 0; j < n; j++) {
    System.out.println(j);
}
```

第一個迴圈跑 `n` 次，第二個迴圈也跑 `n` 次。

總共：

```text
n + n = 2n
```

Big O 忽略常數：

```text
O(n)
```

注意：連續不是相乘，是相加。

## 情況四：雙層巢狀迴圈通常是 O(n^2)

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        System.out.println(i + "," + j);
    }
}
```

外層跑 `n` 次。

每次外層都讓內層跑 `n` 次。

總共：

```text
n * n = n^2
```

所以是：

```text
O(n^2)
```

注意：巢狀通常是相乘。

## 情況五：兩個不同輸入規模是 O(n * m)

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        System.out.println(i + "," + j);
    }
}
```

外層跑 `n` 次，內層跑 `m` 次。

總共：

```text
n * m
```

所以是：

```text
O(nm)
```

不能隨便寫成 `O(n^2)`，除非題目明確說 `m` 和 `n` 規模相同。

## 情況六：三層巢狀迴圈是 O(n^3)

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        for (int k = 0; k < n; k++) {
            System.out.println(i + "," + j + "," + k);
        }
    }
}
```

總共：

```text
n * n * n = n^3
```

所以是：

```text
O(n^3)
```

## 情況七：每次乘以 2 的迴圈是 O(log n)

```java
for (int i = 1; i < n; i *= 2) {
    System.out.println(i);
}
```

`i` 的變化：

```text
1, 2, 4, 8, 16, 32, ...
```

每次變成 2 倍，直到接近 `n`。

問題是：

> 2 要乘幾次才會到 n？

答案就是 `log2 n`。

所以是：

```text
O(log n)
```

## 情況八：每次除以 2 的迴圈也是 O(log n)

```java
while (n > 1) {
    n = n / 2;
}
```

`n` 的變化：

```text
n, n/2, n/4, n/8, ...
```

每次砍半，直到變成 1。

所以也是：

```text
O(log n)
```

## 情況九：外層 n 次，內層 log n 次，是 O(n log n)

```java
for (int i = 0; i < n; i++) {
    for (int j = 1; j < n; j *= 2) {
        System.out.println(i + "," + j);
    }
}
```

外層跑 `n` 次。

內層每次乘以 2，所以跑 `log n` 次。

總共：

```text
n * log n
```

所以是：

```text
O(n log n)
```

## 情況十：內層次數跟外層有關

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < i; j++) {
        System.out.println(i + "," + j);
    }
}
```

內層不是每次都跑 `n` 次，而是：

```text
i = 0 -> 0 次
i = 1 -> 1 次
i = 2 -> 2 次
...
i = n - 1 -> n - 1 次
```

總次數：

```text
0 + 1 + 2 + ... + (n - 1)
```

這個和大約是：

```text
n(n - 1) / 2
```

展開後主項是 `n^2`，所以：

```text
O(n^2)
```

這是國考很常見的陷阱：雖然不是完整雙層 `n * n`，但仍然是平方級。

## 情況十一：遞迴如何看時間複雜度

遞迴(Recursion)就是函式呼叫自己。

看遞迴時間複雜度時，先問兩件事：

1. 每次呼叫會產生幾個新的遞迴呼叫？
2. 每次呼叫時，問題規模變成多大？

### 每次只呼叫一次，規模減 1

```java
void f(int n) {
    if (n <= 0) return;
    f(n - 1);
}
```

呼叫鏈：

```text
f(n) -> f(n-1) -> f(n-2) -> ... -> f(0)
```

大約呼叫 `n` 次。

所以是：

```text
O(n)
```

### 每次只呼叫一次，規模砍半

```java
void f(int n) {
    if (n <= 1) return;
    f(n / 2);
}
```

呼叫鏈：

```text
n -> n/2 -> n/4 -> n/8 -> ...
```

所以是：

```text
O(log n)
```

### 每次呼叫兩次，規模減 1

```java
int f(int n) {
    if (n <= 1) return 1;
    return f(n - 1) + f(n - 1);
}
```

每層都分裂成兩個呼叫，層數大約是 `n`。

所以會接近：

```text
O(2^n)
```

這種成長很快，通常代表暴力遞迴。

## 常見判斷口訣

可以先用這些口訣判斷：

| 程式特徵 | 常見複雜度 |
| --- | --- |
| 只取一個元素、只做固定次數 | `O(1)` |
| 迴圈從 0 到 n | `O(n)` |
| 兩個連續的 n 迴圈 | `O(n)` |
| 兩層 n 巢狀迴圈 | `O(n^2)` |
| 三層 n 巢狀迴圈 | `O(n^3)` |
| 每次乘以 2 或除以 2 | `O(log n)` |
| 外層 n，內層每次乘以 2 | `O(n log n)` |
| 列舉所有子集合 | `O(2^n)` |
| 列舉所有排列 | `O(n!)` |

## 加法規則

如果程式分成兩段連續執行，就把它們相加，再取最大的那個成長項。

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}

for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        System.out.println(i + "," + j);
    }
}
```

第一段是：

```text
O(n)
```

第二段是：

```text
O(n^2)
```

總共：

```text
O(n + n^2)
```

保留最大項：

```text
O(n^2)
```

## 乘法規則

如果一個動作在另一個動作裡面重複，就通常相乘。

```java
for (int i = 0; i < n; i++) {
    for (int j = 1; j < n; j *= 2) {
        System.out.println(i + "," + j);
    }
}
```

外層：

```text
n
```

內層：

```text
log n
```

總共：

```text
O(n log n)
```

## 最好、平均、最差時間複雜度

同一個演算法可能有三種情況：

| 類型 | 英文 | 意思 |
| --- | --- | --- |
| 最好情況 | Best Case | 運氣最好、最快結束 |
| 平均情況 | Average Case | 一般輸入下的平均表現 |
| 最差情況 | Worst Case | 最倒楣、最慢的情況 |

例如某些搜尋問題：

- 第一個位置就找到：最好可能是 `O(1)`。
- 平均掃一半：平均仍是 `O(n)`。
- 最後才找到或找不到：最差是 `O(n)`。

國考若沒有特別說，通常會問最差時間複雜度(Worst-Case Time Complexity)，因為它最保守、最容易比較。

## 時間複雜度不是空間複雜度

時間複雜度(Time Complexity)問：

> 跑多久，做多少步驟？

空間複雜度(Space Complexity)問：

> 額外用了多少記憶體？

例如一個演算法可能：

- 時間複雜度是 `O(n)`
- 空間複雜度是 `O(1)`

意思是它要掃過 `n` 筆資料，但只額外使用固定幾個變數。

## 常見錯誤觀念

### 錯誤一：O(1) 代表只執行一次

不一定。

`O(1)` 代表固定次數，不隨 `n` 成長。

做 3 次、10 次、100 次，只要次數固定，都可以是 `O(1)`。

### 錯誤二：兩個迴圈一定是 O(n^2)

不一定。

連續兩個迴圈：

```text
O(n) + O(n) = O(n)
```

巢狀兩個迴圈：

```text
O(n) * O(n) = O(n^2)
```

### 錯誤三：看到除以 2 就一定是 O(log n)

通常是，但要看除以 2 發生在哪裡。

如果主問題每次真的縮小一半，常見是 `O(log n)`。

如果外面還包了一層跑 `n` 次的迴圈，就可能是 `O(n log n)`。

### 錯誤四：Big O 可以預測實際秒數

不可以。

Big O 只描述成長趨勢。實際秒數還會受硬體、語言、編譯器、資料分布、快取等因素影響。

## 國考作答模板

如果題目要求說明時間複雜度，可以用這種格式：

```text
令 n 為輸入資料筆數。
此演算法主要成本來自 ______。
外層迴圈執行 ______ 次，內層迴圈執行 ______ 次。
因此總執行次數約為 ______。
忽略常數與低階項後，時間複雜度為 O(______)。
```

範例：

```text
令 n 為陣列元素個數。
此演算法主要成本來自雙層巢狀迴圈。
外層迴圈執行 n 次，內層迴圈每次最多執行 n 次。
因此總執行次數約為 n * n = n^2。
忽略常數與低階項後，時間複雜度為 O(n^2)。
```

## 練習題

### 題目一

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}
```

答案：

```text
O(n)
```

原因：迴圈執行 `n` 次。

### 題目二

```java
for (int i = 1; i < n; i *= 2) {
    System.out.println(i);
}
```

答案：

```text
O(log n)
```

原因：`i` 每次變成 2 倍，執行次數約為 `log n`。

### 題目三

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        System.out.println(i + j);
    }
}
```

答案：

```text
O(n^2)
```

原因：外層 `n` 次，內層 `n` 次，總共 `n * n`。

### 題目四

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}

for (int j = 0; j < n; j++) {
    System.out.println(j);
}
```

答案：

```text
O(n)
```

原因：兩段連續迴圈是 `n + n = 2n`，忽略常數後是 `O(n)`。

### 題目五

```java
for (int i = 0; i < n; i++) {
    for (int j = 1; j < n; j *= 2) {
        System.out.println(i + j);
    }
}
```

答案：

```text
O(n log n)
```

原因：外層 `n` 次，內層 `log n` 次，相乘為 `n log n`。

## 最後整理

時間複雜度的核心不是背符號，而是看「資料量變大時，步驟數怎麼長大」。

最重要的基本觀念：

- `O`：大 O 記號，描述成長趨勢。
- `n`：輸入規模，要先看題目定義。
- `log n`：通常代表問題每次被大幅縮小，常見是砍半。
- `O(...)` 括號內放的是步驟數相對於輸入規模的成長函數。
- 連續區塊通常相加，巢狀區塊通常相乘。
- Big O 會忽略常數倍與低階項。
- 國考通常關心最差情況，除非題目另外指定。
