## 〇、先備：二元搜尋樹 BST　【理解】

- **規則**：對每個節點，**左子樹所有值 < 該節點 < 右子樹所有值**。
- **搜尋／插入**：從根比，**小往左、大往右**，走到底 → O(樹高)。
- **特性**：**中序走訪 BST ＝ 由小到大排序**。
- **致命問題**：若資料**照順序插入**（1,2,3,4…），會退化成**偏斜樹**（像鏈結串列），樹高變 **O(n)**，搜尋也退化成 O(n)。
  ```
  1
   \
    2
     \
      3      ← 退化，等於白做了
       \
        4
  ```
> **這就是為什麼要「自我平衡樹」**（AVL、紅黑樹）——強迫樹維持矮胖，保住 O(log n)。

---

## 一、AVL Tree　【理解】＋【練流程】

- **是什麼**：**自我平衡的二元搜尋樹**。
- **平衡條件**：每個節點的**平衡因子 BF ＝ 左子樹高 − 右子樹高**，必須是 **−1、0、+1**（左右高度差 ≤ 1）。
- **怎麼維持**：插入／刪除後若某節點 **BF 變成 ±2（失衡）**，用**旋轉（rotation）**轉回來。四種情況：

| 失衡型 | 形狀 | 解法 |
|---|---|---|
| **LL**（左-左） | 左邊太高、且偏左子的左邊 | **右旋**（單旋） |
| **RR**（右-右） | 右邊太高、且偏右子的右邊 | **左旋**（單旋） |
| **LR**（左-右） | 左邊太高、但偏左子的右邊 | **先左旋再右旋**（雙旋） |
| **RL**（右-左） | 右邊太高、但偏右子的左邊 | **先右旋再左旋**（雙旋） |

LL 範例（依序插入 C、B、A → 左偏 → 右旋）：
```
    C (BF=+2)             B
   /            右旋     / \
  B            ─────►   A   C   ← 平衡了
 /
A
```
- **時間複雜度**：搜尋／插入／刪除都 **O(log n)**。

## 二、B-Tree　【理解】

- **是什麼**：**多路（m-way）平衡搜尋樹**，**一個節點可放多個鍵、多個子節點**（不只 2 個）。常用於**資料庫、檔案系統的索引**。
- **m 階 B-Tree 特性**：
  - 每節點最多 **m 個子**、最多 **m−1 個鍵**。
  - 除根與葉外，每節點至少 **⌈m/2⌉ 個子**。
  - **所有葉節點在同一層**（完美平衡）；節點內鍵值由小到大排。
- **為什麼資料庫愛用**：節點「胖」→ 樹「矮」→ **磁碟 I/O 次數少**（讀一個節點 ≈ 一次 I/O）。
- **調整**：插入滿了會**分裂（split）**，刪除太少會**合併（merge）**。
- **B+ Tree（常一起考）**：B-Tree 變形，**資料只存葉節點**，且**葉節點用鏈結串列串起來** → 適合**範圍查詢**。**資料庫索引最常用 B+ Tree**。
- **時間複雜度**：搜尋／插入／刪除都 **O(log n)**。

---

## 三、Heap（堆積）　【理解】＋【練流程】

- **是什麼**：一棵**完全二元樹（Complete Binary Tree）**，且滿足堆積性質：
  - **Max-Heap 最大堆**：每個節點 **≥ 子節點**（**根最大**）。
  - **Min-Heap 最小堆**：每個節點 **≤ 子節點**（**根最小**）。
- ⚠ Heap 只管「**父子**」大小，**不管左右／兄弟順序**（跟 BST 不同！所以 Heap 搜尋任意值很慢）。
- **用途**：**優先佇列 Priority Queue**、**堆積排序 Heap Sort**、隨時拿最大／最小（看根，O(1)）。
- **常用陣列實作**（完全二元樹可用索引算父子）：
  - 從 **1** 開始：節點 i 的**左子 ＝ 2i**、**右子 ＝ 2i+1**、**父 ＝ ⌊i/2⌋**。
- **插入**：放到最後 → **往上浮（與父比、較大就換）** → O(log n)。
- **刪除根**：把最後一個搬到根 → **往下沉（與較大的子比、交換）** → O(log n)。
- **時間複雜度**：插入／刪除 O(log n)；**取最大／最小 O(1)**；**搜尋任意值 O(n)**。

## 四、紅黑樹 Red-Black Tree　【理解】

- **是什麼**：另一種**自我平衡的二元搜尋樹**，每個節點塗**紅或黑**，靠顏色規則維持「**大致平衡**」。
- **5 條性質**：
  1. 每個節點**非紅即黑**。
  2. **根是黑色**。
  3. 葉節點（NIL 空節點）是**黑色**。
  4. **紅節點的子節點都是黑**（不能有兩個連續紅）。
  5. 從任一節點到其底下所有葉的路徑，**黑節點數相同**（黑高度一致）。
- **為什麼能平衡**：這些規則保證「**最長路徑 ≤ 最短路徑的 2 倍**」→ 大致平衡 → O(log n)。
- **時間複雜度**：搜尋／插入／刪除都 **O(log n)**。

### AVL vs 紅黑樹（常考比較）
| | AVL | 紅黑樹 |
|---|---|---|
| 平衡嚴格度 | **嚴格**（高度差 ≤ 1） | **較鬆** |
| 查詢 | **較快**（更矮） | 略慢 |
| 插入／刪除 | 調整較頻繁、較慢 | **調整少、較快** |
| 適用 | 查詢多 | **插刪頻繁**（Java TreeMap、C++ map 都用它） |

## 五、時間複雜度總表（背這張）　【硬背】

| 結構 | 搜尋 | 插入 | 刪除 | 備註 |
|---|---|---|---|---|
| **BST 平均** | O(log n) | O(log n) | O(log n) | — |
| **BST 最壞（偏斜）** | **O(n)** | O(n) | O(n) | 沒平衡會退化 |
| **AVL** | O(log n) | O(log n) | O(log n) | 嚴格平衡 |
| **紅黑樹** | O(log n) | O(log n) | O(log n) | 鬆平衡、插刪較快 |
| **B-Tree／B+ Tree** | O(log n) | O(log n) | O(log n) | 多路、磁碟友善 |
| **Heap** | **O(n)** | O(log n) | O(log n) | 取根 **O(1)**、搜尋慢 |

## 六、重點整理（背這張）

- **為什麼要高等樹**：BST 沒平衡會退化成 O(n)，所以要自我平衡。
- **AVL**：BF ∈ {−1,0,+1}；失衡靠旋轉，**LL／RR 單旋、LR／RL 雙旋**；O(log n)。
- **B-Tree**：多路、矮、葉同層、**磁碟 I/O 少**；資料庫常用 **B+ Tree**（資料在葉、葉相連、利於範圍查詢）。
- **Heap**：完全二元樹 + 父子大小（Max／Min）；陣列實作 **左 2i、右 2i+1、父 i/2**；取根 O(1)、插刪 O(log n)、**搜尋 O(n)**；用於優先佇列、Heap Sort。
- **紅黑樹**：顏色 5 規則維持大致平衡；**插刪比 AVL 快**，實務常用。
- 全部平衡樹的搜尋／插入／刪除都是 **O(log n)**。
