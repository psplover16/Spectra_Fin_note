## 高等樹是什麼

高等樹（Advanced Tree Structures）是指比一般二元樹（Binary Tree）或二元搜尋樹（Binary Search Tree, BST）更進一步的樹狀資料結構。它們通常不是只拿來表示「父子關係」，而是為了讓搜尋、插入、刪除、排序、索引或優先權處理更有效率。

一般二元搜尋樹（Binary Search Tree, BST）的規則是：左子樹的值比節點小，右子樹的值比節點大。問題是，如果資料剛好照順序插入，例如 1、2、3、4、5，二元搜尋樹可能退化成像鍊結串列（Linked List）一樣，搜尋時間從 O(log n) 變成 O(n)。

高等樹的核心想法，就是用額外規則維持良好的形狀。例如 AVL 樹（AVL Tree）和紅黑樹（Red-Black Tree）會避免樹太歪；B 樹（B-Tree）會讓節點可以放很多鍵值，適合磁碟與資料庫；堆積（Heap）則重視最大值或最小值能不能快速取得。

國家考試常考的不是很複雜的程式碼，而是「定義是否正確」、「操作後長什麼樣子」、「時間複雜度是多少」、「哪一種樹適合哪一種用途」。

## 重要樹種

### AVL 樹（AVL Tree）

AVL 樹（AVL Tree）是一種自平衡二元搜尋樹（Self-Balancing Binary Search Tree）。「自平衡」的意思是，插入或刪除資料後，如果樹變得太歪，就會透過旋轉（Rotation）把高度調回來。

AVL 樹最重要的規則是：任一節點的左子樹高度與右子樹高度差最多只能是 1。這個高度差常稱為平衡因子（Balance Factor），常見定義是：

```text
平衡因子 = 左子樹高度 - 右子樹高度
```

所以 AVL 樹中每個節點的平衡因子只能是 -1、0、1。只要出現 2 或 -2，就代表這個節點失衡，需要旋轉調整。

AVL 樹的核心想法是「比一般二元搜尋樹更嚴格地維持平衡」。因為平衡維持得很嚴，所以搜尋、插入、刪除的平均與最差時間複雜度通常都能維持在 O(log n)。

舉例來說，依序插入 30、20、10 到一般二元搜尋樹時，樹會往左歪：

```text
    30
   /
  20
 /
10
```

這在 AVL 樹中稱為 LL 型失衡（Left-Left Case），需要做右旋（Right Rotation），調整後會變成：

```text
  20
 /  \
10  30
```

國考常考 AVL 樹的四種旋轉：

1. LL 型失衡（Left-Left Case）：左子樹的左邊太高，做一次右旋。
2. RR 型失衡（Right-Right Case）：右子樹的右邊太高，做一次左旋。
3. LR 型失衡（Left-Right Case）：左子樹的右邊太高，先左旋再右旋。
4. RL 型失衡（Right-Left Case）：右子樹的左邊太高，先右旋再左旋。

記憶方式可以很白話：如果是同方向失衡，做一次旋轉；如果是轉折方向失衡，做兩次旋轉。

### B 樹（B-Tree）

B 樹（B-Tree）是一種多路平衡搜尋樹（Multiway Balanced Search Tree）。「多路」的意思是，一個節點不一定只有兩個孩子，而是可以有多個鍵值（Key）與多個子節點（Child）。

B 樹常用在磁碟索引（Disk Index）與資料庫（Database）中，因為磁碟讀取資料的成本比記憶體高很多。如果一個節點可以放很多鍵值，就可以減少樹的高度，進而減少磁碟存取次數。

B 樹的重要規則包括：

1. 每個節點可以有多個 key。
2. 每個節點可以有多個 child。
3. 所有葉節點（Leaf）都在同一層。
4. 樹會保持平衡。
5. 搜尋、插入、刪除的時間複雜度通常是 O(log n)。

以一個節點內有 10、20、30 三個 key 為例，它可以把資料範圍切成四段：

```text
小於 10 | 10 到 20 之間 | 20 到 30 之間 | 大於 30
```

所以 B 樹的搜尋方式很像二元搜尋樹，但一個節點內先做多個 key 的比較，再決定要往哪個 child 走。

B 樹在國考常考的操作有：

1. 分裂（Split）：節點 key 太多時，把中間 key 往上推，左右部分分成兩個節點。
2. 合併（Merge）：刪除後節點 key 太少時，可能要和兄弟節點合併。
3. 借 key（Borrow Key）：刪除後 key 不夠時，若兄弟節點還有多餘 key，可以向兄弟借。
4. 階數（Order）：用來限制一個節點最多可以有多少 child，也會影響最多 key 數。

考 B 樹時，最容易混淆的是「child 數」和「key 數」。一般概念是：如果一個節點有 k 個 key，最多可以對應 k + 1 個 child。若題目給的是 m 階 B 樹，通常會問「最多 m 個 child、最多 m - 1 個 key」，但不同教材對階數定義可能略有差異，作答時要先看題目怎麼定義。

### 堆積（Heap）

堆積（Heap）是一種完全二元樹（Complete Binary Tree）。完全二元樹的意思是，除了最後一層以外，每一層都要填滿；最後一層則由左到右依序填入，不能中間跳空。

堆積最重要的不是像二元搜尋樹那樣「左小右大」，而是父子之間要符合堆積性質（Heap Property）。

最大堆積（Max Heap）是指每個父節點都大於或等於它的子節點：

```text
parent >= children
```

最小堆積（Min Heap）是指每個父節點都小於或等於它的子節點：

```text
parent <= children
```

因此，最大堆積的根節點（Root）一定是整棵樹的最大值；最小堆積的根節點一定是整棵樹的最小值。

堆積常用來實作優先佇列（Priority Queue）。優先佇列不是先進先出，而是每次取出優先權最高或最低的資料。若使用最大堆積，可以快速取出最大值；若使用最小堆積，可以快速取出最小值。

堆積的插入流程是：

1. 先把新資料放到完全二元樹的最後位置。
2. 再向上調整（Percolate Up 或 Heapify Up）。
3. 如果違反堆積性質，就和父節點交換。
4. 重複到堆積性質恢復為止。

刪除根節點的流程是：

1. 先刪除 root。
2. 用最後一個節點補到 root。
3. 再向下調整（Percolate Down 或 Heapify Down）。
4. 持續和較適合的 child 交換，直到堆積性質恢復。

要特別注意：堆積很快能取得最大值或最小值，但不適合搜尋任意值。因為堆積沒有二元搜尋樹的左小右大規則，所以搜尋任意值通常是 O(n)。

堆積的常見時間複雜度如下：

| 操作 | 時間複雜度 | 原因 |
|---|---:|---|
| 取得最大值或最小值 | O(1) | 直接看 root |
| 插入 | O(log n) | 最多往上調整樹高 |
| 刪除 root | O(log n) | 最多往下調整樹高 |
| 搜尋任意值 | O(n) | 沒有完整搜尋順序可利用 |

### 紅黑樹（Red-Black Tree）

紅黑樹（Red-Black Tree）是一種自平衡二元搜尋樹（Self-Balancing Binary Search Tree）。它和 AVL 樹一樣都會維持平衡，但紅黑樹的平衡條件比較寬鬆，因此插入與刪除時通常旋轉次數較少，常用在實務系統中的有序集合或映射結構。

紅黑樹的每個節點都有顏色，顏色只能是紅色（Red）或黑色（Black）。它的核心規則如下：

1. 每個節點不是紅色就是黑色。
2. 根節點（Root）一定是黑色。
3. 紅色節點不能有紅色 child，也就是不能連續兩個紅色。
4. 從任一節點到其 NIL 葉節點（NIL Leaf）的每條路徑，黑色節點數量都相同。
5. 搜尋、插入、刪除的時間複雜度都是 O(log n)。

NIL 葉節點（NIL Leaf）可以理解成紅黑樹中用來表示空子節點的黑色外部節點。考試題目有時會把 NIL 畫出來，有時不畫；判斷黑高（Black Height）時要注意題目是否把 NIL 算入。

紅黑樹的核心想法是：不要求每個節點左右高度差都小於等於 1，而是透過紅黑規則限制最長路徑不會比最短路徑長太多。因此它不像 AVL 樹那麼嚴格，但仍能保證 O(log n) 的效率。

國考常見考法是給一棵紅黑樹，問是否違反規則。例如：

1. root 是否為黑色。
2. 是否有紅色節點接紅色 child。
3. 從同一節點到所有 NIL leaf 的黑節點數是否相同。
4. 是否仍符合二元搜尋樹規則。

## 操作與判斷

### 搜尋

搜尋（Search）是指在樹中找某個 key 是否存在。

AVL 樹與紅黑樹都屬於二元搜尋樹，因此搜尋時可以利用「左小右大」規則，每次往左或往右走，時間複雜度是 O(log n)。

B 樹也是搜尋樹，只是每個節點有多個 key。搜尋時先在節點內比較 key，再決定要往哪個 child 走，時間複雜度也是 O(log n)。

堆積則不同。堆積只保證父節點和子節點的大小關係，沒有保證左子樹全部小於右子樹，也沒有保證某個值一定在某一邊。因此搜尋任意值通常要逐一檢查，時間複雜度是 O(n)。

### 插入

插入（Insertion）是把新 key 放入樹中。

AVL 樹插入時，先照二元搜尋樹規則插入，再檢查是否失衡。若失衡，就用 LL、RR、LR、RL 旋轉修正。

B 樹插入時，會先找到適合的葉節點放入 key。如果節點 key 數超過限制，就要分裂，並把中間 key 往父節點推。

堆積插入時，一定先放在最後位置，維持完全二元樹形狀，再向上調整恢復堆積性質。

紅黑樹插入時，先照二元搜尋樹規則插入，再用重新著色（Recoloring）與旋轉（Rotation）修正紅黑規則。

### 刪除

刪除（Deletion）是從樹中移除某個 key。

AVL 樹刪除後可能造成高度改變，因此要一路往上檢查平衡因子，必要時旋轉。

B 樹刪除時最容易考。刪除後如果節點 key 太少，就要看能不能向兄弟借 key；不能借時就合併。

堆積通常考刪除 root。作法是用最後節點補 root，再向下調整。

紅黑樹刪除後可能破壞黑高或紅黑規則，因此要透過重新著色與旋轉修正。

## 國考常見考法

### 考法一：判斷時間複雜度

常見題目會問「某種樹的搜尋、插入、刪除時間複雜度」。要記住：

| 樹種 | 搜尋 | 插入 | 刪除 |
|---|---:|---:|---:|
| AVL 樹（AVL Tree） | O(log n) | O(log n) | O(log n) |
| B 樹（B-Tree） | O(log n) | O(log n) | O(log n) |
| 堆積（Heap）取 root | O(1) | O(log n) | O(log n) |
| 堆積（Heap）搜尋任意值 | O(n) | O(log n) | O(log n) |
| 紅黑樹（Red-Black Tree） | O(log n) | O(log n) | O(log n) |

最容易出陷阱的是堆積。堆積可以 O(1) 取得最大值或最小值，但搜尋任意值不是 O(log n)，通常是 O(n)。

### 考法二：判斷樹是否合法

題目可能給一張樹圖，要求判斷是否為合法的 AVL 樹、B 樹、堆積或紅黑樹。

判斷 AVL 樹時，要檢查兩件事：

1. 是否符合二元搜尋樹的左小右大。
2. 每個節點左右子樹高度差是否最多為 1。

判斷 B 樹時，要檢查：

1. 節點 key 數是否符合題目限制。
2. child 數是否符合題目限制。
3. 所有 leaf 是否都在同一層。
4. 節點內 key 是否排序正確。
5. 各 child 的資料範圍是否正確。

判斷堆積時，要檢查：

1. 是否為完全二元樹。
2. 是否符合最大堆積或最小堆積的父子大小規則。

判斷紅黑樹時，要檢查：

1. 是否符合二元搜尋樹規則。
2. root 是否為黑色。
3. 紅節點是否沒有紅色 child。
4. 每條往 NIL leaf 的路徑黑節點數是否相同。

### 考法三：畫出插入或刪除後的結果

AVL 樹常考插入後要做哪一種旋轉。拿到題目時，先照二元搜尋樹方式插入，再從新節點往上找第一個失衡節點，接著判斷是 LL、RR、LR、RL。

B 樹常考插入造成節點滿出後如何分裂。重點是找中間 key 往上推，不是隨便把最大或最小 key 推上去。

堆積常考插入後向上調整，或刪除 root 後向下調整。畫圖時務必先維持完全二元樹的形狀，再處理大小順序。

紅黑樹常考規則判斷比較多，若考插入刪除，重點是能看出重新著色與旋轉是為了修正紅黑性質。

## 比較表與易混淆整理

| 項目 | AVL 樹（AVL Tree） | B 樹（B-Tree） | 堆積（Heap） | 紅黑樹（Red-Black Tree） |
|---|---|---|---|---|
| 基本類型 | 自平衡二元搜尋樹 | 多路平衡搜尋樹 | 完全二元樹 | 自平衡二元搜尋樹 |
| 主要目的 | 維持嚴格平衡，加速搜尋 | 降低樹高，適合磁碟索引 | 快速取得最大或最小值 | 用較寬鬆平衡維持 O(log n) |
| 是否有搜尋樹順序 | 有 | 有 | 不一定有 | 有 |
| 是否所有 leaf 同層 | 不一定 | 是 | 不一定 | 不一定 |
| 是否一定是完全二元樹 | 否 | 否 | 是 | 否 |
| 常見操作重點 | LL、RR、LR、RL 旋轉 | 分裂、合併、借 key | 向上調整、向下調整 | 顏色規則、旋轉、重新著色 |
| 常見用途 | 搜尋、排序、集合 | 資料庫、檔案系統、索引 | 優先佇列、堆積排序 | 有序集合、映射結構 |

### AVL 樹與紅黑樹的差異

AVL 樹和紅黑樹都是自平衡二元搜尋樹，但平衡標準不同。

AVL 樹比較嚴格，每個節點左右子樹高度差最多 1，因此搜尋效率很穩定。不過插入或刪除時，為了維持嚴格平衡，可能需要較多調整。

紅黑樹比較寬鬆，只要符合紅黑規則即可，因此實務上常用在需要大量插入、刪除的資料結構中。

簡單記法：

1. AVL 樹：平衡要求嚴，搜尋很穩。
2. 紅黑樹：平衡要求較寬，更新較彈性。

### B 樹與二元搜尋樹的差異

B 樹不是二元樹，因為一個節點可以有多個 child。它的設計目的不是讓每個節點只做一次比較，而是讓樹變矮，減少磁碟存取。

國考看到「資料庫索引」、「磁碟索引」、「多路平衡搜尋樹」、「所有 leaf 同層」，通常要想到 B 樹。

### 堆積與二元搜尋樹的差異

堆積不是二元搜尋樹。最大堆積只保證 parent 大於等於 children，最小堆積只保證 parent 小於等於 children。

例如最大堆積中，左子節點和右子節點誰比較大，沒有固定規則；某個任意值在哪裡，也無法像二元搜尋樹一樣快速判斷方向。

所以看到「快速取得最大值或最小值」要想到堆積；看到「快速搜尋任意 key」通常不要選堆積。

## 國考必背整理

1. AVL 樹（AVL Tree）是自平衡二元搜尋樹。
2. AVL 樹任一節點左右子樹高度差最多為 1。
3. AVL 樹失衡類型有 LL、RR、LR、RL。
4. AVL 樹搜尋、插入、刪除通常都是 O(log n)。
5. B 樹（B-Tree）是多路平衡搜尋樹。
6. B 樹常用於磁碟索引與資料庫。
7. B 樹節點可以有多個 key 與多個 child。
8. B 樹所有 leaf 都在同一層。
9. B 樹常考階數、key 數、child 數、分裂、合併、借 key。
10. 堆積（Heap）是完全二元樹。
11. 最大堆積（Max Heap）滿足 parent >= children。
12. 最小堆積（Min Heap）滿足 parent <= children。
13. 堆積插入是放最後再向上調整。
14. 堆積刪除 root 是最後節點補 root，再向下調整。
15. 堆積搜尋任意值通常是 O(n)。
16. 堆積取最大值或最小值是 O(1)。
17. 紅黑樹（Red-Black Tree）是自平衡二元搜尋樹。
18. 紅黑樹 root 必為黑色。
19. 紅黑樹紅節點不能有紅色 child。
20. 紅黑樹從任一節點到 NIL leaf 的黑節點數相同。
21. 紅黑樹搜尋、插入、刪除都是 O(log n)。

## 容易考的判斷題

1. AVL 樹一定是二元搜尋樹。  
   正確。AVL 樹是自平衡二元搜尋樹。

2. AVL 樹任一節點左右子樹高度差可以大於 1。  
   錯誤。AVL 樹的高度差最多為 1。

3. B 樹的所有 leaf 必須在同一層。  
   正確。這是 B 樹平衡的重要特徵。

4. B 樹每個節點只能有一個 key。  
   錯誤。B 樹節點可以有多個 key。

5. 堆積一定是完全二元樹。  
   正確。堆積的形狀必須符合完全二元樹。

6. 最大堆積的 root 一定是最大值。  
   正確。最大堆積滿足 parent >= children。

7. 最小堆積的 root 一定是最大值。  
   錯誤。最小堆積的 root 是最小值。

8. 堆積搜尋任意值是 O(log n)。  
   錯誤。堆積沒有二元搜尋樹的完整順序，通常是 O(n)。

9. 紅黑樹的 root 必須是黑色。  
   正確。這是紅黑樹基本規則之一。

10. 紅黑樹可以有紅色節點連接紅色 child。  
    錯誤。紅節點不能有紅色 child。

11. 紅黑樹從同一節點到各 NIL leaf 的黑節點數必須相同。  
    正確。這是紅黑樹維持平衡的核心規則。

12. AVL 樹、B 樹、紅黑樹的搜尋時間複雜度都可維持 O(log n)。  
    正確。這些樹都透過平衡或多路設計避免高度過大。

## 考前速記小抄

AVL 樹（AVL Tree）：自平衡 BST，左右高度差最多 1。失衡看 LL、RR、LR、RL，搜尋、插入、刪除都是 O(log n)。

B 樹（B-Tree）：多路平衡搜尋樹，常用於資料庫與磁碟索引。節點可放多個 key，所有 leaf 同層，常考分裂、合併、借 key。

堆積（Heap）：完全二元樹。最大堆積 root 最大，最小堆積 root 最小。取 root 是 O(1)，插入與刪除 root 是 O(log n)，搜尋任意值是 O(n)。

紅黑樹（Red-Black Tree）：自平衡 BST。root 黑、紅節點不能接紅 child、每條到 NIL leaf 的黑節點數相同。搜尋、插入、刪除都是 O(log n)。

最後記一句：要搜尋排序，想 AVL 樹、紅黑樹、B 樹；要資料庫索引，想 B 樹；要快速拿最大或最小，想堆積。
