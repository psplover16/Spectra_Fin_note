## 雜湊法是什麼

雜湊法（Hashing）是一種用來快速儲存與查找資料的方法。它的核心精神是：不要一筆一筆慢慢找，而是先用某個規則把資料的鍵值（Key）轉成陣列中的位置，之後就可以直接到那個位置存取資料。

鍵值（Key）是用來識別資料的欄位，例如學號、身分證字號、商品編號或帳號名稱。雜湊表（Hash Table）是實際存放資料的表格，通常可以想像成一個陣列。雜湊函數（Hash Function）則是把鍵值轉換成雜湊表索引（Index）的規則。

舉例來說，如果雜湊表大小是 10，某個簡單的雜湊函數可以寫成：

```text
h(key) = key mod 10
```

若鍵值是 27，則：

```text
h(27) = 27 mod 10 = 7
```

所以資料會被放在索引 7 的位置。這就是雜湊法（Hashing）最直覺的想法：用雜湊函數（Hash Function）把鍵值（Key）直接對應到雜湊表（Hash Table）的位置。

在國家考試中，雜湊法常考「名詞定義」、「碰撞處理」、「負載因子」與「給定鍵值後畫出雜湊表」。題目通常不難，但很容易因為名詞混淆而失分。

## 雜湊函數與碰撞

雜湊函數（Hash Function）是將鍵值（Key）映射到雜湊表（Hash Table）索引位置的函數。好的雜湊函數要讓資料分布均勻，避免大量資料集中在同一個位置。

例如雜湊表大小為 10，使用：

```text
h(key) = key mod 10
```

鍵值 18 會放到索引 8，鍵值 25 會放到索引 5。看起來很方便，但如果鍵值是 18 和 28，兩者都會映射到索引 8：

```text
h(18) = 18 mod 10 = 8
h(28) = 28 mod 10 = 8
```

碰撞（Collision）是指不同鍵值（Key）經過雜湊函數（Hash Function）後，被映射到同一個雜湊表（Hash Table）位置。也就是說，兩筆不同資料想要佔用同一格。

碰撞（Collision）在雜湊法中是正常現象，不代表雜湊法錯了。因為可能的鍵值通常很多，但雜湊表的格子有限，所以只要資料夠多，就可能發生碰撞。國考常用這個觀念考判斷題：雜湊法不能保證完全沒有碰撞，只能透過好的雜湊函數與碰撞處理方式降低影響。

溢位（Overflow）是指碰撞（Collision）發生後，原本要存放資料的位置或桶（Bucket）已經沒有足夠空間，導致資料必須放到其他地方或需要額外處理。簡單說，碰撞是「撞到同一格」，溢位是「那格或那個桶裝不下」。

## 碰撞與溢位的處理方式

碰撞處理是雜湊法（Hashing）的重點。考試常見方法包括鏈結法（Chaining）、開放定址法（Open Addressing）與重新雜湊（Rehashing）。

### 鏈結法（Chaining）

鏈結法（Chaining）是指雜湊表（Hash Table）的每一格不只放一筆資料，而是接上一串資料，例如鏈結串列（Linked List）或桶（Bucket）。當多個鍵值（Key）被映射到同一格時，就把它們串在同一個位置後面。

例如使用 `h(key) = key mod 10`，鍵值 18、28、38 都會對應到索引 8。用鏈結法處理時，可以想成：

```text
index 8: 18 -> 28 -> 38
```

鏈結法的優點是觀念簡單，插入資料也容易；缺點是如果某一格串得太長，查找時就可能變慢。國考很喜歡問：鏈結法發生碰撞時，通常用 linked list 或 bucket 來保存同一位置的資料。

### 開放定址法（Open Addressing）

開放定址法（Open Addressing）是指所有資料都放在雜湊表（Hash Table）本身的陣列格子中。當碰撞（Collision）發生時，不另外接鏈結串列，而是在表中尋找下一個可用位置。

開放定址法常見三種：

1. 線性探測（Linear Probing）
2. 平方探測（Quadratic Probing）
3. 雙重雜湊（Double Hashing）

線性探測（Linear Probing）是碰撞後依序檢查下一格，例如原本要放在索引 5，但索引 5 已滿，就看索引 6，再看索引 7，直到找到空位。

```text
h(key), h(key) + 1, h(key) + 2, h(key) + 3, ...
```

線性探測的優點是實作簡單，缺點是容易產生主要群聚（Primary Clustering）。主要群聚（Primary Clustering）是指資料容易在連續區段聚成一大塊，使後續碰撞更容易發生，查找效率也會下降。

平方探測（Quadratic Probing）是碰撞後用平方距離尋找下一個位置，例如：

```text
h(key), h(key) + 1^2, h(key) + 2^2, h(key) + 3^2, ...
```

平方探測比線性探測更能減少主要群聚（Primary Clustering），因為它不是每次只往下一格走。不過它仍可能遇到探測不到某些空格的情況，考試通常要求知道它是用平方距離找位置。

雙重雜湊（Double Hashing）是使用第二個雜湊函數（Hash Function）決定每次探測的距離。也就是說，第一個雜湊函數決定起始位置，第二個雜湊函數決定跳躍間隔。

```text
h1(key), h1(key) + h2(key), h1(key) + 2h2(key), ...
```

雙重雜湊通常能讓資料分布更分散，減少群聚現象。國考考到時，最重要的是記住：雙重雜湊（Double Hashing）用第二個雜湊函數決定探測距離。

### 重新雜湊（Rehashing）

重新雜湊（Rehashing）是指當雜湊表（Hash Table）太滿或效率變差時，擴大表格大小，並把原本的資料重新用雜湊函數（Hash Function）放入新的表中。

重新雜湊常發生在負載因子（Load Factor）太高時。負載因子（Load Factor）是已存元素數量除以雜湊表大小：

```text
Load Factor = 已存元素數 / table 大小
```

例如雜湊表大小為 10，已經放入 7 筆資料，負載因子就是：

```text
7 / 10 = 0.7
```

負載因子越高，代表雜湊表越滿，碰撞機率通常越高，查找與插入效率也會下降。因此，實務上常在負載因子超過某個門檻時進行重新雜湊。

## 操作流程與時間複雜度

雜湊法（Hashing）常見操作包括插入、查找與刪除。它們都依賴雜湊函數（Hash Function）快速定位資料。

插入資料時，先把鍵值（Key）丟進雜湊函數（Hash Function），算出索引位置。如果該位置是空的，就直接放入；如果發生碰撞（Collision），就依照鏈結法（Chaining）或開放定址法（Open Addressing）處理。

查找資料時，同樣先用鍵值（Key）算出位置。如果該位置就是目標資料，查找完成；如果不是，就依照碰撞處理規則繼續找。例如鏈結法要沿著串列找，線性探測要沿著探測序列找。

刪除資料時，也要先找到資料所在位置。若使用鏈結法，刪除串列中的節點即可；若使用開放定址法，刪除時要特別小心，因為直接清空格子可能會中斷後續查找路徑。國考若考觀念，常會提醒開放定址法刪除較麻煩。

在理想情況下，雜湊法的插入、查找與刪除平均時間複雜度接近 `O(1)`。但這個 `O(1)` 不是保證永遠如此，而是建立在雜湊函數分布均勻、負載因子不高、碰撞處理良好的前提下。

最壞情況下，如果大量鍵值都映射到同一位置，雜湊法可能退化。例如鏈結法的某一格串列很長，查找就可能接近 `O(n)`。因此國考常問：雜湊法平均很快，但最壞情況不一定是常數時間。

## 國考常見考法

國考考雜湊法（Hashing）時，通常不會只問定義，而是把定義放進小題目裡測你是否真的懂。

第一種考法是名詞解釋。你要能清楚分辨雜湊函數（Hash Function）、雜湊表（Hash Table）、碰撞（Collision）、溢位（Overflow）與負載因子（Load Factor）。尤其碰撞與溢位很容易被混在一起，務必分清楚。

第二種考法是給定鍵值與雜湊函數，要求你算出各資料位置。例如題目給 `h(key) = key mod 11`，再給一串鍵值，要你畫出雜湊表。這類題目一定要逐筆處理，碰撞發生時按照題目指定的方法繼續放。

第三種考法是比較碰撞處理方法。題目可能問線性探測（Linear Probing）的缺點，答案常指向主要群聚（Primary Clustering）；若問雙重雜湊（Double Hashing）的特色，答案就是使用第二個雜湊函數決定探測距離。

第四種考法是負載因子（Load Factor）。題目可能給你雜湊表大小與已存元素數，要你計算負載因子，或問負載因子太高會造成什麼影響。請記住：負載因子太高通常會增加碰撞，進而降低效率。

## 國考必背整理

1. 雜湊函數（Hash Function）會把鍵值（Key）映射到雜湊表（Hash Table）的索引位置。
2. 碰撞（Collision）是不同鍵值映射到同一位置。
3. 溢位（Overflow）是碰撞或桶空間不足導致資料無法直接放入原位置。
4. 鏈結法（Chaining）是在每一格後面接 linked list 或 bucket。
5. 開放定址法（Open Addressing）是在雜湊表內找其他空位。
6. 線性探測（Linear Probing）容易產生主要群聚（Primary Clustering）。
7. 平方探測（Quadratic Probing）用平方距離尋找下一個位置。
8. 雙重雜湊（Double Hashing）用第二個雜湊函數決定探測距離。
9. 重新雜湊（Rehashing）是擴大雜湊表後重新計算位置。
10. 負載因子（Load Factor）等於已存元素數除以 table 大小，太高會降低效率。

## 容易考的判斷題

1. 雜湊法（Hashing）一定不會發生碰撞。  
   錯。碰撞（Collision）是雜湊法中可能發生且必須處理的情況。

2. 不同鍵值可能被同一個雜湊函數映射到同一位置。  
   對。這就是碰撞（Collision）。

3. 線性探測（Linear Probing）碰撞後會依序尋找下一個空位。  
   對。它的特色就是一格一格往後找。

4. 線性探測（Linear Probing）容易造成主要群聚（Primary Clustering）。  
   對。這是國考常見考點。

5. 雙重雜湊（Double Hashing）只使用一個雜湊函數。  
   錯。它會使用第二個雜湊函數決定探測距離。

6. 負載因子（Load Factor）太高時，雜湊表效率可能下降。  
   對。因為碰撞通常會增加。

7. 重新雜湊（Rehashing）通常會把表格擴大並重新放入資料。  
   對。這是降低負載因子與改善效率的常見作法。

## 考前速記小抄

雜湊法（Hashing）就是「鍵值進函數，位置直接算」。雜湊函數（Hash Function）負責把鍵值（Key）轉成索引，雜湊表（Hash Table）負責存資料。

碰撞（Collision）是「不同 key 到同一格」，溢位（Overflow）是「同一格或桶裝不下」。碰撞不是錯誤，而是必須處理的正常狀況。

碰撞處理要記三大類：鏈結法（Chaining）接串列或 bucket；開放定址法（Open Addressing）在表內找空位；重新雜湊（Rehashing）擴大 table 後重新放。

開放定址法中，線性探測（Linear Probing）一格一格找，容易主要群聚（Primary Clustering）；平方探測（Quadratic Probing）用平方距離找；雙重雜湊（Double Hashing）用第二個雜湊函數決定跳多遠。

負載因子（Load Factor）公式必背：

```text
Load Factor = 已存元素數 / table 大小
```

負載因子太高，碰撞通常變多，效率會下降；必要時就重新雜湊（Rehashing）。
