PDU（Protocol Data Unit）＝ 每一層對資料的「包裝單位」名稱。
資料往下送時（7 ➔ 1），每一層都會把上一層的東西「包起來」、再貼上自己這層的標頭（header）這個動作叫 封裝（Encapsulation）
位元（Bit）→ 訊框（Frame）→ 封包（Packet）→ 區段（Segment）→ 資料（Data）

傳輸單位 PDU    Data 資料
    HTTP、HTTPS、FTP、SMTP、POP3、IMAP、DNS、DHCP、SNMP、Telnet
    閘道器 Gateway (家用)

    Data

    （無特定設備）

    建立／管理／結束兩端的連線會議、對話控制
    Data

    （無特定設備）

第 4 層 傳輸層 (Transport)
    端到端傳輸、可靠性、流量控制、分段重組；用 port 區分應用 (把包裹送到電腦裡的哪一個『應用程式（軟體）』)    
    Segment(TCP)／Datagram(UDP)
    TCP、UDP
    閘道器、L4 交換器

第 3 層 網路層 (Network)
    邏輯定址（IP）、路由選路、封包轉送 (把包裹送到哪一台『電腦（主機）』)    
    Packet 封包
    IP、ICMP、IGMP、IPSec、RIP/OSPF/BGP
    路由器 Router、L3 交換器

第 2 層 資料鏈結層 (Data Link)
    實體定址（MAC）、同網段訊框傳遞、錯誤偵測、流量控制
    Frame 訊框
    Ethernet、PPP、HDLC
    交換器 Switch(L2)、橋接器 Bridge、網卡 NIC

第 1 層 實體層 (Physical)
    傳輸原始位元、定義電氣／機械規格（電壓、接頭、纜線、訊號）
    Bit 位元
    （規格，如 RS-232、纜線標準）
    集線器 Hub、中繼器 Repeater、纜線

無狀態 (Stateless)
1. 無狀態是「HTTP 協定天生的死規矩」。 它不是伺服器的一種設定，也不能打勾關閉。伺服器只是「被動遵守」HTTP 每次連線都要斷開的標準規定。
2. 伺服器用了 Session，HTTP 就不算無狀態了嗎？
依然是無狀態。Session 只是我們在應用層加上的「外掛補救機制」。因為 HTTP 本身還是無狀態，所以每次發送請求時，用戶端還是必須自己夾帶 Session ID (號碼牌) 給伺服器，伺服器才能去資料庫裡把你的狀態找出來。伺服器從來沒有「主動記住你」。

核心定義：伺服器「有失憶症」，每個請求都是獨立的（像每次都是第一次見面）。
最大優點：伺服器負擔輕、簡單、容易擴展。
致命缺點：記不住「登入狀態」或「購物車」👉 必須靠 Cookie 或 Session 來補救！

比較項目      Cookie                              Session 
存在哪裡      客戶端(使用者的瀏覽器)                伺服器端 (Server 內部)
安全性        較低(存在本地，有被偷看或竄改的風險)   較高 (資料藏在後台)
伺服器負擔     零負擔                              高 (使用者越多，越吃伺服器記憶體)
兩者合作模式   負責把 Session ID 帶給伺服器         負責在伺服器端儲存真正的私密資料



資訊安全三要素 CIA
    機密性 Confidentiality：別人看不到 → 靠加密。
    完整性 Integrity：資料沒被竄改 → 靠雜湊／數位簽章。
    可用性 Availability：需要時用得到 → 防 DoS、備援。
常見延伸：(CIA是標準，以下是補強)
    不可否認性 Non-repudiation（你不能否認做過） → 靠數位簽章 (Digital Signature)(使用者本人發行)
    鑑別性 / 真實性 (Authenticity)：確認對方的身分是真的（防釣魚、防假冒）。 
        → 靠 數位憑證 (Digital Certificate)：透過憑證機構 (CA) 證明伺服器或網站是真的（例如 HTTPS 的 SSL 憑證）。
    可歸責性 (Accountability)：做過的事一定能追查到特定的人身上（有憑有據）。→ 靠數位簽章


對稱式 vs 非對稱式加密
            對稱式加密	                    非對稱式加密
金鑰	    加解密同一把（祕密金鑰）	      一對：公鑰 + 私鑰
速度	    快	                            慢
主要難題	金鑰怎麼安全交給對方（金鑰分配）   慢，不適合大量資料
代表演算法	AES、DES、3DES	                RSA、ECC、Diffie-Hellman
用途	    大量資料加密	                交換金鑰、數位簽章、身分驗證

網路傳輸（如 HTTPS）通常用「非對稱式」安全地交換一把對稱金鑰，之後大量資料都用「對稱式 (AES)」來跑，結合兩者優點！
公鑰加密 → 私鑰解密 ＝ 保密（Confidentiality）
    白話文：「公鑰」就像路邊的投遞郵筒，任何人都可以投信進去（用公鑰加密）；但只有你擁有「私鑰」能打開信箱看裡面（用私鑰解密）。
    用途：確保資料機密性，別人偷看到也打不開。
私鑰加密 → 公鑰解密 ＝ 簽章／驗身分（Authentication / Non-repudiation）
    白話文：「私鑰」只有你本人有。你用私鑰蓋章（加密），代表這絕對是你發的；大家拿你的「公鑰」來驗證，只要打得開，就證明這真的出自你手（防賴帳）。
    用途：數位簽章、驗明正身。
