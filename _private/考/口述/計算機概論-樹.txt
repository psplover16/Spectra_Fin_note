根節點高度為 1

二元樹：
歪斜樹 (Skewed)：每個節點最多只有 1 個子節點
嚴格二元樹 (Strictly Binary Tree)：每一個非樹葉節點（內部節點）都必須有剛好 0 或 2 個子節點 (不准有獨生子)
完滿二元樹 (Full Binary Tree) & 完美二元樹 (Perfect Binary Tree)：完美正三角形
	一棵高度為 k，且擁有剛好 2^k - 1 個節點的二元樹。
	第 i 層，最多有 2^(i-1) 個節點。
完整二元樹(Complete Binary Tree)：由左至右填滿，但最後一排可以沒排滿。
	當陣列看待時，習慣性索引以 1 開始，索引 1 是根
	i 若為陣列的索引：
		左小孩的位置：2i
		右小孩的位置：2i + 1；
		父節點 (爸爸) 的位置：Math.floor(i/2)


擴充二元樹 (Extended Binary Tree)
定義：將原本二元樹中所有空著的指標（Null），強制補上代表失敗或結局的「外部節點（方形）」，使其成為一棵所有內部節點都有 2 個分支的「嚴格二元樹」。
1. 節點數關係：外部節點數 = 內部節點數 + 1
2. 路徑長關係：外部路徑"總"長 = 內部路徑"總"長 + 內部節點數*2


霍夫曼樹 (Huffman Tree / 哈夫曼樹)
1. 為了「資料壓縮」而生的嚴格二元樹
2. 是 嚴格二元樹。
3. 編碼必定是前置碼 (Prefix Code)，也就是 任何一個字元的編碼，都不能是另一個字元編碼的「開頭」
4. 建構策略：用「由下而上 (Bottom-up)」的方式，每次必定挑出「兩個」最小的權重節點合併成一個新父節點。
	1. 挑出池子裡最小的兩個，將它們合併(相加)，生出一個權重為 加總後的 的父節點。 放回池子
	2. 再從池子裡挑出最小的兩個，再將 將它們合併，生出一個權重為 加總後的 的父節點。 放回池子
	3. 步驟1與步驟2 不停重複，直到出現根。
	4. 統一規定：左邊的 "邊"標上0、右邊的"邊"標上1
	5. 從樹根走到字母，經過的路徑就是它的編碼 
5. 最小加權路徑長 (WPL)：
	0. 加權路徑長：字母頻率(字母權重) * 走到該字母的步數 (深度)
	***1. 把每一個字母的  加權路徑長 相加
	***2. 建構過程中，所有「合併生出來的父節點數字」總和



二元樹走訪
	1. BFS (廣度優先搜尋) 是一種「由近到遠、一層一層向外擴散」的圖形（Graph）或樹（Tree）的搜尋策略。
		1. 就是 層序 Level-order
		2. 佇列(Queue，FIFO) 是 實現 BFS的唯一手段
		3. 必定找到「最短路徑」
		4. 空間複雜度較高 (因為Queue會塞滿 需要處理的所有節點)
		5. 需要記憶體空間 (Queue)
	2. DFS (深度優先搜尋)，從起始頂點開始，沿著邊盡可能深地搜尋各分支，當節點的所有邊都已被探訪過，或無法再深入時，則進行回溯 (Backtracking)，直到所有頂點皆被拜訪為止
		1. 靈魂是 Stack (堆疊) 或 遞迴
		2. 分成 「前序、中序、後序」，完全是看「中（自己）」排在哪個位置。
			前序 Preorder：中 → 左 → 右 	ROOT必定在最前
			中序 Inorder：左 → 中 → 右 	ROOT剛好在中間
			後序 Postorder：左 → 右 → 中 	ROOT必定在最後
		3. 只有「前序+中序」或「中序+後序」能唯一決定一棵樹

走訪畫樹
0. 選定 「前序＋中序」還是「後序＋中序」
1. 抓ROOT，前序 第一個是ROOT；後序，最後一個是ROOT
2. 中序以ROOT切分，分成「左子樹名單」與「右子樹名單」
3. 將 「左子樹名單」與「右子樹名單」的內部順序，調整成 第0步驟選定的 前序或後序 排序
4. 新的左右子序列的ROOT，拿去 步驟1 找下一個ROOT。 重複以上步驟



二元搜尋樹(BST)
1. 左子樹都比自己小、右子樹都比自己大
2. 平均搜尋 O(log n)、最壞 O(n):當資料按順序插入，BST 退化成歪斜樹(像一條鏈結串列)。
3. 對 BST 做中序走訪 (Inorder)，會得到由小到大排序的結果
4. 平衡樹(如 AVL、紅黑樹) 會透過旋轉維持左右高度平衡，避免退化成歪斜樹，保證 O(log n)。
5. 底層是指標
6. BST的插入：從根開始比大小，比目前節點小往左、大往右，一路走到空位就掛上去。新插入的節點，一定是放在nil的位置
7. BST的刪除：
	1. 刪除葉節點，也就是刪除 沒有子節點的節點：直接刪掉。
	2. 刪除的節點只有一個子節點：用那個子節點頂上來取代它。
	3. 刪除的節點有兩個子節點：中序前驅(左子樹的最大值 頂上來)、中序後繼(右子樹的最小值 頂上來)，兩者擇一即可。



堆積 (Heap)
1. 完整二元樹
2. 僅 父節點 與 子節點 有嚴格大小關係。與左右無關。
	最大堆 (Max-Heap)：每個節點都 ≥ 它的子節點 → 根最大。
	最小堆 (Min-Heap)：每個節點都 ≤ 它的子節點 → 根最小。
3. 用途：優先權佇列 (Priority Queue)，因為最大值或最小值，一定在根。
	1. 取得最大或最小，BIGO是 O(1)
	2. ROOT被取走後 只要花 O(log n) 的時間調整一下樹狀結構；
		1. 先把陣列尾巴，抽出來放到第一個 (當作根)
		2. 為了滿足 HEAP 規則，把這新的根由上至下，不停交換
	3. 新增：
		1. 新資料先乖乖填入「最底層、最右邊的下一個空位」也就是 陣列最後一格。
		2. 與 父節點 比大小，不符合規則就交換，持續 檢查 直到 符合規則為止。
	3. 堆積排序 (Heap Sort,O(n log n))。
		1. 建堆積 (Build Heap)，時間是 O(n)。
		2. 重複抓取與調整，每次調整是 O(log n)



運算式表示法
結構：
1. 葉節點 (Leaves)：存放運算元（數字或變數，例如 A, B, C）。
2. 內部節點 (Internal Nodes)：存放運算子（例如 +, -, *, /）。
表示法與特性：
1. 中序，
	1. 人類最習慣的數學寫法。
	2. 當父子節點都是運算子，當子節點的優先權 ≦ 父節點的優先權，與 子節點 結合的子樹 印出來 要強制加上 括號
2. 前序，
	1. 運算子在前
	2. 不需要 括弧，屬於電腦習慣的表示法
	3. 另用 Stack 與 由右至左掃描，掃到運算元 push至stack、掃到運算子 pop出stack，運算後push至stack的方式處理
3. 後序
	1. 運算子在後
	2. 不需要 括弧，屬於電腦習慣的表示法
	3. Stack 與 由左至右掃描



AVL樹
1. 平衡因子：左子樹高度 - 右子樹高度 =  -1、0、1
2. 插入流程
	1. 初始掛載：由根開始，依 BST 大小規則（小左大右）往葉檢查。將新節點掛在葉的下方，也就是 null 位置（成為新的葉節點）。
	2. 尋找失衡點（爺爺）：從新節點由下往上檢查平衡因子（左右子樹高度差）。
	    	遇到第一個「高度差 2」的節點，它就是爺爺。
	3. 鎖定三巨頭（爺、爸、孫）：從「爺爺」開始，往新插入節點的方向往下走兩步，這三個連續的節點就是爺爺、爸爸、孫子。
	   	刪除特例：若遇到左右子樹高度相同的情況，挑選能與爺爺、爸爸「連成一直線」的孫子。
	4. 中位數法：
		1. 找中位數：找出爺、爸、孫三個數字中的中位數。
		2. 上位：把這個中位數往上提拔，取代原本爺爺的位置，成為這個局部子樹的新根節點。
		3. 歸位：剩下的兩個關鍵節點，比新老大小的掛左邊，比新老大大的掛右邊。（重組後必定是一個平衡的小三角形）。
		4. 安頓孤兒：中位數原本的子樹可能變成孤兒串。
			把孤兒串的根節點，拿去跟剛剛重組好的三個關鍵節點比大小，掛進這三人底下的空位。整串孤兒帶著走，內部結構不動。
3. 刪除流程
	1. 採用BST的刪除流程，暫時取得新的 樹
	2. 從剛剛「真正被砍掉節點」的位置出發，一路往上（往樹根方向）檢查平衡因子。
		遇到第一個「高度差 2」的節點，它就是爺爺。
	3. 抓出重組三巨頭，從爺爺開始，往「比較高的那邊」走
		1. 找爸爸：從爺爺出發，挑選比較高的那個子樹，當作「爸爸」。
		2. 找孫子：從爸爸出發，挑選比較高的那個子樹，當作「孫子」。
		3. 如果爸爸的左右子樹「一樣高」，請挑選能跟爺爺、爸爸連成「一直線 (LL或RR)」的那一邊當孫子
	4. 中位數法，與新增的做法相同
	5. 繼續往上檢查 (連鎖反應)

3. 傳統旋轉方式：
	1. LL 型 (左左失衡)：爺爸孫連成一條往左下的直線 (/)。解法： 對失衡節點作 單次右旋。
	2. RR 型 (右右失衡)：爺爸孫連成一條往右下的直線 (\)。解法： 對失衡節點作 單次左旋。
	3. LR 型 (左右失衡)：爺爸孫連成一個「<」型的折線（先往左下、再往右下）。解法：雙重旋轉。先對左子節點左旋（轉成 LL 型），再對失衡節點右旋
	4. RL 型 (右左失衡)：爺爸孫連成一個「>」型的折線（先往右下、再往左下）。解法：雙重旋轉。先對右子節點右旋（轉成 RR 型），再對失衡節點左旋
4. 公式
	1. N(h) = 高度是 h 的 AVL 樹，最少節點數
	   N(h) = N(h−1) + N(h−2) + 1 (前兩項相加，再 +1)
	2. 相較於同樣擁有 N 個節點的完整二元樹，AVL 樹的最大高度大約是其多少倍 ??  1.44倍
	3. 時間複雜度，全部都是 O(log N)



紅黑樹
1. 黑高：bh(x) = 從 x 往下，不考慮x得顏色，到任一 NIL 的路徑上，黑節點的個數
2. 紅黑樹的 NIL 葉節點：是每個內部節點缺少小孩的那個位置所連到的東西 (與一般BST定義不同)
3. 定義：
	1. 是BST，左子樹都比自己小、右子樹都比自己大
	2. 根是黑
	3. 每個葉節點(NIL)是黑
	4. 紅節點的兩個小孩都是黑
	5. 從任一節點到其下方每一個 NIL,經過的黑節點數目相同
4. 結論，
	1. 黑高 b ，內部節點數介於 2^b - 1(完美二元樹，沒有紅節點) ~ 2^2b - 1(要盡可能添加紅節點，黑紅交替)
	2. 給定 N 個節點，紅黑樹的最大高度為 2log_2 N
	3. b <= h <= 2b
	4. 只算內部節點時，黑比紅多是錯的，因為紅色最多可達到黑色的 2 倍
5. 插入規則
	1. 按照BST的插入規則，由根往下找，放到正確位置。
		新節點一律是「紅色 (R)」。
	2. 發生連續兩個紅色 (Double Red) 時，先看「叔叔的顏色」：
	🛑 狀況一：叔叔是紅色： 
		1. 爸叔變黑，爺變紅。
		2. 然後把「爺爺」當成新的當前節點，繼續往上檢查。
		(因為紅黑樹的規則，不能父子都是紅，變成紅色很危險，需要檢查)
	⚫ 狀況二：叔叔是「黑色」 (或 NIL) 
		1. 抓出「爺、爸、孫」三個關鍵節點。
		2. 把中位數提拔當新老大。
		3. 新老大塗成「黑色」，底下的兩個小孩塗成「紅色」。
		4. 安置孤兒：從第三步驟的「新老大」開始 由上 至下，找到孤兒的位置 (比大小)
			孤兒的孩子，整包一起跟著走，顏色都不用動。
