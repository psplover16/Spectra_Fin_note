暫存器
PC(程式計數器)：存放「下一道」準備執行指令的記憶體位址。
IR(指令暫存器)：存放目前正在執行的指令。
Base Register(基底暫存器)：存放程式記憶體區段起始位址。
Limit Register(界限暫存器)：存放程式可用區段"大小"。  d = limit 即為超界
MAR(記憶體位址暫存器)：存放 CPU 當前正要存取的「記憶體位址」。內部與 CPU 相連，外部對應連接「位址匯流排 (Address Bus)」
MDR(記憶體資料暫存器)：暫時存放剛從記憶體讀出、或準備寫入記憶體的「資料或指令」。外部對應連接「資料匯流排 (Data Bus)」；又常被稱為 MBR (記憶體緩衝暫存器)。
Flag Register(旗標暫存器)：記錄運算結果狀態(如零、進位、溢位)。
AC(累加器)：暫存ALU運算的中間或最終結果。


機器指令：CPU 直接看得懂的二進位命令
指令週期流程： 取指令(Fetch) ➔ 解碼(Decode) ➔ 取運算元／算位址(Operand Fetch / Address Calculation) ➔ 執行(Execute) ➔ 寫回(Write Back / Store)
也就是 拿單 ➔ 看懂 ➔ 拿料 ➔ 下鍋 ➔ 裝盤

Opcode：要執行的操作
Operand：被操作的資料、暫存器或位置
Effective Address：真正要存取的記憶體位置

取指令：
依據 PC(程式計數器) 的位址透過 MAR(記憶體位址暫存器) 去記憶體抓取指令
PC 自動遞增以指向下一筆指令
把記憶體抓取到的指令，經由 MDR(記憶體資料暫存器) 存入 IR(指令暫存器) 中等待處理

算位址：Control Unit(控制單元)會對 IR 內的指令進行解碼，並計算出運算元真實存放的有效位址（EA）
拿資料：將此 EA 再次透過 MAR 尋址，從記憶體把真正的運算資料抓回 MDR
最後，ALU 進行運算。

Pipeline 固定五步驟，
IF (Instruction Fetch)：取指令。
ID (Instruction Decode)：指令解碼，並讀取暫存器。
EX (Execute)：ALU 執行運算，或計算有效位址 (EA)。
MEM (Memory Access)：存取主記憶體資料 (Load/Store)。
WB (Write Back)：將結果寫回暫存器。

執行時間公式（假設 n 個指令、k 個階層、週期時間 t）：
非管線化總時間 = n * k * t
管線化總時間 = (k + n - 1) * t

管線化三大危險 (Hazards)：
結構危險 (Structural Hazard)：硬體資源不足
解法：
1. 採用哈佛架構 (Harvard Architecture)，將指令快取與資料快取實體分離。
2. 若無哈佛架構，只能插入氣泡暫停 (Stall)。

資料危險 (Data Hazard)，指令間存在相依性。後續指令需要前面指令「尚未寫回暫存器」的資料（即 RAW 相依）。
解法，
1. 前饋機制 (Forwarding / Bypassing)。不寫回暫存器，直接從 ALU 將運算結果拉線給下一個指令。
2. 要特別注意，當 LOAD 指令後面「緊接」需要該資料的指令時，即使有前饋機制，仍必須強制暫停 (Stall) 1 個週期。

控制危險 (Control Hazard)，遇到分支跳躍指令 (Branch) 時，CPU 不確定下一道指令的位址，導致抓錯指令。
1. 分支預測，搭配分支目標緩衝器 (BTB)，記住上次跳躍的目標位址，直接抄捷徑免重新計算。
只要分支預測猜錯，管線必須將提早拿進來的錯誤指令全部沖刷 (Flush) 作廢。
2. 分支延遲槽, Delay Slot，編譯器刻意在分支指令後方，放入「無論有沒有跳躍都必須執行」的指令，以榨取管線效能。

CPU 排班器：短程排班
1. 最佳化目標：最大化CPU使用率與產能；最小化等待、迴轉與回應時間。
3. 就緒佇列（Ready Queue）：已到達、等 CPU 的隊伍。
4. 到達時間（Arrival Time）：程序進入就緒佇列的"時間點"。
5. 完成時間 (Completion Time)：行程全部做完、離開系統的"時間點"。

6. 執行時間（Burst Time）：程序實際需要佔用 CPU 運算的"總時間"。
7. 迴轉時間(Turnaround Time)：待在系統內的總時間。
	完成時間 - 到達時間
	等待時間 + 執行時間
8. 等待時間 (Waiting Time)：程序於就緒佇列中，等待獲取CPU分配的總累積時間。
	迴轉時間 - 執行時間
9. 回應時間(Response Time)：從到達開始，「第一次拿到 CPU 開始做事」的時間差。為分時系統衡量互動性的關鍵指標
	首次獲取CPU時間 - 到達時間

分時系統：強調讓使用者覺得電腦「同時」在處理很多事，且能即時互動。例如 windows及mac

在 "就緒 (Ready)" 會觸發的排班，就是可搶占。
0. 護航效應 (Convoy Effect)，容易因為超長程序排在前面，而造成堵塞。
1. FCFS 先到先、不可搶占、會有護航效應
2. SJF 最短工作優先、不可搶占、無法預知、飢餓：短程序一直占用，長程序輪不到
3. SRTF 最短剩餘時間優先，SJF的可搶占版本、只要新來程序所需時間 < 目前程序的剩餘時間，觸發搶占。、輪番搶占，上下文成本變高、仍有飢餓
4. Priority (優先權)，搶占、不可搶占都有。優先權高先做，SJF是優先權的一員，Burst越短 = 優先權越高、飢餓、老化：逐漸提高優先權
5. Round Robin 輪轉法 (RR)，可搶占，給每個程序固定時間量子、太大：FCFS、太小：上下文切換成本提高
6. Highest Response Ratio Next 最高響應比優先：不可搶佔
7. MLQ 多層佇列 (Multilevel Queue)：可搶占，程序分層，但不可跨層移動。優先權高的分類會先跑，當優先權最高的分類層是空的，才輪的到優先權次高的分類層，低層佇列發生飢餓機率極高。
8. MLFQ 多層回饋佇列 (Multilevel Feedback Queue)：可搶占，可跨層移動。程序若耗盡時間量子則降級，若等待過久則觸發老化機制升級。

死結：
條件：互斥、持有並等待、不可搶占、循環等待
策略：預防(透過靜態限制破壞條件，效能差)、避免(允許條件存在，但在執行前或執行中事先宣告最大資源需求，進行動態評估)、偵測復原、鴕鳥

銀行家演算法：
0. 算出 各程序的 Need (需求) = Max (最多需要) - Allocation (已借出) 以及需要知道 Available (目前庫存)。
1. 安全性演算法 (找安全序列)，拿 Available (庫存) 去與 各程序的 Need (需求) 比較。可以滿足地就執行，然後回收資源。
2. 資源請求演算法 (動態審核)：專門用在「某個程序在執行過程中(p0)」，突然要求資源
 2-1. 申請量 不超過 當初說的最大需求
 2-2. 目前有足夠的資源可以提供
 2-3. 滿足2-1與2-2，試配置後再跑安全演算法。系統「假裝」答應 p0的要求，然後更新帳本。(p0的Allocation增加、p0需求減少、新的 Available減少)



陣列與線性資料結構
二維陣列：
	A[3][4] 索引從 0開始， 3 列 4 行
	A[2..4][3..5]，表示列是從 2 ~ 4，但行3 ~ 5
動態陣列，本質上還是鎮列，只是資料塞滿記憶體，系統會再找其另一塊2倍大的連續空間
鏈結陣列 Linked List
	執行期，才配置記憶體，不浪費空間、不溢位
	耗費空間較大，因為除了資料，還需要儲存指標
	插入、刪除 BIGO(1)、走訪、存取 BIGO(n)
堆疊 Stack，LIFO，後進先出
	push放入、pop取出、peek檢查
	應用於 括號配對檢查、遞迴、 算術表示式轉換：中序轉後序、中序轉前序
佇列 (Queue)，FIFO，先進先出
	有兩個指標 Rear及Front，分別指向要準備 加入、刪除資料的記憶體位置
	Rear (尾端)：只負責加入資料 (該動作是 Enqueue)
	Front (前端)：只負責拿出/刪除資料 (該動作是 Dequeue) 
環狀佇列，
	佇列空：Front == Rear。
	佇列滿：只要 Rear 再走一步就撞到 Front，就強制喊停。 (Rear + 1) mod MaxSize == Front。 
	所以會少最後一個陣列可以用
雙向佇列（Deque），前後兩端都可以進行插入 (Insert) 與刪除 (Delete) 動作。





分頁與分段記憶體管理
MMU (Memory Management Unit, 記憶體管理單元)：一個硬體，負責在程式執行時，將邏輯位址即時轉換為實體位址。
邏輯位址 / 虛擬位址：程式自己看到的位址，從 0 開始編。程式以為自己獨佔整片連續的記憶體。
實體位址：資料真正放在實體記憶體 (RAM) 上的位址。
內部碎裂，分配給程式的記憶體空間大於其實際需求，導致區塊內部有沒用到的剩餘空間
外部碎裂，記憶體中總剩餘空間足夠，但因為空間不連續（被切得太零碎），導致無法分配給需要大連續空間的程式。


分頁系統，把記憶體切成 固定大小，有內部碎裂
	頁表 (Page Table)：單純頁 框 對應
	邏輯位址、實體位址格式相同  [ 頁號 p | 頁內偏移 d ]
	實體位址 = 框號 * 框大小 + 偏移 d
	位址翻譯，1. 算出邏輯位址的偏移是第幾位 
		  2. 頁表算出對應框號 
		  3. 頁內偏移照抄
	偏移 bits (offset)：由「頁大小（或頁框大小）」決定，若大小為 2^n bytes，則偏移為 n bits。
	頁號 bits：用來決定邏輯空間裡總共有多少頁
	框號 bits：用來決定實體 RAM 裡總共有多少框
	TLB，一塊極快的小快取，專門存「最近用過的 頁號 ➔ 頁框號」對照。
	有效存取時間 (EAT) = 命中率 * 命中所需時間(讀資料 + 查TLB) + 未命中率 * 未命中所需時間(讀資料 + 讀頁表 + 查TLB)


分段系統，是使用者/設計師的觀點。依照程式模組切割，每一塊大小不一樣、外部碎裂	
	段表，Base 與 Limit構成，Base 表示起始位置、Limit表示該段的 長度
	邏輯位址 格式 [ 段號 s | 段內偏移 d ]
	位址翻譯，
		1. 先檢查 段內偏移 必須小於 段表 標註的 Limit
		2. 再將 段表對應的 基礎位址加上邏輯位址的 段內偏移加總，就是實體記憶體位置
	緊縮，可動態重定位的程式，用大量的系統資源 使其緊密告再一起，解決外部碎裂。


段頁式記憶體管理
	邏輯切斷，每一段在切很多同等的頁，再把每一頁分別塞入frame。 有內部碎裂
	邏輯位址 = [ 段號 s | 頁號 p | 頁內偏移 d ]
	極度依賴 TLB，因為要多查表
	實體位址 = 框號 * 框大小 + 偏移 d		
	翻譯步驟：
		利用段號，查詢段表，找到對應頁表。但要檢查頁表長度是否 小於 頁號P
		利用頁表，查到 實體框號
		實體框號 * 框大小 + 偏移 d = 實體位址



Thrashing (震盪 / 輾轉現象)，系統花費在「硬碟與記憶體之間搬移頁面 (Page in/out)」的時間，遠大於「CPU 實際執行程式」的時間。
原因：實體記憶體總容量 < 所有執行中程式的基本需求總和。

CPU 誤判連鎖反應（必考因果順序）
	1. 起因：程式太多，Frame 不夠用，開始頻繁發生 Page Fault。
	2. 現象：頻繁的 Page in / Page out (記憶體與硬碟之間瘋狂搬移資料) CPU 必須一直等待，導致 CPU 使用率急遽下降。
	3. OS 誤判：作業系統（CPU 排班器）看到 CPU 很閒，以為系統負載太低。
	4. 致命錯誤：OS 決定提高「多元程式等級 (Degree of Multiprogramming)」，載入更多新程式進來跑。
	5. 結果：每個程式分到的 Frame 更少，Page Fault 更嚴重，系統徹底癱瘓。
解除 Thrashing 的根本方法
	1. 降低多元程式等級（減少 程式多工）。
	2. 增加實體記憶體 (RAM) 容量。
預防方法
	1. 工作集模型 (Working Set Model)
		1. 基於區域性原理
		2. 追蹤過去存取頁面的歷史紀錄
		3. 算出所有程式的總需求 Frame
		4. 如果大於 (>) 系統實體記憶體的總供給 Frame，代表不夠分，則必須暫停部分程序。
		5. 因為 要求系統必須無時無刻盯著每一個 Process，系統負擔極高
	2. 分頁錯誤頻率 (PFF)
		1. 依據程式發生 Page Fault 的次數頻率
		2. 為每個程式設定缺頁頻率的「上限 (Upper Bound)」與「下限 (Lower Bound)」
		3. 只有當程式「發生缺頁 (Page Fault) 時」系統才介入計算頻率
		4. 頻率大於 (>) 上限，代表 Frame 不夠用，必須增加分配；如果小於 (<) 下限，則回收沒收多餘的 Frame。
		5. 只有出錯 (缺頁) 時系統才需要花心力處理，系統負擔極低，更適合實務應用。
