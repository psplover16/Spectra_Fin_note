# 死結 (Deadlock) — 考試精簡版

> 考前衝刺用。必要條件 → 策略比較 → 銀行家範例 → 高頻考點 → 選擇題。

---

## 一、死結的四個必要條件(中英文 + 解釋)

四個條件必須**同時成立**才會死結,破壞任一個就不會發生。

| 條件 | English | 解釋 |
|---|---|---|
| **互斥** | Mutual Exclusion | 資源一次只能一個程序用,不能共用。 |
| **持有並等待** | Hold and Wait | 抓著手上資源不放,同時又在等別的資源。 |
| **不可搶占** | No Preemption | 資源不能被強行搶走,只能由持有者自願釋放。 |
| **循環等待** | Circular Wait | 等待關係繞成一個環(A 等 B、B 等 C、C 等 A)。 |

---

## 二、四種策略總比較(考前掃這張)

| 策略 | 死結會發生嗎 | 需要事先知道最大需求? | 代表方法 | 特點 |
|---|---|---|---|---|
| 預防 Prevention | 不會 | 否 | 破壞四條件(如資源排序) | 保守、利用率低 |
| 避免 Avoidance | 不會 | **要** | 銀行家演算法 | 動態判斷、需最大需求 |
| 偵測復原 Detection | 會(再解) | 否 | 等待圖 / 偵測演算法 | 事後處理、有開銷 |
| 鴕鳥 Ostrich | 會(不理) | 否 | 不處理 | 真實 OS 常用 |

## 三、安全狀態 + 銀行家演算法(一個題目跑到底)

5 個程序 (P0～P4),3 種資源 (A、B、C)。

**Allocation(已配置)**

| 程序 | A | B | C |
|---|---|---|---|
| P0 | 0 | 1 | 0 |
| P1 | 2 | 0 | 0 |
| P2 | 3 | 0 | 2 |
| P3 | 2 | 1 | 1 |
| P4 | 0 | 0 | 2 |

**Max(最大需求)**

| 程序 | A | B | C |
|---|---|---|---|
| P0 | 7 | 5 | 3 |
| P1 | 3 | 2 | 2 |
| P2 | 9 | 0 | 2 |
| P3 | 2 | 2 | 2 |
| P4 | 4 | 3 | 3 |

**Available(可用)**:A=3、B=3、C=2

### 步驟一:Need = Max − Allocation

| 程序 | A | B | C |
|---|---|---|---|
| P0 | 7 | 4 | 3 |
| P1 | 1 | 2 | 2 |
| P2 | 6 | 0 | 0 |
| P3 | 0 | 1 | 1 |
| P4 | 4 | 3 | 1 |

### 步驟二:安全演算法(找安全序列)

Work = Available =(3,3,2)。反覆找「Need ≤ Work」的程序,跑完把它的 Allocation 加回 Work:

- **P1**:Need(1,2,2)≤(3,3,2) ✔ → Work =(3,3,2)+(2,0,0)=**(5,3,2)**
- **P3**:Need(0,1,1)≤(5,3,2) ✔ → Work =(5,3,2)+(2,1,1)=**(7,4,3)**
- **P0**:Need(7,4,3)≤(7,4,3) ✔ → Work =(7,4,3)+(0,1,0)=**(7,5,3)**
- **P2**:Need(6,0,0)≤(7,5,3) ✔ → Work =(7,5,3)+(3,0,2)=**(10,5,5)**
- **P4**:Need(4,3,1)≤(10,5,5) ✔ → Work =(10,5,5)+(0,0,2)=**(10,5,7)**

全部跑完 → **安全狀態**。安全序列 **<P1, P3, P0, P2, P4>**(可能不只一條)。

### 步驟三:資源請求演算法(該不該答應)

**P1 請求 Request =(1,0,2)**,三步檢查:

1. **Request ≤ Need(P1)?**(1,0,2)≤(1,2,2) ✔
2. **Request ≤ Available?**(1,0,2)≤(3,3,2) ✔
3. **試配置後再跑安全演算法**:
   - Available =(3,3,2)−(1,0,2)=(2,3,0);Allocation(P1)=(3,0,2);Need(P1)=(0,2,0)
   - Work=(2,3,0)→P1✔→(5,3,2)→P3✔→(7,4,3)→P0✔→(7,5,3)→P2✔→(10,5,5)→P4✔→(10,5,7)
   - 仍安全 → **答應請求**。

> 口訣:Request 先 ≤ Need、再 ≤ Available,最後試配置跑安全演算法;任一步不過就拒絕(讓它等)。

## 四、高頻考點速記

- 破壞任一條件 → 不會死結;破壞**循環等待(資源編號依序請求)**最實用。
- RAG:**無環 → 無死結**;有環且**單一 instance → 必死結**;有環且**多 instance → 不一定**。
- **安全 → 一定無死結;不安全 → 可能死結。**
- 偵測:單一 instance 用**等待圖 (RAG)**,有環即死結。
- 復原:**終止程序** 或 **資源搶占(可能 rollback)**。
- 鴕鳥策略 = 不理它,**UNIX/Windows 實務上常用**。

### 解答與解析

| 題 | 答 | 解析 |
|---|---|---|
| 1 | **D** | 必要條件是「不可搶占」,不是「可搶占」;可搶占反而會破壞死結。 |
| 2 | **C** | 四條件必須同時成立,缺一不可。 |
| 3 | **B** | 銀行家演算法是死結「避免」的代表方法。 |
| 4 | **C** | 無環 → 一定無死結(絕對);有環則不一定(看 instance)。 |
| 5 | **A** | 單一 instance 時,有環就一定死結。 |
| 6 | **B** | Need = Max − Allocation。 |
| 7 | **C** | 安全 → 一定無死結;不安全才「可能」死結。 |
| 8 | **D** | 資源排序、依序請求是為了破壞循環等待。 |
| 9 | **B** | 只有「避免」(銀行家)需要事先知道最大需求。 |
| 10 | **C** | 死結罕見、處理成本高,實務上多用鴕鳥策略。 |
| 11 | **B** | 單一 instance 用等待圖,有環即死結。 |
| 12 | **B** | 復原靠終止程序或搶占資源。 |
| 13 | **B** | Available=12−(5+2+2)=3;Need:P0=5、P1=2、P2=7。Work=3→P1(2)✔→5→P0(5)✔→10→P2(7)✔→12,安全,序列 <P1,P0,P2>。 |
| 14 | **B** | 預防=靜態破壞必要條件;避免=執行時動態判斷是否安全。 |
| 15 | **B** | 循環等待=等待關係繞成一個環,不等於「兩個程序互等」也不等於持有並等待。 |
