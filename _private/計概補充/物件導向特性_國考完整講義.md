# 物件導向特性 — 國考完整講義

> 這份講義假設你**完全沒基礎**。
> 順序是「為什麼有物件導向 → 類別與物件 → 四大特性逐一講 → 最愛考的分辨題(覆寫vs多載、抽象類別vs介面) → 考點 → 選擇題」。
> 因為國考考**選擇題**,每段最後都有「★ 常考重點」。這個主題是**觀念題**,沒有計算,重點在「定義清楚、分辨乾淨」。

---

## 一、先定位:為什麼有物件導向

早期的**程序導向 (Procedural)** 寫法,把「資料」和「處理資料的函式」**分開放**。程式一大就出問題:資料到處被不同函式亂改、難維護、難重用。

**物件導向 (Object-Oriented, OO)** 換個思路:把「**資料 + 操作這些資料的方法**」**綁在一起**,包成一個個「物件」,就像真實世界的東西(一台車有它的屬性,也有它能做的動作)。這樣更好維護、更安全、更能重複利用。

而「四大特性」就是達成這些好處的手段:**封裝**保護資料、**繼承**重複利用、**多型**增加彈性、**抽象**管理複雜度。

**★ 常考重點**:OO 相對於程序導向,核心差別是「**把資料與方法封裝在物件中**」,以物件為中心。

---

## 二、最基本:類別 (Class) vs 物件 (Object)

這是整個主題的地基,先分清楚。

- **類別 (Class)**:**設計藍圖、模子**。它定義「這種東西有哪些屬性、能做哪些動作」,但它本身不是實體。
- **物件 (Object)**:用類別**做出來的實體**,也叫**實例 (Instance)**。

比喻最好懂:

> **類別 = 餅乾模子**;**物件 = 用模子壓出來的一塊塊餅乾**。一個模子(類別)可以壓出很多餅乾(很多物件),每塊餅乾口味可以不一樣(屬性值不同),但形狀都一樣(都來自同個類別)。

類別裡有兩種東西:

- **屬性 (Attribute) / 欄位 (Field)**:物件的「資料」,例如車子的顏色、車速。
- **方法 (Method)**:物件能做的「動作」,例如車子的加速、煞車。

**★ 常考重點**:物件是類別的**實例 (instance)**;一個類別可產生多個物件。類別是抽象定義,物件是具體實體。

## 三、四大特性總覽(先記名字)

| 特性 | English | 一句話 |
|---|---|---|
| **封裝** | Encapsulation | 把資料包起來、藏細節,只露必要介面 |
| **繼承** | Inheritance | 子類別重用父類別的東西,再加自己的 |
| **多型** | Polymorphism | 同一個方法名,不同物件有不同表現 |
| **抽象** | Abstraction | 抓重點、隱藏細節,只看該看的 |

**★ 超常考的陷阱**:
- 講「**三大特性**」時,標準答案是 **封裝、繼承、多型**。
- 講「**四大特性**」時,再加上 **抽象**。
- 看題目問三大還是四大,別選錯!

## 四、封裝 (Encapsulation)

### 是什麼

封裝做兩件事:(1) 把「資料 + 方法」**包在一起**成為一個類別;(2) 把內部細節**藏起來**,只對外開放必要的操作介面——這第二點就是**資訊隱藏 (Information Hiding)**。

比喻:

> **遙控器**。你只會按按鈕(對外的公開方法),完全不需要知道裡面的電路怎麼運作(被隱藏的內部細節)。或想成**藥膠囊**:藥粉包在裡面,你只管吞,不用直接碰。

### 怎麼做到:存取修飾子 (Access Modifier)

用「存取權限」控制誰能碰:

| 修飾子 | 可存取範圍 |
|---|---|
| **public** | 任何地方都能存取 |
| **protected** | 同類別 + 子類別(+同套件) |
| (default) | 同套件 |
| **private** | **只有同類別內**能存取 |

小例子(把餘額藏起來,只能透過方法操作):

```
class BankAccount {
    private int balance;               // 私有:外部不能直接亂改
    public void deposit(int amount) {  // 公開介面
        if (amount > 0) balance += amount;   // 方法裡可加檢查
    }
    public int getBalance() { return balance; }
}
```

`balance` 設成 private,外面就**不能** `account.balance = -999` 亂搞,只能呼叫 `deposit()`,而方法裡能加「金額要 > 0」的檢查保護資料。

### 目的

保護資料不被亂改、降低各部分的**耦合**,改內部實作也不影響外部使用者。

**★ 封裝常考重點**:封裝 ≈ **資訊隱藏**;用 **private** 把屬性藏起來,提供 public 方法(getter/setter)存取。目的是**保護資料、降低耦合**。

## 五、繼承 (Inheritance)

### 是什麼

讓一個新類別**直接擁有**既有類別的屬性和方法,不必重寫,還能再加自己的或修改。

- 被繼承的叫**父類別 / 超類別 (Superclass / Parent)**。
- 繼承的叫**子類別 (Subclass / Child)**。

比喻:

> 「**動物 → 狗 → 拉布拉多**」。狗自動擁有動物的共同特徵(會呼吸、會移動),再加自己的(會汪汪叫);拉布拉多又繼承狗的一切,再加自己的。**越下層越特化。**

### is-a vs has-a(常考分辨)

- **繼承 = is-a 關係**:「狗**是一種**動物」(Dog is-a Animal)→ 用繼承。
- **組合 (Composition) = has-a 關係**:「車**有一個**引擎」(Car has-a Engine)→ 不是繼承,是把引擎物件放進車裡。

別把「有一個」硬寫成繼承——這是經典觀念題。

### 單一繼承 vs 多重繼承

- **單一繼承**:一個子類別只繼承一個父類別。
- **多重繼承**:一個子類別繼承多個父類別。**C++ 支援;Java 不支援(類別)**,Java 改用「實作多個介面」來達到類似效果(後面講)。

### 目的

**程式碼重用 (Reusability)**,減少重複,好維護好擴充。

**★ 繼承常考重點**:子類別繼承父類別 = **is-a**;has-a 要用**組合**。**Java 不支援類別多重繼承**(用介面替代),C++ 支援。繼承的好處是**重用**。

## 六、多型 (Polymorphism)

### 是什麼

「多型」= 多種型態。**同一個方法名稱(同一個訊息),套在不同物件上,會有不同的行為。**

比喻:

> 你對不同動物都下同一個命令「**叫**」(`sound()`):狗回你「汪汪」、貓回你「喵喵」、牛回你「哞哞」。**命令一樣,反應因物件而異**,這就是多型。

它讓你能用「統一的方式」操作一群不同的物件,程式更有彈性、好擴充(新增一種動物,呼叫端不用改)。

### 多型的兩種實現(這裡是重災區)

#### （一）多載 / 重載 (Overloading)——編譯期多型

**同一個類別裡**,有多個**同名**方法,靠**參數不同**(個數、型別、順序)來區分:

```
class Calculator {
    int add(int a, int b)          { return a + b; }
    double add(double a, double b) { return a + b; }
    int add(int a, int b, int c)   { return a + b + c; }
}
```

三個都叫 `add`,但參數不同。**編譯時**就能依參數決定呼叫哪一個(靜態繫結)。**跟繼承無關。**

#### （二）覆寫 (Overriding)——執行期多型

**子類別把父類別「已經有」的方法,重新定義一次**(方法簽章**完全相同**),藉此改變繼承來的行為:

```
class Animal {
    void sound() { System.out.println("某種叫聲"); }
}
class Dog extends Animal {
    void sound() { System.out.println("汪汪"); }   // 覆寫
}
```

`Dog` 的 `sound()` 把 `Animal` 的蓋掉。**執行時**才依物件「實際的型別」決定叫哪個(動態繫結)。**這才是真正實現多型的方式**,需要**繼承**。

**★ 多型常考重點(必考)**:
- **多載 (Overload)**:同名、**參數不同**、同類別、**編譯期**、與繼承**無關**。
- **覆寫 (Override)**:同名、**參數完全相同**、子類別改父類別、**執行期**、**需要繼承**,是多型的實現。
- 一句話分:**「載」看參數(Overload),「寫」看繼承(Override)。**

## 七、抽象 (Abstraction)

### 是什麼

只保留「**重要的、共通的特徵**」,把不必要的細節隱藏起來,讓你專注在「該關心的層次」。

比喻:

> 你**開車**只要會操作方向盤、油門、煞車(抽象出來的介面),完全不用懂引擎內部燃燒、變速箱齒輪怎麼運作。抽象就是「給你一個簡單好用的介面,把複雜細節藏在後面」。

### 怎麼做:抽象類別 vs 介面

這是用來「規範共同行為」的兩種工具,差別很常考:

- **抽象類別 (Abstract Class)**:
  - 可以**同時有「已實作的方法」和「抽象方法(只宣告、沒實作)」**。
  - **不能被實例化**(不能 `new` 出抽象類別的物件)。
  - 子類別用 **extends 繼承**,並補上抽象方法的實作。
  - 一個類別**只能繼承一個**抽象類別(單一繼承)。

- **介面 (Interface)**:
  - (傳統定義)**只有方法的宣告,沒有實作**,是「純規範」。
  - 類別用 **implements 實作**它。
  - 一個類別**可以同時實作多個介面** → 這就是 Java 用來達到「類似多重繼承」的方法。
  - (補充:Java 8 後介面可有 default method,但國考多以傳統定義出題。)

**★ 抽象常考重點**:抽象類別**可含已實作方法**、只能**繼承一個**;介面**(傳統)全是宣告**、可**實作多個**。兩者**都不能被實例化**。

---

## 八、其他重要名詞(眼熟一下)

- **建構子 (Constructor)**:物件被 `new` 出來時自動執行的特殊方法,用來初始化屬性。名稱通常與類別同名、沒有回傳值。
- **訊息傳遞 (Message Passing)**:物件之間透過「呼叫對方的方法」來互動,就叫送訊息。
- **多載 vs 覆寫**(上面講過,務必分清)。

## 九、覆寫 vs 多載(超高頻對照表,務必背)

| 比較項 | 多載 Overload | 覆寫 Override |
|---|---|---|
| 方法名稱 | 相同 | 相同 |
| 參數 | **不同**(個數/型別/順序) | **完全相同** |
| 發生位置 | 同一類別內 | 子類別 vs 父類別 |
| 需要繼承? | **不需要** | **需要** |
| 繫結時機 | 編譯期(靜態) | 執行期(動態) |
| 對應多型 | 編譯期多型 | 執行期多型(真多型) |

**口訣**:**多載比參數、覆寫靠繼承;載在編譯期、寫在執行期。**

---

## 十、抽象類別 vs 介面(高頻對照表)

| 比較項 | 抽象類別 Abstract Class | 介面 Interface |
|---|---|---|
| 方法內容 | 可含已實作 + 抽象方法 | (傳統)只有宣告,無實作 |
| 能否實例化 | **否** | **否** |
| 關鍵字 | extends(繼承) | implements(實作) |
| 數量 | 只能繼承**一個** | 可實作**多個** |
| 主要用途 | 共用部分實作 + 規範 | 純規範行為、達成類似多重繼承 |

## 十一、高頻考點速記(直接背)

- OO 三大特性:**封裝、繼承、多型**;四大特性再加**抽象**。
- **類別 = 藍圖**,**物件 = 實例 (instance)**;一個類別可生多個物件。
- 封裝 ≈ **資訊隱藏**;用 **private** 藏資料、public 方法存取,目的是保護資料、降耦合。
- 存取權限大小:**public > protected > (default) > private**;private 只限同類別。
- 繼承 = **is-a**;has-a 用**組合**。**Java 不支援類別多重繼承**,用介面替代;C++ 支援。
- 多型:**多載(Overload)= 同名不同參數、編譯期、不需繼承**;**覆寫(Override)= 同簽章、執行期、需繼承**,是真正的多型。
- 抽象類別**可含已實作方法**、**extends**、只能繼承一個;介面**(傳統)全宣告**、**implements**、可實作多個;兩者都**不能實例化**。
- 建構子:`new` 物件時自動執行,負責初始化。
