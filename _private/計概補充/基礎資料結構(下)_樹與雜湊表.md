## 六、樹 (Tree)

### 基本術語

**階層式(一對多)結構**:資料呈一層一層的父子關係。幾個基本名詞:

- **根 (Root)**:最上面、**沒有父節點**的那個節點,是整棵樹的入口。
- **葉節點 (Leaf,又叫終端節點)**:**沒有任何子節點**的節點(即**分支度 = 0**),也就是樹最末端、往下再沒有東西的點。
- **內部節點 (Internal Node)**:**有**子節點的節點(即非葉節點)。
- **分支度 (Degree)**:一個節點的子節點數。
- **階層 (Level)**:某個節點位在第幾層(根通常算第 1 層),講的是「**單一節點**」的深度。
- **高度 (Height)**:從根到最深葉節點的**最長路徑**,講的是「**整棵樹**」的最大深度。
- (Level 是單一節點的、Height 是整棵樹的,兩者不同,別混用。)
- 重要性質:**n 個節點的樹有 n − 1 條邊 (edge)**。

拿後面走訪用的那棵樹來實際標一次:

```
              A        ← 第 1 層（根 root）
            /   \
          B       C    ← 第 2 層
         / \
        D   E          ← 第 3 層（最深）
```

- **分支度 (Degree)** = 一個節點有幾個子節點:
  - A 有 B、C 兩個 → 分支度 **2**;B 有 D、E 兩個 → 分支度 **2**。
  - C、D、E 沒有子節點 → 分支度 **0**(分支度 0 的就是**葉節點 leaf**)。
  - (整棵樹的分支度 = 所有節點裡最大的 = **2**,所以它是「二元樹」。)
- **階層 (Level)** = 某節點在第幾層:A 在第 **1** 層;B、C 在第 **2** 層;D、E 在第 **3** 層。
- **高度 (Height)** = 從根到最深葉的最長路徑(整棵樹的最大深度):這棵最深到第 3 層 → 高度 **3**(用「層數」算);若改用「邊數」算(A→B→D 共 2 條邊)則為 **2**。

一句話:**分支度看「一個節點有幾個小孩」、階層看「某節點在第幾層」、高度看「整棵樹最深幾層」。**(這棵 5 個節點、4 條邊,符合 n−1。)

### 二元樹 (Binary Tree)

每個節點**最多 2 個子節點**。常見種類(**Full 與 Perfect 的差別最愛考,務必分清**):

- **歪斜樹 (Skewed)**:每個節點**最多只有 1 個**子節點(整棵樹沒有分岔),全往一邊長,退化成像鏈結串列。分左歪斜、右歪斜。→ BST 的最壞情況。
- **完滿二元樹 (Full / 嚴格二元樹)**:每個節點**要嘛 0 個、要嘛 2 個**子節點(**不准只有 1 個**)。注意:**它不要求每層填滿**,只要求「沒有只帶一個小孩的節點」。
- **完美二元樹 (Perfect)**:**每一層都完全填滿**、所有葉節點都在**同一層** → **共 h 層時有 2ʰ − 1 個節點**(h 指層數;若題目把高度定義成邊數,同一棵樹改用 2^(h+1) − 1)。
- **完整二元樹 (Complete)**:除最後一層外都滿,最後一層**由左往右填**(這是 **heap 堆積**的形狀)。

**Full vs Perfect 用圖看**:

```
完滿 Full(但不完美)            完美 Perfect
        A                          A
       / \                        / \
      B   C                      B   C
     / \                        / \ / \
    D   E                      D  E F  G

每個節點都 0 或 2 個小孩 ✓      每層都填滿、葉子同一層 ✓
但 C 那層沒填滿 → 不是完美      (它同時也是 Full)
```

- 左邊每個節點都「0 或 2 個小孩」→ 是 **Full**;但沒填滿、葉子不同層 → **不是 Perfect**。
- **關係:完美 ⊂ 完滿**(完美一定是完滿,完滿不一定完美);`2ʰ − 1` 這公式**只對完美成立**。

| 類型 | 定義 | 重點 |
|---|---|---|
| 歪斜 Skewed | 每節點最多 1 個子節點 | 退化成串列,最壞情況 |
| 完滿 Full | 每節點是 **0 或 2** 個子節點 | **不要求每層填滿** |
| 完美 Perfect | 每層填滿、葉子同層 | h 層共 **2ʰ − 1** 個節點 |
| 完整 Complete | 除最後層外都滿,最後層由左往右填 | **heap 的形狀** |

### 二元樹的重要性質與公式(填空/選擇常考)

- **第 i 層最多有 2^(i-1) 個節點**(根為第 1 層)。例:第 3 層最多 2² = 4 個。
- **高度(層數)h 的二元樹,最多有 2ʰ − 1 個節點**(填滿就是完美二元樹)。
- **n 個節點的完整二元樹,高度 = ⌊log₂n⌋ + 1 層**。
- **葉節點數 = 分支度為 2 的節點數 + 1**,即 **n₀ = n₂ + 1**(超常考的公式)。
  - 驗證前面那棵樹:葉節點 C、D、E 共 3 個(n₀=3),分支度 2 的節點 A、B 共 2 個(n₂=2)→ 3 = 2 + 1 ✓。

### 二元樹走訪 (Traversal)（最高頻,務必會)

四種走訪順序:

- **前序 Preorder**:**根 → 左 → 右**(N-L-R)
- **中序 Inorder**:**左 → 根 → 右**(L-N-R)
- **後序 Postorder**:**左 → 右 → 根**(L-R-N)
- **層序 Level-order**:一層一層由上而下

用這棵樹示範:

```
        A
       / \
      B   C
     / \
    D   E
```

| 走訪 | 口訣 | 順序 |
|---|---|---|
| 前序 | 根左右 | **A B D E C** |
| 中序 | 左根右 | **D B E A C** |
| 後序 | 左右根 | **D E B C A** |
| 層序 | 一層層 | **A B C D E** |

(推導前序:先根 A → 進左子樹 B(B→D→E)→ 再右子樹 C → A B D E C。其餘同理,差別只在「根」放在左、中、右哪個位置念。)

**走訪的遞迴程式**(三種幾乎一樣,差別只在 `print` 擺哪個位置):

```java
void preorder(Node n) {   // 根左右
    if (n == null) return;
    print(n.data);            // ← 印在最前(根)
    preorder(n.left);
    preorder(n.right);
}
void inorder(Node n) {    // 左根右
    if (n == null) return;
    inorder(n.left);
    print(n.data);            // ← 印在中間(根)
    inorder(n.right);
}
void postorder(Node n) {  // 左右根
    if (n == null) return;
    postorder(n.left);
    postorder(n.right);
    print(n.data);            // ← 印在最後(根)
}
```

前中後序都用**遞迴**(屬深度優先 DFS);**層序 (Level-order) 則用佇列 (Queue) 做 BFS**:

```java
void levelOrder(Node root) {
    Queue<Node> q = new LinkedList<>();
    q.offer(root);
    while (!q.isEmpty()) {
        Node n = q.poll();
        print(n.data);
        if (n.left  != null) q.offer(n.left);   // 左小孩排進佇列
        if (n.right != null) q.offer(n.right);  // 右小孩排進佇列
    }
}
```

### 由走訪結果重建二元樹(高頻計算題)

給你**兩種**走訪,可以**倒推出整棵樹**(進而求第三種走訪)。步驟:

1. **前序**的第一個、或**後序**的最後一個 = **根**。
2. 在**中序**裡找到這個根,根的**左邊 = 左子樹、右邊 = 右子樹**。
3. 對左、右子樹**遞迴**重複。

例:前序 = **A B D E C**、中序 = **D B E A C**,求這棵樹:

- 前序第一個 **A = 根**;中序用 A 切開 → 左 `D B E`、右 `C`。
- 左子樹(前序取 `B D E`):第一個 **B = 根**;中序 `D B E` 用 B 切 → 左 `D`、右 `E` → B 左掛 D、右掛 E。
- 右子樹只有 `C`。

得到:

```
    A
   / \
  B   C
 / \
D   E
```

於是**後序** = **D E B C A**。

**★ 陷阱**:只有「**前序+中序**」或「**後序+中序**」能**唯一**決定一棵樹;**「前序+後序」不行**(分不出左右子樹,可能對應多棵樹)。

### 二元樹的陣列表示法(常考)

除了「節點 + 指標」,二元樹也能**用一個陣列**存(**heap 就是這樣存的**)。若根放在**索引 1**(1-based):

- 節點 i 的 **左子 = 2i**、**右子 = 2i + 1**、**父節點 = ⌊i / 2⌋**。

```
      A(1)
     /    \
   B(2)    C(3)
   /  \
 D(4) E(5)

陣列:  [ _, A, B, C, D, E ]
索引:    0  1  2  3  4  5
```

- 驗證:B 在索引 2 → 左子 2×2=4(D)、右子 2×2+1=5(E);D 的父 = ⌊4/2⌋=2(B)。✓
- 優點:完整/完美二元樹沒有空洞,存陣列超省;缺點:歪斜或很稀疏的樹會浪費很多空格。

### 二元搜尋樹 (BST, Binary Search Tree)

規則:**左子樹都比自己小、右子樹都比自己大**。所以搜尋時每比一次就能砍掉一半。

- **平均搜尋 O(log n)**(因為左小右大、每次砍一半)。
- **最壞 O(n)**:當資料按順序插入,BST 退化成**歪斜樹**(像一條鏈結串列),就失去砍半的優勢。
- **關鍵考題**:對 BST 做**中序走訪 (Inorder)**,會得到**由小到大排序**的結果。
- **改善退化**:**平衡樹(如 AVL、紅黑樹)** 會透過旋轉維持左右高度平衡,避免退化成歪斜樹,**保證 O(log n)**。

**BST 的插入與刪除**:

- **插入**:從根開始比大小,**比目前節點小往左、大往右**,一路走到空位就掛上去。
- **刪除**分三種情況:
  1. **葉節點**(沒有子節點):直接刪掉。
  2. **只有一個子節點**:用那個子節點頂上來取代它。
  3. **有兩個子節點**:找**中序後繼**(右子樹的最小值)或**中序前驅**(左子樹的最大值)來取代,再刪掉那個後繼/前驅——這樣才能維持 BST 的排序性質。(**這是申論常客。**)

### 堆積 (Heap)

**heap 是一棵「完整二元樹」**,再加上父子大小規則:

- **最大堆 (Max-Heap)**:每個節點都 **≥ 它的子節點** → **根最大**。
- **最小堆 (Min-Heap)**:每個節點都 **≤ 它的子節點** → **根最小**。
- 注意:heap 只規定「**父子**」的大小關係,**兄弟之間、左右子樹之間沒有順序**(這點跟 BST 不同,別搞混)。
- 常用**陣列表示**(就是上面那套 2i、2i+1);用途:**優先佇列 (Priority Queue)**、**堆積排序 (Heap Sort,O(n log n))**。

**★ 樹常考重點**:
- n 個節點 → **n − 1 條邊**;完美二元樹 h 層 → **2ʰ − 1 個節點**;第 i 層最多 **2^(i-1)** 個。
- **葉節點數 = 分支度 2 的節點數 + 1(n₀ = n₂ + 1)**。
- 三種走訪差別只在「根」的位置:前序=根在前、中序=根在中、後序=根在後;層序用**佇列 (BFS)**。
- **重建樹**:前序/後序找根 + 中序切左右;**「前序+後序」無法唯一決定**。
- **陣列表示**:節點 i → 左子 **2i**、右子 **2i+1**、父 **⌊i/2⌋**。
- **BST 中序走訪 = 由小到大排序**;平均 O(log n)、**最壞 O(n)**(退化,用**平衡樹/AVL** 解)。
- **Heap** = 完整二元樹 + 父子大小關係(max-heap 根最大);只管父子、不管兄弟。

## 七、運算式表示法(中序 / 前序 / 後序)

同一個運算式有三種寫法,差別在**運算子擺哪裡**:

- **中序 Infix**:`A + B`(運算子在中間,一般數學式,人類看的)。
- **前序 Prefix**:`+ A B`(運算子在前,又叫波蘭表示法)。
- **後序 Postfix**:`A B +`(運算子在後,又叫逆波蘭 RPN,電腦最好算)。

**和樹走訪的漂亮連結**:把運算式畫成「運算式樹」,那麼——**前序走訪 = 前序式、中序走訪 = 中序式、後序走訪 = 後序式**。

例:`(A + B) * C` 的運算式樹:

```
        *
       / \
      +   C
     / \
    A   B
```

- **前序(prefix)**:`* + A B C`
- **中序(infix)**:`A + B * C`(注意:中序會丟失括號,需靠優先權或括號還原)
- **後序(postfix)**:`A B + C *`

電腦用**堆疊 (Stack)** 來做「中序轉後序」與「後序求值」。

**★ 常考重點**:前/中/後序 = 運算子在前/中/後;對應運算式樹的前/中/後序走訪。轉換與求值用**堆疊**。

## 八、雜湊表 (Hash Table)

### 概念:它想解決什麼

陣列靠**索引**能 O(1) 直接取值,但前提是「你得先知道索引」。那如果我想用一個**有意義的 key**(例如學號、姓名、身分證字號)直接找到資料呢?

雜湊表的做法:用一個**雜湊函數 (Hash Function)** 把 key「算成」一個陣列索引,再存到那一格。查的時候同樣把 key 算一次就知道位置 → **不用一格格找,直接命中 O(1)**。

比喻:圖書館不用一本本翻,靠書的**索書號**直接算出它在哪個書架;雜湊函數就是那個「key → 位置」的換算規則。

### 雜湊函數 (Hash Function)

把 key 轉成「桌子(陣列)裡的位置」的函數。最常見、最常考的是**除法雜湊法 (Division Method)**:

```
h(k) = k mod m       (m = 雜湊表大小)
```

例:表大小 m = 10,key = 25 → h(25) = 25 mod 10 = **5**,存到第 5 格。

(m 通常取**質數**,能讓 key 分布更均勻、減少碰撞。)

### 碰撞 (Collision)

不同的 key **算到同一個位置**,就叫碰撞。例如 h(15)=5、h(25)=5,兩個都想住第 5 格。

碰撞**無法完全避免**(key 可能無限多、格子有限,鴿籠原理),所以雜湊表的重點就是「**碰撞了怎麼辦**」——這是最核心的考點。

### 碰撞處理:兩大方法

**(一)鏈結法 (Chaining,分離鏈結)**

每一格不是只放一個,而是接一條**鏈結串列**;碰撞的 key 就**掛在同一格的串列後面**。

```
第5格 → [15] → [25] → [35]      (三個都 hash 到 5,串起來)
```

- 優點:實作簡單、桌子不會「滿」。
- 缺點:碰撞多時串列變長,查詢退化成走訪。

**(二)開放定址法 (Open Addressing)**

不另接串列,而是**在桌子裡找下一個空格**塞進去。找法有三種:

- **線性探測 (Linear Probing)**:被占了就找**下一格**:h(k)、h(k)+1、h(k)+2…
  - 缺點:資料容易擠成一坨 → **主要群聚 (Primary Clustering)**。
- **二次探測 (Quadratic Probing)**:跳的間距是平方:h(k)+1²、h(k)+2²、h(k)+3²…
  - 改善主要群聚,但仍有**次要群聚 (Secondary Clustering)**。
- **雙重雜湊 (Double Hashing)**:用**第二個雜湊函數**決定每次跳多遠,最能打散、群聚最少。

### 具體範例

表大小 m = 10,依序插入 key:**15、25、35、22**,用 h(k) = k mod 10:
- h(15)=5、h(25)=5、h(35)=5(三個都撞在第 5 格)、h(22)=2。

**用鏈結法**:

```
第2格 → [22]
第5格 → [15] → [25] → [35]
```

**用線性探測**(撞了就往下一格找空的):

```
15 → 第5格(空)→ 放第5格
25 → 第5格(占)→ 第6格(空)→ 放第6格
35 → 第5格(占)→ 第6格(占)→ 第7格(空)→ 放第7格
22 → 第2格(空)→ 放第2格
結果:第2格=22、第5格=15、第6格=25、第7格=35
```

### 載入因子 (Load Factor)

```
載入因子 α = n / m    (n = 已放入的元素數,m = 桌子大小)
```

- α 越大代表越擠,碰撞越多、越慢。
- α 太高時要**重新雜湊 (Rehashing)**:換一張更大的桌子,把資料重算位置搬過去。

### 複雜度

- **平均**:搜尋 / 插入 / 刪除都是 **O(1)**(雜湊函數一算就到)。
- **最壞**:**O(n)**——當所有 key 都撞在同一格(全擠進同一條串列),就退化成從頭找。

### 應用

字典 / Map、快取 (cache)、資料庫索引、編譯器的符號表 (symbol table)、資料去重。

**★ 常考重點**:
- 雜湊表用**雜湊函數**把 key 換成位置,平均 **O(1)**、**最壞 O(n)**(全部碰撞)。
- 除法雜湊法 **h(k) = k mod m**,m 常取質數。
- 碰撞處理兩大類:**鏈結法**(掛串列)、**開放定址法**(找空格);開放定址又分**線性探測、二次探測、雙重雜湊**。
- 線性探測 → **主要群聚**;二次探測 → **次要群聚**;雙重雜湊最能避免群聚。
- **載入因子 α = n / m**,太高要**重新雜湊 (Rehashing)**。

## 十、高頻考點速記(直接背)

- Big-O 成長:**O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)**。
- 陣列:**隨機存取 O(1)、插入刪除 O(n)**、連續固定。
- 二維位址:Row-major `i×C + j`;Column-major `j×R + i`。
- 鏈結串列:**插入刪除 O(1)、走訪 O(n)**;分單向/雙向/環狀。
- **陣列存取快增刪慢;串列增刪快存取慢。**
- Stack = **LIFO**(函式呼叫、上一頁、運算式轉換);Queue = **FIFO**(排程、緩衝)。
- **環狀佇列**解決線性佇列的**假溢位**。
- 二元樹走訪:前序=根左右、中序=左根右、後序=左右根。
- **BST 中序走訪 = 由小到大**;BST 平均 O(log n)、**最壞 O(n)**。
- n 個節點的樹有 **n−1 條邊**;完美二元樹 h 層有 **2ʰ−1 個節點**。
- 前/中/後序運算式 ↔ 運算式樹的前/中/後序走訪;用堆疊轉換求值。
- 雜湊表平均 **O(1)**,問題是**碰撞**。

---

### 答案與解析

| 題 | 答 | 解析 |
|---|---|---|
| 1 | **C** | 成長速度 O(2ⁿ) > O(n²) > O(n log n) > O(log n)。 |
| 2 | **A** | 陣列靠索引一算就到,隨機存取 O(1)。 |
| 3 | **C** | Row-major:2000 + (2×6 + 3)×2 = 2000 + 30 = 2030。 |
| 4 | **B** | 串列已知位置插入/刪除只改指標 = O(1);其餘皆為陣列特性。 |
| 5 | **B** | LIFO 是堆疊;佇列是 FIFO。 |
| 6 | **B** | 先到先做 = FIFO = 佇列。 |
| 7 | **B** | 函式呼叫返回、運算式轉換都靠 LIFO 的堆疊。 |
| 8 | **B** | 環狀佇列讓空間循環利用,解決假溢位。 |
| 9 | **B** | 後序=左右根:左子樹(4,5,2)、右(3)、根(1) → 4 5 2 3 1。 |
| 10 | **B** | BST 中序走訪 = 由小到大排序。 |
| 11 | **C** | 資料按序插入退化成歪斜樹,最壞 O(n)。 |
| 12 | **A** | * 優先,B C * 先,再與 A 相加:A B C * +。 |
| 13 | **B** | n 個節點的樹有 n−1 條邊。 |
| 14 | **A** | h 層完美二元樹共 2ʰ−1 個節點(如 h=3 → 7)。 |
| 15 | **B** | 陣列存取快增刪慢;串列增刪快存取慢。 |
| 16 | **C** | 雜湊表平均 O(1),主要問題是碰撞。 |
| 17 | **A** | 前序首 1=根;中序 `2│1│4 3 5` 切左右;右子樹根 3(左 4、右 5)→ 後序 2 4 5 3 1。 |
| 18 | **B** | 公式 n₀ = n₂ + 1 → 10 = n₂ + 1 → n₂ = **9**。 |
| 19 | **B** | 左子 = 2i = 2×5 = **10**(右子 2i+1、父 ⌊i/2⌋)。 |
| 20 | **B** | 第 i 層最多 2^(i-1) = 2³ = **8**。 |
| 21 | **B** | max-heap 根最大;heap 是完整二元樹(非 BST),只管父子、不管兄弟。 |
| 22 | **C** | 前序+後序分不出左右子樹,無法唯一決定;需「前序/後序 + 中序」。 |
| 23 | **B** | 用中序後繼(右子樹最小)或中序前驅取代,才能維持 BST 排序性質。 |
