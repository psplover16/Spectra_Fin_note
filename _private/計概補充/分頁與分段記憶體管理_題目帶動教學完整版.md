## 開場：分頁到底在解什麼問題？　【理解】

一句話先記著：**分頁 = 把記憶體切成一樣大的小格子，這樣程式不用「整塊連續」塞進去，哪裡有空格就放哪。**

三個名詞，先建立畫面（**定義 → 核心 → 怎麼用**）：

- **頁（page）**：把**邏輯記憶體**（程式自己以為的記憶體）切成的固定大小小塊。
- **框架（frame，頁框）**：把**實體記憶體**（真正的 RAM）切成的固定大小小塊。
- **頁表（page table）**：一張對照表，記「第幾頁 → 放在第幾個框架」。

> **超關鍵**：**頁大小 = 框架大小**。兩邊格子一樣大，所以「在格子裡的第幾個位元組」搬家前後不會變，只有「在哪一格」需要查表翻譯。這句話是後面所有題目的根。

> **名詞澄清①：「邏輯位址空間」到底是什麼？**（這詞馬上會在 Q1 出現，先搞懂）
>
> | 詞 | 意思 | 例 |
> |---|---|---|
> | 邏輯位址 (logical address) | **一個**位址（一個門牌號） | 2500 |
> | 邏輯位址**空間** (logical address space) | **全部**位址的整個範圍／集合 | 0～65535（共 64 KB） |
>
> 「空間」不是「空的地方」，而是「**位址的範圍**」。記一條換算：**位址 m bits ⟺ 邏輯位址空間 = 2ᵐ bytes**。所以題目寫「邏輯位址空間 = 64 KB = 2¹⁶」，其實是偷偷告訴你「**邏輯位址 = 16 bits**」。
> 對照：**邏輯**位址空間＝程式「以為」自己有的範圍（看位址 bit 數）；**實體**位址空間＝真正 RAM 的範圍（看 RAM 大小）。兩者可以不一樣大（延伸題 Q5 就是這情況）。

## 題型一：把邏輯位址拆成兩半　★【練流程】

### 先看題（先別往下看解法）

> **Q1.** 某系統頁大小 = **4 KB**，邏輯位址空間 = **64 KB**。請問：
> (a) 頁內偏移 (offset) 佔幾個 bit？
> (b) 頁號 (page number) 佔幾個 bit？
> (c) 總共有幾頁？

——卡住了嗎？卡點通常是「為什麼位址要拆兩半、怎麼決定各佔幾 bit」。先補這個觀念。

### 卡點補帖：邏輯位址被砍成「頁號 + 偏移」

CPU 給的邏輯位址，會被硬體 **MMU** 從中間砍一刀，分成高低兩段：

```
邏輯位址 = [  頁號 p  |  偏移 d  ]
              高位        低位
```

- **偏移 d（低位）**：你在「這一頁裡」的第幾個位元組 → **原封不動照抄**到實體位址，不用換。
- **頁號 p（高位）**：你在「第幾頁」 → 拿去**查頁表**換成框號 f。

決定各佔幾 bit 的兩條鐵則（**這就是解題公式**）：

| 已知 | 推出 |
|---|---|
| 頁大小 = 2ⁿ bytes | **偏移 d = n bits**（一頁有 2ⁿ 個位元組，要 n 位才編得完號碼） |
| 邏輯位址空間 = 2ᵐ bytes | **邏輯位址總長 = m bits** |
| 上兩者 | **頁號的 bit 數 = m − n**，**總頁數 = 2^(m−n)** |

> 為什麼「2ⁿ bytes 對應 n bits」？因為要替 **2ⁿ 個格子**各貼一個不重複的二進位門牌，剛好需要 **n 位數**（2 個門牌要 1 位、4 個要 2 位、8 個要 3 位…）。別跟「1 byte = 8 bits」搞混——那是在講一個格子「裝」多少資料，這裡在講「編號」要幾位。

> **名詞澄清②：「頁號 p = (m − n) bits」的 p，是「第幾頁」還是「幾個 bit」？**
>
> 是 **bit 數（頁號這個欄位有幾位）**，**不是**「第幾頁」。「頁號」其實有三層意思，最容易在這裡卡住，分清楚：
>
> | 講的是 | 意思 | Q1 的值 |
> |---|---|---|
> | 頁號的 **bit 數（位數）** | 頁號這一欄要用幾個 0/1 來寫 | **4 bits** |
> | 頁號的 **種類數 ＝ 總頁數** | 這些位數能排出幾種不同頁號 | 2⁴ = **16 頁** |
> | **某位址的頁號（第幾頁）** | 拿某個位址算出來的具體值 | （Q2 的 2500 → 第 **2** 頁） |
>
> 碼表比喻：「**幾位數**」＝ bit 數；「這幾位能排**幾個號碼**」＝ 種類數（總頁數）；「現在**顯示哪個號碼**」＝ 第幾頁。
> 所以：**(m − n) 是頁號的「位數」、2^(m−n) 是頁號的「種類數＝總頁數」、第幾頁是某次算出來的「那個號碼」。** 公式裡寫的是前者（位數）。

### 回頭解 Q1

| 步驟 | 計算 |
|---|---|
| 頁大小換成 2 的次方 | 4 KB = 4 × 1024 = 4096 = **2¹²** → **offset = 12 bits** |
| 邏輯空間換成 2 的次方 | 64 KB = 64 × 1024 = 65536 = **2¹⁶** → 位址總長 = 16 bits |
| 頁號 bits | 16 − 12 = **4 bits** |
| 總頁數 | 2⁴ = **16 頁** |

**驗算**：16 頁 × 4 KB/頁 = 64 KB ✓（剛好等於邏輯空間，對得起來）。

> 換算速記：**KB=×2¹⁰、MB=×2²⁰、GB=×2³⁰**。先把所有單位拉成「2 的某次方 bytes」，指數就是 bit 數，題目一半就解完了。

## 題型二：邏輯位址 → 實體位址（最常考）　★【練流程】

### 先看題

> **Q2.** 頁大小 = **1 KB**。頁表如下：
> | 頁號 | 框號 |
> |---|---|
> | 0 | 5 |
> | 1 | 2 |
> | 2 | 7 |
> | 3 | 1 |
>
> 邏輯位址 = **2500**（十進位）。求**實體位址**。

### 卡點補帖：轉換的三步流程 + 一條公式

**一句話程序**：拆出頁號與偏移 → 查表把頁號換成框號 → 用「框號 × 框大小 + 偏移」拼出實體位址。

```
① 頁號 = 邏輯位址 ÷ 頁大小（取商，去小數）
② 偏移 = 邏輯位址 ÷ 頁大小（取餘數）
③ 查頁表：頁號 → 框號
④ 實體位址 = 框號 × 框大小 + 偏移
```

> 為什麼是「框號 × 框大小 + 偏移」？框號 f 代表「第 f 格」，每格大小是框大小，所以這一格的**起點**在 `f × 框大小`；再往裡走 `偏移` 個位元組，就是真正位置。

### 回頭解 Q2

| 步驟 | 計算 |
|---|---|
| ① 頁號 | 2500 ÷ 1024 = 2 …（2×1024 = 2048，還沒到 3072）→ **頁號 = 2** |
| ② 偏移 | 2500 − 2048 = **452** |
| ③ 查表 | 頁 2 → **框 7** |
| ④ 實體位址 | 7 × 1024 + 452 = 7168 + 452 = **7620** |

**驗算**：7168（框7起點）+ 452（往裡452）= 7620 ✓。偏移 452 < 1024，沒爆出這一頁，合理 ✓。

> 易錯：第④步**乘的是「框號」、不是「頁號」**。頁號只是用來查表的索引，查完就丟掉，真正參與計算的是查到的框號。

## 題型三：用二進位做轉換（看懂「偏移為何照抄」）　★【練流程】

### 先看題（沿用你學過的 16/256 例子）

> **Q3.** 頁大小 = **16 bytes**，邏輯位址空間 = **256 bytes**。頁表中 **頁 5 → 框 11**。
> 邏輯位址 = `01011010`（二進位）。求實體位址（二進位與十進位）。

### 卡點補帖：二進位下，砍一刀就分好了

先用題型一的鐵則定 bit 數：

- 頁大小 16 = 2⁴ → **偏移 = 4 bits**
- 邏輯空間 256 = 2⁸ → 邏輯位址 = **8 bits**
- 頁號 = 8 − 4 = **4 bits**

所以 8 位的邏輯位址，**直接從中間切**：高 4 位是頁號、低 4 位是偏移，連除法都不用算。

```
邏輯位址  0101 1010
          ↑↑↑↑ ↑↑↑↑
          頁號  偏移
          =5   =10
```

轉換時：**頁號那段查表換掉，偏移那段原封照抄、貼回低位。**

### 回頭解 Q3

| 步驟 | 二進位 | 十進位對照 |
|---|---|---|
| 拆邏輯位址 | 頁號 `0101` / 偏移 `1010` | 頁號 5、偏移 10 |
| 查表換框號 | 頁 5 → 框 11 = `1011` | 框號 11 |
| 拼實體位址 | 框 `1011` ++ 偏移 `1010` = **`10111010`** | = **186** |

**驗算**（十進位法對照）：11 × 16 + 10 = 176 + 10 = 186 ✓，且 `10111010`₂ = 128+32+16+8+2 = 186 ✓。

> 這題的價值：你會「親眼看到」**偏移那 4 位從頭到尾沒動過**，只有頁號 `0101` 被換成框號 `1011`。這就是開場那句「**只有在哪一格要翻譯，格子內位置不變**」的具體畫面。考試若給二進位/十六進位，用切 bit 比除法更快更不會錯。

## 題型四：頁表有多大？　★【練流程】

### 先看題

> **Q4.** 邏輯位址 = **32 bit**，頁大小 = **4 KB**，頁表每一項（entry）佔 **4 bytes**。
> 求 (a) 頁表有幾項？(b) 頁表共多大？

### 卡點補帖：頁表項數 = 頁數

頁表是「**一頁一項**」的對照表，所以——

```
頁表項數 = 總頁數 = 2^(頁號 bits)
頁表大小 = 項數 × 每項大小
```

### 回頭解 Q4

| 步驟 | 計算 |
|---|---|
| 偏移 bits | 4 KB = 2¹² → 12 bits |
| 頁號 bits | 32 − 12 = **20 bits** |
| (a) 項數 | 2²⁰ = **1,048,576 項（約 1 M 項）** |
| (b) 頁表大小 | 2²⁰ × 4 bytes = **4 MB** |

**驗算**：2²⁰ = 1,048,576；× 4 = 4,194,304 bytes = 4 MB ✓。

> 弦外之音（考過觀念題）：**一個 process 的頁表就要 4 MB**，跑很多 process 會爆。這就是為什麼要 **多層頁表 (multi-level paging)** ——把頁表本身也切頁、用到才載，省空間。考到「單層頁表缺點」就答這個。

## 延伸題：實體記憶體決定「框號幾 bit」　★【練流程】

> **Q5.** 實體記憶體 = **1 GB**，頁框大小 = **4 KB**。框號要幾 bit？

**程序**：框數 = 實體大小 ÷ 框大小，框號 bits = log₂(框數)。

| 步驟 | 計算 |
|---|---|
| 框數 | 2³⁰ ÷ 2¹² = **2¹⁸ = 262,144 框** |
| 框號 bits | **18 bits** |

**驗算**：262,144 × 4 KB = 1,073,741,824 B = 1 GB ✓。

> 關鍵分辨：**頁號 bits 由「邏輯空間」決定，框號 bits 由「實體空間」決定**，兩者常常不一樣（邏輯可比實體大，那就是虛擬記憶體）。偏移 bits 由「頁/框大小」決定，兩邊一定相同。

## 題型五：TLB 與有效存取時間 (EMAT)　★【練流程】

### 先看題

> **Q6.** 存取一次主記憶體需 **100 ns**，TLB 存取時間可忽略（≈ 0），TLB 命中率 **80%**，採**一層頁表**。求有效記憶體存取時間 (EMAT)。

### 卡點補帖：TLB 是什麼？它到底省了什麼？

- **TLB (Translation Lookaside Buffer)**：一塊很快的**硬體快取**，專門存最近用過的「**頁號 → 框號**」對應。
- 沒有 TLB 時，每次存取都要「先去主記憶體**查頁表**(1 次) + 再去主記憶體**拿資料**(1 次)」= **2 次**慢速存取，太慢。
- **TLB 命中 (hit)**：要的「頁號→框號」剛好在 TLB 裡 → **直接拿到框號**、跳過頁表 → 只剩「拿資料」**1 次**記憶體存取。
- **TLB 未命中 (miss)**：TLB 裡沒有 → 只好乖乖「查頁表(1 次) + 拿資料(1 次)」= **2 次**。

> ⭐ **關鍵精準點（最多人講錯）**：TLB 命中時，你是**直接拿到「框號」**，**不是「拿到頁表」**——命中就**根本不碰頁表**。TLB 省掉的，正是命中時「查頁表那一次記憶體存取」。把「拿到框號」和「拿到頁表」分清楚，這型就不會錯。

**通用公式**（記這條，什麼變體都能算）：
```
EMAT = 命中率 × (TLB時間 + 記憶體時間 × 命中要幾次)
     + 未命中率 × (TLB時間 + 記憶體時間 × 未命中要幾次)
```
一層頁表：命中要 **1 次**記憶體（拿資料），未命中要 **2 次**（查頁表 + 拿資料）。

### 回頭解 Q6

- TLB 時間 = 0（可忽略），記憶體 = 100 ns
- 命中 (0.8)：0 + 100 × 1 = **100 ns**
- 未命中 (0.2)：0 + 100 × 2 = **200 ns**
- EMAT = 0.8 × 100 + 0.2 × 200 = 80 + 40 = **120 ns** ✓

用表看 TLB 到底省了什麼：

| | 查頁表（記憶體） | 拿資料（記憶體） | 共 |
|---|---|---|---|
| 命中 0.8 | **免**（TLB 直接給框號） | 1 次 | 100 ns |
| 未命中 0.2 | 1 次 | 1 次 | 200 ns |

### 兩個常見變體（掃一眼，考到不慌）

1. **TLB 給具體時間**（例：TLB = 20 ns）：命中/未命中都要先花那 20 ns。
   EMAT = 0.8 × (20 + 100) + 0.2 × (20 + 100 + 100) = 0.8 × 120 + 0.2 × 220 = 96 + 44 = **140 ns**。
2. **兩層頁表**：未命中要查兩層頁表(2 次) + 拿資料(1 次) = **3 次**記憶體 → 未命中成本 300 ns（TLB 忽略時）。

## 分頁 · 公式速查表

| 要求的東西 | 公式 |
|---|---|
| 偏移 d 的 bit 數 | 頁大小 = 2ⁿ → **n bits**（這個 n 就是偏移位數） |
| 頁號 p 的 bit 數 | 邏輯空間 = 2ᵐ → **(m − n) bits** |
| 框號 f 的 bit 數 | 實體空間 = 2ᵏ → **(k − n) bits** |
| 總頁數（頁號的「種類數」） | **2^(頁號 bits) = 邏輯空間 ÷ 頁大小** |
| 總框數（框號的「種類數」） | **2^(框號 bits) = 實體空間 ÷ 框大小** |
| 頁號（給十進位位址） | **邏輯位址 ÷ 頁大小**（取商） |
| 偏移（給十進位位址） | **邏輯位址 ÷ 頁大小**（取餘） |
| 實體位址 | **框號 × 框大小 + 偏移** |
| 頁表項數 | **= 總頁數 = 2^(頁號 bits)** |
| 頁表大小 | **項數 × 每項大小** |
| EMAT（一層頁表、TLB 可忽略） | **命中率 × 記憶體 + 未命中率 × (2 × 記憶體)** |
| — 命中要幾次記憶體 | **1 次**（TLB 直接給框號、免查頁表） |
| — 未命中要幾次記憶體 | **2 次**（查頁表 + 拿資料）；兩層頁表 → 3 次 |

**單位換算**：KB = ×2¹⁰、MB = ×2²⁰、GB = ×2³⁰。**先全部化成「2 的某次方 bytes」，指數就是 bit 數。**

---

## 分頁 · 四大易錯點

1. **「2ⁿ bytes ↔ n bits」別跟「1 byte = 8 bits」混**。前者是「替 2ⁿ 個格子編號要 n 位」，後者是「一個格子裝 8 位資料」，兩個 bit 講的是不同事。
2. **算實體位址乘的是「框號」不是「頁號」**。頁號只是查表索引，查完就丟。
3. **頁號 bits 看邏輯空間、框號 bits 看實體空間，可以不一樣**；只有偏移 bits（= 頁/框大小）兩邊保證相同，且偏移在轉換中**永遠照抄不變**。
4. **EMAT：TLB 命中是「直接拿到框號」、跳過頁表**。命中只存記憶體 1 次（拿資料），未命中才 2 次（查頁表 + 拿資料）。別把「拿到框號」講成「拿到頁表」。

# 第二部　分段 (Segmentation)　★【練流程】

> 科目：計算機原理 — 作業系統｜與分頁成對必考（辨別題大戶）

## 開場：分段在解什麼問題？（分頁的痛點）　【理解】

分頁把記憶體切成**一律等大**的格子，好處是好管理、無外部碎裂；但它有個「不管程式邏輯」的缺點：

- 一個函式（code）可能被硬切成兩頁，中間斷掉；
- 想「把整個 code 設成唯讀、整個 stack 設成可讀寫」時，分頁是以「頁」為單位，切得亂七八糟，**共享與保護不好做**；
- 還有內部碎裂（最後一頁用不滿）。

**分段的想法**：不要照機器的固定尺寸切，改**照程式的邏輯單位切** —— code 段、data 段、stack 段、heap 段……**每段大小不一**，一個邏輯單位就是一段。

三個名詞（**定義 → 核心 → 怎麼用**）：

- **段（segment）**：依程式邏輯切出的一塊，大小不固定（一個函式、一個陣列、一段堆疊都可以是一段）。
- **段表（segment table）**：對照表，記「第 s 段 → 放在實體記憶體哪裡、多長」。
- **段號 s ／ 段內偏移 d**：邏輯位址一樣拆成兩半，(s, d)。

> **名詞澄清①：段表每一項存「兩個」東西 —— base 與 limit（這是它跟頁表最大的差別）**
>
> | 欄位 | 意思 | 白話 |
> |---|---|---|
> | **base（基底）** | 這一段在**實體記憶體的起點位址** | 「這段從 RAM 的第幾號開始放」 |
> | **limit（界限／長度）** | 這一段有**多長**（幾個位元組） | 「這段有多大，超過就是非法」 |
>
> 對比：**頁表**每項只存一個**框號**（因為每頁等大，長度不必記）；**段表**每項要存 **base ＋ limit 兩個**（因為每段長度不同，必須記起點也記長度）。這是分頁 vs 分段最愛考的差異。

> **關鍵預告（對照分頁）**：分頁的翻譯是「**框號 × 框大小 ＋ 偏移**，偏移照抄」；分段的翻譯是「**base ＋ 偏移**」——直接相加。**分段沒有「偏移照抄到固定低位」這回事**，因為段大小不一、base 是任意起點。這點等下你會親眼看到。

## 題型一：邏輯位址長怎樣？段表怎麼查？　【理解】

### 先看題（先別往下看解法）

> **Q1.** 一支程式有 4 個段：code、data、heap、stack，分別編號段 0～3。
> 邏輯位址寫成 **(2, 53)**。請問：這在指哪裡？要怎麼找到它在 RAM 的真正位置？

——卡點通常是「(2, 53) 這兩個數字各代表什麼、段表怎麼把它變成真位址」。先補這個。

### 卡點補帖：(段號, 偏移) → 查段表 → base + 偏移

邏輯位址被拆成兩半（跟分頁很像，但意義不同）：

```
邏輯位址 = ( 段號 s , 段內偏移 d )
             哪一段      這段裡第幾個位元組
```

- **段號 s**：拿去**查段表**，取出這段的 **base** 和 **limit**。
- **偏移 d**：在這一段裡往裡走幾個位元組。

翻譯程序（**一句話**）：查段表拿到 base 與 limit → **先檢查 d 有沒有超過 limit** → 沒超過就 **實體位址 = base + d**。

### 回頭解 Q1

(2, 53) = 「第 **2** 段（heap）裡的第 **53** 個位元組」。找法：拿段號 2 去查段表得到 base 和 limit，確認 53 沒超過這段長度，再算 base + 53。實際數字下一題就算。

> 先建立畫面就好：**段號是「查表用的索引」，偏移是「段內位置」**。真正參與加法的是查到的 **base**（不是段號）——這點和分頁「乘的是框號不是頁號」是同一種易錯。

### 補充：位址位元配置 —— 「幾個段？每段多大？」　★【練流程】

> **Q（考型）.** 邏輯位址共 **24 bits**，採分段，最多可有 **256 個段**。每個段最大可為多少 bytes？

跟分頁一樣，一個邏輯位址被切成**兩個欄位**（不是拿總空間去「除」）：
```
邏輯位址 24 bits ＝ [ 段號 s | 段內偏移 d ]
                      ？bit      ？bit
```
拆解：
- **段號幾 bit？** 由「幾個段」決定：256 段 = 2⁸ → 段號 **8 bits**。
- **剩下全給偏移**：24 − 8 = **16 bits**。
- **每段最大 ＝ 偏移能定位的範圍**：2^(偏移 bits) = 2¹⁶ = 65536 = **64 KB** ✓。

> ⚠️ **別用「總空間 ÷ 段數」**：分段的段**大小不一**，「平均每段」根本沒意義。這算法只在「段數和大小都是 2 的次方、又剛好用滿整個位址」時**巧合算對**（因為除法 = 指數相減）；一遇到「**規定每段最大只有 X**、不讓你用滿位址」的變形題就會錯。正解永遠是**拆欄位**：
> - **「幾個段」→ 決定段號 bits**（前半欄位）
> - **「每段多大」→ 看偏移 bits**（後半欄位），每段最大 = 2^(偏移 bits)
>
> 這套「**[ 號碼 | 偏移 ] 拆欄位、看位數**」和分頁的 [ 頁號 | 偏移 ] 完全一樣，分頁／分段／段頁式通用。

## 題型二：邏輯位址 → 實體位址（★ 核心，含段錯誤）　★【練流程】

### 先看題

> **Q2.** 段表如下（單位：byte）：
>
> | 段號 s | base | limit |
> |---|---|---|
> | 0 | 1400 | 1000 |
> | 1 | 6300 | 400 |
> | 2 | 4300 | 400 |
> | 3 | 3200 | 1100 |
>
> 求下列邏輯位址的實體位址（若非法請指出）：
> (a) (2, 53)　(b) (3, 852)　(c) (1, 500)　(d) (0, 1000)

### 卡點補帖：先檢查界限，再相加

**一句話程序**：
```
① 用段號查段表 → 拿到 base、limit
② 界限檢查：偏移 d 是否 < limit ？
     • d <  limit → 合法：實體位址 = base + d
     • d ≥ limit → 非法：段錯誤（Segmentation Fault / trap）
```

> 為什麼是 **base + d**？base 是「這段在 RAM 的起點」，往裡走 d 個位元組，就是真正位置——就像「這段從 4300 號開始，第 53 格 = 4300 + 53」。
> 為什麼要界限檢查？段表的 limit 就是這段的**合法長度**，偏移只要 ≥ limit 就是踩到別段或空地 → 硬體立刻擋下（這是分段天生的**保護機制**）。

### 回頭解 Q2

| 位址 | 查表 (base, limit) | 界限檢查 d < limit? | 實體位址 |
|---|---|---|---|
| (a) (2, 53) | (4300, 400) | 53 < 400 ✓ | 4300 + 53 = **4353** |
| (b) (3, 852) | (3200, 1100) | 852 < 1100 ✓ | 3200 + 852 = **4052** |
| (c) (1, 500) | (6300, 400) | 500 < 400 ✗ | **段錯誤（trap）** |
| (d) (0, 1000) | (1400, 1000) | 1000 < 1000 ✗ | **段錯誤（trap）** |

**驗算 / 說明**：
- (a) 4300 + 53 = 4353，且 4353 落在 [4300, 4700) 段內 ✓。
- (c) 段 1 只有 400 長（合法偏移 0～399），偏移 500 超界 → 擋下 ✓。
- (d) **邊界陷阱**：limit = 1000 代表這段有 1000 格，合法偏移是 **0～999**；偏移剛好 = 1000 已經是**第 1001 格**，超出 → 段錯誤。所以是「**< limit**」不是「≤ limit」。（若題目問「這段最後一個合法位址」= base + limit − 1 = 1400 + 999 = 2399。）

> **和分頁最大的手感差別**：這裡是 **base + 偏移（相加）**，偏移沒有「照抄到固定低位」，因為每段起點 base 是任意值、長度也不同。分頁能照抄是因為「頁 = 框等大」；分段做不到，所以改用「相加 + 界限檢查」。

### 補充：一個段的「合法位址範圍」＋各數值的邊界　【理解】

一個段不是一個點，是**一整排連續的合法位址**。以段 3（base = 3200、limit = 1100）為例：

```
偏移 d：   0      1     ...    1099  | 1100（超界→段錯誤）
實體位址：3200  3201    ...    4299  | 4300（下一段的地盤）
          ↑首                  ↑尾
```

看題目問「首／尾／長度」給不同答案（超好用的辨別）：

| 問的是 | 公式 | 段3 的值 |
|---|---|---|
| 第一個合法位址（首） | **base** | 3200 |
| 最後一個合法位址（尾） | **base + limit − 1** | 3200 + 1099 = **4299** |
| 這段有多大（長度） | **limit** | 1100 |

⚠️ 常錯：把「尾」寫成 base + limit = 4300 —— 那是**下一段的起點**、已經超界（少減了 1）。

**各數值的合法邊界（一起記牢）：**

| 數值 | 意義 | 最小 | 最大 |
|---|---|---|---|
| **base** | 段在 RAM 的起點 | **0**（位址從 0 號起、無負位址） | **RAM 大小 − limit**（段尾不能超出 RAM） |
| **偏移 d** | 段內第幾格 | 0 | limit − 1 |
| **limit** | 段的長度 | 通常 ≥ 1 | ≤ RAM 大小 |

所以 base 完整範圍：**0 ≤ base ≤（實體記憶體大小 − limit）**。
例：RAM = 8 KB（位址 0～8191）、某段 limit = 1000，則 base 最大只能到 8192 − 1000 = **7192**；再往後，段尾就爆出 RAM 外了。

## 題型三：分段的碎裂 —— 外部碎裂 & 緊縮　【理解】

### 先看題

> **Q3.** 實體記憶體目前有 3 塊空洞（不相鄰）：**200K、150K、300K**。
> 現在來了一個需要 **350K** 的新段。放得下嗎？空閒總量夠嗎？怎麼救？

### 卡點補帖：段要「整塊連續」放，所以會外部碎裂

每個段在 RAM 裡是**一整塊連續**擺放（因為 base + 偏移要連續才對）。當空閒空間**散成好幾個小洞**時，就算**加起來夠**，也可能**湊不出一塊夠大的連續空間** → 這叫 **外部碎裂（External Fragmentation）**。
救法：**緊縮（Compaction）** —— 把已使用的段全部往一邊挪、擠在一起，讓零散空洞合併成一大塊連續空間。

### 回頭解 Q3

- 空閒總量 = 200 + 150 + 300 = **650K**（夠！）
- 但**最大的單一空洞只有 300K < 350K** → **放不下**（這就是外部碎裂：空間夠但不連續）。
- **緊縮**後：三塊空洞合併成連續 **650K** ≥ 350K → **放得下**了。

> **辨別重點（必背，和分頁剛好相反）**
> - **分段**：段大小不一、要連續擺 → **有外部碎裂**、**無內部碎裂**。
> - **分頁**：頁一律等大、可散放 → **有內部碎裂**、**無外部碎裂**。
> 一句話記反向：**「分段外、分頁內」**。

### 補充：緊縮 (Compaction) 到底在做什麼？　【理解】

**定義**：把散落在記憶體各處、**正在使用**的段，全部搬到記憶體一邊、**緊緊靠在一起**，讓零散小洞**合併成一整塊連續大空間**。**目的：專治外部碎裂**（空間夠但不連續 → 挪一挪擠回一整塊）。

用 Q3 的場景看：
```
【緊縮前】總空閒 650K 夠，但被切碎、350K 放不下
┌─────┬──────┬─────┬──────┬─────┬──────┐
│ 段A │ 200K │ 段B │ 150K │ 段C │ 300K │   ← 洞被段夾住、各自為政
└─────┴──────┴─────┴──────┴─────┴──────┘

        ↓ 緊縮：段 A/B/C 全往左推、擠在一起 ↓

【緊縮後】三洞合併成連續 650K
┌─────┬─────┬─────┬────────────────────┐
│ 段A │ 段B │ 段C │   650K 連續 → 放得下 │
└─────┴─────┴─────┴────────────────────┘
```

**三個考點**：
1. **前提是「可重定位」**：段搬家後 **base 會變**，只要把段表該段的 base 更新成新起點，程式（靠 base + 偏移）就能繼續正確存取——所以段能搬。
2. **成本高**：搬移大量資料很花時間，且進行時系統常需暫停，屬「不得已才用」的手段。
3. **分頁不需要緊縮**：分頁任何頁可放任何框、不必連續 → 沒有外部碎裂 → **免緊縮**。⭐ 又一組辨別點：**「分段要緊縮、分頁免緊縮」**。

**外部碎裂的三條解法（完整地圖）**：

| 路線 | 方法 | 說明 |
|---|---|---|
| 事後救 | **緊縮 Compaction** | 已碎了，搬家併成連續（本題） |
| 事前防 | 配置演算法 First/Best/Worst-fit | 挑洞挑聰明點，減緩碎裂速度 |
| 根本免除 | 改用**分頁／段頁式** | 底層分頁 → 不需連續 → 外部碎裂消失 |

## 題型四：分頁 vs 分段 —— 終極比較表（辨別題必背）　【理解】＋【硬背】

> **Q4.** 考題最愛問：「下列關於分頁與分段的敘述，何者正確？」——把下表刻進腦子就能秒殺。

| 比較項 | 分頁 Paging | 分段 Segmentation |
|---|---|---|
| 怎麼切 | 固定大小、**不管程式邏輯** | 依**程式邏輯單位**(code/data/stack)、大小不一 |
| 每塊大小 | **一律相等**（頁 = 框） | **可變**、各段不同 |
| 邏輯位址 | (頁號 p, 偏移 d) | (段號 s, 偏移 d) |
| 對照表存什麼 | 頁表：一欄（**框號**） | 段表：兩欄（**base ＋ limit**） |
| 翻譯算法 | 框號 × 框大小 ＋ 偏移（**偏移照抄**） | **base ＋ 偏移**（相加） |
| 界限／保護 | 靠 valid bit、頁號範圍 | **每次比對 d < limit**，超界→段錯誤 |
| 碎裂 | **內部**碎裂、**無外部** | **外部**碎裂、**無內部** |
| 外部碎裂處理 | **不需緊縮**（頁可散放） | **需緊縮 Compaction**（段要連續） |
| 實體要連續嗎 | **不用**，各頁隨意散放 | **每個段內部要連續** |
| 對程式設計師 | **透明**（看不到、純底層機制） | **可見**（段就是邏輯單位） |
| 共享／保護 | 以「頁」為單位，較不自然 | 以「段」為單位，**自然好做**（整個 code 段設唯讀等） |

> **一句話總結**：**分頁 = 固定大小、機器角度、內部碎裂、對人透明；分段 = 依邏輯、程式角度、外部碎裂、對人可見。** 碎裂方向與可見性剛好相反，這兩點最常入題。

## 延伸：段頁式（Segmentation with Paging）—— 兩者結合　【理解】＋【練流程】

### 為什麼要結合？
- 分段的優點：**符合邏輯、好共享與保護**；缺點：**外部碎裂**。
- 分頁的優點：**無外部碎裂**；缺點：不管邏輯。
- **段頁式 = 先分段（保留邏輯性），再把每一段內部拿去分頁（消掉外部碎裂）** —— 取兩者之長。

### 位址結構與翻譯流程
邏輯位址拆成**三段**：
```
邏輯位址 = ( 段號 s , 頁號 p , 偏移 d )
```
翻譯（**一句話**）：段號查「段表」找到這段專屬的**頁表** → 頁號查該「頁表」換成**框號** → **框號 × 框大小 + 偏移**（回到分頁，偏移又照抄了）。

### 小例子
> 框大小 = 1 KB（=1024）。邏輯位址 = (段 1, 頁 2, 偏移 100)。段 1 的頁表中「頁 2 → 框 8」。
- 段 1 → 找到段 1 的頁表
- 頁 2 → 查該頁表 → 框 8
- 實體位址 = 8 × 1024 + 100 = 8192 + 100 = **8292**

**驗算**：8 × 1024 = 8192；+100 = 8292 ✓。

> 記憶點：段頁式要查**兩張表**（先段表、再頁表），最後一步又變回分頁的「框號 × 框大小 + 偏移」。它**沒有外部碎裂**（因為底層是分頁），是實務上常用的折衷。

## 分段 · 公式速查表

| 要求的東西 | 公式／要點 |
|---|---|
| 邏輯位址格式 | 分段：**(段號 s, 偏移 d)**；段頁式：**(段號 s, 頁號 p, 偏移 d)** |
| 段表每項存 | **base（起點）＋ limit（長度）** 兩個 |
| 界限檢查 | **d < limit → 合法**；**d ≥ limit → 段錯誤（trap）** |
| 實體位址（分段） | **base ＋ 偏移 d**（相加；偏移**不**照抄） |
| 某段最後一個合法位址 | **base ＋ limit − 1** |
| 分段碎裂 | **有外部碎裂、無內部碎裂**（救法：**緊縮 Compaction**） |
| 實體位址（段頁式） | 查段表→查頁表得框號 → **框號 × 框大小 + 偏移**（偏移照抄） |

**與分頁一句話對照**：分頁「框號 × 框大小 + 偏移，偏移照抄」；分段「base + 偏移，要先檢查 d < limit」。

## 分段 · 四大易錯點

1. **段表存 base + limit「兩個」，頁表只存「一個」框號**。這是分頁 vs 分段最愛考的差別，別答反。
2. **分段翻譯是「base + 偏移」相加，不是分頁的「框號 × 框大小 + 偏移」**；分段**沒有「偏移照抄」**，因為段大小不一、base 是任意起點。
3. **碎裂方向相反**：分段 = **外部**碎裂（無內部）；分頁 = **內部**碎裂（無外部）。口訣「**分段外、分頁內**」。
4. **界限檢查是「< limit」不是「≤」**：偏移 = limit 就已經超界（合法偏移是 0 ～ limit−1），會觸發**段錯誤**。這是分段的保護機制。

## 附錄：考前 30 秒總複習

一次把分頁 vs 分段最會考的辨別點掃過：

1. **切法**：分頁 = 固定大小、不管邏輯；分段 = 依邏輯單位、大小不一。
2. **對照表**：頁表存「框號」一欄；段表存「base ＋ limit」兩欄。
3. **翻譯**：分頁「框號 × 框大小 + 偏移，**偏移照抄**」；分段「**base + 偏移**（相加）、**先檢查 d < limit**」。
4. **碎裂（反向）**：分頁 = 內部碎裂、免緊縮；分段 = 外部碎裂、需緊縮。口訣「**分段外、分頁內**」。
5. **可見性**：分頁對程式設計師**透明**；分段**可見**（段就是邏輯單位）。
6. **位元配置**：一律「**[ 號碼 | 偏移 ] 拆欄位、看位數**」——號碼 bits 由「幾個」決定，最大容量由「偏移 bits」決定（= 2^偏移bits）。
7. **段頁式**：先查段表 → 再查頁表 → 框號 × 框大小 + 偏移；有分段的邏輯性、又無外部碎裂。
