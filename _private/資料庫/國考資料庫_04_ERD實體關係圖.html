一定義

實體關係圖（Entity-Relationship Diagram, ERD）由 Peter Chen 於 1976 年提出，以圖形描述資料庫的概念設計：包含有哪些「實體」、實體的「屬性」，以及實體間的「關係」。它對應到資料庫設計的概念層，是轉換為關聯式表格前的藍圖。

二三大元素與全部符號

ERD 以三種基本圖形為核心：實體（矩形）、屬性（橢圓）、關係（菱形）。各符號的種類與功能如下：

類別圖案名稱代表功能
實體單矩形強實體 Strong Entity能靠自身主鍵識別的事物；對應一張表
實體雙矩形弱實體 Weak Entity無法自身識別、須依賴其他實體
屬性橢圓簡單屬性 Simple實體的特性；對應一個欄位
屬性橢圓＋底線主鍵 Key Attribute唯一識別實體的屬性
屬性橢圓＋虛線底線部分鍵 Partial Key弱實體的鑑別屬性，須配合所屬強實體主鍵
屬性雙橢圓多值屬性 Multivalued一個實體可有多個值
屬性虛線橢圓衍生屬性 Derived可由其他屬性計算、不實際儲存
屬性橢圓串子橢圓複合屬性 Composite可再拆成更小的屬性
關係單菱形一般關係 Relationship兩個以上實體間的關聯
關係雙菱形識別關係 Identifying連接弱實體與其依賴之強實體
關係菱形連橢圓關係屬性屬於「關係本身」、不屬於任一實體的屬性
連線標 1:1／1:N／M:N基數 Cardinality一端的一筆對應另一端的數量
連線雙線全部參與 Total該實體每個實例都「必須」參與關係
連線單線部分參與 Partial該實體實例可參與、可不參與
💡 理解（兩個易混點）雙框 = 弱：弱實體用雙矩形、識別關係用雙菱形。屬性的外框決定種類：底線=主鍵、虛線底線=部分鍵、雙線=多值、虛線=衍生。注意「雙線（參與）」和「雙框（弱）」是兩回事。

三完整 ERD 範例（員工–部門–眷屬）

員工、部門為強實體（單框）；眷屬為弱實體（雙框），以識別關係「撫養」（雙菱形）連到員工。員工編號／部門編號加底線=主鍵；眷屬姓名虛線底線=部分鍵；電話雙橢圓=多值；年齡虛線橢圓=衍生；地址連縣市／路名=複合；到職日連在菱形上=關係屬性。眷屬→撫養雙線=全部參與。（手機可放大檢視）

四基數（Cardinality）與 M:N 的處理

基數三種

  • 1:1（一對一）：如一個人對一本護照。
  • 1:N（一對多）：如一個部門對多位員工。
  • M:N（多對多）：如多位學生對多門課程。

M:N 的處理（重要）

關聯式資料庫不能直接儲存 M:N，須拆成「兩個 1:N ＋ 一張中間表（橋接表）」；中間表的主鍵通常是兩個外來鍵組成的複合鍵。

💡 理解例：學生 ⟷ 課程（M:N）→ 拆成 學生 1:N 選課表、課程 1:N 選課表；選課表 = {學號(FK), 課號(FK), 成績}，主鍵 = {學號, 課號}。若關係本身有屬性（如成績），剛好放進這張中間表。

五如何手繪（申論步驟）

  1. 找出實體，畫成矩形；弱實體畫雙矩形。
  2. 找出每個實體的屬性，以橢圓連到實體；主鍵加底線、多值畫雙橢圓、衍生畫虛線橢圓、複合屬性再連子橢圓。
  3. 找出實體間的關係，以菱形連接；連接弱實體的識別關係畫雙菱形。
  4. 在關係兩端連線上標基數（1、N、M）；必須全部參與者畫雙線。
  5. 若關係本身有屬性（如成績、到職日），把橢圓連到菱形上。

六什麼是關聯表

關聯表（Relation／Table）是關聯式資料庫儲存資料的基本單位，為一個二維表格，由「列」與「欄」組成。

學生表範例：上方標頭是「欄（屬性）」，每一橫列是一筆「紀錄（tuple）」

基本術語

  • 關聯（Relation）＝ 表（Table）：「關聯」是 relation 的中文翻譯，指的就是一張表，不是「關係／連結」的意思。
  • 列（Row／Tuple）＝ 一筆紀錄（如一位學生）。
  • 欄（Column／Attribute）＝ 一個欄位／屬性（如學號、姓名）。
  • 定義域（Domain）＝ 一個欄位允許的值範圍（如「系所」只能填有效系名）。
  • 度數（Degree）＝ 表的欄數；基數（Cardinality）＝ 表的列數。
  • 表與表之間以「值」（外來鍵）連結（關聯式最大特徵）。
💡 別混淆這裡的「基數」指「表有幾列」；和前面 ERD 的「關係基數」（1:1、1:N、M:N）是不同的東西，只是中文都叫基數。

關聯表的基本規則

  • 每個欄位值都是單一值（原子性；對應 1NF）。
  • 每一列都唯一，由主鍵保證、不可重複。
  • 列與欄的排列順序不影響資料意義。
💡 理解（一句話）關聯表就是 Excel 那種「橫列、直欄」的表：一張表存一種東西，表跟表用「值」串起來。

七ERD → 關聯表的轉換

將 ERD 轉成關聯式表格，依下列規則：

  • 強實體 → 一張表：簡單屬性變欄位、主鍵變表主鍵；複合屬性只取最小組成當欄位；衍生屬性通常不儲存。
  • 多值屬性 → 另立一張表：新表 = ｛多值屬性 ＋ 原實體主鍵（FK）｝，兩者組成複合主鍵。
  • 弱實體 → 一張表：含自身屬性 ＋ 所依賴強實體的主鍵（FK）；主鍵 = 強實體主鍵 ＋ 自身部分鍵。
  • 1:1：把一方主鍵當外來鍵放到另一方（通常放「全部參與」那方）。
  • 1:N：把「1」方主鍵當外來鍵，放到「N」方的表；關係屬性也放在 N 方。
  • M:N：另立中間表 = ｛雙方主鍵（皆為外來鍵）｝；主鍵 = 兩外來鍵的複合鍵；關係屬性放此表。

範例（承本篇「員工–部門–眷屬」ERD；底線為主鍵）

  • 部門（部門編號、名稱）
  • 員工（員工編號、姓名、生日、地址_縣市、地址_路名、部門編號 FK、到職日）
  • 員工電話（員工編號 FK、電話）　← 多值屬性「電話」另立表
  • 眷屬（員工編號 FK、姓名、…）　← 弱實體，主鍵 = 員工主鍵 ＋ 部分鍵
  • 「年齡」為衍生屬性，不儲存。
💡 理解（一句話）實體變表、屬性變欄；關係看基數——1:N 把外來鍵放 N 方、M:N 另立中間表。多值屬性與弱實體都各自獨立成一張表。

八結論

ERD 以實體（矩形）、屬性（橢圓）、關係（菱形）三大元素描述概念設計；再透過弱實體、各類屬性、識別關係、基數與參與等細項，完整表達資料語意，作為轉換成關聯式表格的藍圖。

⚠️ 考點提醒
  • 三大元素符號：實體=矩形、屬性=橢圓、關係=菱形（最基本，必記）。
  • 雙框 = 弱：弱實體用雙矩形、識別關係用雙菱形。
  • 屬性外框決定種類：底線=主鍵、虛線底線=部分鍵、雙橢圓=多值、虛線橢圓=衍生。
  • 雙線（參與）≠ 雙框（弱），勿混淆。
  • M:N 不能直接存，須拆中間表，主鍵為兩 FK 的複合鍵。
  • ERD 由 Peter Chen 於 1976 年提出。
  • ERD 轉表：1:N 外來鍵放 N 方；M:N 另立中間表（複合主鍵）；多值屬性、弱實體各自獨立成表。
