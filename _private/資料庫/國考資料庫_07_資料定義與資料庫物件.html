一先搞懂：資料表與「建表」是什麼

一張資料表（Table）就像一張 Excel 表格：每一列（row）是一筆資料、每一欄（column）是一個欄位。例如 student 表，每列代表一個學生，欄位有「學號、姓名、成績…」。

建立資料表（CREATE TABLE）就是在資料庫裡開一張新表，並把三件事講清楚：有哪些欄、每欄放什麼型別的資料、套用哪些規則（約束）。本講義先教怎麼建表（含約束），再介紹兩個常用物件：VIEW（虛擬表）與 INDEX（索引）。

💡 名詞定位這些「建立／修改／刪除結構」的指令屬於 DDL（資料定義語言），和講義 08／09「對資料增刪改查」的 DML 是不同層次：DDL 蓋房子（定義結構）、DML 搬家具（操作資料）。

二CREATE TABLE 與資料型別

基本語法：CREATE TABLE 表名 ( 欄名 型別 [約束], … );

每個欄位都要指定資料型別，告訴資料庫這欄放什麼種類的資料：

類別型別說明
整數INT整數，如年齡、數量
精確小數DECIMAL(p,s)金額、成績（見講義 08）
定長文字CHAR(n)固定 n 個字元
變長文字VARCHAR(n)最多 n 字元，實際多長就佔多長
日期／時間DATE / DATETIME日期 / 日期＋時間
CREATE TABLE student ( id CHAR(8), name VARCHAR(20) );
💡 CHAR 還是 VARCHAR？CHAR(10) 存「abc」也固定佔 10 格；VARCHAR(10) 存「abc」只佔 3。長度固定（如身分證字號）用 CHAR；長度不定（如姓名、地址）用 VARCHAR。

三六種約束（Constraints）

約束是資料庫幫你「把關」的規則，確保存進去的資料不會亂。國考常考下面六種：

約束作用範例寫法
PRIMARY KEY
主鍵		每列的唯一身分，不可重複、不可空id CHAR(8) PRIMARY KEY
FOREIGN KEY
外來鍵		指向另一張表的主鍵，確保關聯有效FOREIGN KEY (sid) REFERENCES student(id)
NOT NULL
非空		此欄一定要有值，不能留白name VARCHAR(20) NOT NULL
UNIQUE
唯一		此欄不可重複（但可留空）email VARCHAR(50) UNIQUE
CHECK
檢查		值必須滿足自訂條件CHECK (score BETWEEN 0 AND 100)
DEFAULT
預設		沒給值時自動填入預設值status VARCHAR(10) DEFAULT '在學'
💡 外來鍵到底在做什麼它強制「子表的值必須在父表存在」。例如 enrollment 表的 student_id 必須是 student 表裡真的有的學號 —— 這樣就不會出現「幫一個不存在的學生選課」。父表那筆被刪除時的處理方式：ON DELETE CASCADE（子表一起刪）、SET NULL（子表設為空）、RESTRICT（禁止刪除）。
💡 主鍵 vs UNIQUE（必考差異）兩者都保證「不重複」，差別在：主鍵還要「不可空」且「一張表只能一個」；UNIQUE 則「可以空」且「一張表可以有多個」。

四完整建表範例（申論標準寫法）

把約束組合起來，這就是申論題「請寫出建立資料表的 SQL」的標準答案形式：

CREATE TABLE student ( id CHAR(8) PRIMARY KEY, -- 主鍵 name VARCHAR(20) NOT NULL, -- 不可空 email VARCHAR(50) UNIQUE, -- 不可重複 score DECIMAL(5,2) CHECK (score BETWEEN 0 AND 100), -- 限 0~100 status VARCHAR(10) DEFAULT '在學' -- 預設「在學」 ); CREATE TABLE enrollment ( id INT PRIMARY KEY, student_id CHAR(8) NOT NULL, course VARCHAR(30), FOREIGN KEY (student_id) REFERENCES student(id) ON DELETE CASCADE -- 學生被刪，其選課一併刪 );
💡 怎麼讀這段每一行＝「欄名　型別　約束」。enrollment 最後一行的外來鍵，把 student_id「綁」到 student 表的 id；有了它，資料庫就不准你新增一筆對不到任何學生的選課。

五VIEW 檢視表

VIEW（檢視表）是一張「虛擬的表」：它本身不存資料，存的是一段 SELECT 查詢。每次你查這個 VIEW，資料庫就即時跑那段查詢把結果給你看。

虛線框＝虛擬。VIEW 不另存資料，查它時資料庫即時跑那段 SELECT
CREATE VIEW passed_student AS SELECT name, score FROM student WHERE score >= 60;

之後就能像查一般表一樣使用：SELECT * FROM passed_student;

為什麼要用 VIEW

  • 簡化：把複雜的多表 JOIN 包成一個名字，之後直接查這個 VIEW。
  • 安全：只開放部分欄位給某些使用者（例如隱藏薪資欄）。
  • 邏輯獨立：底層表改了，VIEW 仍可維持原本的查詢介面。
💡 可更新性（考點）簡單的 VIEW 可以透過它去改底層資料；但含 JOIN、GROUP BY、彙總函式、DISTINCT 的 VIEW 通常不可更新（因為改了無法對應回唯一一筆原始資料）。

六INDEX 索引

INDEX（索引）是替某欄位額外建立的「查找結構」，讓資料庫能快速定位，不必把整張表一列一列掃過。

💡 用書本理解索引就像書本後面的「索引頁」。要找「正規化」這個詞，你不會從第一頁翻到最後，而是查書末索引 → 直接翻到那一頁。資料庫索引同理：先查索引、再直接取資料。

建立語法（內部通常用 B-tree／B+tree 結構）：

CREATE INDEX idx_student_name ON student(name);

兩種索引（考點）

  • 叢集索引（Clustered）：決定資料的「實體排列順序」，一張表只能有一個（像書的內容本身就按章節順序排）。
  • 非叢集索引（Non-clustered）：另外建一份「欄位值 → 位置」的對照，一張表可有多個（像書末另附的索引頁）。

優缺點（為什麼不是每欄都建）

  • 優點：查詢（WHERE、JOIN、ORDER BY）大幅變快。
  • 缺點：占額外儲存空間；且每次新增／修改／刪除資料，索引也要跟著更新 → 寫入變慢。
  • 所以只在「經常用來查詢」的欄位建索引，而非全部。

七結論

建表要講清楚三件事：欄位、型別、約束；六種約束（主鍵、外來鍵、NOT NULL、UNIQUE、CHECK、DEFAULT）替資料正確性把關。VIEW 是不存資料的虛擬表（用於簡化、安全、邏輯獨立）；INDEX 是加速查詢的查找結構（讀快、寫慢）。這些屬於 DDL／資料庫物件，補上後 SQL 三條主線——定義、操作、查詢——就到齊了。

⚠️ 考點提醒
  • 六種約束：PRIMARY KEY（唯一＋非空）、FOREIGN KEY（參照他表主鍵）、NOT NULL、UNIQUE、CHECK、DEFAULT。
  • 主鍵 vs UNIQUE：主鍵唯一＋不可空＋一表一個；UNIQUE 唯一＋可空＋可多個。
  • 外來鍵確保參照完整性；刪父表列可設 ON DELETE CASCADE／SET NULL／RESTRICT。
  • VIEW 是虛擬表（不存資料）；含 JOIN／GROUP BY／彙總 通常不可更新。
  • INDEX 加快讀取、拖慢寫入；叢集（實體排序、一個）vs 非叢集（對照、多個）；常用 B-tree／B+tree。
