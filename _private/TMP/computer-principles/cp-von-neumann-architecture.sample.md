# 馮紐曼架構教材樣張

## [必背] 兩大特色

馮紐曼架構(Von Neumann Architecture)：一種電腦組織方式，主張「程式」與「資料」都放在同一套記憶體中，並由中央處理器依序讀取與執行指令。

第一個特色是程式內儲概念(Stored-Program Concept)：程式指令與資料都儲存在記憶體(Memory)中。記憶體是用來保存指令與資料的儲存單元。這個概念重要，因為電腦不必為每一種任務重新接線，只要更換記憶體中的程式，就能執行不同工作，是現代通用電腦的基礎。

第二個特色是指令循序執行(Sequential Instruction Execution)：中央處理器(Central Processing Unit, CPU)通常依照記憶體位址順序，進行取指令、解碼、執行。取指令(Fetch)是把指令從記憶體取到 CPU；解碼(Decode)是判斷指令要做什麼；執行(Execute)是完成運算、存取或控制動作。例外情況是跳躍指令(Jump Instruction)：改變下一個執行位置；以及中斷(Interrupt)：外部或內部事件暫停目前流程，轉去處理特定事件。

最小背誦句：馮紐曼架構的兩大特色是程式與資料共用記憶體，CPU 通常依序取指、解碼、執行。

國考作答模板：馮紐曼架構是一種以程式內儲為核心的電腦架構，程式與資料皆存於同一記憶體，CPU 依序取出指令並完成解碼與執行；除非遇到跳躍或中斷，才會改變執行順序。

易錯提醒：不要寫成「程式存在 CPU 裡」。CPU 負責處理，記憶體才是存放程式與資料的主要位置。

## [必背] 五大單元

馮紐曼架構可分成五大單元。輸入單元(Input Unit)：將外部資料或命令送入電腦，例如鍵盤、滑鼠、感測器。輸出單元(Output Unit)：將處理結果送出，例如螢幕、印表機。記憶單元(Memory Unit)：保存程式、資料與運算結果。算術邏輯單元(Arithmetic Logic Unit, ALU)：執行加減乘除、比較、AND、OR 等算術與邏輯運算。控制單元(Control Unit, CU)：負責解讀指令並協調各單元動作。

五大單元重要，是因為國考常用它檢查考生是否理解「電腦如何完成一次處理」。輸入資料先進入記憶體，CPU 中的 CU 決定要執行哪個指令，ALU 負責運算，結果再放回記憶體或送到輸出單元。

最小背誦句：馮紐曼五大單元為輸入、輸出、記憶、ALU、CU。

國考作答模板：馮紐曼架構由輸入單元、輸出單元、記憶單元、算術邏輯單元與控制單元組成，其中 ALU 負責運算，CU 負責控制與協調，記憶單元負責存放程式與資料。

易錯提醒：ALU 與 CU 合起來通常屬於 CPU 的核心部分，但記憶體不是 CPU 的一部分。

## [比較] 馮紐曼架構 vs 哈佛架構

哈佛架構(Harvard Architecture)：一種將程式記憶體與資料記憶體分開的電腦架構，因此取指令與取資料可使用不同通道。

| 比較項目 | 馮紐曼架構 | 哈佛架構 |
|---|---|---|
| 程式與資料 | 共用同一記憶體 | 分開存放 |
| 匯流排 | 常共用匯流排 | 指令與資料可分開通道 |
| 優點 | 設計簡單、彈性高 | 可同時取指令與資料 |
| 缺點 | 容易發生傳輸瓶頸 | 設計較複雜 |
| 常見場景 | 一般電腦概念模型 | 嵌入式系統、快取設計 |

匯流排(Bus)：連接 CPU、記憶體與輸入輸出裝置的資料傳輸通道。兩者差異的原因在於記憶體與傳輸通道是否分離。馮紐曼架構共用記憶體與匯流排，硬體設計較簡單，但 CPU 取指令與取資料會競爭同一通道。哈佛架構分離指令與資料路徑，因此效率可能較高。

考試常問法：哪一種架構容易產生馮紐曼瓶頸？答案抓「程式與資料共用記憶體或匯流排」。哪一種架構可同時取指令與資料？答案抓「哈佛架構、分離記憶體」。

判斷關鍵字：共用、同一記憶體、同一匯流排，通常指馮紐曼；分離、同時取指令與資料，通常指哈佛。

## [必背] 馮紐曼瓶頸

馮紐曼瓶頸(Von Neumann Bottleneck)：CPU 與記憶體之間資料傳輸速度不足，導致 CPU 等待資料或指令，整體效能受限的現象。

它重要是因為 CPU 運算速度通常比記憶體存取速度快很多。如果 CPU 很快，但資料送不進來，就像考生會算題卻一直拿不到題目，實際速度仍被資料傳輸限制。

常見解法包括快取(Cache)：位於 CPU 與主記憶體之間的高速小容量記憶體，用來保存常用資料；預取(Prefetching)：事先把可能會用到的指令或資料取入；增加匯流排寬度(Bus Width)：一次傳更多位元；提高記憶體頻寬(Memory Bandwidth)：增加單位時間可傳輸資料量；管線化(Pipelining)：將指令處理分成多階段重疊執行；平行處理(Parallel Processing)：同時執行多個工作；記憶體階層(Memory Hierarchy)：用暫存器、快取、主記憶體、輔助儲存裝置形成速度與容量的層級。

最小背誦句：馮紐曼瓶頸是 CPU 與記憶體傳輸速度不足，使 CPU 等待資料。

國考作答模板：馮紐曼瓶頸來自程式與資料共用記憶體及傳輸通道，當 CPU 存取記憶體速度跟不上運算速度時，會造成等待；可透過快取、預取、增加頻寬、管線化與記憶體階層改善。

易錯提醒：瓶頸不是指 CPU 不會運算，而是資料與指令供應速度不足。

## [會畫] 馮紐曼資料流

可背繪圖順序：先畫輸入單元，再畫記憶體，中央畫 CPU，CPU 內分成 CU 與 ALU，接著畫回記憶體，最後畫輸出單元。

```text
輸入單元
   ↓
記憶體
   ↓
CPU：控制單元 CU  +  算術邏輯單元 ALU
   ↓
記憶體
   ↓
輸出單元
```

箭頭一「輸入 → 記憶體」代表外部資料或程式被送入並暫存。箭頭二「記憶體 → CPU」代表 CPU 從記憶體取出指令與資料。箭頭三「CPU 內 CU/ALU」代表 CU 控制流程，ALU 執行運算。箭頭四「CPU → 記憶體」代表運算結果或中間結果存回記憶體。箭頭五「記憶體 → 輸出」代表處理完成的結果送到輸出設備。

考試畫圖時，重點不是美觀，而是必須看出「程式與資料在記憶體中，CPU 從記憶體取用，處理後再回存或輸出」。這就是馮紐曼架構資料流的最低得分關鍵。
