Normalization（1NF ～ BCNF ～ 5NF）

一定義、目的與三種異常

正規化（Normalization）是依據函數相依（Functional Dependency），將關聯表逐步分解，以消除資料重複與更新異常的設計程序。目的是讓每個事實只儲存一次，避免下列三種異常：

  1. 新增異常（Insertion Anomaly）：因缺少其他資料而無法新增某筆資料。
  2. 刪除異常（Deletion Anomaly）：刪除某筆資料時，連帶遺失其他不該遺失的資訊。
  3. 修改異常（Update Anomaly）：同一資訊重複存放，修改時須改多處，易造成不一致。

二低階正規化（1NF ～ 3NF）

（一）第一正規化 1NF

要求：所有欄位值皆為單一值（atomic），不可有重複群組或多值欄位。

處理方式：將非原子的欄位拆成單一值；若為重複群組，則把該群組分離成新關聯，並以原表主鍵作為外來鍵連結。

範例（違反 → 修正）

學號姓名電話
S01王小明0912-111、0922-222
S02李小華0933-333

問題：S01 的「電話」一格塞了兩個值，違反 1NF（欄位值不是單一值）。

處理後（把電話另立一張表，每格只放單一值）：

  • 學生（學號、姓名）
  • 學生電話（學號 FK、電話）　主鍵 = {學號, 電話}

（二）第二正規化 2NF

要求：在 1NF 之上，消除「部分相依」——非主屬性不可只依賴複合主鍵的一部分。（只有複合主鍵的表才可能違反 2NF）

處理方式：找出部分相依，將「該部分主鍵及其所決定的非主屬性」取出另立新關聯（以該部分鍵為主鍵），原關聯刪除這些非主屬性、保留該部分鍵作為外來鍵。

範例（違反 → 修正）

原表：選課（學號, 課號, 成績, 課名），主鍵 = {學號, 課號}。函數相依：

  • {學號, 課號} → 成績　需要兩個鍵才能決定 → 完全相依（OK）
  • 課號 → 課名　只靠課號就能決定 → 部分相依（違反 2NF）

為何違反：課名只依賴主鍵的「一部分」（課號），不是整個主鍵。

處理後（把「課號＋課名」抽出另立表，原表保留課號當外來鍵）：

  • 選課（學號、課號、成績）　主鍵 = {學號, 課號}；課號 為 FK → 課程
  • 課程（課號、課名）

（三）第三正規化 3NF

要求：在 2NF 之上，消除「遞移相依」——非主屬性不可依賴另一個非主屬性。

處理方式：將遞移相依中「非鍵的決定因素及其相依屬性」取出，建立新關聯（以該決定因素為主鍵），並將相依屬性自原關聯刪除，保留該決定因素作為外來鍵。

範例（違反 → 修正）

原表：學生（學號, 系所, 系主任），主鍵 = {學號}。函數相依：

  • 學號 → 系所（學生屬於某系）
  • 系所 → 系主任（系決定系主任）
  • ⇒ 推得 學號 → 系主任，為遞移相依

為何違反：系主任（非主屬性）是透過「系所」間接依賴主鍵，即依賴另一個非主屬性。

處理後（把「系所＋系主任」抽出另立表，原表保留系所當外來鍵）：

  • 學生（學號、系所 FK）
  • 系所（系所、系主任）
💡 理解（一句話記 2NF／3NF ＋ 共通解法）2NF 趕走「只靠半把鑰匙就能決定的欄位」（部分相依）；3NF 趕走「靠另一個非鍵欄位就能決定的欄位」（遞移相依）。
解法共通模式：2NF／3NF／BCNF 都是同一招——把「決定因素 ＋ 被它決定的屬性」搬到新表（決定因素當主鍵），原表保留該決定因素當外來鍵。

三高階正規化：BCNF

BCNF（Boyce-Codd 正規化）：對每一個非顯然的函數相依 X → A，X 都必須是「超鍵」（即每個決定因素都是超鍵）。比 3NF 更嚴格。

3NF 與 BCNF 的差別：3NF 允許「X → A 中 A 是主屬性」即可（即使 X 不是超鍵）；BCNF 不允許這個例外。

處理方式：找出違反的函數相依 X → Y（X 非超鍵），將 {X 及 Y} 取出另立新關聯（X 為主鍵），原關聯刪除 Y、保留 X 作為外來鍵。此分解保證無損，但可能犧牲相依保存。

經典例：符合 3NF 但違反 BCNF

指導(學生, 科目, 老師)，已知 {學生,科目} → 老師、老師 → 科目。候選鍵為 {學生,科目} 與 {學生,老師}，故學生、科目、老師皆為主屬性。

  • 檢查 老師 → 科目：老師不是超鍵，但科目是主屬性 → 符合 3NF。
  • 同一條 老師 → 科目：老師不是超鍵 → 違反 BCNF。

處理後（依違反的 老師 → 科目 拆解）：

  • 授課（老師、科目）
  • 指導（學生、老師）

注意：此分解無損，但原相依 {學生,科目} → 老師 跨兩表、無法保存——正是「BCNF 不保證相依保存」之例（詳見第五節）。

💡 理解（BCNF 為何更嚴）3NF 留了一個後門——只要被決定的是主屬性就放行；BCNF 把這個後門關上，要求所有決定因素都必須是超鍵。

四4NF 與 5NF（簡述）

  • 4NF：在 BCNF 之上，消除多值相依（Multivalued Dependency, MVD）。當一個實體有兩組互相獨立的多值屬性存在同一表時會產生重複。處理方式：將彼此獨立的多值屬性，各自與鍵組成獨立關聯。範例：員工(員工, 技能, 語言)，技能與語言彼此獨立 → 拆成 員工-技能、員工-語言。
  • 5NF（又稱 PJNF）：在 4NF 之上，消除合併相依（Join Dependency），處理必須拆成三張以上表才能無損還原的特殊情形。實務罕見，了解即可。

五無損分解與相依保存 ★高頻

分解關聯表時有兩個目標：

  • 無損分解（Lossless-join）：分解後再 JOIN 回來，不會多出或遺失資料。
  • 相依保存（Dependency Preservation）：原本的函數相依，分解後仍能在各表內檢查。

關鍵結論：

  • 分解到 3NF：一定能同時做到「無損分解」與「相依保存」。
  • 分解到 BCNF：一定能「無損分解」，但不保證相依保存。
  • 因此當 BCNF 分解會破壞相依保存時，常選擇停在 3NF。

承上例：指導表拆成 (老師,科目) 與 (學生,老師) 雖無損，但 {學生,科目} → 老師 跨兩表、相依無法保存。

六正規化階梯與優缺點

由下而上：每層消除一種相依、限制更嚴格，且包含下層（符合 3NF 必符合 2NF、1NF）

優缺點

  • 優點：消除三種異常、降低資料重複、提升一致性。
  • 缺點：表格變多、查詢需大量 JOIN、查詢效能下降；故實務有時刻意反正規化（Denormalization），以空間換取查詢速度。

七結論

正規化以函數相依為依據，從 1NF 逐步消除部分相依（2NF）、遞移相依（3NF）、非超鍵決定因素（BCNF）、多值相依（4NF）。其中 3NF 兼顧無損與相依保存，是實務最常採用的平衡點。

⚠️ 考點提醒
  • 各階消除的相依：1NF 原子性；2NF 部分相依；3NF 遞移相依；BCNF 決定因素須為超鍵；4NF 多值相依。
  • 只有複合主鍵的表才可能違反 2NF。
  • 3NF 保證無損＋相依保存；BCNF 保證無損但不保證相依保存（最高頻）。
  • 3NF 形式定義：對每個非顯然 X→A，X 為超鍵 或 A 為主屬性。
  • 反正規化是為了提升查詢效能（以空間換時間）。
