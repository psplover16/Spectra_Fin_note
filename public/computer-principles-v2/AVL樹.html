Ⅰ　地基

⓪ 定義:高度與平衡因子【硬背】

高度 h(x)

h(x) = 以 x 為根的那棵子樹的高度。

每個節點都是「某一棵子樹的根」→ 每個節點都有自己的高度。平常講的「樹高」,只是 h(根節點) 這個特例。

寫法意思值
h(null)空樹0
h(葉節點)它自己就是一棵單節點的樹1
h(root)整棵樹樹高

遞迴式

h(x) = 1 + max( h(x.left), h(x.right) )        基底:h(null) = 0
        ↑                ↑
     x 自己那一層     取比較深的那邊

h(葉) = 1 + max(0, 0) = 1 ← 不是規定,是「h(null) = 0」的必然推論。

平衡因子 BF(x)

BF(x) = h(x.left) − h(x.right)

合法值只有 −1 / 0 / +1。出現 ±2 就是失衡。正號 = 左邊高(+2 → 左邊太重 → 往右扳)。

實際標一次

        50 (h=3)
      /         \
   30 (h=2)    70 (h=1)
   /      \
20 (h=1)  40 (h=1)
節點算式BF
50h(30) − h(70) = 2 − 1+1
30h(20) − h(40) = 1 − 10
20 40 70h(null) − h(null) = 0 − 00

樹高 = h(50) = 3

⚠️ BF(50) 用的是 30 和 70 各自的高度,不是樹高。

這就是為什麼每個節點都要存一個 height 欄位。

const h  = (n) => (n ? n.height : 0);          // ← h(null) = 0 在這裡實作
const bf = (n) => (n ? h(n.left) - h(n.right) : 0);

為什麼「葉 = 1」和「空 = 0」必須差 1?

BF 的作用就是分辨「這邊有一個節點」和「這邊什麼都沒有」。

   P
  /
 L        ← L 是葉,P 的右邊是空的
BF(P)結果
正確(葉=1、空=0)1 − 0 = +1判定左重 ✔
錯誤(葉也算 0)0 − 0 = 0誤判為完美平衡 ✗

用 1/0 還是 0/−1 都行 —— 只要差 1。

所以 BF 與旋轉判斷完全不受高度約定影響(見 ⑧)。

高度 vs 深度

從哪量到哪根葉
深度 depth(x)從根往下數到 x0最大
高度 h(x)從 x 往下數到最遠的葉樹高1

方向相反、起點不同。「根的深度 = 0」和「根的高度 = 3」同時成立。

① 三句話定生死【理解】

  1. AVL 只管「何時該轉」(|BF| ≥ 2 就轉);「怎麼轉」是旋轉自己的規則,普通 BST 就有。
  2. 旋轉 = 父子上下對調,不是轉圈。
  3. 中序順序永遠不變 —— 這是旋轉的鐵律,也是唯一的驗算工具。

Ⅱ　考場核心

② 旋轉通用公式(只背這兩張圖)【硬背】

右旋(修 BF = +2,左歪)

        P                              L
       / \                            / \
      L   c    ──右旋(P)──►         a   P
     / \                                / \
    a   b                              b   c

兩邊中序都是 a < L < b < P < c

步驟動作
①L 升上來當家長(L = P.left)
②P 掉下去當 L 的右小孩 → 所以叫「右」旋
③b 換邊:L.right → P.left

左旋(修 BF = −2,右歪)—— 完全鏡像

        P                              R
       / \                            / \
      a   R    ──左旋(P)──►          P   c
         / \                        / \
        b   c                      a   b

兩邊中序都是 a < P < b < R < c

左右對照【硬背】

右旋左旋
誰升上去左小孩 L右小孩 R
P 往哪倒往右倒往左倒
b 是誰L.rightR.left
b 換到哪P 的左邊P 的右邊

一句話統一

b 永遠是「升上去那個節點,靠近 P 那一側的子樹」,永遠搬到「P 空出來的那一側」。

把紙翻面,兩張圖是同一張。

b 的三個真相(最常誤解)

  1. b 是一個「位置」,不是特定節點。 對誰旋轉,b 就換人。
  2. b 常常是 null —— 三節點的小例子裡它全是空的,所以你看不見它,不代表它不存在。
  3. b 不需要動態判斷。 用指標抓(L.right),不比大小。rotateRight 裡連一個 if 都沒有。

⚠️ 名字的坑

右旋抬上去的是「左」小孩。

名字講的是「舊家長往哪邊倒」,不是「你把東西移去哪邊」。

Ⅲ　流程

⑤ 插入流程【練流程】

  1. 照 BST 規則走到底(小往左、大往右),新節點掛在 null 的位置,一定是葉,h = 1
  2. 沿著剛才走下來的那條路徑往回,逐層更新 h、算 BF(其他旁支完全不用碰)
  3. 找最低的(第一個)|BF| ≥ 2 的節點 ★
  4. 查表 ③ → 旋轉 → 結束

插入最多 1 組旋轉。 修好 ★ 之後,子樹高度還原成插入前 → 上層自動歸位。

插入 SOP(圖解流程)

跟刪除同一套回溯;差別只在:插入碰到失衡就轉 1 組、轉完立刻收工,不會連鎖。

顏色的意思

灰前置 / 計算(BST 插入、更新高度與 BF)
琥珀判斷(是否平衡、查表分型)
藍單旋(LL 右旋 / RR 左旋)
紫雙旋(LR / RL,先橋直再轉)
珊瑚仍平衡 → 往上一層,迴圈回 ①
青旋轉後 or 走到根 → 結束

四型旋轉速查

+2 / 較高子 +1 或 0右旋(LL,單旋)
+2 / 較高子 −1LR:先對左小孩左旋,再對失衡點右旋
−2 / 較高子 −1 或 0左旋(RR,單旋)
−2 / 較高子 +1RL:先對右小孩右旋,再對失衡點左旋
和刪除最大的差異:插入修好失衡點後,子樹高度還原成插入前 → 上層 BF 不變、不可能再失衡 → 最多 1 組旋轉、絕不連鎖。圖中只有「仍平衡」那條路會往上迴圈;一旦旋轉就直接收工。

⑥ 刪除 SOP【練流程】

第一步|找出「真正要刪的節點」

設 D = 你要刪的那個值所在的節點。

D 的小孩數做什麼
0移除 D
1把那個小孩接到 D 原本的位置
2從 D.right 一路往左走到底,得到 S。把 S 的值抄進 D。改成去刪 S(S 一定只有 0 或 1 個小孩,套上面兩列)

被移除節點的父親 = 你的起點。

第二步|從起點往上,一路做到根

對路徑上的每一個節點,依序做四件事:

① 重算高度

h = 1 + max( h(左小孩), h(右小孩) )

左右小孩的高度直接讀,不用重算。空的算 0。

② 算 BF

BF = h(左小孩) − h(右小孩)

③ 判斷

  • |BF| ≤ 1 → 不動,跳到 ④
  • |BF| = 2 → 看較高的那個小孩的 BF,查表旋轉:
這個節點 BF較高子 BF做什麼
+2+1 或 0對這個節點右旋
+2−1先對左小孩左旋,再對這個節點右旋
−2−1 或 0對這個節點左旋
−2+1先對右小孩右旋,再對這個節點左旋

④ 往上一層,回到 ①

直到處理完根節點為止。

就這樣。

不用管「高度有沒有變」「要不要提早停」—— 那是省時間的優化。手算時一路做到根,答案一定對。

(選配)提早停手的規則

考試時間不夠、或考卷問「連鎖到哪一層」才需要:

這一層發生了什麼子樹高度可以停?
沒失衡,h 沒變不變停
沒失衡,h 少 1矮 1往上
單旋,較高子 BF = ±1矮 1往上
單旋,較高子 BF = 0不變停
雙旋(LR / RL)矮 1往上

「較高子 BF = 0」只發生在刪除。它同時代表歸單旋和連鎖到此為止。

⑦ 插入 vs 刪除(超高頻)【理解】

修完一次之後結果
插入子樹高度還原成插入前上層無感 → 收工,最多 1 組
刪除子樹高度可能又矮一層上層要重算 → 連鎖,最壞 O(log n) 組

這是同一份程式碼跑出來的:rebalance() 寫在遞迴的回程,從動過的位置一路呼叫到根。插入時上層 BF 自然正常,不會轉;刪除時上層可能真的失衡,就會再轉。

Ⅳ　收尾

⑧ 唯一要背的公式:N(h)

N(h) = N(h−1) + N(h−2) + 1　　N(0) = 0、N(1) = 1

白話:前兩項相加,再 +1

其他所有數字,都從這條式子(加上 h(x) = 1 + max(左,右) 和 |BF| ≤ 1)推出來。

一、N 是什麼?

N 只是一個函數的名字,像數學課的 f(x)。

N(h) = 「高度是 h 的 AVL 樹,最少要幾個節點」

  • N 取自 Number(節點數)
  • 括號裡是輸入(高度),算出來是輸出(節點數)
  • N(h−1)、N(h−2) 是同一個函數,只是餵不同高度進去
寫法唸成值
N(4)高度 4 的樹,最少幾個節點7
N(5)高度 5 的樹,最少幾個節點12

有些課本寫 n(h)、T(h)、minNodes(h) —— 同一個東西。

二、遞迴式怎麼來的(用推的,不用背)

要撐出 h 層,根節點底下:

        根                  ← 那個 +1(根自己)
       /   \
   高 h−1   高 h−2
   N(h−1)   N(h−2)
  • 一邊必須有 h−1 層(不然撐不到 h 層)→ 用最瘦的,N(h−1) 個
  • 另一邊愈矮愈省料,但 |BF| ≤ 1 只准差 1 層 → 最矮只能是 h−2 層 → N(h−2) 個

整條式子的靈魂只有一句:AVL 只准左右差一層,所以矮的那邊只能矮一層,不能更矮。

基底(直接從高度約定看出來)

意思節點數
N(0)空樹0
N(1)單一節點1

六、三種用法

用法 ①|正問:高度 h,最少幾個節點?

「高度為 6 的 AVL 樹,最少有幾個節點?」

查表 → N(6) = 20

用法 ②|反問:n 個節點,最高幾層?(最常考)

「一棵 AVL 樹有 1000 個節點,樹高最多是多少?」

做法:找最大的 h 使 N(h) ≤ n

N(13) = 609  ≤ 1000  ✔
N(14) = 986  ≤ 1000  ✔
N(15) = 1596 > 1000  ✘   ← 超過

→ 最高 14 層

原理:要長到 15 層,至少得有 1596 個節點。手上只有 1000 個,撐不起來。

再練一次:n = 100 → N(9) = 88 ≤ 100、N(10) = 143 > 100 → 最高 9 層

用法 ③|判斷題:這棵樹可能存在嗎?

N(h) 給下界,2^h − 1(滿二元樹)給上界:

高度 h 的 AVL 樹,節點數必定滿足　N(h) ≤ n ≤ 2^h − 1

h最少 N(h)最多 2^h − 1合法範圍
3474 ≤ n ≤ 7

6206320 ≤ n ≤ 63

例:「高度 5 的 AVL 樹有 10 個節點」→ N(5) = 12 > 10 → 節點不夠 → 錯

「葉節點高度 = 0」「空子樹高度 = −1」「2^(h+1) − 1」約定 B

台灣課本傳統(root 為 level 1)偏 約定 A;演算法課(CLRS / Weiss)用 約定 B。

題目沒講就自己在卷上寫一行約定,不會扣分,自己也不會算亂。

⑨ 七大陷阱【硬背】

#陷阱正解
1一看到根失衡就下手從最低往上找第一個 |BF| ≥ 2
2樹長得歪就以為失衡一定要算 BF,|BF| ≤ 1 就合法
3+2 就直接右旋先看較高子的 BF,異號要先橋直
4雙旋只轉一次LR / RL 一定是 2 次基本旋轉
5以為右旋抬的是右小孩抬的是左小孩
6刪除只修一層就收工一路回溯,可能連鎖
7以為 b 要看數值判斷搬哪b 固定 = L.right(右旋)/ R.left(左旋),零判斷

高頻是非題

敘述答案理由
插入一定要旋轉✗沒失衡就不轉
刪除一定要旋轉✗同上
AVL 刪除最多一組旋轉✗那是插入的性質
雙旋可用一次單旋取代✗之字形轉一次仍失衡
旋轉會改變中序結果✗中序永不變
中序後繼可能有兩個小孩✗它是最左者,沒有左小孩
AVL 一定比紅黑樹快✗只有查詢通常較快

⑩ 實作 checklist(申論 / 程式題)【練流程】

function rotateRight(P) {          function rotateLeft(P) {
  const L = P.left;                  const R = P.right;
  const b = L.right;   // 換邊       const b = R.left;    // 換邊
  L.right = P;         // P 下來      R.left  = P;        // P 下來
  P.left  = b;         // b 換邊      P.right = b;        // b 換邊
  update(P);           // 先「下」     update(P);          // 先「下」
  update(L);           // 再「上」     update(R);          // 再「上」
  return L;            // 新根        return R;           // 新根
}                                  }

rebalance 就是判斷表 ③ 的翻譯

BF > 1   → 若 bf(左子) < 0  先左旋左子(LR)  → 再對自己右旋
BF < -1  → 若 bf(右子) > 0  先右旋右子(RL)  → 再對自己左旋
檢查點錯了會怎樣
update() 先下後上高度永遠錯,不報錯,樹會慢慢歪
旋轉函式要 return 新根子樹整棵斷線
insert / remove 回程都 rebalance刪除的連鎖旋轉不會發生
刪除兩個小孩時只搬 key指標亂掉、子樹遺失
h(null) 回傳 0(不是 -1)與 height: 1 的葉節點約定衝突

⑪ 考場最後 60 秒

  1. 找失衡點 ★:從最低往上,第一個 |BF| ≥ 2
  2. 判類型:★ 與較高子 ◆ 同號單旋、異號雙旋
  3. 定方向:跟歪的那邊相反(左歪右轉)
  4. 畫旋轉:
    • 右旋 → 填 P L a b c,b(= L.right)搬到 P 的左邊
    • 左旋 → 填 P R a b c,b(= R.left)搬到 P 的右邊
  5. 驗算:唸一次中序,順序沒變就對了
  6. 刪除多做一步:子樹矮了往上,沒矮收工
