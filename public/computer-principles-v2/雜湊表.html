雜湊表 (Hash Table)

一、核心觀念與時間複雜度

雜湊表透過雜湊函數 (Hash Function) 將資料的鍵值 (Key) 轉換為陣列的索引值 (Index),達成極快速的資料存取。

  • Key(鍵):尋找資料的唯一識別碼(如:學號、身分證字號)。
  • Hash Function(雜湊函數):負責將 Key 轉換成 Index 的數學公式。
  • Bucket / Slot(儲存格):雜湊表陣列中的位置。

🌟 必考:時間複雜度 (Time Complexity)

運作情形搜尋 (Search)插入 (Insert)刪除 (Delete)
平均情況 (Average)O(1)O(1)O(1)
最差情況 (Worst)O(n)O(n)O(n)

最差情況成因:當所有 Key 經過計算都對應到同一個 Index(嚴重碰撞),雜湊表會退化成單向鏈結串列,必須從頭遍歷到尾。

二、常見雜湊函數設計法(附詳細推導範例)

好的雜湊函數必須計算快速,且能將資料均勻分布以減少碰撞。

1. 除算法 (Division Method) 🌟 出題率最高

  • 公式:h(k) = k mod m
  • 重要考點:表格大小 m 務必選擇質數(Prime Number),避免接近 2 的次方。
  • 範例:設 m = 11, k = 35。計算:h(35) = 35 mod 11 = 2。放入 Index 2。

2. 乘算法 (Multiplication Method)

  • 公式:h(k) = ⌊ m · (k · A mod 1) ⌋
  • 重要考點:此方法對 m 較不敏感,通常 m 可選用 2 的次方。常數 A 通常取 0 < A < 1(著名學者 Knuth 建議使用黃金比例的小數部分,約 0.618)。

📝 具體推導範例:設雜湊表大小 m = 1000,常數 A = 0.618,給定關鍵字 k = 12345。

  • 步驟 1(乘上常數):12345 · 0.618 = 7629.21。
  • 步驟 2(取小數部分):提取小數部分 0.21。
  • 步驟 3(乘上表大並向下取整):⌊ 1000 · 0.21 ⌋ = ⌊ 210 ⌋ = 210。
  • 結果:該資料將放入 Index 210。

3. 平方取中法 (Mid-Square Method)

  • 作法:將 Key 平方,擷取中間位數作為 Index。
  • 範例:設 m = 100 (需兩位數 Index),k = 45。計算:45² = 2025 → 取中間兩位數 02。放入 Index 2。

4. 摺疊法 (Folding Method)

  • 作法:將極長的 Key 分割成數個等長區段,再相加求 Index(超出表大則取餘數)。
  • 範例:設 m = 1000 (需三位數),k = 12345678。計算:12 + 345 + 678 = 1035 → 1035 mod 1000 = 35。放入 Index 35。

三、🌟 核心考區:載入因子與重新雜湊 (Rehashing)

當雜湊表不斷塞入資料,可用空間會越來越少,碰撞發生的機率會急遽上升。為了解決這個問題,我們需要了解「載入因子」與「重新雜湊」的運作機制。

1. 載入因子 (Load Factor, α)

這是用來評估雜湊表「有多擠」的指標。

  • 公式:α = n / m (n 為目前儲存的資料總數,m 為雜湊表的總格數)。
  • 物理意義:如果 α = 0.75,代表表格已經有 75% 被填滿了。
  • 國考重點(容忍度差異):
    • 開放定址法:α 絕對不能大於 1。通常當 α 超過 0.5 ~ 0.7 時,效能就會大幅滑落,必須進行擴充。
    • 鏈結法:α 可以大於 1(因為格子裡塞的是指標)。但 α 過高意味著 Linked List 變得很長,搜尋時間一樣會退化。

2. 重新雜湊 (Rehashing)

當 α 超過系統設定的危險閾值時,雜湊表必須進行「大搬家」,這個過程稱為 Rehashing。

運作步驟(極重要,不可直接把舊資料搬過去):

  1. 擴大表格:建立一個新的陣列,大小通常是原表格的兩倍大並尋找下一個質數(例如原本 m = 7,新表格可能是 m新 = 17)。
  2. 改變雜湊函數:因為 m 變了,雜湊函數必須更新為 h新(k) = k mod 17。
  3. 重新計算與搬移:走訪舊表格中的每一筆資料,用「新的雜湊函數」重新計算它們在新表格中的 Index,並一筆一筆插入。

時間複雜度:因為要把 n 筆資料全部重新算過並搬移,所以 Rehashing 的時間複雜度為 O(n)。雖然是一項極度昂貴的操作,但因為不常發生(平攤分析 Amortized Analysis),整體而言平均搜尋時間仍能維持在 O(1)。

四、碰撞解決機制 (Collision Resolution)

當兩個不同的 Key 算出相同的 Index,即發生碰撞(Collision)。

陣營 A:開放定址法 (Open Addressing)

碰撞時,依據探測規則在表內尋找下一個空位。

  1. 線性探測法 (Linear Probing)
    • 公式:hᵢ(k) = (h(k) + i) mod m
    • 缺點:易產生主要聚集 (Primary Clustering),資料容易卡成一大塊。
  2. 二次探測法 (Quadratic Probing)
    • 公式:hᵢ(k) = (h(k) + i²) mod m
    • 缺點:解決主要聚集,但會產生次要聚集 (Secondary Clustering)。
  3. 雙重雜湊法 (Double Hashing)
    • 公式:hᵢ(k) = (h₁(k) + i · h₂(k)) mod m
    • 重點:效果最好。h₂(k) 絕對不能為 0,且必須與 m 互質。

陣營 B:鏈結法 (Chaining)

碰撞時,將資料串接在同一個儲存格的鏈結串列(Linked List)上。不會有「找不到空位」的問題。

五、高階觀念:雜湊表的陣列到底裝什麼?

1. 鏈結法(陣列 = 指標集合庫)

  • 儲存型態:陣列中的每一格,存放的都是一個指標(Pointer),指向 Linked List 的開頭。
  • C語言虛擬碼概念:Node* HashTable[100];

2. 開放定址法(陣列 = 實體資料集合庫)

  • 儲存型態:陣列的格子是直接用來存放「真實資料」或「結構體」,沒有任何指標。
  • C語言虛擬碼概念:Data HashTable[100];

六、開放定址法 vs. 鏈結法 終極比較表

比較項目開放定址法 (Open Addressing)鏈結法 (Chaining)
陣列內容物實體資料 (Data)指標 (Pointer)
空間使用只使用表格本身。需額外的動態記憶體配置 (Nodes)。
載入因子 α必須 ≤ 1可 > 1
刪除操作困難,需標記為「已刪除 (Tombstone)」,不可直接清空。簡單,直接移除 Linked List 中的節點。
聚集問題易發生 Primary/Secondary Clustering絕對不會發生聚集問題
適用場景資料量固定、記憶體空間極度受限時。資料量不可測、經常需要增刪資料時。

題目 3:雙重雜湊法

條件:大小 m = 7。h₁(k) = k mod 7。h₂(k) = 1 + (k mod 5)。依序插入:8, 15。

過程:

  • 8:8 mod 7 = 1 (放 Slot 1)。
  • 15:15 mod 7 = 1 (碰撞) → h₂(15) = 1 + (15 mod 5) = 1 → (1 + 1 · 1) mod 7 = 2 (放 Slot 2)。

條件:大小 m = 5。h(k) = k mod 5。依序插入:5, 12, 10, 22, 7。(新節點插入前端)
