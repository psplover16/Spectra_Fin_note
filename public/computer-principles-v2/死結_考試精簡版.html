死結 (Deadlock) — 考試精簡版

考前衝刺用。必要條件 → 策略比較 → 銀行家範例 → 高頻考點 → 選擇題。

一、死結的四個必要條件(中英文 + 解釋)

四個條件必須同時成立才會死結,破壞任一個就不會發生。

條件English解釋
互斥Mutual Exclusion資源一次只能一個程序用,不能共用。
持有並等待Hold and Wait抓著手上資源不放,同時又在等別的資源。
不可搶占No Preemption資源不能被強行搶走,只能由持有者自願釋放。
循環等待Circular Wait等待關係繞成一個環(A 等 B、B 等 C、C 等 A)。

步驟二:安全演算法(找安全序列)

Work = Available =(3,3,2)。反覆找「Need ≤ Work」的程序,跑完把它的 Allocation 加回 Work:

  • P1:Need(1,2,2)≤(3,3,2) ✔ → Work =(3,3,2)+(2,0,0)=(5,3,2)
  • P3:Need(0,1,1)≤(5,3,2) ✔ → Work =(5,3,2)+(2,1,1)=(7,4,3)
  • P0:Need(7,4,3)≤(7,4,3) ✔ → Work =(7,4,3)+(0,1,0)=(7,5,3)
  • P2:Need(6,0,0)≤(7,5,3) ✔ → Work =(7,5,3)+(3,0,2)=(10,5,5)
  • P4:Need(4,3,1)≤(10,5,5) ✔ → Work =(10,5,5)+(0,0,2)=(10,5,7)

全部跑完 → 安全狀態。安全序列 <P1, P3, P0, P2, P4>(可能不只一條)。

步驟三:資源請求演算法(該不該答應)

P1 請求 Request =(1,0,2),三步檢查:

  1. Request ≤ Need(P1)?(1,0,2)≤(1,2,2) ✔
  2. Request ≤ Available?(1,0,2)≤(3,3,2) ✔
  3. 試配置後再跑安全演算法:
  • Available =(3,3,2)−(1,0,2)=(2,3,0);Allocation(P1)=(3,0,2);Need(P1)=(0,2,0)
  • Work=(2,3,0)→P1✔→(5,3,2)→P3✔→(7,4,3)→P0✔→(7,5,3)→P2✔→(10,5,5)→P4✔→(10,5,7)
  • 仍安全 → 答應請求。

口訣:Request 先 ≤ Need、再 ≤ Available,最後試配置跑安全演算法;任一步不過就拒絕(讓它等)。

四、高頻考點速記

  • 破壞任一條件 → 不會死結;破壞循環等待(資源編號依序請求)最實用。
  • RAG:無環 → 無死結;有環且單一 instance → 必死結;有環且多 instance → 不一定。
  • 安全 → 一定無死結;不安全 → 可能死結。
  • 偵測:單一 instance 用等待圖 (RAG),有環即死結。
  • 復原:終止程序 或 資源搶占(可能 rollback)。
  • 鴕鳥策略 = 不理它,UNIX/Windows 實務上常用。

(B) 安全,序列 <P1, P0, P2>
(C) 安全,序列 <P0, P1, P2>
(D) 無法判斷

(A) 兩者都允許死結發生再處理
(B) 預防是靜態破壞條件,避免是動態判斷狀態
(C) 避免不需要任何額外資訊
(D) 預防一定比避免有效率

15. 關於循環等待 (Circular Wait),下列何者正確?
(A) 只要有兩個程序互等就一定是循環等待
(B) 它是指等待關係形成一個環
(C) 破壞它必須讓資源可共用
(D) 它與持有並等待是同一件事

解答與解析

題答解析
1D必要條件是「不可搶占」,不是「可搶占」;可搶占反而會破壞死結。
2C四條件必須同時成立,缺一不可。
3B銀行家演算法是死結「避免」的代表方法。
4C無環 → 一定無死結(絕對);有環則不一定(看 instance)。
5A單一 instance 時,有環就一定死結。
6BNeed = Max − Allocation。
7C安全 → 一定無死結;不安全才「可能」死結。
8D資源排序、依序請求是為了破壞循環等待。
9B只有「避免」(銀行家)需要事先知道最大需求。
10C死結罕見、處理成本高,實務上多用鴕鳥策略。
11B單一 instance 用等待圖,有環即死結。
12B復原靠終止程序或搶占資源。
13BAvailable=12−(5+2+2)=3;Need:P0=5、P1=2、P2=7。Work=3→P1(2)✔→5→P0(5)✔→10→P2(7)✔→12,安全,序列 <P1,P0,P2>。
14B預防=靜態破壞必要條件;避免=執行時動態判斷是否安全。
15B循環等待=等待關係繞成一個環,不等於「兩個程序互等」也不等於持有並等待。
