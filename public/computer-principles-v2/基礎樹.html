樹 (Tree)

基本術語

階層式(一對多)結構:資料呈一層一層的父子關係。幾個基本名詞:

  • 根 (Root):最上面、沒有父節點的那個節點,是整棵樹的入口。
  • 葉節點 (Leaf,又叫終端節點):沒有任何子節點的節點(即分支度 = 0),也就是樹最末端、往下再沒有東西的點。
  • 內部節點 (Internal Node):有子節點的節點(即非葉節點)。
  • 分支度 (Degree):一個節點的子節點數。
  • 階層 (Level):某個節點位在第幾層(根通常算第 1 層),講的是「單一節點」的深度。
  • 高度 (Height):從根到最深葉節點的最長路徑,講的是「整棵樹」的最大深度。
  • (Level 是單一節點的、Height 是整棵樹的,兩者不同,別混用。)
  • 重要性質:n 個節點的樹有 n − 1 條邊 (edge)。

拿後面走訪用的那棵樹來實際標一次:

              A        ← 第 1 層（根 root）
            /   \
          B       C    ← 第 2 層
         / \
        D   E          ← 第 3 層（最深）
  • 分支度 (Degree) = 一個節點有幾個子節點:
  • A 有 B、C 兩個 → 分支度 2;B 有 D、E 兩個 → 分支度 2。
  • C、D、E 沒有子節點 → 分支度 0(分支度 0 的就是葉節點 leaf)。
  • (整棵樹的分支度 = 所有節點裡最大的 = 2,所以它是「二元樹」。)
  • 階層 (Level) = 某節點在第幾層:A 在第 1 層;B、C 在第 2 層;D、E 在第 3 層。
  • 高度 (Height) = 從根到最深葉的最長路徑(整棵樹的最大深度):這棵最深到第 3 層 → 高度 3(用「層數」算);若改用「邊數」算(A→B→D 共 2 條邊)則為 2。

一句話:分支度看「一個節點有幾個小孩」、階層看「某節點在第幾層」、高度看「整棵樹最深幾層」。(這棵 5 個節點、4 條邊,符合 n−1。)

二元樹 (Binary Tree)

每個節點最多 2 個子節點。常見種類(Full 與 Perfect 的差別最愛考,務必分清):

  • 歪斜樹 (Skewed):每個節點最多只有 1 個子節點(整棵樹沒有分岔),全往一邊長,退化成像鏈結串列。分左歪斜、右歪斜。→ BST 的最壞情況。
  • 完滿二元樹 (Full / 嚴格二元樹):每個節點要嘛 0 個、要嘛 2 個子節點(不准只有 1 個)。注意:它不要求每層填滿,只要求「沒有只帶一個小孩的節點」。
  • 完美二元樹 (Perfect):每一層都完全填滿、所有葉節點都在同一層 → 共 h 層時有 2ʰ − 1 個節點(h 指層數;若題目把高度定義成邊數,同一棵樹改用 2^(h+1) − 1)。
  • 完整二元樹 (Complete):除最後一層外都滿,最後一層由左往右填(這是 heap 堆積的形狀)。

Full vs Perfect 用圖看:

完滿 Full(但不完美)            完美 Perfect
        A                          A
       / \                        / \
      B   C                      B   C
     / \                        / \ / \
    D   E                      D  E F  G

每個節點都 0 或 2 個小孩 ✓      每層都填滿、葉子同一層 ✓
但 C 那層沒填滿 → 不是完美      (它同時也是 Full)
  • 左邊每個節點都「0 或 2 個小孩」→ 是 Full;但沒填滿、葉子不同層 → 不是 Perfect。
  • 關係:完美 ⊂ 完滿(完美一定是完滿,完滿不一定完美);2ʰ − 1 這公式只對完美成立。

歪斜 Skewed每節點最多 1 個子節點退化成串列,最壞情況

二元樹的重要性質與公式(填空/選擇常考)

  • 第 i 層最多有 2^(i-1) 個節點(根為第 1 層)。例:第 3 層最多 2² = 4 個。
  • 高度(層數)h 的二元樹,最多有 2ʰ − 1 個節點(填滿就是完美二元樹)。
  • n 個節點的完整二元樹,高度 = ⌊log₂n⌋ + 1 層。
  • 葉節點數 = 分支度為 2 的節點數 + 1,即 n₀ = n₂ + 1(超常考的公式)。
  • 驗證前面那棵樹:葉節點 C、D、E 共 3 個(n₀=3),分支度 2 的節點 A、B 共 2 個(n₂=2)→ 3 = 2 + 1 ✓。

二元樹走訪 (Traversal)（最高頻,務必會)

四種走訪順序:

  • 前序 Preorder:根 → 左 → 右(N-L-R)
  • 中序 Inorder:左 → 根 → 右(L-N-R)
  • 後序 Postorder:左 → 右 → 根(L-R-N)
  • 層序 Level-order:一層一層由上而下

用這棵樹示範:

        A
       / \
      B   C
     / \
    D   E
走訪口訣順序
前序根左右A B D E C
中序左根右D B E A C
後序左右根D E B C A
層序一層層A B C D E

(推導前序:先根 A → 進左子樹 B(B→D→E)→ 再右子樹 C → A B D E C。其餘同理,差別只在「根」放在左、中、右哪個位置念。)

走訪的遞迴程式(三種幾乎一樣,差別只在 print 擺哪個位置)。先定義節點 Node 的資料格式——每個節點存一個資料 data,再加兩個指標 left、right 指向左、右子節點(沒有小孩時為 null):

class Node {
    int  data;    // 節點存的資料(這裡以整數為例)
    Node left;    // 指向左子節點,沒有則為 null
    Node right;   // 指向右子節點,沒有則為 null
}

有了這個節點格式,三種走訪就能對 n.data、n.left、n.right 進行遞迴:

void preorder(Node n) {   // 根左右
    if (n == null) return;
    print(n.data);            // ← 印在最前(根)
    preorder(n.left);
    preorder(n.right);
}
void inorder(Node n) {    // 左根右
    if (n == null) return;
    inorder(n.left);
    print(n.data);            // ← 印在中間(根)
    inorder(n.right);
}
void postorder(Node n) {  // 左右根
    if (n == null) return;
    postorder(n.left);
    postorder(n.right);
    print(n.data);            // ← 印在最後(根)
}

前中後序都用遞迴(屬深度優先 DFS);層序 (Level-order) 則用佇列 (Queue) 做 BFS:

void levelOrder(Node root) {
    Queue<Node> q = new LinkedList<>();
    q.offer(root);
    while (!q.isEmpty()) {
        Node n = q.poll();
        print(n.data);
        if (n.left  != null) q.offer(n.left);   // 左小孩排進佇列
        if (n.right != null) q.offer(n.right);  // 右小孩排進佇列
    }
}

由走訪結果重建二元樹(高頻計算題)

給你兩種走訪,可以倒推出整棵樹(進而求第三種走訪)。步驟:

  1. 前序的第一個、或後序的最後一個 = 根。
  2. 在中序裡找到這個根,根的左邊 = 左子樹、右邊 = 右子樹。
  3. 對左、右子樹遞迴重複。

例:前序 = A B D E C、中序 = D B E A C,求這棵樹:

  • 前序第一個 A = 根;中序用 A 切開 → 左 D B E、右 C。
  • 左子樹(前序取 B D E):第一個 B = 根;中序 D B E 用 B 切 → 左 D、右 E → B 左掛 D、右掛 E。
  • 右子樹只有 C。

得到:

    A
   / \
  B   C
 / \
D   E

於是後序 = D E B C A。

★ 陷阱:只有「前序+中序」或「後序+中序」能唯一決定一棵樹;「前序+後序」不行(分不出左右子樹,可能對應多棵樹)。

二元樹的陣列表示法(常考)

除了「節點 + 指標」,二元樹也能用一個陣列存(heap 就是這樣存的)。若根放在索引 1(1-based):

  • 節點 i 的 左子 = 2i、右子 = 2i + 1、父節點 = ⌊i / 2⌋。
      A(1)
     /    \
   B(2)    C(3)
   /  \
 D(4) E(5)

陣列:  [ _, A, B, C, D, E ]
索引:    0  1  2  3  4  5
  • 驗證:B 在索引 2 → 左子 2×2=4(D)、右子 2×2+1=5(E);D 的父 = ⌊4/2⌋=2(B)。✓
  • 優點:完整/完美二元樹沒有空洞,存陣列超省;缺點:歪斜或很稀疏的樹會浪費很多空格。

二元搜尋樹 (BST, Binary Search Tree)

規則:左子樹都比自己小、右子樹都比自己大。所以搜尋時每比一次就能砍掉一半。

  • 平均搜尋 O(log n)(因為左小右大、每次砍一半)。
  • 最壞 O(n):當資料按順序插入,BST 退化成歪斜樹(像一條鏈結串列),就失去砍半的優勢。
  • 關鍵考題:對 BST 做中序走訪 (Inorder),會得到由小到大排序的結果。
  • 改善退化:平衡樹(如 AVL、紅黑樹) 會透過旋轉維持左右高度平衡,避免退化成歪斜樹,保證 O(log n)。

BST 的插入與刪除:

  • 插入:從根開始比大小,比目前節點小往左、大往右,一路走到空位就掛上去。
  • 刪除分三種情況:
  1. 葉節點(沒有子節點):直接刪掉。
  2. 只有一個子節點:用那個子節點頂上來取代它。
  3. 有兩個子節點:不能直接刪(刪了兩個小孩不知掛誰),要找一個「大小最接近它、且不會破壞左小右大規則」的節點頂上來取代,再回頭刪掉那個被搬走的節點。這個替身有兩個選擇——中序後繼(右子樹的最小值)或中序前驅(左子樹的最大值),兩者擇一即可。(這是申論常客。)

為什麼是「右子樹最小」或「左子樹最大」? 因為對 BST 做中序走訪會由小到大排,要刪的節點在這串排序裡,緊接在它後面的(後繼)就是右子樹最小值、緊接在它前面的(前驅)就是左子樹最大值。用這兩個「鄰居」之一來頂替,排序順序幾乎不變,才不會破壞「左小右大」。

用例子走一遍(刪除有兩個小孩的節點 50):

            50            ← 要刪的節點(有左、右兩個小孩)
          /    \
        30      70
       /  \    /  \
      20  40  60   80
                \
                 65

做法一:用「中序後繼」= 右子樹的最小值

  • 到 50 的右子樹(根為 70),一路往左走到底找最小 → 70 → 60,60 沒有左小孩 → 後繼 = 60。
  • 把 60 的值搬去頂替 50,再刪掉原本的 60。60 只有一個右小孩 65,依「只有一個子節點」的規則讓 65 頂上來。
            60            ← 60 頂替了 50
          /    \
        30      70
       /  \    /  \
      20  40  65   80     ← 原本的 60 被刪,其右小孩 65 補上

做法二:用「中序前驅」= 左子樹的最大值

  • 到 50 的左子樹(根為 30),一路往右走到底找最大 → 30 → 40,40 沒有右小孩 → 前驅 = 40。
  • 把 40 搬去頂替 50,再刪掉原本的 40(它是葉節點,直接刪)。
            40            ← 40 頂替了 50
          /    \
        30      70
       /       /  \
      20      60   80
                \
                 65

兩種做法都對,得到的樹雖然長得不同,但都仍是合法的 BST(中序走訪一樣是 20 30 40 60 65 70 80,只少了 50)。這就是「找後繼/前驅取代」能維持排序性質的原因。

堆積 (Heap)

heap 是一棵「完整二元樹」,再加上父子大小規則:

  • 最大堆 (Max-Heap):每個節點都 ≥ 它的子節點 → 根最大。
  • 最小堆 (Min-Heap):每個節點都 ≤ 它的子節點 → 根最小。
  • 注意:heap 只規定「父子」的大小關係,兄弟之間、左右子樹之間沒有順序(這點跟 BST 不同,別搞混)。
  • 常用陣列表示(就是上面那套 2i、2i+1);用途:優先佇列 (Priority Queue)、堆積排序 (Heap Sort,O(n log n))。

圖形範例:最大堆 vs 最小堆(注意兩者都只要求「父 ≥ 子」或「父 ≤ 子」,兄弟大小不管):

   最大堆 Max-Heap（根最大）        最小堆 Min-Heap（根最小）
          90                              10
         /  \                            /  \
       70    80                        30    20
      /  \   /                        /  \   /
    40  60 75                       50  40 25

  每個父節點都 ≥ 兩個小孩 ✓        每個父節點都 ≤ 兩個小孩 ✓

看最大堆:90≥70、90≥80;70≥40、70≥60;80≥75 → 全部「父≥子」成立,所以根 90 是最大值。注意 70 和 80 是兄弟卻沒有規定誰大(70<80 也 OK),左子樹的 60 甚至比右子樹的 75 小 → heap 不管兄弟、不管左右子樹之間的大小(這正是跟 BST 最大的差別)。

陣列存法(根放索引 1,左子=2i、右子=2i+1):上面那個最大堆存成——

陣列: [ _, 90, 70, 80, 40, 60, 75 ]
索引:   0   1   2   3   4   5   6

  90(1) 的左子=2×1=2 → 70、右子=2×1+1=3 → 80 ✓
  70(2) 的左子=2×2=4 → 40、右子=5 → 60 ✓

反例(這不是 heap):

        50
       /  \
     80    30      ← 80 > 50,父比子小,違反 max-heap

因為 80 比它的父 50 大,破壞了「父 ≥ 子」,所以這棵不是最大堆(要成立就得把 80 換到根)。

插入示範(往最大堆插入 85)——「先放尾端,再往上浮 (sift-up)」:

① 先把 85 放到「完整二元樹的下一個空位」(60 的右邊):
          90
         /  \
       70    80
      /  \   / \
    40  60 75  85   ← 新來的 85 暫放尾端

② 85 和父節點 80 比:85 > 80 → 互換(往上浮一層):
          90
         /  \
       70    85      ← 85 浮上來、80 沉下去
      /  \   / \
    40  60 75  80

③ 85 再和新的父節點 90 比:85 < 90 → 停,插入完成。

堆積排序 (Heap Sort)

功能與目的:Heap Sort 是一種比較式排序法,把一堆亂序的數字排成由小到大。它的三個特點:

  • 穩定的 O(n log n):不論資料長什麼樣,最好、平均、最壞都是 O(n log n)(不像快速排序最壞會退化成 O(n²))。
  • 原地排序 (in-place):直接在原陣列上換位置,幾乎不用額外記憶體(O(1) 額外空間)。
  • 缺點:它不是穩定排序(相同值的前後順序可能被打亂),實務上的常數也比快排大一些。

核心構想:借用 max-heap「根一定是最大值」這個特性 ——一直把根(最大值)挖走、放到陣列尾端,挖 n 次,最大的先被推到最後、次大的推到倒數第二…… 從左看回來自然就由小到大。所以整個演算法只需要兩件事:①把資料整理成 max-heap;②反覆取出根並修復。

你只需要學會一個動作:往下沉 (sift-down)。當某個節點比它的小孩小(違反 max-heap)時,就把它跟「比較大的那個小孩」對調,一路往下換,直到它比小孩大或沉到底,heap 就修回合法:

根 1 比小孩小            1 跟較大的 5 對調         1 沉到底、沒小孩 → 停
      1                        5                        5
     / \    ──換 5──>         / \    ──到底──>         / \
    5   3                    1   3                    1   3
效果:根從 1 變回 5,新的最大值又浮回根

下面用 4 10 3 5 1 走一遍完整流程(目標:由小到大)。先記住:圖裡的「樹」和「陣列」是同一份資料的兩種畫法 —— 陣列由上到下、由左到右對應樹的節點,排序時其實一直都在動同一個陣列。

第一步:建最大堆 (Build Max-Heap)——先把原始 4 10 3 5 1 照陣列順序塞成一棵完整二元樹(此時還不是 heap),再把它調整成 max-heap。先看「前 → 後」概觀,詳細步驟在下面一步步拆:

原始資料當成完整二元樹        調整後的最大堆
        4                          10
       / \                        /  \
     10   3         ──>          5    3
     / \                        / \
    5   1                      4   1

陣列: [4,10,3,5,1]           陣列: [10,5,3,4,1]  ← 根 10 是最大

詳細步驟——先把節點按陣列位置編號(索引 i 的小孩 = 2i、2i+1):

索引: 1  2  3  4  5
值:   4  10 3  5  1

          4  ←索引1
         / \
   索引2 10   3 索引3
       / \
索引4 5   1 索引5

規則:從「最後一個有小孩的節點」開始,由後往前,對每個節點做一次 sift-down(往下沉);葉節點(沒有小孩)直接跳過。這裡 n=5,索引 3、4、5 都是葉節點,最後一個有小孩的是索引 2,所以處理順序是 索引 2 → 索引 1:

【處理 索引2 = 10】小孩是 5、1
   10 已經 ≥ 5、也 ≥ 1  →  已合法,不用動 ✔

【處理 索引1 = 4】小孩是 10、3  →  4 比小孩小,跟「較大的小孩 10」對調,然後 4 繼續往下沉:

      4                10                10
     / \    ─換 10→   / \    ─換 5→     / \
   10   3            4   3             5   3
   / \              / \               / \
  5   1            5   1             4   1
              4 沉到索引2,        4 又比小孩 5 小,
              小孩剩 5、1          再換 → 沉到底、停

   陣列:[4,10,3,5,1]  →  [10,4,3,5,1]  →  [10,5,3,4,1]

建堆完成,得到合法 max-heap [10,5,3,4,1]。逐一驗證「父 ≥ 子」:10≥5、10≥3、5≥4、5≥1 全部成立 → 最大值 10 已坐上根,「隨手取最大」的舞台架好了,接著進入第二步反覆取出根。

第二步:反覆取出最大值。重複下面三個動作,直到 heap 只剩 1 個。每做一輪,就有一個數字被永久鎖定在尾端:

  • ① 對調:把根(目前最大)和 heap 的最後一格對調 → 最大值被丟到尾端。
  • ② 縮小:把剛丟到尾端的那格踢出 heap 範圍(它已排好,之後不再碰),圖裡用 | 這條線的右邊表示「已排序區」。
  • ③ 往下沉修復:剛換上來當根的是個小數字,對它做一次 sift-down,讓剩下的部分變回合法 max-heap,新的最大值又浮到根,準備下一輪。

看圖時抓住兩件事:每一小格(①②③…)左邊是「對調前」、右邊是「往下沉修復後」;那條 | 分隔線會一輪一輪往左移,右邊的已排序區逐漸長大。

① 根 10 (最大) 與尾端 1 對調 → 10 歸位到最後,剩前 4 個重整:
      10 ⇄ 1                        5
      / \                          / \
     5   3       取出10後          4   3      已排序區:[10]
    / \          往下沉修復        /
   4  (1)→尾                     1
   陣列: [1,5,3,4 | 10]          陣列: [5,4,3,1 | 10]

② 根 5 與尾端 1 對調 → 5 歸位,剩前 3 個重整:
   取出 5 → 往下沉修復              4
                                  / \
                                 1   3       已排序區:[5,10]
   陣列: [3,4,1 | 5,10]          陣列: [4,1,3 | 5,10]

③ 根 4 與尾端 3 對調 → 4 歸位,剩前 2 個重整:
   陣列: [3,1 | 4,5,10]  → 修復 → 陣列: [3,1 | 4,5,10]（3≥1 已合法)

④ 根 3 與尾端 1 對調 → 3 歸位:
   陣列: [1 | 3,4,5,10]

⑤ 只剩 1 個,結束。最終:[1,3,4,5,10] ✓(由小到大)

逐輪看「圖案怎麼變」(| 右邊 = 已鎖定的已排序區):

  • ① 取出 10:根 10 ⇄ 尾端 1,10 鎖進尾端;前 4 格 [1,5,3,4] 對新根 1 做 sift-down → [5,4,3,1],5 浮上來當根。結果 [5,4,3,1 | 10]。
  • ② 取出 5:根 5 ⇄ 尾端,5 鎖進尾端;前 3 格修復 → 4 當根。結果 [4,1,3 | 5,10]。
  • ③ 取出 4:根 4 ⇄ 尾端 3,4 鎖進尾端;剩 [3,1] 本來就 3≥1 合法,不用動。結果 [3,1 | 4,5,10]。
  • ④ 取出 3:根 3 ⇄ 尾端 1,3 鎖進尾端。結果 [1 | 3,4,5,10]。
  • ⑤ 只剩 1 個 → 結束。最終 [1,3,4,5,10] ✓ 由小到大。

可以看到已排序區的數字是 10 → 5 → 4 → 3 一路「由大到小」從右往左填進去的,填滿之後,整個陣列剛好就變成由小到大。

重點:Heap Sort = 建 max-heap(架好「隨時取最大」的舞台)+ 反覆「取根 → 丟尾端 → 縮小 → 往下沉修復」。取 n 次、每次修復 O(log n) → 合計 O(n log n),而且是原地排序。用 max-heap 會排出「由小到大」(因為最大的先被丟到最後面)。

Java 實作範例——把上面兩步驟(建堆 + 反覆取根)直接寫成程式,用同一組資料 {4,10,3,5,1} 驗證:

public class HeapSort {

    // 對外:把整個陣列排成「由小到大」
    public static void heapSort(int[] a) {
        int n = a.length;

        // 【第一步】建最大堆:從最後一個「有小孩的節點」往前,逐一往下沉
        // 註:程式是 0-based,最後一個非葉節點 = n/2 - 1
        //     (對應圖上 1-based 的索引 2,這裡就是 index 1)
        for (int i = n / 2 - 1; i >= 0; i--) {
            siftDown(a, n, i);
        }

        // 【第二步】反覆取出根(最大值)放到尾端
        for (int end = n - 1; end > 0; end--) {
            swap(a, 0, end);       // ① 根(最大)換到目前尾端 → 鎖定
            siftDown(a, end, 0);   // ② 縮小範圍成 end + ③ 對新根往下沉修復
        }
    }

    // 往下沉:把 index i 一路和「較大的小孩」對調,直到「父 ≥ 子」或到底
    // n = 目前 heap 的有效大小(尾端已排序區不算在內)
    private static void siftDown(int[] a, int n, int i) {
        while (true) {
            int largest = i;           // 先假設自己最大
            int left  = 2 * i + 1;     // 0-based 左小孩
            int right = 2 * i + 2;     // 0-based 右小孩

            // 「< n」是邊界檢查:確認這個小孩「存在且可碰」才去比較,擋住兩件事——
            //   ① 索引越界:葉節點的 2i+1 會超過陣列 → 讀到不存在的小孩會當掉
            //   ② 誤碰已排序區:n 是 heap 目前大小,index >= n 是尾端排好的值,不能換回來
            if (left  < n && a[left]  > a[largest]) largest = left;   // 左小孩比目前最大還大?
            if (right < n && a[right] > a[largest]) largest = right;  // 右小孩比目前最大還大?

            if (largest == i) break;   // 父已比兩個小孩都大 → 合法,停

            swap(a, i, largest);       // 和較大的小孩對調
            i = largest;               // 位置下移,繼續往下沉
        }
    }

    private static void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }

    public static void main(String[] args) {
        int[] a = {4, 10, 3, 5, 1};
        heapSort(a);
        System.out.println(java.util.Arrays.toString(a));
        // 輸出:[1, 3, 4, 5, 10]
    }
}

對照前面的圖:heapSort 裡第一個迴圈就是第一步(建堆)、第二個迴圈就是第二步(反覆取根);而 siftDown 正是那個「一路和較大的小孩對調」的往下沉動作 —— 三處都對得上。

小提醒:圖用 1-based(根在索引 1、小孩 = 2i、2i+1)方便講解;程式用 0-based(根在索引 0、小孩 = 2i+1、2i+2、最後一個非葉節點 = n/2 − 1)。兩者只是編號起點不同,邏輯完全一樣。實務上若只是要用 heap(不是自己排序),也可以直接用 java.util.PriorityQueue(預設是 min-heap)。

為什麼完整的 heapSort 是 O(n log n)? 拆成兩步看,「取根」那步主導整體:

  • 地基:一次 sift-down = O(log n)。往下沉最多從根換到葉,走過的層數 = 樹高;n 個節點的完整二元樹高度約 log₂n(n=100 萬 → 樹高才約 20),所以一次修復最多 O(log n)。
  • 第二步 反覆取根 = O(n log n)(主角):迴圈跑 n−1 次,每圈 swap 是 O(1)、siftDown 是 O(log n) → (n−1) × O(log n) = O(n log n)。
  • 第一步 建堆(配角):約 n/2 次 sift-down,用寬鬆上界 O(n log n) 就足以下結論;其實有更緊的分析是 O(n)(越底層的節點越多、但能往下沉的高度越矮,加權總和收斂成 O(n),考試常直接記「建堆 = O(n)」)。
T(n) =   O(n)      +   O(n log n)     =   O(n log n)
         ↑建堆           ↑取 n 次根          ↑取兩者中成長較快的那項

而且最好、平均、最壞都是 O(n log n):不管資料原本長怎樣,樹高永遠是 log n、取根一定取 n 次,沒有「運氣好變快、運氣壞變慢」——這正是 heap sort 比快速排序(最壞 O(n²))穩定的地方。

★ 樹常考重點:

  • n 個節點 → n − 1 條邊;完美二元樹 h 層 → 2ʰ − 1 個節點;第 i 層最多 2^(i-1) 個。
  • 葉節點數 = 分支度 2 的節點數 + 1(n₀ = n₂ + 1)。
  • 三種走訪差別只在「根」的位置:前序=根在前、中序=根在中、後序=根在後;層序用佇列 (BFS)。
  • 重建樹:前序/後序找根 + 中序切左右;「前序+後序」無法唯一決定。
  • 陣列表示:節點 i → 左子 2i、右子 2i+1、父 ⌊i/2⌋。
  • BST 中序走訪 = 由小到大排序;平均 O(log n)、最壞 O(n)(退化,用平衡樹/AVL 解)。
  • Heap = 完整二元樹 + 父子大小關係(max-heap 根最大);只管父子、不管兄弟。
